# 체험 서버 공식 템플릿

체험 서버(`conf.json` 의 `trial`)의 갤러리에 나오는 템플릿입니다. 파일 하나가 템플릿 하나이고,
이 폴더의 `*.json` 을 모두 읽습니다. 파일을 고치면 앱을 다시 시작하지 않아도 다음 화면부터 반영됩니다.

템플릿은 **시작하기 전의 대화 한 벌**입니다 — 누가(참여자), 어떤 방식으로(토론 방식·횟수), 무엇을
묻고(입력 칸), 그 답을 어떤 요청문으로 바꿀지(요청문 틀).

설정 파일과 같은 규칙으로 읽습니다. `//` 로 시작하는 키는 설명이고, 여러 줄 글은 문자열 배열로 적을 수
있습니다 (한 줄이 한 항목). 깨진 파일은 갤러리에서 빠지고, 이유는 운영자 화면(`/trial/admin`)에 나옵니다.

## 항목

| 키 | 필수 | 뜻 |
| :--- | :---: | :--- |
| `id` | | 영문·숫자·`-`·`_`. 비우면 파일 이름. 방문자의 기록과 통계가 이 값으로 템플릿을 가리키므로 바꾸지 마세요 |
| `title` | ✓ | 갤러리 카드 제목 (80자) |
| `summary` | | 카드의 한 줄 설명 |
| `category` | | 갤러리의 분류 칩 (예: `문서 검토`) |
| `order` | | 갤러리 순서. 작을수록 앞 (기본 100) |
| `estimated_minutes` | | 카드에 보이는 예상 시간 |
| `strategy` | | `sequential_debate`(차례로 검토) · `adversarial_debate`(찬반 대결) · `orchestrator_led`(사회자가 지휘) · `parallel_dispatch`(동시에 의견 내기). 그래프 토론은 체험에서 쓰지 않습니다 |
| `max_rounds` | | 토론 횟수 (1–10). 느린 사내 LLM 에서는 1–2 를 권합니다 |
| `result_hint` | | 시작 화면의 "결과로 받는 것" |
| `custom_instructions` | | 모든 참여자에게 주는 지침 |
| `participants` | ✓ | 참여자 목록 (아래). `key: orchestrator` 인 사회자가 반드시 있어야 하고, 그 밖에 한 명 이상 |
| `inputs` | ✓ | 시작 양식의 입력 칸 (아래) |
| `prompt` | ✓ | 요청문 틀. `{입력 칸 id}` 자리에 방문자가 적은 값이 들어갑니다. 비운 선택 칸은 `(없음)` |
| `example` | | "예시로 채우기" 가 넣을 값 (`{입력 칸 id: 값}`) |
| `followups` | | 결과 화면의 "이어서 요청하기" 단추 문구 |

### 참여자 (`participants`)

| 키 | 뜻 |
| :--- | :--- |
| `key` | 영문 소문자로 시작하는 식별자. 사회자는 `orchestrator` |
| `base` | 모델·엔드포인트·키를 빌려 올 conf.json 에이전트. 비우면 같은 키의 에이전트, 없으면 `orchestrator` |
| `name`, `role` | 카드에 보이는 이름과 한 줄 역할 |
| `system_prompt` | 이 참여자가 무엇을 보고 어떻게 말하는지. 비우면 `base` 의 것을 씁니다 |
| `stance` | `proponent` · `critic` · `neutral` — 찬반 대결에서의 편 |
| `color`, `icon` | 카드 색(`#rrggbb` 또는 Quasar 색 이름)과 Material 아이콘 이름 |

참여자는 목록 순서대로 발언합니다 (사회자는 늘 맨 앞). **도구는 붙지 않습니다** — `base` 에이전트에
`allowed_mcp_servers` 가 있어도 체험 대화에서는 비웁니다.

### 입력 칸 (`inputs`)

| 키 | 뜻 |
| :--- | :--- |
| `id` | 요청문 틀에서 `{id}` 로 가리킬 이름 |
| `label` | 칸 제목 |
| `kind` | `long_text`(여러 줄, 기본) 또는 `text`(한 줄) |
| `required` | 비우면 시작할 수 없는 칸인지 (기본 true) |
| `placeholder`, `help` | 칸 안의 예시 글과 칸 아래 도움말 |
| `allow_file` | `.txt`·`.md`·`.csv` 파일에서 내용을 가져오는 단추를 붙입니다 (UTF-8·CP949) |

## 잘 만드는 법

- 사회자의 `system_prompt` 에 **최종 정리의 형식**을 적으세요 (예: 한 줄 총평 → 고칠 점 표 → 수정안).
  결과 화면의 주인공이 그 정리입니다.
- 참여자는 서로 **겹치지 않는 관점**으로 셋 안팎이 적당합니다. 많을수록 느려집니다.
- `example` 은 시작 양식을 그대로 통과해야 합니다 (필수 칸을 모두 채우기). 테스트가 확인합니다.
- 운영자 화면의 "미완료" 와 "아쉬워요" 가 많은 템플릿부터 고치세요.
