# ADR-026. 스킬은 MCP 서버가 아닌 호스트 도구로 실시간 제공합니다

> [ADR 목록](README.md) · 이전: [ADR-025](ADR-025-resume-speeches-by-tool-step.md)

## 상태 (Status)

채택됨 · 2026-09-30 · 관련: [ADR-002](ADR-002-litellm-gateway.md), [ADR-003](ADR-003-mcp-tool-protocol.md), [ADR-006](ADR-006-airgap-first-packaging.md), [ADR-011](ADR-011-session-config-snapshot.md)

## 맥락 (Context)

- 조직마다 표준화된 작업 방식이 존재합니다. 다이어그램 작성 규칙, 보고서 양식, 코드 검토 체크리스트 등이 대표적입니다. 기존에는 이러한 지침을 에이전트의 `system_prompt`나 세션 맞춤 지침에 직접 붙여넣어야 했습니다. 이 방식은 해당 지침이 불필요한 발언에도 상시 포함되어 토큰을 낭비하고, 에이전트마다 중복 복사하여 개별 수정해야 하는 관리 비효율을 초래합니다.
- Anthropic의 Agent Skills 규격이 사실상의 표준으로 자리 잡았습니다. 독립 폴더 내에 YAML 머리말(name, description)이 포함된 `SKILL.md`를 배치하고, 평소에는 요약 설명만 인지시키다가 작업이 부합할 때 본문 지침을 불러와 참조하는 방식(점진적 공개, Progressive Disclosure)입니다. 모델 자체의 특화 기능이 아니라 프롬프트 안내와 파일 조회로 동작하므로 모델 종류를 가리지 않습니다. 다만 Anthropic API에 내장된 스킬 기능은 Claude 전용이자 원격 컨테이너 기반이므로, LiteLLM 게이트웨이 기반 폐쇄망 모델([ADR-002](ADR-002-litellm-gateway.md))에는 직접 활용할 수 없습니다.
- 시스템 연동 방안으로는 세 가지 대안을 검토하였습니다.
  - **작업 공간에 배치하고 filesystem 도구로 조회하는 방안:** 애플리케이션 코드를 수정할 필요가 없다는 장점이 있습니다. 그러나 대화 세션마다 작업 공간이 다를 수 있어 스킬 파일을 매번 복사해야 하고, 파일 쓰기 도구를 가진 에이전트가 스킬 원본을 변조할 위험이 있으며, 스킬 목록을 시스템 프롬프트에 수동으로 작성해야 하는 한계가 있습니다.
  - **스킬 전용 MCP 서버를 구축하는 방안:** 기존 도구 루프, 감사 기록, UI 접이식 카드 체계를 그대로 활용할 수 있습니다([ADR-003](ADR-003-mcp-tool-protocol.md)). 그러나 MCP 서버의 도구 목록은 프로세스 기동 시 1회 고정되므로, 호출 주체와 무관하게 동일한 목록을 제공하게 됩니다. 따라서 에이전트별 차등 할당이나 런타임 동적 변경 목록을 지원할 수 없습니다.
  - **호스트 엔진이 스킬 도구를 직접 제공하는 방안:** 에이전트별 권한 필터링과 실시간 변경 사항을 완벽하게 수용할 수 있습니다.
- 사용자 요구사항 및 설계 제약:
  - 스킬은 **실시간 동적 반영**을 지원해야 합니다. 대화 세션 스냅샷([ADR-011](ADR-011-session-config-snapshot.md))에 고정하지 않고 활성화/비활성화 상태를 유연하게 제어합니다.
  - 에이전트별로 사용할 스킬을 선별적으로 지정할 수 있어야 합니다(`allowed_skills`).
  - 스크립트가 포함된 스킬은 작업 공간에 복사한 뒤 실행 도구(`run_python_file`)를 통해 안전하게 실행해야 합니다.

## 결정 (Decision)

**스킬은 `skills/<이름>/SKILL.md` 디렉터리 구조로 정의하며, MADO 호스트 엔진이 `skills__load_skill` 및 `skills__read_skill_file` 두 도구를 통해 에이전트에 직접 제공합니다.**

- 스킬 목록(이름 및 설명)은 `load_skill` 도구의 파라미터 설명에 탑재합니다. 본문 지침은 해당 도구를 호출할 때 전달하며, 부속 문서는 `read_skill_file` 도구를 통해 필요한 경우에만 선별 조회합니다. 스킬 도구를 보유한 에이전트의 시스템 프롬프트에만 "부합하는 스킬이 있으면 먼저 호출하여 지침을 준수하십시오"라는 상시 지침을 추가합니다.
- 에이전트에게 노출되는 스킬은 `allowed_skills` ∩ 활성화된 스킬 ∩ 오류가 없는 스킬의 교집합입니다. 이 카탈로그는 **매 발언 시점마다** 스킬 디렉터리와 `skills.disabled` 설정을 다시 스캔하여 구성합니다. `load_skill` 도구는 실제 호출되는 순간에도 가용 여부를 다시 검증합니다.
- **스냅샷 고정 항목과 비고정 항목의 분리:** 스킬 본문 내용, 디렉터리 추가/삭제, 활성화/비활성화 상태는 스냅샷에 고정하지 않습니다. 진행 중인 대화 세션에도 다음 발언부터 즉시 반영되며, 이는 MCP 서버 활성화/비활성화 정책과 동일한 예외를 적용한 것입니다. 반면 `allowed_skills`는 에이전트 구성 속성이므로 `allowed_mcp_servers`와 마찬가지로 대화 시작 시점에 스냅샷으로 고정됩니다.
- 스킬 도구는 **별도의 도구 보안 판정(승인 카드)을 거치지 않습니다.** 설치 디렉터리에 보관된 운영자의 지침 파일을 호스트 엔진이 대리로 조회할 뿐이며, 작업 공간 파일이나 외부 네트워크에 직접 접근하지 않기 때문입니다. 사용 권한 역시 `allowed_skills` 및 활성화 여부로 통제됩니다. 파일 읽기는 해당 스킬 디렉터리 내부로 엄격히 한정하며 상위 디렉터리 참조(`..`), 절대 경로, 숨김 파일, 외부 심볼릭 링크는 모두 거부합니다.
- **스크립트 실행 생명주기:** 스킬 폴더는 설치 디렉터리 내에 위치하므로 에이전트의 일반 도구 접근이 차단됩니다 (고정 보호 정책). 따라서 스크립트가 포함된 스킬을 실행 도구를 보유한 에이전트가 호출하면, 해당 스킬 폴더를 이번 대화 세션의 작업 공간 `.mado/skills/<이름>/` 디렉터리로 복사하고 실행 경로를 안내합니다. 실제 스크립트 실행은 샌드박스 도구를 통해 이루어지므로 사전 코드 검사 및 도구 보안 승인 정책이 정상 적용됩니다. 호출 시마다 변경된 파일만 선별 복사하며, 원본에 없는 추가 생성 파일은 보존합니다 (스크립트 실행 결과물 보호). 실행 도구가 없는 에이전트에게는 스크립트를 복사하지 않습니다.
- `skills`는 MCP 서버 식별자로 등록할 수 없습니다. 도구 접두사 `skills__…` 충돌을 방지하기 위함입니다.
- YAML 머리말은 스킬 정의에 실제로 필요한 부분 집합(`key: value`, 따옴표, `|` 및 `>` 블록 스칼라, 들여쓰기된 연속 줄)만을 파싱하는 자체 내장 경량 파서를 사용합니다. 폐쇄망 배포 환경에서 불필요한 서드파티 라이브러리 의존성을 배제하기 위함입니다([ADR-006](ADR-006-airgap-first-packaging.md)).

## 결과 (Consequences)

**긍정적 효과**

- 조직 표준 작업 방식을 디렉터리 단위로 간편하게 설치, 수정, 비활성화할 수 있습니다. 수정한 지침은 진행 중인 대화 세션에도 즉시 적용됩니다.
- 매 발언마다 소비되는 프롬프트 비용이 스킬 요약 설명 몇 줄로 최소화됩니다. 상세 본문 지침은 실제 필요한 발언에만 동적으로 주입됩니다.
- 특정 LLM 프로바이더에 종속되지 않습니다. Function Calling을 지원하는 모델이라면 폐쇄망의 로컬 모델에서도 동일하게 동작합니다.
- 기존 도구 루프, 실행 기록, 접이식 카드 UI, 중단된 발언 이어가기 메커니즘([ADR-025](ADR-025-resume-speeches-by-tool-step.md))과 완벽히 호환됩니다.

**고려 사항 및 제약**

- 불러온 본문 지침은 해당 발언의 도구 루프 컨텍스트 내에서만 유효합니다. 후속 발언자의 컨텍스트에는 도구 실행 결과가 포함되지 않으므로, 다음 차례 발언자가 동일 지침을 필요로 할 경우 다시 호출해야 합니다.
- 스킬 내용을 수정하면 진행 중인 대화 세션의 에이전트 동작이 변경될 수 있습니다. 이는 의도된 동작이며, 발언 시점에 참조한 실제 지침 내용은 도구 감사 기록에 보존되므로 사후 추적이 가능합니다.
- 스킬 조회 도구 자체는 보안 판정 대상에서 제외됩니다. 스킬 디렉터리에 신뢰할 수 있는 내용만을 배치하는 것은 운영자의 관리 영역입니다. 단, 보조 스크립트의 **실제 실행**은 도구 보안 판정 체계 내에서 철저히 관리됩니다.
- 샌드박스의 `run_python_file` 도구는 별도의 명령줄 인자를 지원하지 않습니다. 따라서 스킬 스크립트는 인자 없이 실행되거나, 작업 공간 내 파일 입출력을 통해 데이터를 주고받도록 설계해야 합니다.
- 스크립트 소스 코드 내부의 문자열도 사전 보안 검사를 거칩니다. 경로 형태의 문자열은 잠재적 파일 읽기로 분석되므로, 건너뛸 디렉터리명으로 `.memory-graphs` 등을 직접 기재하면 고정 보호 정책에 의해 실행이 차단됩니다. 예제 스크립트와 같이 첫 글자(`.`) 패턴을 기준으로 필터링해야 합니다.
