# ADR-026. 스킬은 MCP 서버가 아니라 호스트 도구로, 실시간으로 준다

> [ADR 목록](README.md) · 이전: [ADR-025](ADR-025-resume-speeches-by-tool-step.md)

## 상태 (Status)

채택됨 · 2026-09-30 · 관련: [ADR-002](ADR-002-litellm-gateway.md), [ADR-003](ADR-003-mcp-tool-protocol.md), [ADR-006](ADR-006-airgap-first-packaging.md), [ADR-011](ADR-011-session-config-snapshot.md)

## 맥락 (Context)

- 조직마다 정해 둔 작업 방식이 있습니다. 다이어그램 규칙, 보고서 양식, 검토 목록 같은 것입니다. 지금은 이것을 에이전트의 `system_prompt`나 세션 지침에 붙여 넣는 수밖에 없습니다. 그러면 필요 없는 발언에도 전부 실리고, 에이전트마다 복사해 따로 고쳐야 합니다.
- Anthropic의 Agent Skills 모양이 사실상 표준이 되었습니다. 폴더 하나에 머리말(name, description)이 달린 `SKILL.md`를 두고, 평소에는 설명만 보여 주다가 일이 맞을 때 본문을 불러 읽게 하는 방식(점진적 공개)입니다. 모델의 기능이 아니라 프롬프트와 파일 읽기로 이루어지므로 모델을 가리지 않습니다. 다만 Anthropic API에 내장된 스킬 기능은 Claude와 코드 실행 컨테이너 전용이라, LiteLLM 뒤의 폐쇄망 모델([ADR-002](ADR-002-litellm-gateway.md))에는 쓸 수 없습니다.
- 넣는 방법은 셋이었습니다.
  - **작업 공간에 두고 filesystem 도구로 읽게 한다.** 코드를 고칠 필요가 없습니다. 하지만 대화마다 작업 공간이 다를 수 있어 스킬을 복사해 다녀야 하고, 쓰기 도구를 가진 에이전트가 스킬을 고칠 수 있고, 목록을 시스템 프롬프트에 손으로 적어야 합니다.
  - **스킬 MCP 서버를 하나 둔다.** 도구 루프·기록·접이식 카드를 그대로 탑니다([ADR-003](ADR-003-mcp-tool-protocol.md)). 하지만 서버의 도구 목록은 기동할 때 한 번 받고 부르는 쪽과 무관합니다. 에이전트마다 다른 목록도, 앱이 도는 중에 바뀌는 목록도 담을 수 없습니다.
  - **호스트가 도구를 직접 만든다.**
- 사용자가 정한 것:
  - 스킬은 **실시간**입니다. 대화 스냅샷([ADR-011](ADR-011-session-config-snapshot.md))에 굳히지 않고 켜기·끄기로 다룹니다.
  - 에이전트마다 쓸 스킬을 정합니다(`allowed_skills`).
  - 스크립트가 든 스킬은 작업 공간에 복사해 실행 도구(`run_python_file`)로 돌립니다.

## 결정 (Decision)

**스킬은 `skills/<이름>/SKILL.md` 폴더이고, 호스트가 `skills__load_skill`과 `skills__read_skill_file` 두 도구로 에이전트에게 줍니다.**

- 목록(이름과 설명)은 `load_skill`의 도구 설명에 싣습니다. 본문은 그 도구를 부를 때, 부속 파일은 `read_skill_file`로 필요할 때만 읽습니다. 스킬 도구를 가진 에이전트에게만 "맞는 스킬이 있으면 먼저 불러 따르라"는 두 줄을 시스템 프롬프트에 더합니다.
- 에이전트가 보는 스킬은 `allowed_skills` ∩ 켜진 스킬 ∩ 깨지지 않은 스킬입니다. 이 목록은 **발언마다** 스킬 폴더와 `skills.disabled`를 다시 읽어 만듭니다. `load_skill`은 부르는 순간에도 한 번 더 확인합니다.
- **굳히는 것과 굳히지 않는 것.** 스킬의 내용, 폴더의 추가·삭제, 켜기·끄기는 굳히지 않습니다. 진행 중인 대화에도 다음 발언부터 걸립니다. MCP 서버 켜기·끄기와 같은 예외입니다. `allowed_skills`는 에이전트 설정이라 `allowed_mcp_servers`처럼 대화가 시작될 때 굳습니다.
- 스킬 도구는 **도구 보안 판정을 거치지 않습니다.** 설치 폴더 안에 있는 운영자의 지침 파일을 호스트가 대신 읽을 뿐이고, 작업 공간과 네트워크에는 닿지 않습니다. 누가 쓸지는 `allowed_skills`와 켜기·끄기로 이미 정했습니다. 읽기는 그 스킬의 폴더 안으로 한정합니다(`..`, 절대 경로, 숨김 파일, 폴더 밖을 가리키는 링크는 거부).
- **스크립트.** 스킬 폴더는 설치 폴더 안이라 에이전트의 도구가 닿지 않습니다(고정 보호). 그래서 스크립트가 든 스킬을 실행 도구를 가진 에이전트가 불러오면, 폴더를 그 대화의 작업 공간 `.mado/skills/<이름>/`으로 복사하고 실행할 경로를 알려 줍니다. 실행은 샌드박스 도구로 하므로 코드 검사와 승인을 그대로 거칩니다. 복사본은 부를 때마다 원본에 맞춥니다.
- `skills`는 MCP 서버 이름으로 쓸 수 없습니다. 도구 이름 `skills__…`가 겹치기 때문입니다.
- 머리말은 스킬에 실제로 쓰이는 YAML의 부분 집합(`key: value`, 따옴표, `|`·`>` 블록, 이어지는 줄)만 직접 읽습니다. 폐쇄망 번들에 YAML 라이브러리를 더하지 않기 위해서입니다([ADR-006](ADR-006-airgap-first-packaging.md)).

## 결과 (Consequences)

**좋은 점**

- 조직의 작업 방식을 폴더 하나로 설치하고, 고치고, 끌 수 있습니다. 고친 지침은 진행 중인 대화에도 바로 닿습니다.
- 발언마다 드는 비용은 스킬 설명 몇 줄입니다. 본문은 필요한 발언에만 실립니다.
- 모델을 가리지 않습니다. 도구 호출만 되면 폐쇄망의 로컬 모델도 씁니다.
- 기존 도구 루프·호출 기록·접이식 카드·끊긴 발언 이어 가기([ADR-025](ADR-025-resume-speeches-by-tool-step.md))를 그대로 탑니다.

**대가**

- 불러온 본문은 그 발언의 도구 루프 안에만 있습니다. 다음 발언자의 맥락에는 도구 결과가 들어가지 않으므로, 다음 차례에 필요하면 다시 불러야 합니다.
- 진행 중인 대화의 동작이 스킬 수정으로 바뀔 수 있습니다. 의도한 것입니다. 무엇을 보고 답했는지는 도구 기록에 불러온 본문이 남아 있어 추적할 수 있습니다.
- 스킬 도구는 보안 판정 밖에 있습니다. 스킬 폴더에 무엇을 넣을지는 운영자의 책임입니다. 스크립트 **실행**은 판정 안에 있습니다.
- 샌드박스의 `run_python_file`은 인자를 받지 않습니다. 스킬의 스크립트는 인자 없이 돌거나, 입력을 작업 공간의 파일에서 읽도록 써야 합니다.
