# ADR-017. 저장 실패로 결과물을 잃지 않는다

> [ADR 목록](README.md) · 이전: [ADR-016](ADR-016-per-workspace-mcp-runtime.md) · 다음: [ADR-018](ADR-018-orchestrator-writes-conclusions.md)

## 상태 (Status)

채택됨 · 2026-09-13 (v0.7.1) · 관련: [ADR-004](ADR-004-sqlite-persistence.md), [ADR-014](ADR-014-tool-failure-is-observation.md)

## 맥락 (Context)

사용자가 자리를 비워 화면이 잠긴 사이, 최종 합성 보고서가 `database is locked`로 저장되지 않았습니다. 보고서는 화면에
흘러갔기 때문에 아무 이상이 없어 보였고, 새로고침하자 사라졌습니다. 원인은 두 가지였고, 어느 하나만으로도 잃기에
충분했습니다.

1. **SQLite를 기본값으로 썼습니다.** 잠금을 5초만 기다렸고, 기록할 때마다 저널 파일을 만들었다 지웠습니다. Windows에서는
   다른 프로세스가 연 파일을 교체할 수 없어서, 백신 검사, 검색 색인, 백업·동기화 프로그램이 DB 파일을 몇 초만 열어도
   기록이 실패합니다. Windows는 바로 그런 작업을 사용자가 없을 때 돌립니다.
2. **기록 실패를 로그 한 줄로 남기고 버렸습니다.** 발언 하나 저장에 실패했다고 토론을 멈추면 뒤의 발언을 모두 잃으니,
   의도는 옳았습니다. 문제는 최종 합성도 같은 길을 탔다는 것입니다.

덧붙여, DB 설명 문서에는 코드에 없는 WAL 설정이 적혀 있었습니다. 문서와 코드가 달랐던 것도 원인을 늦게 찾은 이유입니다.

## 결정 (Decision)

**기다리고, 다시 시도하고, 그래도 안 되면 다른 곳에 보존하고 알린 뒤 계속 간다.**

연결 설정

- 연결마다 잠금 대기 30초, WAL 저널 모드, 동기화 수준 NORMAL을 건다.
- DB가 **네트워크 위치**(UNC 경로, 네트워크 드라이브)에 있으면 WAL을 켜지 않는다. WAL은 공유 메모리로 조율하는데 네트워크
  파일 시스템은 이를 보장하지 않아 파일이 깨질 수 있다. 대기 시간은 그래도 적용한다.

기록 경로

- 엔진의 모든 기록(발언과 도구 기록, 산출물, 사용자 발언, 안내 메모)을 **하나의 저장 경로**로 모은다.
- 실패하면 롤백하고 2초, 5초 뒤 다시 시도한다(SQLite 대기 위에 얹힌다). 롤백하면 넣었던 객체가 분리되므로 시도마다
  같은 ID로 행을 새로 만든다.
- 끝내 실패하면 내용을 앱 데이터 폴더의 미저장 폴더에 마크다운으로 쓴다. 머리에 세션 ID와 오류를 적고, 최종 합성은
  파일 이름에 `synthesis`를 넣어 가장 먼저 찾게 한다.
- 닫을 때까지 남는 알림을 띄운다.
- 예외를 올리지 않는다(취소만 예외). 기록 실패가 토론을 멈추면 앞으로의 발언을 모두 잃는다.

문서

- DB 설명 문서를 코드가 실제로 하는 일에 맞춘다.

## 결과 (Consequences)

**좋아지는 것**

- 다른 연결이 7초 동안 쓰기 잠금을 잡은 상태에서 쟀습니다. 고치기 전에는 5.5초 만에 `database is locked`로 실패했고,
  고친 뒤에는 7초를 기다렸다가 성공했습니다.
- 최악의 경우에도 결과물이 파일로 남고, 사람이 그 사실을 압니다.

**치르는 비용**

- WAL 모드는 DB 옆에 `-wal`, `-shm` 파일을 만듭니다. 패키징 스크립트는 이미 이 파일들을 빼고 있었습니다.
- 네트워크 드라이브에 둔 DB는 여전히 잠금에 약합니다. 운영 문서에 "DB는 로컬 디스크에, 가능하면 백신 실시간 검사와 동기화
  대상에서 제외"를 적었습니다.
- 미저장 파일을 DB로 되돌리는 기능은 없습니다. 사람이 읽고 필요하면 옮깁니다.

**교훈**

- 알림은 **그 일이 일어나는 상황**에 맞아야 합니다. 이 실패는 대개 아무도 보지 않을 때 일어나고, 몇 초 뒤 사라지는
  알림은 그때 아무 쓸모가 없습니다.
- "실패하면 버린다"와 "실패하면 멈춘다" 사이에 세 번째 선택지가 있습니다. **다른 곳에 보존하고, 알리고, 계속 간다.**
