# ADR-002. 모든 LLM 호출은 LiteLLM을 거친다

> [ADR 목록](README.md) · 이전: [ADR-001](ADR-001-python-single-process.md) · 다음: [ADR-003](ADR-003-mcp-tool-protocol.md)

## 상태 (Status)

채택됨 · 2026-08-26 (초기 설계) · 관련: [ADR-007](ADR-007-no-simulated-answers.md), [ADR-015](ADR-015-reasoning-out-of-prompts.md)

## 맥락 (Context)

- 에이전트마다 다른 모델을 쓰는 것이 이 시스템의 전제입니다. 서로 다른 모델이 토론해야 한 모델의 맹점을
  다른 모델이 짚을 수 있습니다.
- 모델이 놓인 곳도 제각각입니다. 클라우드 API(OpenAI, Anthropic, Google), 사내 게이트웨이, 사내 GPU 서버의
  vLLM, 개인 PC의 Ollama나 LM Studio.
- 도구 호출(function calling)의 형식이 공급자마다 다릅니다. MCP 도구 스키마를 공급자별로 따로 변환하고 싶지
  않았습니다.
- 모델을 바꾸는 일이 코드 수정이 되면, "설정이 곧 시스템 구성"이라는 원칙이 깨집니다.

## 결정 (Decision)

모든 LLM 호출은 **LiteLLM의 비동기 채팅 완성 호출 하나**를 거친다. 공급자별 SDK를 직접 부르지 않는다.

- 모델은 `공급자/모델` 형식의 문자열로 지정한다(`openai/gpt-4o`, `anthropic/claude-...`, `ollama_chat/...`).
- 메시지와 도구는 OpenAI 형식 하나로 만든다.
- 엔드포인트가 모르는 파라미터는 조용히 빼는 옵션(`drop_params`)을 켠다.
- 키가 필요 없는 로컬 서버에도 빈 문자열 대신 더미 키를 넣는다.
- 사내 게이트웨이가 요구하는 헤더나 본문 필드는 설정으로 넣을 수 있게 한다.

## 결과 (Consequences)

**좋아지는 것**

- 모델 교체가 설정 문자열 변경입니다. 에이전트마다 다른 공급자를 섞어 쓰는 구성이 설정만으로 됩니다.
- 도구 스키마 변환이 OpenAI 형식 한 가지로 끝납니다.

**치르는 비용**

LiteLLM은 호출 방법을 통일하지만 **공급자별 대화 규칙**까지 지워 주지는 않습니다. 이 차이가 하나씩
장애로 드러났고, 결국 LiteLLM 앞에 요청 모양을 정리하는 층을 따로 두게 되었습니다.

| 드러난 차이 | 증상 | 대응 |
| :--- | :--- | :--- |
| 연속된 `user` 메시지 거부 (Anthropic, Gemini, 일부 호환 서버) | 계획은 성공하고 전문가 발언만 전부 실패 | 같은 역할 메시지 합치기, 자른 뒤에 합치기 |
| 도구 기록은 있는데 도구 정의가 없는 요청 거부 (Anthropic) | 도구를 많이 쓴 Claude 발언만 400 | 도구를 정의하되 호출은 막기(`tool_choice: "none"`) |
| 게이트웨이가 상류 400을 500으로 감쌈 | 이유 없는 실패, 결정적 오류를 재시도 | 실패 시 요청 지문을 로그에 남김 |
| 추론 모델의 `reasoning_content` | 본문이 빈 발언 | 추론 끝부분을 넘겨 결론을 다시 요청 |
| 서버의 도구 호출 파서 불일치 | 호출 문법이 본문으로 새어 나옴 | 흔한 형식을 찾아내 다시 호출하게 함 |

추상화 라이브러리를 써도 경계에서 새는 차이를 흡수하는 책임은 우리에게 남는다는 것, 이 ADR에서 가장 크게
배운 점입니다.

**이후에 따라온 결정**

- 초기에는 엔드포인트에 연결되지 않으면 답을 흉내 내는 시뮬레이터가 LLM 호출 경로 안에 있었습니다. 이 부분은
  [ADR-007](ADR-007-no-simulated-answers.md)에서 폐기되었습니다.
- 추론 모델의 사고 과정을 어디까지 다른 에이전트에게 보낼지는 [ADR-015](ADR-015-reasoning-out-of-prompts.md)에서
  정했습니다.
