# ADR-002. 모든 LLM 호출은 LiteLLM을 거친다

> [ADR 목록](README.md) · 이전: [ADR-001](ADR-001-python-single-process.md) · 다음: [ADR-003](ADR-003-mcp-tool-protocol.md)

## 상태 (Status)

채택됨 · 2026-08-26 (초기 설계) · 관련: [ADR-007](ADR-007-no-simulated-answers.md), [ADR-015](ADR-015-reasoning-out-of-prompts.md)

## 맥락 (Context)

- 에이전트마다 서로 다른 모델을 사용하는 것이 이 시스템의 핵심 전제입니다. 다양한 모델이 토론에 참여해야 한 모델의 맹점을 다른 모델이 비판하고 보완할 수 있습니다.
- 모델이 배포된 인프라 환경도 제각각입니다. 상용 클라우드 API(OpenAI, Anthropic, Google)부터 사내 보안 게이트웨이, 온프레미스 GPU 서버의 vLLM, 로컬 PC의 Ollama나 LM Studio까지 다양합니다.
- 함수 호출(Function Calling/Tool Call) 규격이 공급자마다 상이합니다. 각 공급자별로 MCP 도구 스키마를 매번 별도로 변환하는 중복 작업을 피하고자 했습니다.
- 모델을 변경할 때마다 소스 코드를 수정해야 한다면, "설정이 곧 시스템 구성이다"라는 설계 원칙이 훼손됩니다.

## 결정 (Decision)

모든 외부 LLM 호출은 **LiteLLM의 비동기 채팅 완성(Chat Completion) 단일 엔드포인트**를 통과하도록 합니다. 공급자별 전용 SDK를 애플리케이션 코드에서 직접 호출하지 않습니다.

- 모델 지정은 `공급자/모델명` 형식의 표준 문자열 규격을 사용합니다 (`openai/gpt-4o`, `anthropic/claude-3-5-sonnet`, `ollama_chat/...` 등).
- 대화 메시지와 도구 스키마는 OpenAI 표준 형식 하나로 통일하여 구성합니다.
- 엔드포인트가 지원하지 않는 부가 파라미터는 자동으로 제외하는 옵션(`drop_params=True`)을 활성화합니다.
- API 키가 불필요한 로컬 추론 서버라도 클라이언트 초기화 오류를 방지하기 위해 빈 문자열 대신 더미(Dummy) 키를 전달합니다.
- 사내 보안 게이트웨이가 요구하는 특수 헤더나 요청 본문 필드는 설정 파일을 통해 동적으로 주입할 수 있도록 지원합니다.

## 결과 (Consequences)

**좋아지는 점**

- 모델 교체가 단순한 설정 파일의 문자열 변경으로 완결됩니다. 에이전트마다 서로 다른 공급자의 모델을 조합하여 운용하는 작업이 코드 수정 없이 가능합니다.
- 도구 스키마 변환 작업이 OpenAI 표준 규격 하나로 일원화됩니다.

**치르는 비용**

LiteLLM이 호출 인터페이스는 단일화해 주지만, **공급자별 내부 대화 규칙의 차이**까지 완전히 감춰 주지는 못합니다. 이러한 미세한 차이들이 런타임 장애로 속속 드러났으며, 결국 LiteLLM 앞단에 요청 규격을 정제하는 전처리 계층을 별도로 구축하게 되었습니다.

| 드러난 차이점 | 장애 증상 | 대응 조치 |
| :--- | :--- | :--- |
| 연속된 `user` 메시지 거부 (Anthropic, Gemini, 일부 호환 서버) | 계획 수립 단계는 통과하지만 전문가 발언 단계에서 전원 오류 발생 | 동일 역할 메시지 자동 병합, 토큰 한도 초과 절삭 후 재병합 수행 |
| 도구 호출 기록은 존재하지만 도구 정의 스키마가 없는 요청 거부 (Anthropic) | 도구를 다량 활용한 Claude 에이전트의 발언에서만 400 Bad Request 발생 | 도구 스키마를 요청에 명시하되 추가 호출을 방지(`tool_choice: "none"`)하도록 제어 |
| 상위 게이트웨이가 상류 400 클라이언트 오류를 500 서버 오류로 은폐 | 명확한 원인 분석 불가, 결정적인 클라이언트 오류를 불필요하게 무한 재시도 | 실패 발생 시 전송했던 요청 지문(Fingerprint)을 로그에 정량 기록 |
| 추론 전용 모델의 `reasoning_content` 반환 | 응답 본문이 비어 있어 발언 내용이 누락됨 | 추론 블록의 말미를 컨텍스트로 전달하여 최종 결론 작성을 재요청 |
| 로컬 서버별 도구 호출 파서의 불일치 | 도구 호출 JSON 문법이 일반 텍스트 본문으로 새어 나옴 | 흔히 발생하는 JSON 호출 패턴을 정규식으로 감지하여 파싱 후 재호출 유도 |

추상화 라이브러리를 도입하더라도 계층의 경계에서 새어나오는 세부 차이를 완충하는 책임은 오롯이 호스트 시스템에 남는다는 점이 이 결정 과정에서 얻은 가장 중요한 교훈입니다.

**이후에 따라온 결정**

- 기동 초기에는 엔드포인트 연결 실패 시 답변을 흉내 내는 시뮬레이터가 LLM 호출 경로에 존재했으나, [ADR-007](ADR-007-no-simulated-answers.md)에서 이를 전면 폐기했습니다.
- 추론 모델의 중간 사고 과정을 타 에이전트에게 어디까지 공유할 것인지는 [ADR-015](ADR-015-reasoning-out-of-prompts.md)에서 확정했습니다.
