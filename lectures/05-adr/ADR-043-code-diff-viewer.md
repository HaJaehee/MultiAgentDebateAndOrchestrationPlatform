# ADR-043. 코드 변경점은 통합·좌우 보기로 비교하고, 라운드 경계에 작업 공간 스냅샷을 남긴다

> [ADR 목록](README.md) · 이전: [ADR-042](ADR-042-plugins.md)

## 상태 (Status)

채택됨 · 2026-11-01 (v1.5.1) · 관련: [ADR-024](ADR-024-turns-as-records.md), [ADR-033](ADR-033-render-long-text-off-the-loop.md), [ADR-036](ADR-036-retry-one-speech-and-inline-comments.md)

## 맥락 (Context)

- 턴 변경 창은 `git diff` 글을 `ui.code` 에 그대로 보여 주었습니다. 줄 번호도, 좌우 비교도, 줄 안에서 무엇이 바뀌었는지도 보이지 않았습니다.
- 산출물 뷰어의 코드 탭은 코드만 보여 주었습니다. 라운드가 거듭되며 코드가 어떻게 달라졌는지 보려면 탭 두 개를 눈으로 대조해야 했습니다.
- 작업 공간 스냅샷은 턴의 시작과 끝뿐이라, 어느 라운드에서 무엇이 바뀌었는지 알 길이 없었습니다.
- 코드 산출물에는 파일 이름도 턴 id 도 없고, 턴마다 전문가별 **마지막 발언**의 코드만 올라옵니다. 그래서 산출물끼리만 비교하면 라운드별 변화가 보이지 않습니다.
- 내용은 모델과 작업 공간에서 온 것이라 믿을 수 없고, 수천 줄이 될 수 있습니다.

## 결정 (Decision)

### 1. 차이 계산과 그리기를 나눈다

`app/code_diff.py` 는 화면을 모르는 순수 함수입니다. `git diff` 글은 `parse_unified`, 두 코드는 `diff_texts` 로 읽어 같은 모델(`FileDiff`)을 만듭니다. 통합·좌우 보기는 이 모델을 다르게 그릴 뿐이라 전환할 때 다시 계산하지 않습니다.

두 곳 모두 코드를 보여 주므로 `app/ui/components/diff_viewer.py` 하나를 함께 씁니다.

### 2. 줄 안 강조는 비슷한 줄의 짝에만 건다

바뀐 묶음에서 비슷한 줄끼리 순서를 지켜 짝짓고, 짝의 낱말 차이만 표시합니다. 위에 한 줄이 끼어들어도 아래 줄들이 어긋나지 않습니다. 묶음이 200줄을 넘거나 한 줄이 2,000자를 넘으면 시도하지 않고 줄 단위 색만 칠합니다.

### 3. 줄마다 요소를 만들지 않고, 글은 모두 이스케이프한다

수천 줄에 NiceGUI 요소를 만들면 화면이 멈춥니다. HTML 문자열을 워커 스레드에서 만들어 `ui.html` 로 넘기고, 150행 묶음 단위로 `content-visibility: auto` 를 겁니다. 들어가는 글은 한 함수(`_escape`)를 거치며, `ui.html` 의 DOMPurify 도 그대로 켜 둡니다.

### 4. 라운드별 작업 공간 변경은 경계 스냅샷으로 얻는다

라운드(`round-N`)·그래프 단계(`step-N`)가 시작할 때와 토론이 끝났을 때(`debate-end`) `refs/mado/turns/<턴 id>/` 아래에 스냅샷을 남깁니다. DB 스키마와 `checkpoint` 값은 그대로이고, 저장소의 이름이 곧 기록입니다. 되돌리기와 대화 분기는 이 이름을 읽지 않으므로 항상 턴 단위로 동작합니다.

- 검토한 대안: 도구 호출 기록에서 재구성 → 셸 명령이 고친 파일을 알 수 없어 기각.
- 이어 가는 턴은 이미 지난 경계를 덮어쓰지 않습니다. 덮어쓰면 끊기기 전의 변경이 사라집니다.
- 스냅샷이 실패해도 턴은 그대로 진행합니다. 그 턴은 구간을 고르지 못할 뿐입니다.

### 5. 산출물 비교의 기준은 발언 기록에서 찾아 제안한다

라운드별 코드는 발언 기록에 있습니다. 산출물 수집과 같은 기준으로 코드 블록을 모아 버전으로 삼고(`app/code_versions.py`), 같은 언어의 앞선 코드 가운데 낱말이 가장 많이 겹치는 것을 비교 기준으로 제안합니다. 어느 코드가 어느 코드의 이전 모습인지 알 방법이 없으므로 **추측임을 드러냅니다.** 목록에 유사도를 적고, 사람이 바꿀 수 있게 하며, 20% 미만이면 다른 코드일 수 있다고 알립니다.

기록을 읽지 못하면 코드 산출물끼리 비교합니다. 이 경우 턴 사이의 변화만 보입니다.

## 결과 (Consequences)

**이점**

- 변경점을 줄 번호, 좌우 정렬, 낱말 강조와 함께 볼 수 있습니다.
- 턴 변경 창에서 턴 전체와 라운드별 구간을 오갈 수 있습니다.
- 코드 탭에서 앞선 라운드·턴의 코드와 바로 비교할 수 있습니다.

**비용과 한계**

- 라운드마다 스냅샷 한 번만큼 git 명령이 더 실행됩니다 (별도 스레드에서 실행하고, 바뀌지 않은 파일은 다시 해시하지 않습니다).
- 이 결정 이전의 턴에는 경계 스냅샷이 없어 턴 전체만 볼 수 있습니다.
- 다시 실행한 발언이 고친 파일은 턴의 끝 스냅샷에 합쳐지므로 `토론 이후` 구간에 나타납니다.
- 다시 실행하기 전의 코드는 비교 기준에 들어가지 않습니다.
- 문법 색은 칠하지 않습니다. 변경 표시와 겹치고, 헝크만으로는 여러 줄 문자열 같은 문맥을 알 수 없습니다.
- 비교는 코드 산출물만 대상으로 합니다. 보고서와 다이어그램은 그대로입니다.

**함께 고친 것**

스냅샷의 임시 인덱스를 `copyfile` 로 만들어 파일 시각이 지금으로 바뀌었습니다. git 은 인덱스보다 늦거나 같은 시각에 고친 파일만 내용을 다시 읽으므로, 인덱스가 기록된 그 초에 같은 크기로 고친 파일을 변경 없음으로 보았습니다 (재현 6회 중 4회). 체크포인트와 되돌리기에도 영향을 주던 문제입니다. `copy2` 로 시각까지 복사해 고쳤습니다 (6회 중 0회).
