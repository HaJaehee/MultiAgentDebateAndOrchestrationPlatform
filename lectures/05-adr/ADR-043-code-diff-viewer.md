# ADR-043. 코드 변경 사항의 통합·좌우 Diff 비교 뷰 제공 및 라운드 경계 작업 공간 스냅샷 기록

> [ADR 목록](README.md) · 이전: [ADR-042](ADR-042-plugins.md)

## 상태 (Status)

채택됨 · 2026-11-01 (v1.5.1) · 관련: [ADR-024](ADR-024-turns-as-records.md), [ADR-033](ADR-033-render-long-text-off-the-loop.md), [ADR-036](ADR-036-retry-one-speech-and-inline-comments.md)

## 맥락 (Context)

- 기존 턴 변경 내역 다이얼로그는 `git diff` 텍스트 출력을 `ui.code` 컴포넌트에 원문 그대로 렌더링하여, 라인 번호 표시나 Split(좌우 비교) 뷰, 라인 내부의 인라인 변경 사항(Word Diff) 강조가 지원되지 않았습니다.
- 산출물 뷰어의 코드 탭은 단일 코드 본문만 표시하여, 라운드 진행에 따른 코드 수정 추이를 확인하려면 복수의 탭을 육안으로 대조해야 하는 불편이 있었습니다.
- 작업 공간 체크포인트 스냅샷이 턴 시작 및 종료 시점에만 생성되어, 개별 라운드 단위의 파일 변경 이력을 추적할 수 없었습니다.
- 코드 산출물 메타데이터에는 파일 경로와 턴 ID가 포함되지 않으며, 매 턴마다 각 전문가의 **최종 발언** 코드 블록만 수집됩니다. 따라서 최종 산출물 간의 단순 대조만으로는 라운드별 점진적 코드 변화를 추적하기 어려웠습니다.
- 코드 본문은 LLM 및 샌드박스 작업 공간에서 생성된 신뢰할 수 없는 대용량 텍스트이므로 수천 행에 달할 수 있어 안전한 렌더링 및 XSS 방어가 요구됩니다.

## 결정 (Decision)

### 1. Diff 연산 로직과 UI 렌더링 계층의 분리

`app/code_diff.py`는 UI 프레임워크에 독립적인 순수 함수 모듈로 설계되었습니다. `git diff` 출력은 `parse_unified`로, 두 텍스트 코드는 `diff_texts`로 파싱하여 동일한 자료구조(`FileDiff`)로 정규화합니다. Unified(통합) 뷰와 Split(좌우 나란히) 뷰는 이 동일 모델을 다르게 렌더링하므로 뷰 모드 전환 시 Diff 재연산이 발생하지 않습니다.

턴 변경 내역 다이얼로그와 산출물 코드 탭 모두 `app/ui/components/diff_viewer.py` 컴포넌트를 공통으로 재사용합니다.

### 2. 라인 단위 인라인 단어 강조(Word Diff) 및 정렬 최적화

수정된 헝크(Hunk) 내에서 유사한 라인끼리 순서를 보존하며 페어링하고, 매칭된 라인 쌍에 대해서만 단어(Word) 단위 차이점을 강조합니다. 상단에 단일 라인이 삽입되더라도 후속 라인 매칭이 어긋나지 않도록 방지합니다. 헝크 크기가 200행을 초과하거나 단일 라인이 2,000자를 초과하는 경우 계산 복잡도 방지를 위해 단어 단위 계산을 생략하고 라인 단위 하이라이트만 적용합니다.

### 3. DOM 요소 최소화, 가상화(content-visibility) 및 XSS 방어

수천 행의 코드에 대해 개별 NiceGUI 요소를 생성할 경우 브라우저 렌더링 스레드가 블로킹됩니다. 이를 방지하기 위해 백그라운드 워커 스레드에서 정적 HTML 문자열을 사전 빌드하여 `ui.html`로 주입하며, 150행 블록 단위로 `content-visibility: auto` 스타일을 적용하여 렌더링 부하를 최적화합니다. 모든 텍스트는 `_escape` 함수를 통해 철저히 이스케이프되며 `ui.html`의 DOMPurify 새니타이징도 활성화 상태를 유지합니다.

### 4. 라운드별 작업 공간 변경 추적을 위한 경계 스냅샷 기록

각 라운드(`round-N`) 및 적응형 그래프 단계(`step-N`) 시작 시점과 토론 종료 시점(`debate-end`)에 `refs/mado/turns/<turn_id>/` 네임스페이스 하위에 Git 경계 스냅샷을 기록합니다. DB 스키마 및 `checkpoint` 컬럼 구조는 변경하지 않고 Git ref 명명 규칙을 통해 메타데이터를 유지합니다. 턴 롤백(Revert)과 세션 포크(Fork)는 해당 ref를 참조하지 않고 불변의 턴 단위 스냅샷을 기준으로 동작합니다.

- 검토 대안: 도구 호출(Tool Call) 로그 기반 재구성 → Bash 셸 등 임베디드 명령어가 수정한 파일을 정확히 특정할 수 없어 기각.
- 중단 후 재개(Resume)된 턴은 기통과한 라운드 경계를 덮어쓰지 않습니다. 덮어쓸 경우 중단 이전의 파일 변경 이력이 유실되기 때문입니다.
- 스냅샷 기록에 실패하더라도 턴 실행은 중단 없이 계속 진행됩니다. 해당 턴에서는 라운드별 세부 구간 필터링만 비활성화됩니다.

### 5. 발언 이력 기반 코드 산출물 비교 기준 자동 추천

라운드별 코드 변화 추이는 대화 발언 이력(Message History)에 누적되어 있습니다. 최종 산출물 수집 규칙과 동일한 파서를 통해 발언 내 코드 블록들을 버전 이력으로 추출하고(`app/code_versions.py`), 동일 프로그래밍 언어의 이전 코드 블록 중 어휘 유사도(단어 중복도)가 가장 높은 코드를 비교 기준으로 자동 추천합니다. 명시적 계통 관계가 정의되어 있지 않으므로 시스템 추정치임을 UI에 명확히 표기합니다. 셀렉터에 유사도 백분율을 표시하여 사용자가 비교 대상을 자유롭게 변경할 수 있도록 지원하며, 유사도가 20% 미만일 경우 상이한 코드일 수 있음을 안내합니다.

발언 이력을 불러올 수 없는 환경에서는 턴별 최종 코드 산출물 간의 비교로 폴백합니다. 이 경우 턴 간의 변화 추이만 대조됩니다.

## 결과 (Consequences)

**이점**

- 코드 변경 사항을 라인 번호, Split(좌우 나란히) 정렬, 단어 단위 하이라이트와 함께 정밀하게 열람할 수 있습니다.
- 턴 변경 내역 다이얼로그에서 턴 전체 또는 개별 라운드/단계별 구간 필터를 선택하여 변경 내역을 확인할 수 있습니다.
- 산출물 뷰어 코드 탭에서 이전 라운드 및 이전 턴의 코드 버전과 즉각적인 Diff 비교가 가능합니다.

**비용과 한계**

- 라운드 전환 시마다 1회의 Git 스냅샷 커맨드가 추가 실행됩니다 (백그라운드 스레드에서 비동기 오프로드 실행되며, 변경되지 않은 파일은 Git 인덱스 캐시를 통해 재해싱을 생략합니다).
- 본 기능 도입 이전에 생성된 기존 턴은 라운드 경계 스냅샷이 부재하므로 턴 전체 단위의 변경 사항만 조회됩니다.
- 단일 발언 재생성으로 인해 수정된 파일은 턴 최종 스냅샷에 병합 반영되므로 `토론 이후` 구간에 집계됩니다.
- 발언 재생성 이전의 과거 시도 코드는 비교 기준 추천 대상에서 제외됩니다.
- 신택스 하이라이팅(Syntax Highlighting)은 적용하지 않습니다. Diff 하이라이트와 시각적으로 충돌하며, 단편적인 Diff 헝크만으로는 멀티라인 문자열 등의 구문 문맥을 정확히 파악하기 어렵기 때문입니다.
- Diff 비교 기능은 소스 코드 산출물에 한정하여 적용되며, 마크다운 종합 보고서와 다이어그램 산출물은 기존 방식을 유지합니다.

**버그 수정 내역 (Defect Fixes)**

체크포인트 스냅샷 생성 시 임시 Git 인덱스를 `shutil.copyfile`로 복사하면서 파일의 타임스탬프(mtime)가 현재 시각으로 갱신되는 문제가 있었습니다. Git은 인덱스 타임스탬프보다 늦거나 동일한 시각에 수정된 파일에 대해서만 변경 여부를 재검사하므로, 인덱스가 생성된 동일 초(second) 내에 동일한 파일 크기로 수정된 파일이 변경 없음(clean)으로 오인식되어 커밋 및 롤백 대상에서 누락되던 결함이 있었습니다 (재현율: 6회 중 4회 발생). 이는 체크포인트 생성과 롤백 정확도 모두에 영향을 미치던 잠재 결함으로, 파일 메타데이터 및 타임스탬프를 보존하는 `shutil.copy2`로 교체하여 문제를 근본 해결했습니다 (수정 후 재현율 0회).
