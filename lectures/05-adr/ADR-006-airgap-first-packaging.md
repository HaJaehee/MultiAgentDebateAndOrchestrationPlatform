# ADR-006. 폐쇄망 반입을 전제로 두 종류의 패키지를 만든다

> [ADR 목록](README.md) · 이전: [ADR-005](ADR-005-long-lived-mcp-sessions.md) · 다음: [ADR-007](ADR-007-no-simulated-answers.md)

## 상태 (Status)

채택됨 · 2026-08-26 전체 번들, 2026-08-28 소스 갱신 패키지 · 관련: [ADR-001](ADR-001-python-single-process.md), [ADR-021](ADR-021-graph-debate.md)

## 맥락 (Context)

- 운영 환경은 인터넷이 없는 망입니다. pip, npm, CDN 어느 것도 쓸 수 없습니다.
- 반입하는 파일은 심사를 받습니다. 반입량이 클수록, 자주 반입할수록 비용이 큽니다.
- 런타임(파이썬, Node, 라이브러리)은 한 번 반입하면 거의 바뀌지 않지만, 앱 코드는 하루에도 여러 번 바뀝니다.
- wheel을 모으기만 한 번들은 폐쇄망에 들어간 뒤에야 빠진 의존성이 드러납니다. 그때는 다시 반입하는 것 말고
  방법이 없습니다.
- 동봉한 샌드박스 서버는 `mcp` 상한을 적어 두지 않아, 아무 제약 없이 받으면 호환되지 않는 2.x가 들어옵니다.
- 개발 PC와 운영 PC의 경로가 다릅니다. 설정 파일을 환경마다 따로 관리하고 싶지 않았습니다.

## 결정 (Decision)

패키지를 **두 종류**로 나눈다.

**전체 번들** (처음 반입, 런타임을 바꿀 때)

- 포터블 CPython, `node.exe`(npm 제외), 오프라인 wheel, Node MCP 서버 설치본, 샌드박스 서버와 커널용
  라이브러리, 소스, 설명서, 실행 스크립트를 담는다.
- wheel을 포터블 런타임에 **실제로 설치하고 핵심 패키지를 import해 본다.** 실패하면 번들을 만들지 않는다.
- 제약 파일로 `mcp<2`를 강제한다.
- 작업 공간 폴더를 git 저장소로 초기화해 둔다. git 서버는 저장소가 아니면 기동에 실패한다.
- 실행 스크립트는 자기 위치를 기준으로 런타임, MCP 서버, 작업 공간 경로를 환경변수로 넣고 앱을 띄운다.

**소스 갱신 패키지** (코드만 바뀌었을 때)

- 담을 것을 **허용 목록**으로 관리한다.
- 반드시 있어야 하는 파일(예: 동봉한 화면 라이브러리)이 빠지면 중단한다.
- 운영 설정 파일(`conf.json`)은 담지 않는다.
- 2MB를 넘는 파일, 키처럼 보이는 값이 있으면 중단한다.
- 파일마다 SHA-256을 적은 목록을 함께 담는다.
- 이번 갱신이 새로 요구하는 파이썬 패키지가 있으면 그 wheel만 함께 담을 수 있게 한다.

**공통**

- 설정 파일의 경로와 주소는 모두 `${변수:-기본값}`으로 적어, 개발 PC와 번들이 같은 설정 파일을 쓴다.
- 화면에 쓰는 브라우저 라이브러리는 CDN에서 받지 않고 앱 안에 동봉한다.

## 결과 (Consequences)

**좋아지는 것**

- 코드 갱신이 수백 KB로 끝납니다. v0.5.0은 새 기능 넷을 표준 라이브러리만으로 만들어 391KB짜리 소스 패키지
  하나로 갱신했습니다.
- 번들 안에서 import가 실패하는 일은 빌드 PC에서 먼저 드러납니다.
- 소스 패키지가 운영 설정을 덮어쓰거나 비밀을 실어 나르는 사고를 스크립트가 막습니다.

**치르는 비용**

- 전체 번들은 Windows 빌드 PC에서 만들어야 합니다. 포터블 런타임과 wheel이 빌드하는 플랫폼 기준으로 수집됩니다.
- 의존성 목록이 바뀌면 원칙적으로 전체 번들을 다시 반입해야 합니다. 그래서 새 기능을 만들 때 **표준
  라이브러리로 해결할 수 있는지를 먼저 따지는** 압력이 생깁니다. 이 압력은 대체로 좋은 쪽으로 작용했습니다.
- 실행 스크립트는 생성기가 원본이고 저장소의 파일은 사본입니다. 사본만 고치면 번들에 실리는 스크립트는 바뀌지
  않습니다. 원본이 둘처럼 보이는 구조는 늘 혼동을 부릅니다.
- 설정 예시에 새 항목이 생기면 운영 쪽 설정 파일에 **사람이 옮겨 적어야** 합니다. 운영 설정을 덮어쓰지 않는
  규칙의 대가입니다.

**드러난 사고 사례**

- 다이어그램을 "독립 실행 HTML"로 내보내는 기능이 CDN에서 렌더러를 받아 오고 있었습니다. 폐쇄망에서는 흰 화면에
  흰 글씨만 보였습니다. 렌더링된 SVG를 파일에 넣고 외부 URL을 하나도 쓰지 않게 고쳤습니다. 폐쇄망 원칙은
  "앱이 뜨는가"만이 아니라 **앱이 만들어 내보내는 파일**에도 적용되어야 합니다.
- 소스 패키징 스크립트가 압축 파일을 다 만들어 놓고 마지막 안내 문구에서 죽은 적이 있습니다. 출력을 CP949로
  리다이렉트한 한국어 Windows에서 문구의 특수 문자를 찍지 못해 인코딩 오류가 났고, 산출물은 멀쩡한데 종료
  코드가 1이라 성공한 실행이 실패로 보였습니다. 문자를 하나씩 바꾸는 대신 스크립트의 출력 스트림을 UTF-8로
  돌리고, 그래도 못 찍는 문자는 대체 문자로 흘리게 했습니다.
