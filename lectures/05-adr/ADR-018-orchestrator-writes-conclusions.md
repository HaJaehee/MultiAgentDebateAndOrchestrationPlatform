# ADR-018. 오케스트레이터는 결론과 다이어그램만 쓴다

> [ADR 목록](README.md) · 이전: [ADR-017](ADR-017-never-lose-a-write.md) · 다음: [ADR-019](ADR-019-owner-token-remote-access.md)

## 상태 (Status)

채택됨 · 2026-09-14 (v0.7.2) · 관련: [ADR-007](ADR-007-no-simulated-answers.md), [ADR-020](ADR-020-conversation-memory.md)

## 맥락 (Context)

토론 세션의 턴이 거듭될수록 이전 턴의 토론 결과물이 UI 상에서 사라진다는 사용자 결함 보고가 접수되었습니다. 원인을 정밀 추적한 결과 두 가지 독립적인 결함이 겹쳐 있었습니다.

- **산출물 뷰어 컴포넌트가 탭 전체를 무차별 교체했습니다.** 턴이 종료될 때마다 UI가 해당 턴의 최신 산출물로 탭 목록을 완전히 덮어썼으며, 토론 진행 중 브라우저를 새로고침해도 동일한 현상이 발생했습니다. 그 결과 다회차 턴으로 구성된 긴 대화 세션에서는 오직 마지막 턴의 결과물 탭만 화면에 남았습니다.
- **빈 종합 보고서가 정상 보고서로 둔갑하여 저장되었습니다.** LLM 종합 호출이 빈 응답(Empty Response)을 반환했을 때, 내용이 텅 빈 본문이 정상적인 보고서 제목으로 데이터베이스에 영속화되었습니다. 그 여파로 화면 뷰어에는 텅 빈 탭 하나만 덩그러니 표시되었습니다. (과거 턴의 보고서들은 SQLite 데이터베이스에 정상 보존되어 있었습니다.)

종합 호출이 빈 응답을 반환하는 근본 원인을 추적하자 프롬프트 엔지니어링의 구조적 문제가 드러났습니다.

- 종합 프롬프트와 기본 오케스트레이터 페르소나가 "모든 변경 사항이 완벽히 반영되어 즉시 실행 가능한 소스 코드 전문"을 요구하고 있었습니다. 이에 오케스트레이터 모델은 전문가들이 토론 중에 작성했던 방대한 소스 코드를 **자신의 종합 본문에 처음부터 끝까지 그대로 다시 옮겨 적었고**, 그 과정에서 모델의 최대 출력 토큰 한도(`max_tokens`)를 모두 소진해 버렸습니다.
- 이렇게 생성된 방대한 코드 덤프 종합 보고서가 다음 턴의 대화 이력 컨텍스트에 그대로 주입되면서, 턴이 진행될 때마다 모델의 컨텍스트 윈도우를 급속도로 고갈시켰습니다.

동일한 시기에 계획 수립 프롬프트의 결함도 확인되었습니다. 턴 1의 계획 프롬프트 내부에 "(Architect, Coder, Critic)"이라는 역할명이 하드코딩되어 있어서, 다른 에이전트 구성을 사용하는 대화 세션에서도 존재하지 않는 유령 에이전트에게 업무를 배분하려 시도했습니다. 심지어 턴 2 이후부터는 참여자 명단 정보 자체가 프롬프트에서 누락되어 있었습니다.

## 결정 (Decision)

**오케스트레이터의 출력 책임을 간소화하고 코드 복제를 금지합니다.**

- 오케스트레이터가 작성하는 종합 보고서는 오직 두 가지 핵심 영역으로 압축하도록 합니다.
  1. **고수준 결론**: 확정된 아키텍처 결정과 논리적 근거, 기각된 대안과 배제 사유, 미해결 기술 쟁점 및 잔존 위험.
  2. **단일 종합 다이어그램**: 핵심 구조를 시각화하는 Mermaid 다이어그램 1개.
- 오케스트레이터가 전문가들이 작성한 소스 코드를 종합 본문에 다시 옮겨 적거나 붙여넣는 행위를 엄격히 금지합니다. 소스 코드는 파일 상대 경로, 모듈명, 함수/클래스 심볼 식별자로만 참조하도록 지침을 강제합니다.
- UI 상의 '코드(Code)' 탭은 오케스트레이터가 아니라 **전문가들의 원본 발언 데이터**에서 직접 추출하여 구성합니다. 전문가별로 유효한 소스 코드 블록을 포함한 가장 최근 발언을 파싱하고, 사고 과정 흔적을 제거한 뒤, 중복 코드를 배제하여 최대 12개까지 탭으로 제공합니다.

**실패는 투명하게 실패로 기록합니다.**

- 종합 응답이 비어 있거나, 토큰 한도 초과 안내 또는 사고 과정 흔적만으로 채워진 경우 "합성 실패 (빈 응답)" 상태로 명확히 기록합니다. LLM 통신이 중도 단절된 경우는 "합성 실패 (LLM 연결 끊김)"으로 기록합니다.
- 종합 실패 탭에는 시스템 오류 안내와 함께, 이번 턴에서 전문가들이 남긴 마지막 발언들을 **추가적인 LLM 호출 없이** 결정론적으로 취합하여 대체 본문으로 채워 넣습니다.
- 종합 단계가 실패한 턴은 시스템 상태를 완전한 '합의 도출'로 표기하지 않습니다.

**산출물 이력을 탭으로 누적합니다.**

- 산출물 뷰어 컴포넌트는 기존 탭을 파기하지 않고 신규 탭을 추가(Append)하는 방식으로 개편합니다. 탭 제목 서두에 해당 턴의 종료 타임스탬프를 명시하며, 화면 진입 시 가장 최근 보고서 탭을 기본 활성화합니다.

**계획 단계에 실제 참여자 명단을 동적 주입합니다.**

- 계획 수립 프롬프트에 이번 턴에 실제로 활성화된 전문가들의 이름, 역할, 보유 도구 서버 목록을 단일 행으로 명확히 주입합니다. 페르소나 시스템 프롬프트 전문은 주입하지 않습니다 (태스크 분배에는 에이전트당 수십 토큰의 메타 정보면 충분하며, 장문의 페르소나 전문은 불필요한 토큰 낭비를 유발하기 때문입니다).
- 계획 모델이 목록에 명시된 전문가의 정확한 식별자를 호명하여 태스크와 산출물을 할당하도록 유도하고, 도구 작업이 필요한 태스크는 해당 도구 권한을 보유한 전문가에게만 정확히 배분하도록 프롬프트를 구성합니다.
- 발언자 동적 지명 및 태스크 분배 프롬프트 역시 동일한 동적 참여자 명단을 참조하도록 일원화합니다.

## 결과 (Consequences)

**좋아지는 점**

- 종합 모델의 토큰 출력 예산이 불필요한 코드 중복 복제에 낭비되지 않으며, 다음 턴의 입력 컨텍스트가 거대한 코드 덤프로 인해 조기 고갈되는 현상이 완전히 해소되었습니다.
- 긴 대화 세션에서도 모든 턴의 역사적 산출물이 UI 탭에 온전히 보존되어 전 회차의 결론을 자유롭게 대조할 수 있습니다.
- 설령 종합 생성이 실패하더라도 사용자는 전문가들의 최종 발언 발췌본이라는 실질적으로 유용한 정보를 획득할 수 있으며, 시스템이 실패 사실을 솔직하게 고지하므로 거짓된 결론에 오도되지 않습니다.

**치르는 비용**

- 오케스트레이터가 소스 코드의 "단일 통합본"을 직접 산출물로 생성해 주지 않습니다. UI 코드 탭은 전문가별 최신 코드 조각들의 모음이며, 실제로 통합된 실행 코드는 작업 공간 디렉터리 내의 실제 파일에 영속화되어 있습니다. 따라서 작업 공간 파일 시스템이 실질적인 최종 코드 산출물 저장소 역할을 수행하게 됩니다.
- 기존에 설치되어 운용 중이던 배포본의 설정 파일에 "코드를 직접 작성하라"는 레거시 오케스트레이터 프롬프트가 남아 있을 경우 관리자가 직접 수정해야 합니다. 기존 운영 설정을 덮어쓰지 않는다는 폐쇄망 패키징 원칙([ADR-006](ADR-006-airgap-first-packaging.md))에 따른 대가입니다.

**교훈**

"에이전트에게 더 방대한 역할을 부여하고 더 많은 텍스트를 작성하게 할수록 더 훌륭한 산출물이 도출된다"는 통념은 LLM 기반 파이프라인에서 대부분 거짓으로 판명됩니다. 에이전트의 책임과 출력 범위를 정밀하게 축소할수록 출력 토큰 한도 초과, 컨텍스트 윈도우 오염, 런타임 실패 위험이 동시에 획기적으로 감소합니다.
