# ADR-042. 토론 전략과 호스트 도구를 코드 수정 없이 플러그인으로 확장하고 도구 보안 정책을 적용한다

> [ADR 목록](README.md) · 이전: [ADR-041](ADR-041-postgresql-compatibility.md)

## 상태 (Status)

채택됨 · 2026-10-31 (v1.5.1) · 관련: [ADR-012](ADR-012-agent-owned-debate-order.md), [ADR-014](ADR-014-tool-failure-is-observation.md), [ADR-026](ADR-026-skills-as-host-tools.md), [ADR-039](ADR-039-lazy-tool-schemas.md)

## 맥락 (Context)

- 신규 토론 전략을 추가하려면 `app/orchestration/strategies.py`의 `STRATEGY_MAP`을 직접 수정해야 했습니다. 소스 업데이트 패키지를 적용하면 사용자가 수정한 전략 등록 코드가 덮어써져 유실되는 문제가 있었습니다.
- 내장 호스트 도구(`skills`, `peers`, `ask`, `tools`)가 점차 확장되면서 도구를 하나 추가할 때마다 시스템 전반의 여러 파일을 수정해야 했습니다.
  - 도구 스키마를 집계하는 두 위치(`ConversationMemory.tools_for`와 런타임 빌더) 간의 정의 불일치.
  - 시스템 프롬프트 지침 블록 4개, 실행 분기 3개 및 `tools` 전용 분기 1개, 보안 검사 예외 조건 1개, 예약어 매핑 분기 등 수정 범위의 파편화.
- 외부 플러그인 형태로 호스트 도구를 로드할 수 있게 확장함에 따라, 내장 도구에만 적용되던 보안 가정이 깨지게 되었습니다.
  - 내장 도구는 샌드박스 내부의 엄격한 자체 규칙으로 제어되므로 보안 검증을 건너뛰었으나, 외부 플러그인 코드가 어떤 작업을 수행하는지 애플리케이션 계층에서는 알 수 없습니다.
  - 기존 `ToolGate._check`는 매니저가 인식하지 못하는 도구를 무조건 통과시키는 구조였습니다. 외부 호스트 도구를 동일한 방식으로 처리하면 보안 검증을 받는 것처럼 보이면서도 실제로는 무제한 허용되는 보안 결함이 발생할 위험이 있었습니다.
- 플러그인은 메인 애플리케이션과 동일한 권한으로 실행되는 파이썬 코드입니다. 파일 쓰기 권한을 가진 에이전트가 플러그인 디렉터리에 파일을 생성할 수 있다면, 차기 서버 기동 시 샌드박스를 우회한 임의 코드 실행 권한을 획득하게 됩니다.

## 결정 (Decision)

### 1. 탐색 경로: 디렉터리 기반 로드 및 패키지 엔트리포인트(Entry Point) 지원

| 종류 | 기본 디렉터리 경로 | 엔트리포인트(Entry Point) 그룹 | 기본 추상 클래스 |
| :--- | :--- | :--- | :--- |
| 토론 전략 | `plugins.strategies_dir` (`strategies/`) | `mado.strategies` | `BaseDebateStrategy` |
| 호스트 도구 | `plugins.host_tools_dir` (`host_tools/`) | `mado.host_tools` | `HostToolProvider` |

디렉터리 탐색 시 개별 `.py` 파일 또는 패키지 디렉터리를 단일 플러그인 단위로 인식하며, `_` 또는 `.`으로 시작하는 파일/디렉터리는 무시합니다. 엔트리포인트는 클래스, 인스턴스, 모듈을 유연하게 바인딩할 수 있습니다. 폐쇄망 환경에서는 디렉터리 파일 배치가, 외부 패키지 설치 시에는 엔트리포인트 방식이 적합합니다.

`strategies/`와 `host_tools/` 디렉터리는 Git 추적 대상에서 제외하여 소스 업데이트 패키지 적용 시 사용자의 커스텀 플러그인이 삭제되지 않도록 보호합니다. 플러그인 작성 예제는 앱이 자동 로드하지 않는 `docs/examples/plugins/` 경로에 배치합니다.

### 2. 서버 기동 시 1회 정적 로드

스킬(Skills)은 텍스트 프롬프트이므로 런타임 실시간 수정을 허용하지만, 플러그인은 실행 가능한 파이썬 코드입니다. 실시간 핫 리로드를 허용하면 파일 쓰기 도구를 가진 에이전트가 샌드박스를 즉시 탈출할 위험이 있습니다. 또한 실행 중인 토론 세션에서 참조 중인 전략 인스턴스를 동적으로 교체할 경우 런타임 일관성을 보장하기 어렵습니다. 따라서 서버 시작 시 1회만 정적으로 로드하며 동적 언로드(Unload)는 지원하지 않습니다.

### 3. 플러그인 디렉터리에 대한 도구 쓰기 접근 차단

`protected_files()` 보호 목록에 플러그인 디렉터리를 추가하여 에이전트 도구의 파일 쓰기 호출을 원천 차단합니다. 또한 기본 작업 공간(Workspace) 내부의 디렉터리는 플러그인 탐색 경로로 설정할 수 없도록 강제 검증합니다.

### 4. 호스트 도구 레지스트리 일원화 및 플러그인 보안 정책 적용

`HostToolProvider` 인터페이스 하나가 도구 이름(`prefix`, `tails`, `owns`), 스키마 정의(`enabled_for`, `tools_for`), 시스템 프롬프트 지침(`guidance`), 실행 로직(`run`), 보안 정책 메타데이터(`gated`, `risk`)를 모두 통합 제공합니다.

| 구분 | 내장 호스트 도구 | 플러그인 호스트 도구 |
| :--- | :--- | :--- |
| 보안 검증 | 생략 (`gated=False`) | **필수 검증 대상 (`gated=True`)** |
| 활성화 방식 | 자체 도메인 규칙 | `allowed_mcp_servers`에 접두사 명시 |
| 호출 식별자 | 접두사 생략 호출 지원 | `접두사__도구명` 전체 식별자 필수 |

- **플러그인 도구에 대한 보안 정책 적용**: `host_tool_meta()`가 `ToolMeta`를 생성하여 MCP 도구와 동일하게 `ToolGate` 및 정책 필터링을 거치도록 일원화했습니다.
- **위험 등급(Risk Level) 명시**: 플러그인은 자체 위험 등급(`risk`)을 선언할 수 있습니다. 등급을 명시하지 않으면 '미분류 도구'로 취급되어 기본 모드에서는 사용자 승인을 요구하고 읽기 전용 모드 및 헤드리스 환경에서는 실행이 거부됩니다.
- **도구 가로채기 방지**: 내장 도구의 핵심 이름이나 타 플러그인의 접두사를 가로채는 행위를 등록 단계에서 차단합니다.

### 5. 오류 격리 및 시스템 탄력성 유지

- **로드 실패 격리**: 임포트 실패나 이름 충돌이 발생한 플러그인은 등록에서 제외되고 상세 오류 로그가 남으며, 타 정상 플러그인 및 애플리케이션의 기동을 방해하지 않습니다.
- **전략 실행 예외 처리**: 토론 전략 실행 중 예외가 발생하거나 발언자가 선정되지 않을 경우 우선순위 순차 연결(Priority order)로 안전하게 폴백(fallback)하고 타임라인에 폴백 발생 이력을 기록합니다.
- **도구 실행 예외 처리**: 호스트 도구 실행 중 발생한 예외는 일반 MCP 도구와 동일하게 관찰 메모(Observation)로 변환하여 에이전트에게 전달합니다.

## 결과 (Consequences)

**이점**

- 애플리케이션 소스 코드를 직접 수정하지 않고도 신규 토론 전략과 호스트 도구를 자유롭게 확장할 수 있습니다.
- 소스 패키지 업데이트 시에도 사용자의 커스텀 플러그인이 영구히 보존됩니다.
- 외부 플러그인 도구에도 엄격한 도구 보안 정책 및 승인 결재선이 일관되게 적용됩니다.
- 호스트 도구 등록/관리 로직이 단일 레지스트리로 통합되어 코드 응집도가 향상되었습니다.
