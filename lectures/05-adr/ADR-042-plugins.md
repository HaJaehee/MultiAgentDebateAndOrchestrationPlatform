# ADR-042. 토론 전략과 호스트 도구는 코드를 고치지 않고 플러그인으로 더하고, 플러그인은 도구 보안 판정을 받는다

> [ADR 목록](README.md) · 이전: [ADR-041](ADR-041-postgresql-compatibility.md)

## 상태 (Status)

채택됨 · 2026-10-31 (v1.5.1) · 관련: [ADR-012](ADR-012-agent-owned-debate-order.md), [ADR-014](ADR-014-tool-failure-is-observation.md), [ADR-026](ADR-026-skills-as-host-tools.md), [ADR-039](ADR-039-lazy-tool-schemas.md)

## 맥락 (Context)

- 새 토론 전략을 더하려면 `app/orchestration/strategies.py` 의 `STRATEGY_MAP` 을 고쳐야 했습니다. 설명서도 그렇게 안내했습니다. 소스 업데이트 패키지를 적용하면 그 수정은 사라집니다.
- 호스트 도구는 넷으로 늘었고(`skills`, `peers`, `ask`, `tools`), 하나를 더할 때마다 여러 곳을 고쳐야 했습니다.
  - 도구 정의를 모으는 곳 두 군데. 둘이 이미 어긋나 있었습니다. 전사 크기를 정하는 쪽(`ConversationMemory.tools_for`)은 `ask` 를 빠뜨렸습니다.
  - 시스템 프롬프트의 지침 네 블록, 실행 분기 세 개와 `tools` 전용 분기 하나, 판정을 건너뛰는 조건 하나, 예약어 표와 거의 같은 `if` 네 개.
- 호스트 도구를 밖에서 더할 수 있게 하면, 지금까지 내장 도구에만 맞던 가정이 깨집니다.
  - **내장 도구가 판정을 건너뛰는 이유는 그 도구들의 사정입니다.** 파일과 네트워크에 닿지 않거나 자기 규칙으로 통제됩니다. 외부 코드가 무엇을 하는지 앱은 모릅니다.
  - **`ToolGate._check` 는 매니저가 모르는 도구를 통과시킵니다.** 매니저가 'Unknown tool' 로 답할 것이기 때문입니다. 호스트 도구를 같은 길로 보내면 판정을 받는 것처럼 보이면서 언제나 허용됩니다.
- 플러그인은 앱 권한으로 도는 코드입니다. 파일을 쓸 수 있는 에이전트가 그 폴더에 쓸 수 있으면, 다음 시작 때 샌드박스 밖의 권한을 얻습니다.

## 결정 (Decision)

### 1. 찾는 곳은 폴더와 entry point 두 가지다

| 종류 | 폴더 (기본값) | entry point 그룹 | 기반 클래스 |
| :--- | :--- | :--- | :--- |
| 토론 전략 | `plugins.strategies_dir` (`strategies/`) | `mado.strategies` | `BaseDebateStrategy` |
| 호스트 도구 | `plugins.host_tools_dir` (`host_tools/`) | `mado.host_tools` | `HostToolProvider` |

폴더에서는 파일 하나나 패키지 폴더 하나가 플러그인 하나이고, `_` 나 `.` 으로 시작하는 이름은 건너뜁니다. 그 안의 구체 클래스를 전부 등록합니다. entry point 는 클래스, 객체, 모듈을 가리킬 수 있습니다. 폐쇄망에서는 폴더가, 패키지로 배포할 때는 entry point 가 맞습니다.

`strategies/` 와 `host_tools/` 는 저장소에 두지 않습니다. 소스 업데이트 패키지가 폴더를 통째로 바꾸는 대상(`SOURCE_DIRS`)에 들어가지 않아 사용자의 플러그인이 지워지지 않습니다.

### 2. 시작할 때 한 번만 읽는다

스킬은 실시간으로 반영하지만 플러그인은 그러지 않습니다. 스킬은 글이고, 플러그인은 코드입니다. 실시간으로 읽으면 그 폴더에 쓸 수 있는 누구나 곧바로 코드를 실행합니다. 등록한 것을 내리는 길도 만들지 않았습니다. 진행 중인 토론이 쓰는 객체를 바꾸면 그 토론이 어떻게 될지 정할 수 없기 때문입니다.

### 3. 플러그인 폴더는 도구로 건드릴 수 없다

`protected_files()` 에 플러그인 폴더를 넣어 고정 보호로 막습니다. 기본 폴더는 이미 설치 폴더 보호 안에 있고, 이 항목은 설정으로 다른 곳을 가리킨 경우까지 막습니다. 고정 보호는 작업 공간 예외보다 먼저 보므로 작업 공간 안쪽을 가리켜도 막힙니다.

**기본 작업 공간 안의 폴더는 아예 읽지 않습니다.** 고정 보호는 경로를 알 수 있는 호출만 막습니다. 코드 실행 도구가 경로를 동적으로 만들면 작업 공간 안쪽에는 쓸 수 있으므로, 그 자리의 파일을 앱 권한으로 실행하면 샌드박스를 넘게 됩니다. 대화마다 고르는 작업 공간은 시작할 때 알 수 없어 이 검사로 막지 못합니다. 그래서 설치 폴더 밖을 가리킬 때는 작업 공간으로 쓰지 않는 곳을 고르라고 설명서에 적었습니다.

### 4. 호스트 도구는 한 레지스트리에 모으고, 플러그인은 기본으로 판정을 받는다

`HostToolProvider` 하나가 이름(`prefix`, `tails`, `owns`), 정의(`enabled_for`, `tools_for`), 지침(`guidance`), 실행(`run`), 판정(`gated`, `risk`)을 함께 답합니다. 호출부는 레지스트리만 봅니다. 등록 순서가 곧 정의와 지침이 실리는 순서이고, 내장 네 묶음의 순서는 그대로라 프롬프트 캐시가 깨지지 않습니다.

|  | 내장 | 플러그인 |
| :--- | :--- | :--- |
| 판정 | 건너뜀 (`gated=False`) | **받음** |
| 켜는 법 | 각자의 규칙 (`allowed_skills`, 세션 설정, `peers` 는 `allowed_mcp_servers`) | `allowed_mcp_servers` |
| 이름 | 접두사를 빼고 불러도 받음 | 전체 이름만 받음 |

- **판정을 받는 길을 실제로 만들었습니다.** `host_tool_meta()` 가 `ToolMeta` 를 지어 주므로 `ToolGate` 와 `filter_tools` 가 MCP 도구와 같은 규칙을 적용합니다. 규칙은 `mcp(접두사/이름)` 입니다.
- **등급은 플러그인이 밝힙니다** (`risk`, `risk_of`). 밝히지 않으면 '등급을 모르는 도구' 입니다. 기본 모드에서는 묻고, 읽기 전용에서는 거부되며, 물을 사람이 없으면 거부됩니다. 앱 권한으로 도는 코드가 밝힌 값을 믿는다고 더 내주는 것은 없습니다. 다만 `trusted=False` 로 두어 `read_file` 같은 이름이 `KNOWN_TOOLS` 로 풀리지 않게 합니다.
- **`allowed_mcp_servers` 로 켭니다.** 체험 대화, 자문의 도구 상한 0, 합성처럼 도구 목록을 비우는 자리에서 저절로 빠집니다. 받지 않은 에이전트가 이름을 짐작해 불러도 `run_host_tool` 이 실행하지 않습니다.
- **맨이름을 받지 않습니다.** 내장 도구는 모델이 `load_skill` 로 불러도 받지만, 플러그인의 `lookup` 이 같은 이름의 MCP 도구를 가로채면 안 됩니다.

`tools__load_tools` 도 같은 길을 탑니다. 이번 요청의 `tools` 를 바꾸므로 `HostToolCall.loop` 를 씁니다.

### 5. 실패는 앱을 막지 않는다

- **읽을 때**: import 실패, 잘못된 이름, 내장 이름 가로채기는 그 플러그인만 빠지고 이유가 남습니다. 로그, `GET /api/plugins`, 로스터의 전략 칸 경고로 볼 수 있습니다. 설정을 고치려면 화면이 떠야 합니다.
- **전략이 돌 때**: 엔진은 `speakers_for_round` 로 묻습니다. 전략이 터지거나 아무도 부르지 않으면 우선순위 순서로 물러서고 그 사실을 타임라인에 남깁니다. 사람이 고른 전략대로 돌았다고 믿으면 안 되기 때문입니다. 이 토론에 없는 에이전트는 걸러 냅니다.
- **호스트 도구가 돌 때**: 예외는 다른 도구처럼 관측이 됩니다([ADR-014](ADR-014-tool-failure-is-observation.md)). 자기 접두사가 아닌 이름의 정의는 버립니다. 실어 주면 그 호출이 MCP 서버나 다른 제공자에게 가서, 정의를 지은 쪽과 실행하는 쪽이 갈라집니다.
- **이름을 가로챌 수 없습니다.** 저장된 대화가 내장 전략과 옛 이름을 들고 있으므로, 덮어쓰면 그 대화들이 모르는 사이에 다른 전략으로 돕니다.

## 검토한 대안

- **`strategies/` 와 `host_tools/` 대신 `plugins/` 폴더 하나**: 전략과 그 전용 도구를 한 파일에 둘 수 있어 끌렸지만, 파일 하나를 넣었을 때 무엇이 켜지는지 폴더 이름으로 알 수 없습니다. 둘을 함께 배포하려면 entry point 를 씁니다.
- **예약어를 레지스트리로 옮기기**: `config` 는 `agents` 를 import 할 수 없고, 설정 검증이 레지스트리보다 먼저 돕니다. 그래서 내장 네 개는 `RESERVED_SERVER_NAMES` 에 그대로 두고, 플러그인 접두사는 등록할 때 더합니다. 시험이 두 표가 같은지 지킵니다.
- **플러그인을 샌드박스에서 실행**: 전략은 엔진이 라운드마다 동기로 부르고, 호스트 도구는 이번 발언의 문맥(에이전트, 도구 루프)을 봅니다. 프로세스 밖에 둘 수 있는 도구라면 MCP 서버로 만들면 됩니다.

## 결과 (Consequences)

- 전략을 더하는 데 앱 코드를 고치지 않아도 되고, 소스 업데이트에도 남습니다. 화면, 헤드리스 API, 내장 MCP 서버, `bench` 가 모두 `STRATEGY_MAP` 을 보므로 따로 할 일이 없습니다.
- 호스트 도구 하나를 더할 때 고치는 곳이 제공자 클래스 하나로 줄었습니다. `ask` 가 전사 예산에서 빠져 있던 어긋남도 함께 사라졌습니다.
- **플러그인은 앱과 같은 권한으로 돕니다.** 판정은 호출을 막을 수 있을 뿐, 플러그인 안에서 무엇을 하는지는 보지 못합니다. 폴더에 파일을 넣는 일은 패키지를 설치하는 일과 같은 무게입니다.
- 호스트 도구 플러그인은 인자 단위 판정을 받지 못합니다. 경로를 받는 도구라면 `read(경로)` 규칙이 걸리지 않고 도구 단위로만 판정되며, 고정 보호도 플러그인이 스스로 지켜야 합니다.
- 전략은 순수 함수여야 하지만 강제하지 못합니다. 이벤트 루프를 붙잡는 전략은 진단 기록의 멈춤으로만 드러납니다.
- 플러그인을 지우면 그 전략을 쓰던 대화는 기본 전략으로 돌아갑니다. 로그에 한 번 남습니다. 플러그인을 다시 넣으면 대화의 전략은 돌아옵니다(대화가 이름을 그대로 들고 있습니다).
- 플러그인을 바꾸면 서버를 다시 시작해야 합니다.
