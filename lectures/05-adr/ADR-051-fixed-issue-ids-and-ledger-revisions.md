# ADR-051. 미해결 쟁점에 서버가 고정 번호를 붙이고, 장부가 바뀔 때마다 개정 이력을 바로 저장한다

## 상태 (Status)

채택됨 · 2026-11-06 · 관련: [ADR-020](ADR-020-conversation-memory.md), [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-034](ADR-034-adaptive-graph-and-sub-debates.md), [ADR-038](ADR-038-edit-the-ledger-directly.md), [ADR-041](ADR-041-postgresql-compatibility.md), [ADR-049](ADR-049-execution-grounded-diagnostician-and-stagnation-observer.md)

## 맥락 (Context)

- 에이전트가 3명 이상이고 라운드가 2회를 넘어가면 단순 시간순 피드만으로는 토론 흐름을 추적하기 어렵습니다. UI 화면에 "라운드별 미해결 쟁점 해소 추이"를 시각화하고, 발언 간 상호 인용 시 쟁점을 고유 식별자로 참조하려면(후속 ADR-052) 쟁점의 불변 정체성(Identity)이 보장되어야 합니다.
- 결정 장부는 오케스트레이터가 매 라운드마다 **전체를 새로 작성합니다**(ADR-020). 동일한 쟁점이라도 라운드마다 표현이 달라져 쟁점 고유의 정체성이 유지되지 못했습니다. 서브 토론(ADR-034)은 쟁점을 목록 위치(인덱스)나 본문 텍스트 일치로 식별해야 했고, 정체 관찰자(ADR-049) 역시 본문 텍스트 정규화 서명에 의존하여 문장이 조금만 바뀌어도 상태 감지에 실패했습니다.
- 결정 장부는 턴 종료 시점에만 `sessions.decision_ledger`에 저장됩니다. 라운드별 중간 장부는 정체 관찰자 메모에만 부분적으로 남고 턴 종료 시 소멸되었습니다. 따라서 라운드별 개정 이력을 체계적으로 영속화해야 했습니다.
- 검토한 선택지:
  - **LLM 에게 번호를 맡기기** — 모델은 번호를 빠뜨리고, 겹치게 쓰고, 지어냅니다. 닫힌 쟁점의 번호를 다른 쟁점에 다시 붙이기도 합니다.
  - **쟁점 표를 따로 두기** — 쟁점 행과 장부 글이 서로 어긋날 수 있고, 장부를 다시 쓸 때마다 두 곳을 맞춰야 합니다.
  - **SAVEPOINT 로 개정 저장 실패를 격리하기** — SQLite 드라이버(pysqlite·aiosqlite)에서 SAVEPOINT 를 제대로 쓰려면 엔진 전체의 트랜잭션 시작 방식을 바꾸는 우회가 필요합니다.

## 결정 (Decision)

**미해결 쟁점의 번호는 서버가 부여합니다** (`app/orchestration/ledger_history.py`의 `assign_issue_ids`). 장부의 `## 미해결 쟁점` 항목은 `- [I-3] 내용` 형식을 취하며, 나머지 4개 섹션은 기존 구조를 유지합니다. 프롬프트는 "직전 장부의 `[I-n]` 태그는 유지하고, 신규 쟁점은 번호 없이 작성하라"고만 지시합니다. 각 항목의 번호는 다음 순서에 따라 결정됩니다:

1. 유효한 태그가 존재하고 그 번호가 기존 최대 번호 이하이며, 현재 장부에서 아직 사용되지 않았다면 그대로 유지합니다.
2. 그렇지 않은 경우, 정규화된 텍스트가 세션의 쟁점 색인(`IssueIndex`) 내 기존 쟁점과 일치하면 해당 번호를 재사용합니다 (종결된 쟁점 포함).
3. 위 조건에 해당하지 않으면 순차적으로 신규 번호를 발급합니다.

- 해결된 쟁점은 목록에서 제거합니다. 목록에서 제외되면 종결된 것으로 간주하며, 과거 번호가 다시 나타나면 동일 쟁점이 재개된 것으로 처리합니다. 문구가 일부 변경된 채 재개된 쟁점까지 식별하기 위해, 장부 프롬프트에 **최근에 닫힌 쟁점** 목록(최대 5개)을 번호와 함께 제공합니다.
- **번호는 결코 재사용하지 않습니다.** 다음 발급 번호는 개정 이력의 `issue_high`, 현재 장부 본문의 최대 번호, 메모리 색인 내 값 중 최댓값에 1을 더해 산출합니다. 장부 본문을 함께 검토하는 이유는 `continue_session`으로 텍스트만 인계된 세션이나 저장이 누락된 개정을 보완하기 위함입니다. 비정상 종료되거나 폐기된 턴의 번호는 해당 턴의 개정 이력과 함께 삭제되므로 재사용될 수 있습니다.
- 미해결 쟁점 외 다른 섹션으로 이전된 항목(예: 결정 사항으로 이전된 안건) 머리에 붙은 태그는 자동으로 제거합니다.

**장부가 바뀔 때마다 개정 이력을 바로 저장합니다.** 표는 `ledger_revisions` 하나이고, 쟁점 목록은 그 행의 JSON 칸(`open_issues`)에 둡니다. 별도 쟁점 표는 두지 않습니다.

- `update_ledger(db=, kind=)` 가 갱신에 성공할 때마다 한 행을 넣습니다. 부르는 곳 6곳이 종류를 밝힙니다: `round`·`step`·`subdebate`·`final`·`resume`·`retry`. 직접 수정(ADR-038)은 `edit` 를 남깁니다.
- `decided`·`rejected` 는 **개수만** 저장합니다. 변화량 머리줄과 요약 띠에는 개수만 필요하고, 항목은 같은 행의 `ledger` 글에서 다시 꺼냅니다. `open_issues` 는 장부 글에서도 꺼낼 수 있지만, 색인과 비교가 장부를 매번 파싱하지 않도록 따로 둡니다.
- 정렬 키로는 세션 내 순번 `seq`를 사용합니다. Windows 환경(Python 3.12)의 타이머 해상도(약 15ms)로 인해 동일 라운드 개정의 `created_at` 타임스탬프가 동일하게 기록되는 정렬 불안정 문제를 해결하기 위해 도입되었습니다.
- **트랜잭션은 본 저장소의 기존 원칙을 철저히 준수합니다.** 레코드 삽입 즉시 커밋하며, 실패 시 롤백 후 `persist_failed` 이벤트를 발행합니다. 토론 진행은 중단되지 않습니다. 오케스트레이션 엔진의 모든 저장은 즉시 커밋되므로 호출 시점에 미커밋 상태의 다른 변경이 없으며, 롤백은 해당 개정 이력 1행만 취소합니다. 이 전제는 단위 테스트를 통해 엄격히 검증됩니다 (호출 시점마다 `db.new`, `db.dirty`, `db.deleted`의 공백 상태 단정). 모든 컬럼 값은 파이썬 레벨에서 확정하며 커밋 후 재조회하지 않습니다. 롤백 시 만료된 ORM 인스턴스를 비동기 컨텍스트에서 접근하려다 발생하는 예외를 원천 방지하기 위함입니다.
- 쟁점 색인은 턴 내 최초 장부 갱신 시점에 DB 개정 이력을 1회 조회하여 구축합니다. 조회가 끝난 직후 트랜잭션을 닫아 커넥션을 풀에 반환합니다(ADR-041). 직후에 장시간 소요되는 LLM 호출이 이어지기 때문입니다. 세션 재개 시에는 상태를 다시 초기화하므로 해당 턴의 이전 개정까지 모두 재조회하여 색인의 완전성을 보장합니다.

**쓰는 곳.**

- 서브 토론: 프롬프트에 번호 붙은 쟁점을 보여 주고 `"issue_id": "I-3"` 으로 받습니다. 지금 열린 번호만 받습니다. System 1 판정(`evaluate_sub_debate`)은 고른 항목에서 태그를 떼어 번호를 따로 돌려줍니다(`app.agents` 는 `app.orchestration` 을 가져올 수 없어 태그 패턴을 따로 둡니다). 안내 메모에 `issue_no` 를 저장하고, 결론 머리줄은 `[서브 토론 결론 · I-3 · …]` 입니다.
- 정체 관찰자: 번호가 있으면 서명에 `issue:I-3` 을 씁니다.
- 직접 수정: 편집기 UI는 쟁점 번호를 수정 불가능한 칩으로 렌더링하며, 저장 시 신규 쟁점에 새 번호를 발급합니다. 변경 안내 메시지는 쟁점 번호 기반으로 비교·작성됩니다(수정·종결·추가).
- 수렴 판정과 합의 판정은 개수만 보므로 그대로입니다. 장부를 자를 때 붙는 생략 표시 줄이 쟁점으로 세어지던 문제도 함께 고쳤습니다.

## 결과 (Consequences)

**장점 (Positive Consequences)**

- 쟁점이 라운드, 턴, 세션 재개를 거쳐도 불변 고유 식별자를 유지합니다. 서브 토론과 정체 관찰자가 모호한 문장 대신 고유 번호로 쟁점을 정확히 참조합니다.
- 라운드별 장부 개정 이력이 체계적으로 보존되어 (턴, 라운드) 단위의 상태 변화량(`round_deltas`: 결정 +n, 종결, 신규 쟁점)을 정확히 산출할 수 있습니다. 이는 UI 요약 띠와 라운드 묶음 헤더 구현의 기반이 됩니다.
- 개정 이력 저장이 실패하더라도 인메모리 쟁점 번호와 토론 진행은 안전하게 보존되며, 후속 개정 이력은 정상 기록됩니다.

**비용 및 제약 (Negative Consequences)**

- 장부를 갱신할 때마다 DB 읽기(순번)와 쓰기가 한 번씩 늘고, 턴의 첫 갱신에는 이력 읽기가 한 번 더 있습니다.
- 장부 프롬프트가 조금 길어집니다(번호 규칙 두 줄, 닫힌 쟁점 최대 5줄).
- 글을 바꿔 다시 연 쟁점에 모델이 번호를 되살리지 않으면 새 번호를 받습니다. 막지 않습니다.
- 개정 이력 없이 장부 글만 바뀐 경우(사람이 DB 를 직접 고친 경우 등)에는 그 글에만 있던 쟁점의 글을 다음 턴이 모릅니다. 번호는 `issue_high` 로 지켜지지만, 같은 글로 다시 연 쟁점을 알아보지 못합니다.
- 옛 대화에는 개정 이력이 없습니다. 옛 데이터를 채워 넣지 않습니다(배포 전이라 하위호환을 두지 않습니다).

**이후에 따라올 결정**

- ADR-052: 발언 번호(`[S14]`)와 쟁점 번호(`[I-3]`)로 인용하고 화면에서 그 자리로 이동합니다.
- 쟁점별 스레드 보기는 이번 번호를 바탕으로 따로 다룹니다.
