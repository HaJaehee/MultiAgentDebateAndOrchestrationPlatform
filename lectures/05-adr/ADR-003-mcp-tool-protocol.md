# ADR-003. 도구는 MCP 서버로, 앱과 다른 프로세스에서 돌린다

> [ADR 목록](README.md) · 이전: [ADR-002](ADR-002-litellm-gateway.md) · 다음: [ADR-004](ADR-004-sqlite-persistence.md)

## 상태 (Status)

채택됨 · 2026-08-26 (초기 설계), 2026-08-31 원격 서버 지원 추가 · 관련: [ADR-005](ADR-005-long-lived-mcp-sessions.md), [ADR-010](ADR-010-host-defined-tool-scope.md), [ADR-016](ADR-016-per-workspace-mcp-runtime.md)

## 맥락 (Context)

- 에이전트가 주장을 검증하려면 다양한 도구가 필요합니다. 파일을 읽고 쓰고, 코드를 실행하며, Git 변경 이력을 조회하고, 합의된 사실을 지식 베이스에 영속화해야 합니다.
- 이러한 도구 기능들을 메인 애플리케이션 내부에 파이썬 함수로 직접 구현하면, 도구가 메인 웹 앱과 동일한 프로세스, 동일한 권한 수준에서 동작하게 됩니다. 만약 샌드박스 커널이 비정상 종료되거나 무한 루프에 빠지면 메인 서버 프로세스도 함께 중단됩니다.
- 향후 추가될 도구의 종류(사내 문서 검색, 슬라이드 발표자료 생성 등)가 지속적으로 늘어날 것이 확실했습니다.
- MCP(Model Context Protocol)는 개방형 표준 규격이며, 파일 시스템, 메모리 그래프, 순차적 사고 등 공식 참조 서버와 다국어 SDK가 이미 성숙하게 제공되고 있었습니다.

## 결정 (Decision)

MCP Python SDK를 활용하여 호스트(Host)를 직접 구현하고, **모든 도구를 외부 MCP 서버 프로세스로 분리하여 연동하도록 합니다.**

- 기본 도구 서버(filesystem, memory, git, sandbox)는 메인 애플리케이션이 **독립된 자식 프로세스로 직접 기동하고 표준 입출력(stdio)을 통해 통신하도록 합니다.**
- 도구 식별자는 `서버명__도구명` 형식의 네임스페이스를 부여하고, OpenAI 도구 호출 스키마로 변환하여 모델에게 전달합니다.
- 에이전트 설정마다 `allowed_mcp_servers` 필드를 두어, 사전에 인가된 서버의 도구만을 모델 컨텍스트에 노출합니다.
- MCP SDK 라이브러리 버전은 `>=1.29.0,<2` 범위로 엄격히 고정합니다. MCP 2.x에서 서버 API 인터페이스가 크게 변경되어 동봉된 샌드박스 서버와 Git 서버의 기동이 실패하는 호환성 문제를 방지하기 위함입니다.
- (2026-08-31 추가) 외부 네트워크에 이미 기동 중인 원격 MCP 서버는 URL 주소를 통해 연동합니다. 서버 설정 시 `command`와 `url` 중 정확히 하나만 선언해야 하며, 둘 다 선언하거나 둘 다 비워둘 경우 설정 검증 단계에서 즉시 거절합니다. 전송 프로토콜은 최신 Streamable HTTP 방식을 우선 시도하고, 실패할 경우 HTTP+SSE 방식으로 폴백합니다.

## 결과 (Consequences)

**좋아지는 점**

- 도구 실행 런타임이 메인 웹 애플리케이션과 독립된 프로세스로 격리됩니다. 코드 실행 커널이 크래시되더라도 메인 서버는 안정적으로 생존하며, 파일 시스템 서버는 허용된 루트 디렉터리 외부의 파일 접근 시도를 자체적으로 차단합니다.
- 새로운 도구를 시스템에 추가하는 작업이 단순 설정 파일에 실행 명령어 또는 원격 접속 주소를 등록하는 작업으로 단순화됩니다.
- Node.js 기반 생태계의 서버와 Python 기반 서버를 동일한 표준 규격 아래 유연하게 혼합 운용할 수 있습니다.

**치르는 비용**

프로세스 격리 아키텍처는 결코 비용이 공짜가 아닙니다. 이 결정 이후 호스트 오케스트레이터가 떠안아야 하는 복잡성이 지속적으로 증가했습니다.

- 비동기 세션의 수명 주기 관리, 연결 단절 감지 및 복구 재연결 메커니즘 구축 ([ADR-005](ADR-005-long-lived-mcp-sessions.md))
- 자식 프로세스 기동 실패 시 표준 오류(stderr) 스트림을 캡처하여 사용자에게 원인을 시각화하는 기능 구현
- 무응답 상태에 빠진 도구 프로세스에 대한 타임아웃 강제와 과도하게 큰 응답 크기 제한 ([ADR-014](ADR-014-tool-failure-is-observation.md))
- 프로세스 ID 재사용 문제를 회피하기 위한 OS 프로세스 핸들 기반의 엄밀한 자원 회수
- 복수의 대화 세션이 단일 도구 서버 프로세스를 공유할 때 발생하는 데이터 격리 보장 ([ADR-010](ADR-010-host-defined-tool-scope.md))
- 도구 서버의 작업 디렉터리가 프로세스 기동 시점에 고정되어 발생하는 동시성 제약 해결 ([ADR-009](ADR-009-refuse-cross-workspace-debates.md), [ADR-016](ADR-016-per-workspace-mcp-runtime.md))
- MCP SDK의 메이저 버전 변경에 따른 라이브러리 하위 호환성 유지 관리

**교훈**

"개방형 표준 규격을 따르는 외부 서버를 연동한다"는 결정은 개별 도구의 기능 구현 부담을 크게 덜어 주는 대신, **분산 시스템이 수반하는 고유한 복잡성과 장애 관리 책임**을 호스트에게 전가합니다. 독립 프로세스가 하나 늘어날 때마다 잠재적인 실패 지점도 정비례하여 증가한다는 사실을 시스템 기획 단계부터 철저히 고려해야 합니다.
