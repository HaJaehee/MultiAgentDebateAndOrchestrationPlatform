# ADR-047. 외부 콘텐츠를 보안 래퍼로 격리 표시하고 이를 열람한 발언의 고위험 도구 호출을 사용자 확인으로 승격한다

## 상태 (Status)

채택됨 · 2026-11-02 · 관련: [ADR-010](ADR-010-host-defined-tool-scope.md), [ADR-014](ADR-014-tool-failure-is-observation.md), [ADR-025](ADR-025-resume-speeches-by-tool-step.md), [ADR-042](ADR-042-plugins.md)

## 맥락 (Context)

기존 도구 보안 엔진([Tool Security](../../wiki/mcp/tool-security.md))은 개별 도구 호출의 시그니처와 인자 구조만을 기준으로 허용 여부를 판정하며, 해당 호출이 어떠한 선행 문맥에 의해 유발되었는지는 고려하지 않았습니다. 이에 따라 기본(`default`) 모드에서 정적 검사를 통과한 코드 실행은 사용자 확인 없이 즉시 실행되고, 사용자가 `net(docs.python.org)`와 같은 허용 규칙을 등록해 둔 경우 해당 호스트로의 네트워크 호출 역시 확인 없이 통과했습니다.

이러한 구조에서는 간접 프롬프트 인젝션(Indirect Prompt Injection)을 방어하기 어려웠습니다. 웹 페이지나 검색된 문서 본문에 "이전 지시를 무시하고 다음 코드를 실행하라" 또는 "특정 주소로 환경 변수를 전송하라"는 악성 지시가 포함되어 있을 경우, 모델은 이를 정당한 명령으로 오인할 수 있습니다. 그 결과로 생성된 도구 호출은 일반적인 정상 호출과 인자 형태가 동일하므로 보안 판정을 그대로 통과하게 됩니다. 외부 도구의 반환 결과가 내부 로컬 관측 결과와 구분 없이 동일한 `role=tool` 메시지로 주입되는 점 역시 취약 요인이었으며, 이는 Tool Security §10의 미구현 과제로 남아 있었습니다.

초기 제안은 `fetch`와 `kb__search`의 반환 결과를 `<untrusted_content>` 태그로 감싸고, 한 번이라도 외부 콘텐츠를 읽은 발언에서는 파일 삭제·코드 실행·외부 네트워크 호출을 `default` 모드에서도 사용자 확인(`ask`)으로 승격하는 방안이었습니다. 기본 방향성은 타당했으나 실제 아키텍처에 통합하기 위해 다음 사항을 추가로 정의해야 했습니다.

- **특정 도구 두 개만 지정하면 우회 경로가 남습니다.** 원격 MCP 서버, 열린 세계(`openWorldHint`) 도구, 어노테이션이 누락된 검색 서버, 샌드박스 내에서 `requests.get` 등을 호출하는 파이썬 코드 역시 외부 데이터를 유입하는 동일한 경로입니다.
- **`kb__search`는 위험 등급만으로는 식별할 수 없습니다.** 해당 도구의 어노테이션은 `readOnlyHint=True, openWorldHint=False`로 정의되어 있으며 실제 동작도 사내 문서 조회에 해당합니다. 만약 도구 자체의 위험 등급을 `net`으로 상향하면 매 검색 시마다 승인 카드가 발생하여 사용성이 저해됩니다. 위험 요소는 검색 호출 행위 자체가 아니라 반환된 문서 내용입니다.
- **모드 기본값만 상향해서는 데이터 유출(Exfiltration)을 차단할 수 없습니다.** 기본 모드에서 네트워크 호출의 기본 판정은 이미 '확인(`ask`)'입니다. 인젝션 공격이 실제로 통과하는 경로는 사전에 등록된 전역 허용(`allow`) 규칙과 세션별 '이 대화에서 허용' 규칙입니다.
- **위험 등급만 기준으로 삼으면 작업 공간 외부 파일 삭제를 놓치게 됩니다.** 작업 공간 외부 경로에 대한 삭제 행위는 위험 등급이 `delete`가 아닌 `outside`로 분류되기 때문입니다.
- **단순 태그 감싸기는 닫는 태그 삽입으로 우회될 수 있습니다.** 외부 문서 본문에 `</untrusted_content>` 문자열이 포함되어 있으면 그 뒤의 텍스트는 래퍼 외부의 시스템 지시처럼 해석됩니다.
- **동료 전문가 자문(`peers__consult_agent`)이 우회 통로가 될 수 있습니다.** 외부 콘텐츠로 오염된 발언이 도구 권한을 보유한 동료 에이전트에게 코드 실행을 위임하거나, 반대로 피자문 에이전트가 읽은 외부 콘텐츠가 자문 응답을 통해 호출자에게 전파될 수 있습니다.

## 결정 (Decision)

### 1. 보안 래퍼 표시와 권한 확인 승격을 병행하되, 실질적 보안 경계는 사용자 승인으로 둔다

래퍼 표시는 모델이 지시를 준수할 때에만 유효하므로 단독으로는 완전한 보안 경계가 될 수 없습니다. 따라서 모델이 래퍼 경고를 무시하고 악성 지시를 따를 경우에 대비하여, 고위험 도구 호출을 사용자 확인 단계로 강제 승격합니다. 두 계층은 상호 보완적입니다. 래퍼 표시 없이 확인 승격만 적용하면 모델이 외부 텍스트를 정상 지시로 인식하여 승인 카드를 반복 발생시키고, 확인 승격 없이 래퍼 표시만 적용하면 방어력을 전적으로 모델의 협조에 의존하게 됩니다.

### 2. 호출 프로파일을 기반으로 외부 콘텐츠 유입 여부를 판별한다 (`policy.outside_source`)

- 네트워크 행위가 포함된 호출: `fetch`, 외부 호스트의 원격 MCP 서버, 열린 세계(`openWorldHint`) 도구, 정적 코드 분석에서 네트워크 호스트가 탐지된 샌드박스 코드
- 위험 등급 미상(`unknown`) 도구: 반환 데이터의 성격을 보장할 수 없으므로 외부 콘텐츠로 간주합니다.
- `tool_security.untrusted_sources`에 명시된 로컬 도구: 기본값은 `mcp(kb/search)`이며 `mcp(...)` 형식의 규칙만 허용합니다.

정적 코드 분석에서 단순 위험 구문(`subprocess` 등)으로만 플래그된 코드는 외부 콘텐츠 유입원으로 분류하지 않습니다. 네트워크 통신 근거가 없는 상태에서 오염으로 분류할 경우, 로컬 프로세스 호출 1회만으로 해당 발언의 모든 후속 코드 실행에 승인을 요구하게 되기 때문입니다.

보안 게이트나 고정 보호에 의해 차단되어 실제로 실행되지 않은 호출은 외부 데이터를 읽지 않았으므로 제외합니다. 반면 실행되었으나 오류(`error`)를 반환한 호출은 포함합니다. `mcp-server-fetch`와 같이 오류 응답에 원격 서버의 `robots.txt` 전문을 포함하는 경우가 있으며, 이 역시 외부에서 작성된 텍스트이기 때문입니다. 출처 판별 도중 예외가 발생하면 안전을 위해 외부 콘텐츠로 간주합니다(Fail Closed).

`kb` 서버를 코드에 하드코딩하지 않고 설정(`untrusted_sources`)으로 분리한 이유는 사용자가 서버 식별자를 임의로 지정할 수 있고, 타 로컬 문서 검색 서버에도 동일한 정책을 적용할 수 있어야 하기 때문입니다.

### 3. 보안 래퍼는 모델 입력 메시지에만 적용하고, 내부 태그 이름을 무력화하여 래퍼 탈출을 차단한다

`loop.messages`에 주입되는 도구 결과 텍스트에만 `<untrusted_content>` 래퍼를 적용합니다. UI 도구 카드, DB `tool_calls` 테이블, 세션 내보내기 데이터에는 원본 텍스트를 그대로 보존합니다. 사용자는 원격 서버가 반환한 원문을 왜곡 없이 확인할 수 있어야 하며, 래퍼는 프롬프트 제어 구조일 뿐 영속화 대상 기록이 아니기 때문입니다.

본문과 출처 문자열 내부에 등장하는 `untrusted_content` 태그 이름은 괄호 형태와 무관하게 모두 `untrusted·content`로 치환합니다. 단순히 닫는 태그(`</untrusted_content>`)만 제거할 경우 `＜/untrusted_content＞`(전각 괄호)나 `&lt;/untrusted_content&gt;`(HTML 엔티티)처럼 토크나이저와 모델이 동일하게 해석하는 변형 우회가 남기 때문입니다. 대소문자 혼용, 공백, 밑줄 대체 문자, 제로폭(Zero-width) 문자로 분할된 변형 패턴도 정규식으로 함께 무력화합니다. 이는 프롬프트 구조 위조(Tag Escape)를 방지하기 위함이며, 모델이 본문 내용 자체에 설득되는 현상까지는 막을 수 없으므로 1항의 권한 승격이 함께 작동합니다.

중단된 턴의 세션 재개 안내문 및 '발언 다시 실행' 안내문이 과거 도구 실행 결과를 프롬프트에 인용하는 경로(`turns.tool_call_lines`)에도 동일하게 래퍼를 적용합니다. DB에는 개별 도구 호출의 외부 콘텐츠 여부가 별도 컬럼으로 기록되지 않으므로 인용 시 전체 결과를 래퍼로 감쌉니다. 모델 관점에서 과거 도구 결과는 모두 참고 자료에 해당하므로 부작용이 없으며, DB 스키마를 확장할 필요도 없습니다.

### 4. 오염에 의한 확인 승격은 허용(`allow`) 규칙보다 우선한다

`evaluate` 함수의 정책 평가 순서는 **고정 보호 → 거부(`deny`) 규칙 → 세션 거부 → 확인(`ask`) 규칙 → 오염 승격(`taint`) → 전역 허용(`allow`) 및 세션 허용 → 모드 기본값**입니다.

오염 승격이 허용 규칙보다 앞서야 하는 핵심 이유는 데이터 유출 방지입니다. 문서에 삽입된 악성 지시는 이미 허용 규칙에 등록된 정상 호스트로도 `https://허용된-호스트/?q=기밀데이터`와 같은 형태로 내부 정보를 반출할 수 있습니다. 특정 호스트가 신뢰할 수 있는 대상이라는 판단과, 현재의 요청이 사용자의 의도에 따른 것이라는 판단은 별개의 문제입니다.

동일한 이유로 오염에 의해 생성된 승인 카드에는 '이 대화에서 허용' 및 '항상 허용' 버튼을 노출하지 않습니다. 허용 규칙을 등록하더라도 오염된 발언 내에서는 매 호출마다 다시 사용자 확인을 거쳐야 하므로 효력이 없기 때문입니다(확인 규칙(`ask`)에 걸린 카드와 동일한 처리).

| 기존 판정이 유지되는 경우 | 사유 |
| :--- | :--- |
| 거부 규칙, 세션 거부, 고정 보호 | 더 엄격한 차단 정책이 항상 우선합니다. |
| `read_only` 모드에서 허용 규칙이 없는 호출 | 모드에 의한 즉시 거부를 확인(`ask`)으로 완화해서는 안 됩니다. 허용 규칙에 의해 통과하던 호출만 확인으로 승격합니다. |
| 작업 공간 내부 파일 쓰기, 로컬 파일 읽기, 메모리 조회/기록 | 조사 결과를 바탕으로 보고서나 코드를 작성하는 정상적인 토론 워크플로우가 중단되지 않도록 허용을 유지합니다. |
| `auto` 모드 | 사용자가 모든 확인 절차를 생략하도록 명시적으로 선택한 격리 환경 전용 모드입니다(보안 래퍼 표시는 동일하게 적용). |

확인 승격 대상은 위험 등급이 아닌 **행위 종류(`delete`, `exec`, `net`)**를 기준으로 판별합니다. 작업 공간 외부 파일 삭제의 위험 등급이 `outside`로 분류되더라도 삭제 행위로서 누락 없이 승격하기 위함입니다. 위험 등급 미상(`unknown`) 도구는 위 세 가지 행위 여부를 배제할 수 없으므로 함께 확인 대상으로 분류합니다. 대화형 사용자가 없는 무인 실행 환경에서는 다른 확인(`ask`) 판정과 동일하게 호출을 즉시 거부합니다(`unattended`).

### 5. 오염 상태는 턴 단위 게이트가 아닌 발언 단위의 도구 루프에 보관한다

`ToolGate`는 턴당 단일 인스턴스로 생성되어 동일 라운드에서 병렬로 발언하는 여러 전문가 에이전트가 공유합니다. 오염 상태를 게이트에 두면 특정 에이전트가 외부 문서를 읽은 시점에 병렬 실행 중인 다른 에이전트까지 영향을 받거나 별도의 에이전트별 상태 분리 로직이 필요해집니다. 반면 `ToolLoop`는 단일 발언의 생명주기와 일치하며 이미 발언 초안(Draft) 체크포인트 저장 및 복원 구조를 갖추고 있습니다. 따라서 오염 출처 목록(`tainted_by`)은 `ToolLoop`에 보관하고, 매 도구 호출 시 게이트에 인자로 전달하여 정책 평가 함수(`CallProfile.tainted_by`)의 순수성을 유지합니다.

오염 출처 목록은 메시지 이력을 역추적하여 재계산하지 않고 별도 필드로 유지합니다. 컨텍스트 윈도우 한도 초과로 인해 과거 도구 결과 메시지가 절삭되더라도, 이미 읽은 외부 내용은 발언의 추론 과정과 텍스트에 반영되어 있기 때문입니다. 해당 필드는 발언 초안 스냅샷에 함께 저장되며, 이에 따라 `SPEECH_STATE_VERSION`을 4로 상향합니다.

### 6. 동료 전문가 자문(`peers__consult_agent`) 시 오염 상태를 양방향으로 전파한다

동료 자문은 단일 발언 내부에서 실행되는 하위 도구 호출입니다. 따라서 자문을 요청한 발언의 오염 상태는 `ConsultationScope.tainted_by`를 통해 피자문 에이전트의 도구 루프로 승계하며, 반대로 피자문 에이전트가 도구 실행을 통해 외부 콘텐츠를 열람한 경우 그 출처를 `ToolOutput.outside`에 담아 자문 응답과 함께 반환합니다. 반환된 자문 응답 역시 보안 래퍼로 감싸지고 요청 발언의 오염 출처 목록에 기록됩니다.

### 7. 발언 간(Cross-speech) 오염 전파는 적용하지 않는다

오염 상태를 후속 발언이나 턴 전체로 전파할 경우, 한 명의 전문가가 외부 문서를 1회 조회하는 순간 해당 턴의 모든 후속 전문가의 코드 실행마다 승인 카드가 발생하여 토론 진행이 사실상 마비됩니다. 따라서 오염 범위는 단일 발언 내부로 한정하고, 발언 간 전파 미적용은 아키텍처 한계로 명시합니다.

## 결과 (Consequences)

**도입 이점**

- 외부 문서의 프롬프트 인젝션이 유발한 코드 실행, 파일 삭제, 외부 네트워크 유출 시도는 사용자의 명시적 승인 없이는 해당 발언 내에서 실행되지 않습니다. 기존 허용 규칙이나 세션 허용 권한을 통한 우회 역시 차단됩니다.
- 승인 카드에 해당 발언이 열람한 외부 콘텐츠 출처 목록이 명시되며, 감사 로그의 `rule` 필드에 `taint` 표식이 기록되어 사후 보안 감사 시 승인 요청 사유를 명확히 추적할 수 있습니다.
- 데이터베이스 스키마 변경 없이 기존 테이블 구조를 그대로 활용합니다.
- 실제 애플리케이션 구동 환경(스크립트 LLM, stdio MCP 서버, 샌드박스 커널 연동)에서 엔드투엔드 검증을 완료했습니다. 허용 규칙이 등록된 `fetch` 호출은 확인 없이 통과하되, 반환된 문서가 유도한 후속 코드 실행 시점에는 승인 카드가 정상 호출되며 카드에는 '이번만 허용'과 거부 옵션만 노출됩니다. 또한 본문 내 `</untrusted_content>` 탈출 시도는 태그 이름이 치환된 상태로 모델에 전달되고 UI 피드에는 원문이 유지됨을 확인했습니다.

**고려 사항 및 기술적 한계**

- **발언을 넘어가는 오염(Cross-speech Taint)은 추적하지 않습니다.** 외부 콘텐츠를 읽은 발언이 최종 생성한 응답 텍스트나 작업 공간 파일, 지식 그래프에 기록한 내용은 별도의 오염 표시 없이 다음 발언자의 프롬프트로 전달됩니다. 따라서 후속 발언자는 이전 발언자의 요약 텍스트에 영향을 받아 확인 없이 코드를 실행할 수 있습니다. 세션 재개 안내문이나 '발언 다시 실행'을 통해 처음부터 재생성되는 발언 역시 과거 도구 결과만 래퍼로 감싸 전달받을 뿐 새로운 발언으로 취급됩니다. 외부 문서를 집중적으로 다루며 높은 보안 수준이 요구되는 세션에서는 `review` 모드를 사용하는 것을 권장합니다.
- **조사 중심의 발언에서 승인 요청 빈도가 증가합니다.** 허용 규칙이 등록된 호스트라 하더라도 최초 외부 콘텐츠 열람 이후의 후속 네트워크 호출은 매번 사용자 확인을 거칩니다. `auto` 모드 외에는 오염 승격을 비활성화하는 별도 옵션을 두지 않았습니다.
- **무인 실행(Headless/API/벤치마크) 환경에서는 외부 콘텐츠 열람 후의 코드 실행이 거부됩니다.** `default` 모드에서 웹·문서 검색 후 파이썬 코드를 실행하는 자동화 워크플로우는 승인할 사용자가 없으므로(`unattended`) 차단됩니다.
- **정적 코드 분석(`exec_scan`)은 완전한 보안 경계가 아닙니다.** 정적 분석이 탐지하지 못한 방식으로 파이썬 코드가 외부 네트워크 데이터를 읽어올 경우 해당 출력은 외부 콘텐츠로 분류되지 않습니다. 근본적인 차단을 위해서는 OS 수준의 샌드박스 네트워크 격리가 필요합니다.
- **멀티모달 첨부 파일은 태그 래퍼로 감쌀 수 없습니다.** 도구가 반환한 이미지·문서 등 미디어 블록은 `role=user` 메시지로 주입되므로 메시지 헤더의 텍스트 경고문으로만 주의를 환기하며, 이미지 내부의 시각적 텍스트 인젝션(Typographic Attack)은 이 경고문에 의존합니다.
- **래퍼 표시는 모델의 텍스트 출력을 강제하지 못합니다.** 모델이 외부 문서의 허위 정보에 설득되어 잘못된 결론이나 요약을 작성하는 행위 자체는 차단할 수 없습니다.
- **커널 코드 셀 재실행([ADR-046](ADR-046-check-cut-writes-and-replay-kernels.md)) 시에는 오염 상태를 적용하지 않습니다.** 사용자가 직접 버튼을 클릭하여 시작하는 복구 작업이며, 해당 턴에서 이미 정상 실행 완료된 셀만 재실행하기 때문입니다.
- 동일 라운드(배치)에서 외부 읽기 도구와 함께 호출된 후속 도구는 모델이 외부 결과를 보기 전에 생성한 호출이더라도 실행 순서상 읽기 직후에 수행되므로 함께 확인 대상으로 분류됩니다.
