# ADR-012. 발언 순서와 진영은 에이전트가 들고, 전략은 순서와 지침만 정한다

> [ADR 목록](README.md) · 이전: [ADR-011](ADR-011-session-config-snapshot.md) · 다음: [ADR-013](ADR-013-json-config.md)

## 상태 (Status)

채택됨 · 2026-08-30 (v0.1) · 관련: [ADR-011](ADR-011-session-config-snapshot.md), [ADR-021](ADR-021-graph-debate.md)

## 맥락 (Context)

- 발언 순서가 전략 코드 안에 `{"architect": 0, "coder": 1, "critic": 2}`처럼 박혀 있었습니다.
- 화면에서 에이전트를 만들 수 있게 되자 이 방식이 무너졌습니다. 표에 없는 키는 모두 같은 우선순위로 묶여
  언제나 맨 뒤로 밀렸고, 디베이트 전략에서는 제안자도 비판자도 아닌 "기타"로 빠졌습니다. 새로 만든 에이전트는
  자유 토론에서만 제자리를 찾았습니다.
- 에이전트별 맥락을 만드는 코드가 전략을 보지 않았기 때문에, "자유 토론"과 "순차 검증"은 발언 순서 말고는 다를
  것이 없었습니다. 순서를 한 기준으로 통일하면 두 전략은 완전히 같아질 상황이었습니다.
- 매 라운드 모든 에이전트가 말하는 방식은 긴 대화에서 토큰을 낭비했습니다. 필요한 사람만 부르는 방법이 필요했습니다.

## 결정 (Decision)

**에이전트가 자기 자리를 안다.**

- 발언 순서(`debate_priority`, 작을수록 먼저)와 진영(`debate_stance`: 제안, 비판, 중립)을 에이전트 설정 항목으로 둔다.
  지정하지 않으면 모두 같은 기본값이라 설정 파일에 적힌 순서가 그대로 유지된다.
- 로스터에서 카드를 끌면 순서를 10, 20, 30...으로 다시 매긴다. 사이에 자리를 남겨 두면 한 명을 끼워 넣을 때
  나머지를 다시 쓰지 않는다.
- 기본 에이전트들의 자리는 설정 파일에 적는다. 코드가 알던 것을 설정으로 옮긴다.
- 전략 코드에 남는 에이전트 키는 `orchestrator` 하나다. 그것은 역할이 아니라 시스템의 구조다.

**전략은 순서만 정하지 않는다.**

- 전략은 발언마다 붙는 **지침**도 돌려준다. 이것이 전략 사이의 실제 차이다.
- "자유 토론"과 "순차 검증"을 **순차 토론** 하나로 합친다. 우선순위 순서로 모두 말하되, 바로 앞 사람을 이름으로
  지목하고 그 결론을 이어받게 한다. 이 지침이 없으면 라운드는 독백 세 개가 된다.
- 이미 저장된 대화(당시 365건)가 옛 전략 이름을 들고 있으므로 **별칭 표**로 새 이름에 연결한다. 대화를 문서로
  내보낼 때는 저장된 키가 아니라 실제로 도는 전략의 이름을 적는다.

**오케스트레이터 지명 전략을 더한다.**

- 매 라운드 오케스트레이터가 지금까지의 토론을 보고 필요한 에이전트만 고른다. 한 명만 불러도 된다.
- 지명 호출은 도구와 단계적 사고를 끈 오케스트레이터 사본으로 보낸다.
- 응답이 JSON이 아니어도 본문에서 아는 키를 등장 순서대로 긁는다.
- 엔드포인트가 없거나 아는 키를 하나도 못 찾으면 우선순위 순서로 물러서고, **물러선 사실을 기록한다.**
- 전략 객체는 LLM을 직접 부르지 않는다. "발언자를 오케스트레이터가 고른다"는 표시만 하고, 호출과 대체는 엔진이 한다.

## 결과 (Consequences)

**좋아지는 것**

- 사용자가 만든 에이전트가 모든 전략에서 제자리를 찾습니다.
- 새 전략을 추가하기 쉬워졌습니다. 바로 다음 날 병렬 지시 전략이 같은 틀 위에 올라갔고, 보름여 뒤에는 그래프
  토론이 올라갔습니다([ADR-021](ADR-021-graph-debate.md)).
- 전략이 순수 함수로 남아, v0.5.0에서 화면의 **발언 순서 미리보기**가 엔진과 같은 함수를 그대로 부를 수 있었습니다.
  카드 순서와 실제 발언 순서가 다른 전략(디베이트, 지명, 병렬)에서 "카드를 끌어도 아무 일도 없다"는 오해가 사라졌습니다.

**치르는 비용**

- 기본 에이전트의 순서와 진영을 설정 파일에 적어 두지 않으면, 디베이트 전략이 진영을 찾지 못해 한 줄 순서로
  주저앉습니다. 설정이 코드의 지식을 대신하게 된 만큼 설정 예시를 잘 관리해야 합니다.
- 옛 전략 이름의 별칭 표를 유지해야 합니다.

**새 전략을 만드는 사람을 위한 규칙**

- 에이전트 키로 분기하지 말고 에이전트 속성을 읽는다. 키는 사용자가 정하는 값이다.
- LLM이 필요하면 전략에서 부르지 말고 엔진에 표시한다.
- 은퇴시킨 전략 키는 별칭 표에 넣는다.
