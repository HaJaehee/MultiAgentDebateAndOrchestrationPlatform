# ADR-048. 에이전트별·라운드별 토큰 소모량과 소요 시간 미니 차트 시각화 및 기존 기록 기반 집계

> [ADR 목록](README.md) · 이전: [ADR-047](ADR-047-taint-speeches-that-read-outside-content.md) · 다음: [ADR-049](ADR-049-execution-grounded-diagnostician-and-stagnation-observer.md)

## 상태 (Status)

채택됨 · 2026-11-02 · 관련: [ADR-025](ADR-025-resume-speeches-by-tool-step.md), [ADR-036](ADR-036-retry-one-speech-and-inline-comments.md), [ADR-045](ADR-045-claude-prompt-cache-markers.md)

## 맥락 (Context)

- v1.5부터 발언과 턴의 토큰 및 LLM 소요 시간을 계측하고 있었으나(`app/agents/llm_usage.py`), UI상에서는 발언 카드의 툴팁과 턴 종료 후 상태 표시줄을 통해서만 확인할 수 있었습니다. 따라서 어느 에이전트나 라운드가 토큰과 시간을 많이 소모하는지 파악하려면 카드를 일일이 확인하여 수작업으로 계산해야 했습니다.
- 기록된 수치를 단순 합산할 경우 다음과 같은 4가지 불일치 문제가 발생합니다.
  1. 캐시 토큰은 입력 토큰에, 추론 토큰은 출력 토큰에 포함되므로, 이를 그대로 누적 막대로 쌓으면 막대 길이가 전체 토큰 합계를 초과하게 됩니다.
  2. 재실행된 발언([ADR-036](ADR-036-retry-one-speech-and-inline-comments.md))의 이전 버전 기록은 `messages.revisions`에 저장됩니다. 턴 합계에는 이 사용량이 포함되어 있으므로, 현재 버전만 합산하면 이전 버전의 사용량이 보조 호출로 오분류됩니다.
  3. 병렬 라운드에서는 여러 에이전트의 발언 시간대가 중복됩니다. 개별 발언 소요 시간을 단순 합산하면 실제 소요된 경과 시간(elapsed)보다 길어집니다.
  4. 중단 후 재개된 발언([ADR-025](ADR-025-resume-speeches-by-tool-step.md))은 중단 전의 시작 시각을 그대로 유지합니다. 서버가 장시간 꺼져 있었다면 해당 발언이 비정상적으로 긴 병목인 것처럼 왜곡되어 표시됩니다.
- MADO는 불필요한 차트 라이브러리 의존성을 지양해 왔습니다. NiceGUI에 내장된 ECharts가 있으나, 몇 개 행에 불과한 막대 그래프를 위해 무거운 Canvas 차트를 도입하면 접이식(Accordion) 패널 내 리사이징 문제나 색각 접근성 지원 등 불필요한 복잡도가 증가합니다.

## 결정 (Decision)

### 1. 집계 로직을 UI와 분리된 순수 함수로 구성하고 기존 기록만 조회

`app/orchestration/usage_report.py`의 `build_report` 함수가 턴 및 발언 레코드를 전달받아 집계 데이터를 생성합니다. 별도의 신규 계측이나 전용 집계 테이블을 추가하지 않습니다. 패널을 펼칠 때만 조회하고 메시지 본문(`content`)은 읽지 않으므로, 대화가 길어져도 턴마다 불필요한 쿼리가 발생하지 않습니다.

- 토큰은 중복되지 않는 4가지 세부 구성(캐시 제외 입력, 캐시, 추론 제외 출력, 추론)으로 분할합니다 (`token_parts`). 4개 항목의 합은 항상 `total_tokens`와 일치합니다. 캐시 쓰기(cache write) 토큰은 입력의 일부로 처리하며 툴팁과 상세 수치 표에 별도 표기합니다.
- 재실행된 이전 버전의 사용량도 합산합니다. 해당 턴에서 실제로 소모된 토큰이기 때문입니다.
- 턴 전체 합계에서 발언들의 합을 차감한 나머지는 **보조 호출** 항목으로 분류합니다. 의사결정 장부 기록·중간 요약·라우팅 호출 및 중단되어 기록되지 못한 발언의 호출이 포함됩니다. 단, 병목 분석 대상에서는 제외합니다.
- 전체 합계는 턴 레코드의 값을 그대로 사용하지 않고 '발언 합계 + 나머지(보조 호출)'로 계산합니다. 턴 합계는 단계 전환 시점에만 갱신되므로, 진행 중인 턴에서는 완료된 발언들의 합계보다 작을 수 있기 때문입니다.

### 2. 대상의 성격에 따라 시간 막대 표현 방식 분리

| 대상 | 막대 표시 방식 | 근거 |
| :--- | :--- | :--- |
| 에이전트 | 소요 시간 = LLM 소요 시간 + 도구·대기 | 병목 원인이 모델 응답 지연인지, 도구 실행 및 승인 대기인지 구분하기 위함입니다. |
| 라운드 · 턴 | 총 경과 시간 (구간들의 합집합) | 병렬 실행 시 개별 LLM 소요 시간의 합이 실제 경과 시간보다 길 수 있어 분할 표시가 어렵습니다 (LLM 합계는 툴팁과 수치 표에 별도 표기). |

### 3. 중단 후 재개된 발언의 시간 측정 기준점 보정

`llm_meta.resumed_at` 필드를 새로 기록합니다. 발언 카드는 기존처럼 최초 시작 시각부터 표시하되, 사용량 분석 시에는 이 재개 시점부터 경과 시간을 계산합니다. 재개된 발언의 토큰 역시 재개 이후의 호출분만 반영되므로([ADR-025](ADR-025-resume-speeches-by-tool-step.md)), 토큰과 시간의 집계 범위가 일치하게 됩니다. 중단 이전의 호출은 턴 합계에 남아 보조 호출로 정상 집계됩니다.

### 4. UI 노출 위치와 모달 다이얼로그 설계

- **결론 카드**에는 해당 턴의 패널을, **사이드바 하단**에는 현재 대화 전체의 패널을 배치합니다. 결론 카드에만 둘 경우 중단되거나 실패하여 결론 카드가 없는 턴의 사용량을 확인할 수 없기 때문입니다.
- 단일 턴은 라운드별로, 복수 턴 대화는 턴별로 집계합니다. 여러 턴에 걸쳐 동일한 라운드 번호를 단순 합산하는 것은 의미가 없기 때문입니다. 단, 턴이 하나뿐인 대화는 단일 막대만 표시되는 것을 방지하기 위해 라운드별로 보여줍니다.
- 크게 보기 다이얼로그는 페이지당 단일 인스턴스를 유지하며 데이터만 동적으로 갱신합니다. 범위 선택 셀렉터를 통해 대화 전체와 개별 턴 사이를 자유롭게 전환할 수 있습니다.
- 해당 패널은 전문가 화면(Expert Page)에만 적용됩니다. 초심자 및 체험 화면은 콜백을 전달하지 않아 기존 UI를 유지합니다.

### 5. 경량 순수 HTML/CSS 막대 구현 및 접근성 고려

별도의 Canvas 라이브러리 없이 순수 HTML/CSS로 막대를 렌더링합니다. 요약 값은 각 행의 우측에 표시하고, 상세 수치는 행 전체에 연결된 툴팁과 다이얼로그의 수치 표를 통해 제공합니다. 색상은 다크 테마 배경(`#0f172a`)에서 색각 이상 접근성 검사를 통과한 팔레트를 적용했습니다. 토큰은 4가지 범주형 색상으로 구분하며, 시간은 LLM 소요 시간만 강조색을 쓰고 기타 대기 시간은 중립 회색을 사용합니다. 라운드 경과 시간 막대에는 LLM 강조색을 쓰지 않는데, 전체가 LLM 시간인 것으로 오인되는 것을 방지하기 위함입니다.

## 결과 (Consequences)

**도입 효과 (Benefits)**

- 최상단 행과 `시간 병목`·`토큰 최다` 하이라이트 문구를 통해 주요 병목 요소를 즉시 파악할 수 있습니다.
- 토론 진행 중에도 펼쳐진 패널과 열린 다이얼로그가 발언 완료 이벤트에 맞춰 자동으로 실시간 갱신됩니다 (닫혀 있을 때는 불필요한 조회를 생략).
- 차트 세그먼트의 합계와 턴 DB 기록이 정확히 일치하도록 보장됩니다 (`tests/test_usage_report.py`).

**고려 사항 및 한계 (Trade-offs & Limitations)**

- '도구·대기' 시간은 전체 경과 시간에서 LLM 순수 응답 시간을 제외한 나머지 시간을 의미합니다. 도구 실행, 게이트 순번 대기, 사용자 승인 대기 등을 개별적으로 세분화하지 않으므로, 사용자가 승인을 오래 지체할 경우 해당 에이전트의 대기 시간이 길어져 병목으로 보일 수 있습니다.
- 중간에 비정상 종료되어 기록되지 못한 호출은 발생 에이전트를 특정할 수 없으므로 보조 호출로 통합 집계됩니다.
- 비용(금액)은 별도로 계산하거나 표시하지 않으며, 모델별 토큰 단가는 다루지 않습니다.
- `resumed_at` 필드가 도입되기 전에 재개된 과거 발언은 중단 유휴 시간이 소요 시간에 포함될 수 있습니다 (이전 기록에 대한 별도 마이그레이션은 수행하지 않음).
- 토론 진행 중 실시간으로 차트가 다시 렌더링될 때 패널 내부 스크롤 위치가 미세하게 변경될 수 있습니다.
