# ADR-015. 추론 흔적은 사람에게만 보이고 프롬프트에는 넣지 않는다

> [ADR 목록](README.md) · 이전: [ADR-014](ADR-014-tool-failure-is-observation.md) · 다음: [ADR-016](ADR-016-per-workspace-mcp-runtime.md)

## 상태 (Status)

채택됨 · 2026-09-09 (v0.5.0) · 관련: [ADR-002](ADR-002-litellm-gateway.md), [ADR-020](ADR-020-conversation-memory.md)

## 맥락 (Context)

- 에이전트에게 순차적 단계별 사고(Chain-of-Thought)를 수행하도록 유도할 수 있습니다. 프롬프트를 통해 "생각 1..N을 단계별로 전개하고 최종 결론을 도출하라"고 지시하거나, 모델 공급자의 네이티브 추론 기능(Reasoning tokens)을 사용하거나, 순차적 사고 전용 MCP 도구를 호출하도록 구성합니다.
- `show_steps` 설정 플래그는 원래 **사용자에게** 이러한 중간 사고 과정을 UI 상에서 시각화하여 보여줄지 여부를 제어하는 디스플레이 옵션이었습니다. 그러나 실제로는 의도치 않게 두 가지 역할을 동시에 수행하고 있었습니다. 이 플래그가 활성화되면 중간 사고 전문이 발언 본문 텍스트에 통째로 포함되었고, 그 본문이 다음 발언자들의 입력 프롬프트 컨텍스트에 그대로 복사되어 전달되었습니다.
- 그 결과 다음과 같은 심각한 문제가 발생했습니다.
  - 몇 라운드만 지나도 프롬프트 컨텍스트의 대부분이 **다른 에이전트들의 장황한 내부 사고 과정**으로 가득 찼습니다. 컨텍스트 축소(Trimming) 알고리즘이 토론의 초기 목표와 핵심 설계 논의를 먼저 제거하고, 정작 불필요한 타 에이전트의 중간 사고 과정만을 우선 보존하는 왜곡이 발생했습니다.
  - 계획 수립, 발언자 지명, 태스크 분배 프롬프트는 직전 발언들을 250~300자 분량으로 짧게 인용합니다. 그런데 중간 사고(추론) 과정이 머리말에 위치하다 보니 인용란에 "생각 1: 문제 정의..."와 같은 서두만 잘려 들어가고, **핵심 최종 결론은 단 한 글자도 인용되지 못하는 치명적인 결함**이 발생했습니다.

## 결정 (Decision)

`show_steps` 플래그는 **사람이 화면에서 무엇을 볼 것인지만을** 결정하도록 책임을 단일화합니다. 언어 모델이 컨텍스트로 읽어 들일 정보는 이와 완전히 독립적으로 엄격히 제어하도록 합니다.

- 발언 본문이 프롬프트 컨텍스트에 삽입되는 **모든 실행 지점**(후속 발언자 컨텍스트, 최종 종합 보고서 이력, 계획 수립, 발언자 동적 지명, 태스크 분배 프롬프트)에서 중간 사고 과정(추론 흔적)을 완전히 제거하도록 합니다. 단, 데이터베이스 영속 레코드와 브라우저 UI 화면에는 원본 사고 전문을 온전히 보존합니다.
- 중간 사고(추론) 과정이 나타나는 두 가지 대표적인 패턴을 모두 파싱하여 정제합니다. 프롬프트 기반 CoT의 "최종 결론" 명시 태그와, 모델 공급자 추론 모드가 본문 서두에 부착하는 인용(Blockquote) 블록을 감지하여 제거합니다.
- 발언 본문 자체가 원래 인용 블록으로 시작하거나 텍스트 전체가 중간 사고(추론) 내용뿐이어서 결론과 사고를 명확히 분리할 수 없는 경우에는 본문을 임의로 훼손하지 않고 원문을 유지합니다.
- 에이전트 **자신이** 이전 라운드에 작성했던 과거 사고 과정 역시 후속 프롬프트에 다시 주입하지 않습니다. 지난 라운드의 자기 추론을 다시 읽게 되면 해당 생각에 고정(Anchoring)되어 편향이 발생하는데, 다자간 토론에서 새로운 라운드를 진행하는 본질적인 목적은 동료들의 새로운 증거와 반론을 수용하는 데 있기 때문입니다.
- 중간 추론 과정 정제 규칙은 프롬프트 생성 파이프라인의 단일 진실 공급원 계층에서 일괄 적용하도록 합니다.

## 결과 (Consequences)

**좋아지는 점**

- 전문가 3인이 3라운드에 걸쳐 토론하는 대화 세션에서 프롬프트 소비량이 **5,556토큰에서 1,848토큰**으로 약 67% 대폭 절감되었습니다.
- 단문 인용 컨텍스트에 서두의 장황한 사고 과정 대신 명확한 최종 결론이 정확히 포함됩니다. 이에 따라 오케스트레이터의 동적 지명 및 태스크 분배가 실제 본질적인 논의 내용을 토대로 정밀하게 수행됩니다.
- 사용자는 여전히 UI 화면에서 에이전트들의 심층 사고 과정을 투명하게 모니터링할 수 있습니다.

**치르는 비용**

- 에이전트가 동료의 **내부 추론 과정 자체**를 직접 검토하고 비판할 수 없게 됩니다. 오직 도출된 최종 결론과 명시적인 근거만을 확인하게 됩니다. 만약 잘못된 전제에서 출발했으나 우연히 올바른 결론에 도달한 경우가 있다면, 다른 에이전트가 그 논리적 비약을 지적하기 어려워집니다. 이 한계는 v0.8.3에서 발언 말미의 요약문에 결론뿐만 아니라 **핵심 근거 요약**을 반드시 포함하도록 프롬프트 지침을 강화하여 일부 보완했습니다.
- 중간 사고 과정을 판별하는 휴리스틱 규칙이 공급자 및 모델별 출력 포맷에 다소 의존하므로, 새로운 추론 모델이 전혀 다른 형식의 사고 태그를 도입할 경우 정제 파서를 업데이트해야 합니다.

**이후에 따라온 결정**

"사람에게 보여줄 정보와 언어 모델 컨텍스트에 주입할 정보를 엄격히 분리한다"는 아키텍처 철학은 v0.8.3의 대화 기억 최적화 설계로 계승되었습니다. 오래된 과거 발언은 간결한 요약문으로 압축하고 긴 소스 코드는 파일 참조 경로로 축약하여 프롬프트에 주입하되, 원본 데이터는 데이터베이스와 UI 화면에 완전한 형태로 영구 보존합니다 ([ADR-020](ADR-020-conversation-memory.md)).
