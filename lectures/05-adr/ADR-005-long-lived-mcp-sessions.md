# ADR-005. MCP 세션은 한 번 열어 오래 유지한다

> [ADR 목록](README.md) · 이전: [ADR-004](ADR-004-sqlite-persistence.md) · 다음: [ADR-006](ADR-006-airgap-first-packaging.md)

## 상태 (Status)

채택됨 · 2026-08-26 · 관련: [ADR-003](ADR-003-mcp-tool-protocol.md), [ADR-010](ADR-010-host-defined-tool-scope.md)

## 맥락 (Context)

첫 구현은 도구를 호출할 때마다 stdio 연결을 새로 열었습니다. 호출 한 번에 서버 프로세스를 띄우고, 호출하고,
죽였습니다. 기능은 도는 것처럼 보였지만 두 가지 문제가 있었습니다.

- **상태가 남지 않았습니다.** 샌드박스 서버는 네임스페이스별 파이썬 커널에 변수와 데이터프레임을 유지하는 것이
  핵심 기능입니다. 프로세스가 매번 새로 뜨니 서버는 "네임스페이스를 재사용한다"고 응답하면서도 빈 커널을
  돌려주었습니다. 같은 네임스페이스로 두 번 부르면 두 번째에서 `NameError`가 났습니다.
- **느렸습니다.** Node 런타임이나 파이썬 커널을 띄우는 데 1~2초가 걸립니다. 파일 쓰기 다섯 번에 1.36초가
  걸렸습니다.

세션을 오래 유지하려면 기술적인 제약 하나를 풀어야 했습니다. MCP SDK가 쓰는 anyio의 취소 범위는 **그것을 연
태스크에 묶여** 있어서, 한 태스크가 연 연결을 다른 태스크가 닫으면 런타임 오류가 납니다.

같은 시기에 발견한 문제가 하나 더 있습니다. 도구 실행이 실패하면 오류 문자열을 "성공" 상태로 감싸서 넘기고
있었습니다.

## 결정 (Decision)

- 서버에 처음 연결할 때 세션을 열고 **앱이 내려갈 때까지 유지**한다.
- 세션을 열고 닫는 일은 **전용 태스크 하나**가 소유한다. 호출하는 쪽은 그 세션에 요청만 넣는다. 여러 태스크의
  동시 호출은 한 세션 위에서 다중화된다.
- 세션이 끊기면 다음 호출에서 **한 번** 자동으로 다시 연결한다. 프로세스가 죽어도 소유 태스크는 곧바로 끝나지
  않으므로, 스트림 계열 예외를 사망 신호로 판단한다.
- 살아 있는 서버가 "도구 실행 실패"를 돌려주면 **재시도하지 않는다.** 파일 덧붙이기나 커밋 같은 부작용이 두 번
  일어날 수 있다.
- 도구 실행 실패는 "오류" 상태로 기록한다. 오류 메시지에는 예외 타입 이름을 넣는다. 메시지가 비어 있는 예외도
  있기 때문이다.

## 결과 (Consequences)

**좋아지는 것**

- 같은 네임스페이스로 여러 번 부르면 변수와 import가 유지됩니다.
- 파일 쓰기 다섯 번이 1.36초에서 0.02초로 줄었습니다.
- 동시 호출 다섯 건이 모두 성공하고, 서버 프로세스를 강제로 죽여도 다음 호출이 새 프로세스로 다시 붙습니다.
  이 동작은 상태를 가진 가짜 stdio 서버로 회귀 테스트를 만들어 고정했습니다(수정 전에는 카운터가 1에 머물고
  프로세스 번호가 매번 바뀌어 실패하는 것을 확인).

**치르는 비용**

- **오래 사는 프로세스가 상태를 섞기 시작했습니다.** 서버 프로세스를 모든 대화가 공유하게 되자, 다음 대화가
  이전 대화의 지식 그래프를 읽었습니다. [ADR-010](ADR-010-host-defined-tool-scope.md)으로 이어집니다.
- **서버가 볼 폴더가 기동 시점에 고정됩니다.** 대화마다 다른 폴더를 쓰려면 서버를 다시 띄우거나 따로 띄워야
  합니다. [ADR-009](ADR-009-refuse-cross-workspace-debates.md), [ADR-016](ADR-016-per-workspace-mcp-runtime.md)으로
  이어집니다.
- **응답하지 않는 서버가 턴을 붙잡을 수 있습니다.** 호출마다 새로 띄울 때는 드러나지 않던 문제입니다. 도구 호출
  시간 상한으로 막았습니다([ADR-014](ADR-014-tool-failure-is-observation.md)).
- 프로세스를 정리하는 책임이 앱에 생겼습니다. 종료할 때 모든 세션을 닫고 자식 프로세스를 정리합니다.
