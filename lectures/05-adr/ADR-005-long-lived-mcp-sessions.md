# ADR-005. MCP 세션은 한 번 열어 오래 유지한다

> [ADR 목록](README.md) · 이전: [ADR-004](ADR-004-sqlite-persistence.md) · 다음: [ADR-006](ADR-006-airgap-first-packaging.md)

## 상태 (Status)

채택됨 · 2026-08-26 · 관련: [ADR-003](ADR-003-mcp-tool-protocol.md), [ADR-010](ADR-010-host-defined-tool-scope.md)

## 맥락 (Context)

초기 구현에서는 도구를 호출할 때마다 stdio 연결을 매번 새로 수립했습니다. 단 한 번의 도구 호출을 위해 서버 프로세스를 기동하고, 요청을 처리한 뒤 프로세스를 종료시켰습니다. 기능상으로는 동작하는 것처럼 보였으나 두 가지 심각한 문제가 드러났습니다.

- **프로세스 내부 상태가 보존되지 않았습니다.** 샌드박스 서버의 핵심 가치는 네임스페이스별 파이썬 커널에 전역 변수와 데이터프레임 상태를 유지하는 것입니다. 프로세스가 호출마다 새로 기동되다 보니, 서버는 "네임스페이스를 재사용함"이라고 응답하면서도 실제로는 비어 있는 초기 커널을 반환했습니다. 그 결과 동일한 네임스페이스로 두 번째 호출을 수행하면 즉시 `NameError`가 발생했습니다.
- **실행 지연이 심각했습니다.** Node.js 런타임이나 파이썬 인터프리터를 기동하는 데 매번 1~2초가 소모되었습니다. 단순 파일 쓰기를 5회 연속 호출하는 데만 1.36초가 소요되었습니다.

세션을 장기간 유지하려면 하나의 기술적 난제를 해결해야 했습니다. MCP SDK가 내부적으로 사용하는 anyio 라이브러리의 취소 범위(Cancel Scope)는 **해당 연결을 생성한 비동기 태스크에 귀속**되어 있어서, 한 태스크가 수립한 연결을 다른 태스크가 임의로 닫으려 하면 런타임 오류가 발생했습니다.

동일한 시기에 또 다른 결함이 확인되었습니다. 도구 실행이 실패했을 때 오류 문자열을 정상 "성공" 상태로 감싸서 모델에게 전달하고 있었습니다.

## 결정 (Decision)

서버에 최초 연결할 때 세션을 초기화하고 **애플리케이션이 종료될 때까지 장수(Long-lived) 세션으로 유지하도록 합니다.**

- 세션의 생성과 종료 수명 주기는 **단일 전용 소유 태스크(Session Ownership Task)**가 독점적으로 관리하도록 합니다. 실제 호출을 요청하는 비동기 워커들은 해당 세션에 I/O 요청만을 위임하며, 다중 태스크의 동시 호출은 단일 세션 위에서 안전하게 멀티플렉싱(Multiplexing)됩니다.
- 네트워크 단절이나 프로세스 비정상 종료 시, 다음 호출 시점에 **최대 1회** 자동으로 재연결을 시도하도록 합니다. 자식 프로세스가 크래시되더라도 소유 태스크는 즉각 종료되지 않으므로, stdio 스트림 계열의 예외를 감지하여 프로세스 사망 신호로 판정합니다.
- 정상적으로 기동 중인 서버가 "도구 실행 실패" 결과를 반환할 경우에는 **자동 재시도를 수행하지 않습니다.** 파일 추가 쓰기(Append)나 Git 커밋과 같은 상태 변경 부수 효과가 중복 실행되는 위험을 방지하기 위함입니다.
- 도구 실행 실패는 명확히 "오류(error)" 상태로 기록합니다. 오류 메시지에는 예외의 클래스명을 명시하여, 메시지 본문이 비어 있는 예외라도 원인을 추적할 수 있도록 합니다.

## 결과 (Consequences)

**좋아지는 점**

- 동일 네임스페이스에서 다수의 도구 호출을 수행하더라도 변수 상태와 import 내역이 온전히 보존됩니다.
- 5회 파일 쓰기 소요 시간이 1.36초에서 0.02초로 대폭 단축되었습니다.
- 5건의 동시 도구 호출이 모두 정상 처리되며, 외부에서 서버 프로세스를 강제 종료하더라도 후속 호출 시 새 프로세스로 자동 재연결됩니다. 이 동작은 상태를 지닌 모의 stdio 서버를 활용한 회귀 테스트로 검증 및 고정되었습니다.

**치르는 비용**

- **장수 프로세스가 세션 간 상태를 혼합시키는 격리 문제가 발생했습니다.** 서버 프로세스를 모든 대화 세션이 공유하게 되자, 새로운 대화 세션이 이전 대화의 지식 그래프 기억을 그대로 조회하는 데이터 누출이 발생했습니다 ([ADR-010](ADR-010-host-defined-tool-scope.md)).
- **도구 서버가 감시할 작업 디렉터리가 프로세스 기동 시점에 고정됩니다.** 대화 세션마다 서로 다른 작업 공간을 참조하려면 서버를 재기동하거나 공간별로 별도 분리해야 합니다 ([ADR-009](ADR-009-refuse-cross-workspace-debates.md), [ADR-016](ADR-016-per-workspace-mcp-runtime.md)).
- **무응답 상태에 빠진 도구 서버가 에이전트의 턴 전체를 무한 대기시킬 위험이 있습니다.** 호출마다 프로세스를 새로 띄울 때는 부각되지 않던 문제입니다. 이는 도구 호출별 최대 실행 시간 상한을 도입하여 차단했습니다 ([ADR-014](ADR-014-tool-failure-is-observation.md)).
- 자식 프로세스의 정상 종료와 자원 회수 책임이 애플리케이션 수명 주기 관리 코드로 이전되었습니다. 메인 앱 종료 시 모든 열린 세션을 질서정연하게 닫고 좀비 프로세스를 정리해야 합니다.
