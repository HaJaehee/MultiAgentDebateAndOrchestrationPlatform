# ADR-016. 작업 공간마다 MCP 런타임을 따로 띄운다

> [ADR 목록](README.md) · 이전: [ADR-015](ADR-015-reasoning-out-of-prompts.md) · 다음: [ADR-017](ADR-017-never-lose-a-write.md)

## 상태 (Status)

채택됨 · 2026-09-09 (v0.6.0) · [ADR-009](ADR-009-refuse-cross-workspace-debates.md)를 대체 · 관련: [ADR-005](ADR-005-long-lived-mcp-sessions.md), [ADR-010](ADR-010-host-defined-tool-scope.md)

## 맥락 (Context)

- 앱 전체에 MCP 매니저가 하나였고, MCP 서버는 볼 폴더를 기동할 때 받습니다. 그래서 작업 공간이 다른 두 토론을 동시에
  돌릴 수 없었고, 두 번째 토론은 거절되었습니다([ADR-009](ADR-009-refuse-cross-workspace-debates.md)). 정직한 선택이었지만
  여러 대화를 동시에 쓰는 것이 불가능했습니다.
- "대화마다 MCP와 Node 런타임을 격리한다"는 요구는 Node를 여러 벌 설치하라는 뜻으로 들리기 쉽습니다. 실제로 대화 사이에
  새던 것은 실행 파일이 아니라 **프로세스 상태**(메모리, 작업 디렉터리, 임시 폴더, 볼 폴더, 기억 파일 위치, 커널)였습니다.
- 매니저를 둘 이상 두려면 먼저 매니저들이 서로의 상태를 덮어쓰지 않아야 했습니다. 당시 코드에는 전역 상태가 두 군데
  있었습니다.
  - 작업 공간 경로를 서버 설정에 적용하는 함수가, 자식에게 물려주려고 **프로세스 전역 환경변수를 직접 바꿨습니다.**
  - 서버가 볼 수 있는 폴더를 물을 때 답하는 콜백이 같은 전역 값을 읽었습니다.

## 결정 (Decision)

**작업 공간마다 MCP 매니저를 하나씩 두는 런타임 풀**을 만든다.

- 키는 대화가 아니라 **작업 공간**이다. 같은 폴더를 쓰는 대화는 서버 묶음을 함께 쓴다(대화 사이의 격리는 메타데이터
  스코프가 맡는다, [ADR-010](ADR-010-host-defined-tool-scope.md)). 다른 폴더면 서버 묶음이 따로 뜬다.
- 참조는 대화 ID의 **집합**으로 센다. 같은 대화가 두 번 빌려도 한 번이다.
- 턴은 시작할 때 빌리고, 어떻게 끝나든(정상, 정지, 취소, 예외) 반납한다.
- 반납된 묶음은 유휴 시간(기본 300초) 동안 살려 둔다. 연달아 오는 턴이 기동 비용을 다시 치르지 않게 한다.
- 묶음 수에 상한(기본 4)을 둔다. 메모리 예산이지 동시 토론 수의 제한이 아니다. 자리가 필요하면 만료된 유휴 묶음, 가장
  오래 쉰 유휴 묶음 순으로 정리한다. **사용 중인 묶음은 절대 정리하지 않는다.** 정리할 것이 없으면 어느 대화가 자리를
  잡고 있는지 알려 주며 거절한다.
- 묶음마다 자기 환경을 얹어 서버를 띄운다. 볼 폴더, 작업 공간 안의 전용 임시 폴더, npm 캐시 위치, 그리고 전체 커널
  예산을 묶음 수로 나눈 값.
- 사용자 홈 디렉터리는 **바꾸지 않는다.** git 설정과 파이썬 사용자 패키지가 거기 있어서, 옮기면 격리가 아니라 고장이다.
- 실행 파일과 설치된 패키지는 공유한다. 실행 중 읽기 전용이라 새지 않는다.

그 전에 전역 상태를 없앤다.

- 경로 적용은 전역 환경변수를 바꾸지 않고, 치환기에 덮어쓸 값을 넘겨 각 서버의 환경에 명시적으로 적는다.
- 폴더 질의 콜백은 연결마다 따로 묶는다.
- 작업 공간 준비(git 초기화)는 별도 스레드에서, 경로별 잠금을 걸고 실행한다. 두 묶음이 같은 폴더를 동시에 초기화하지
  않게 하고, 화면을 멈추지 않게 한다.
- 매니저의 기동, 종료, 재연결이 서로의 연결 목록을 지우지 않도록 수명 잠금을 둔다.

## 결과 (Consequences)

**좋아지는 것**

- 서로 다른 폴더의 토론이 동시에 돕니다. 대화 하나를 완전히 격리하고 싶으면 그 대화에 전용 폴더를 지정하면 됩니다.
- 거절 규칙은 형태를 바꿔 남았습니다. "두 폴더를 동시에 열 수 없다"에서 "지금 묶음을 하나 더 띄울 예산이 없다"로.
  남의 폴더를 조용히 읽고 쓰느니 시작을 막는다는 원칙은 그대로입니다.

**치르는 비용**

- 프로세스 수가 작업 공간 수에 비례해 늘어납니다. 상한을 올리는 것은 정당하지만, 하나 올릴 때마다 스레드가 아니라
  서버 프로세스 묶음 하나가 늘어납니다.
- 서버 기동이 앱 기동 시점에서 "그 폴더의 첫 토론" 시점으로 옮겨 갔습니다. 화면의 서버 상태 표시가 이를 따라가지 못해,
  서버는 2~3초 만에 떴는데 턴이 끝날 때까지 "미기동"으로 보인 버그가 있었습니다(v0.6.1.1에서 수정). 아직 런타임이 없는
  대화에 **기본 작업 공간의 상태**를 대신 보여 주던 버그도 함께 고쳤습니다.
- MCP 서버 설정은 여전히 설정 파일 하나가 정본입니다. 화면에서 서버를 편집하면 **살아 있는 모든 묶음을 다시** 띄우고,
  토론이 하나라도 돌고 있으면 편집을 막습니다.
- MCP 상태 API의 응답 모양이 배열에서 (런타임 목록을 담은) 객체로 바뀌었습니다.

**도중에 발견한 것**

전역 상태를 걷어 내는 과정에서 원래부터 있던 Windows 버그가 드러났습니다. 경로 정규화가 확장 길이 경로(`\\?\C:\...`)를
돌려주면 URI 변환이 `file://?/C:/...`를 만들고, 서버는 잘못된 URL이라며 거절합니다. 파일 시스템 서버는 허용 폴더 없이
떴고, 흔적은 로그 한 줄뿐이었습니다. URI로 바꾸기 전에 접두사를 걷어 내도록 고쳤습니다.

**교훈**

같은 컴포넌트를 여러 개 두려면, 먼저 그 컴포넌트가 **전역 상태를 쓰지 않는지**부터 확인해야 합니다. 이 작업의 절반은
풀을 만드는 일이 아니라 전역 상태를 없애는 일이었습니다.
