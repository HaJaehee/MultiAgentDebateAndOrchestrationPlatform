# ADR-007. 연결에 실패한 LLM의 답을 흉내 내지 않는다

> [ADR 목록](README.md) · 이전: [ADR-006](ADR-006-airgap-first-packaging.md) · 다음: [ADR-008](ADR-008-background-debate-runner.md)

## 상태 (Status)

채택됨 · 2026-08-28 · 초기 설계의 "오프라인 시뮬레이터"를 전면 폐기 · 관련: [ADR-002](ADR-002-litellm-gateway.md), [ADR-014](ADR-014-tool-failure-is-observation.md)

## 맥락 (Context)

초기 설계에는 LLM 엔드포인트에 접속할 수 없거나 API 자격 증명이 유효하지 않을 때 **사전 정의된 페르소나에 맞춰 그럴듯한 답변을 임의로 생성해 내는 시뮬레이터**가 포함되어 있었습니다. 개발 초기 단계에서는 이 방식이 일정 부분 유용했습니다. 실제 API 키가 없어도 UI 화면 레이아웃과 토론 진행 흐름을 즉시 확인할 수 있었고, 자동화 테스트 하네스 역시 이 시뮬레이터를 LLM 모의 대역으로 활용했습니다.

그러나 실제 개발 및 검증을 본격화하자 심각한 문제점들이 드러났습니다.

- 엔드포인트가 500 내부 서버 오류를 반환하더라도 토론은 겉보기에 정상적으로 완결된 것처럼 위장되었습니다. 사용자는 네트워크 단절 사실을 전혀 인지하지 못했습니다.
- 임의로 지어낸 허위 발언이 다음 에이전트의 입력 컨텍스트로 전달되었습니다. 그 결과 다른 에이전트들이 실재하지 않는 주장에 동조하거나 논박하는 왜곡이 발생했습니다.
- 최종 종합 보고서에도 시뮬레이터가 꾸며낸 내용이 무분별하게 혼합되었습니다. 산출물 보고서만 보아서는 어디까지가 실제 모델의 토론 결과인지 판별할 수 없었습니다.

## 결정 (Decision)

프로덕션 제품 코드에서 시뮬레이터 폴백 메커니즘을 **완전히 제거하도록 합니다.**

- 엔드포인트에 연결할 수 없는 경우 LLM 호출기는 대상 모델명, 엔드포인트 URL, 원인 오류를 명시한 "LLM 사용 불가" 예외를 발생시키도록 합니다.
- 오케스트레이션 엔진은 발언 단위로 이 예외를 안전하게 포착하여 "해당 발언은 모델의 응답을 수신하지 못함"이라는 **오류 발언(Error Utterance)**으로 기록하고 다음 발언자로 순서를 넘깁니다.
- 연결이 단절되기 전까지 스트리밍으로 수신된 텍스트 조각들은 실패 안내 블록 상단에 안전하게 보존합니다.
- 오류 발언 레코드는 후속 발언자의 입력 컨텍스트 및 최종 종합 보고서 프롬프트에서 **명시적으로 제외합니다.** 실패 안내 시스템 메시지가 에이전트의 대화 맥락에 노출되면, 다른 에이전트들이 해당 오류 메시지 자체에 대해 논평하기 시작하기 때문입니다.
- 대신 최종 종합 프롬프트에 **어떤 전문가 에이전트가 통신 실패로 발언하지 못했는지** 결측 사실을 투명하게 명시하여, 모델이 결측된 에이전트의 의견을 임의로 날조하지 못하도록 방지합니다.
- 발언에 실패한 에이전트가 단 하나라도 존재한다면 해당 턴을 완전한 '합의 도출' 상태로 표기하지 않고, 턴 종료 요약에 결측 전문가 명단을 정확히 고지합니다.
- 테스트용 LLM 모의 대역(Mock/Stub)은 단위 테스트 전용 디렉터리로 완전히 이전합니다. 제품 런타임 코드베이스 내부에는 어떠한 가짜 생성 로직도 남겨두지 않습니다.

## 결과 (Consequences)

**좋아지는 점**

- 대화 및 토론 이력의 신뢰성이 완전히 보장됩니다. 데이터베이스에 영속화된 모든 발언은 실제 언어 모델이 생성한 진실된 결과물입니다.
- 네트워크 통신 장애가 발생하는 즉시 사용자에게 투명하게 노출됩니다. 실패 카드가 시각적으로 구분되어 표시되며, 어떤 에이전트가 어느 엔드포인트와의 통신에 실패했는지 명확한 진단 정보가 제공됩니다.

**치르는 비용**

- 유효한 API 자격 증명이 없는 로컬 개발 환경에서는 애플리케이션이 "정상 동작하는 것처럼" 보이지 않습니다. UI 동작을 확인하려면 유효한 실제 API 엔드포인트나 로컬 추론 서버(Ollama, LM Studio 등)가 필수적으로 준비되어야 합니다.
- 기존 자동화 테스트들이 프로덕션 코드 내의 시뮬레이터에 의존하고 있었으므로, 테스트 전용 모의 객체 하네스를 새롭게 재구축해야 했습니다.

**원칙으로 정립된 가치**

이 ADR은 "존재하지 않는 가짜 결과를 지어내지 않는다"는 MADO 핵심 아키텍처 원칙의 확고한 출발점이 되었습니다. 이후 이 원칙은 시스템의 다양한 영역으로 일관되게 확장 적용되었습니다.

- 대체 경로(Fallback)로 전환할 때는 반드시 전환 사실을 시스템 상태에 기록합니다 (발언자 동적 지명, 과업 분배, 품질 게이트 판정).
- 종합 단계에서 빈 응답이 반환된 경우 정상 보고서로 포장하지 않고 "종합 실패" 상태로 솔직하게 기록합니다 ([ADR-018](ADR-018-orchestrator-writes-conclusions.md)).
- 에이전트 간 컨텍스트 인수인계 노트에는 전달되지 못한 정보의 한계를 명확히 밝힙니다.
- 구버전 데이터베이스의 발언 레코드를 이관할 때, 누락된 시작·종료 타임스탬프를 마이그레이션 시점의 시간으로 임의 날조하여 채워넣지 않습니다.

**교훈**

개발 편의를 위해 임시로 도입한 편법 장치가 프로덕션 실행 경로에 남아 있으면, 훗날 실제 운영 장애를 감추는 치명적인 독이 됩니다. 모든 테스트 대역은 엄격히 테스트 코드 영역에만 격리되어야 합니다.
