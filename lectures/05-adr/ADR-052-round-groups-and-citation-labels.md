# ADR-052. 전문가 피드를 라운드 묶음으로 접고, 발언·쟁점을 `[S14]`·`[I-3]` 으로 가리킨다

> [ADR 목록](README.md) · 이전: [ADR-051](ADR-051-fixed-issue-ids-and-ledger-revisions.md)

## 상태 (Status)

채택됨 · 2026-11-07 · 관련: [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-025](ADR-025-resume-speeches-by-tool-step.md), [ADR-036](ADR-036-retry-one-speech-and-inline-comments.md), [ADR-041](ADR-041-postgresql-compatibility.md), [ADR-045](ADR-045-claude-prompt-cache-markers.md), [ADR-051](ADR-051-fixed-issue-ids-and-ledger-revisions.md)

## 맥락 (Context)

- 에이전트가 3명 이상이고 라운드가 2회를 넘으면 시간순 피드만으로는 토론을 따라가기 어렵습니다. 카드마다 "Round N" 배지만 있고 접고 펴는 단위는 카드 한 장이라, 지난 라운드를 접어 두고 지금 라운드만 보는 방법이 없었습니다.
- 발언과 쟁점을 가리킬 이름도 없었습니다. 쟁점은 ADR-051 로 고정 번호를 얻었지만 발언은 아니었습니다. `round_number` 는 턴마다 1부터 다시 세는데 에이전트는 세션 전체 기록을 보므로 `R2-3` 같은 라벨은 턴을 건너면 모호합니다.
- 검토한 선택지:
  - **(턴, 라운드, 순번) 라벨** — 사람이 읽기는 좋지만 모델이 틀리게 쓰기 쉽고, 재실행·재개·병렬에서 순번이 흔들립니다.
  - **메시지 id 의 앞자리** — 고정되지만 읽을 수 없고 모델이 옮겨 쓰다 틀립니다.
  - **대화 안에서 늘어나는 정수** — 짧고, 한 번 붙으면 바뀌지 않으며, 모델이 그대로 옮겨 씁니다. 이것을 택합니다.
  - 라운드 묶음 대신 **쟁점별 스레드 보기** — 쟁점 번호가 생긴 뒤에야 가능하고 범위가 큽니다. 후속 과제로 미룹니다.

## 결정 (Decision)

**발언에 대화 안의 고정 번호를 붙입니다** (`messages.speech_no`, `DebateMessage.tag` → `S14`).

- 에이전트와 오케스트레이터의 발언(`SpeechRunner.speak`)에만 붙고, 유저 발언과 메모(지명·분배·판정 등)에는 붙이지 않습니다.
- 턴에서 처음 번호를 낼 때 계수기를 `max(DB 의 messages.speech_no 최대값, 이 턴 발언 초안에 적힌 번호, 메모리의 계수기)` 로 한 번 맞추고(`turns.ensure_speech_counter`), 그 뒤로는 메모리에서만 늘어납니다. 한 세션에서는 턴이 하나씩만 돌므로 경쟁은 없습니다. 읽은 트랜잭션은 바로 닫습니다(ADR-041).
- 발언 초안(ADR-025)에 예약 번호를 적어 두고, 초안에서 이어 가는 발언은 그 번호를 그대로 씁니다. 그래서 새 번호는 초안의 번호보다 커야 합니다. 예약만 하고 저장되지 않은 번호(초안도 없이 끊긴 발언)는 다시 쓰여도 됩니다. 그 번호는 어떤 프롬프트에도 실린 적이 없습니다.
- 동시에 도는 발언은 시작 순서가 제각각이므로 병렬 지시는 배정 순서대로, 그래프는 활성화 순서대로 번호를 미리 잡습니다.
- 실패한 발언도 번호를 지킵니다(빈 번호 허용). 다시 실행(ADR-036)은 원래 번호를 쓰고, 갈래 대화는 번호를 그대로 복사합니다.

**프롬프트 기록의 머리줄에 번호를 싣습니다** (`[System Architect (역할) · S14]:`, `DebateMessage.speaker_label`).

- 발언 맥락, 장부·요약 입력(`render_message`), 합성 전사와 대체 보고서, 그래프 입력, 서브 토론 발언·결론이 같은 머리줄을 씁니다.
- 번호는 메시지 자신에 저장된 값이라 라운드가 바뀌어도 앞부분이 같습니다(ADR-045 의 캐시 규칙). `recording.load_history` 도 번호를 실어, 다시 연 대화의 첫 턴에서도 머리줄이 같습니다.
- 인용 지시(`context_memory.CITE_INSTRUCTION`)를 발언·그래프 노드·서브 토론·합성 지시에 넣습니다. 다른 발언은 `[S14]`, 쟁점은 `[I-3]` 으로 가리키고, 발언 머리줄은 직접 쓰지 말라고 합니다. 발언 지시에서는 요지 지시 앞에 둡니다.
- 새 대화로 이어 가면(`continue_session`) 발언 번호가 1부터 다시 시작하므로 넘겨받는 장부에서 `[S…]` 를 지웁니다. 쟁점 번호는 남깁니다.

**전문가 화면은 카드를 라운드 묶음으로 접고, 인용을 링크로 그립니다.** 초급자·체험 화면은 바뀌지 않으며, 라벨은 글자로만 보입니다.

- 묶음 열쇠는 (턴, 라운드)입니다(그래프는 "Step N"). 요청·계획·결론처럼 턴을 여닫는 기록과 턴 밖의 기록은 묶지 않아, 묶음을 다 접어도 무엇을 묻고 무엇을 얻었는지 보입니다. 머리줄에 발언·도구 수와 그 라운드의 장부 변화량(ADR-051 의 `round_deltas`)을 적습니다.
- 새 묶음은 늘 펼친 채 만들고 애니메이션은 끕니다. 따라가는 중이면 새 라운드가 올 때 직전 묶음을 접되, 사람이 연 묶음과 생성 중인 카드가 든 묶음은 접지 않습니다. 불러올 때는 끝난 턴을 모두 접고 진행 중인 턴의 마지막 묶음만 폅니다.
- 펼친 뒤의 스크롤(`reveal_js`)은 목표 위 접이식 칸 어디에도 Quasar 가 붙잡아 둔 인라인 높이가 없고 목표의 자리가 두 프레임 그대로일 때 합니다. 애니메이션을 꺼도 슬라이드 전환이 본문을 잠깐 `height: 0` 으로 붙잡아, 정해 둔 프레임 수만 기다리면 옛 바닥에서 멈췄습니다.
- 카드 머리에 `S14` 칩을 붙이고, 본문의 `[S14]`·`[I-3]` 을 `#mado-ref-…` 링크로 바꿉니다. 바꾸기는 수식 자리표시자를 만든 뒤 글 구간에서만 하므로 코드와 수식 안은 빠집니다. 앞이 `[`·`\`·글자이거나 뒤가 `]`·`(` 이면 바꾸지 않습니다. 줄 첫머리의 `[S14]:` 는 링크로 바꿔 마크다운의 참조 정의로 사라지지 않게 합니다.
- 링크를 누르면 document 의 위임 리스너가 먼저 `preventDefault()` 로 해시 이동을 막고 서버에 알립니다. 발언이면 그 카드의 묶음을 펴고 카드로 가고, 쟁점이면 요약 띠의 칩을 강조하고, 이 대화에 없으면 알립니다.

## 결과 (Consequences)

**좋아지는 점**

- 긴 토론을 라운드 단위로 접어 두고, 머리줄만으로 라운드마다 무엇이 정해지고 닫혔는지 봅니다. 새로고침해도 같은 모양입니다.
- 에이전트가 "아키텍트의 앞선 제안" 대신 `[S14]` 로 정확히 가리키고, 사람은 그 링크로 바로 갑니다. 저장 문서(내보내기)도 머리줄에 번호를 적습니다.
- 번호가 메시지에 저장되어 프롬프트 캐시를 깨지 않습니다.

**치르는 비용**

- 모든 발언 머리줄이 몇 토큰 길어지고, 발언 지시에 인용 지시가 한 줄 늘어납니다.
- 접힌 묶음 안의 글은 브라우저 찾기(Ctrl+F)에 걸리지 않습니다. 앱 검색은 묶음을 펴고 갑니다.
- 모델이 `[S14]` 를 지어내거나 틀린 번호를 쓸 수 있습니다. 없는 번호는 눌렀을 때 알릴 뿐 바로잡지 않습니다.
- 옛 대화의 발언에는 번호가 없고 채워 넣지 않습니다(배포 전이라 하위호환을 두지 않습니다).
- 요약으로 접힌 옛 발언은 번호를 잃어도 됩니다. 요약 글에 번호를 보존하지 않습니다.

**이후에 따라올 결정**

- 쟁점별 스레드 보기, 접힌 묶음을 처음 펼칠 때 그리기(지연 렌더링), 쟁점 팝오버는 후속 과제입니다.
