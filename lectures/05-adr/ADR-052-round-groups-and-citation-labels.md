# ADR-052. 전문가 피드의 라운드 묶음 접기/펼치기 및 `[S14]`·`[I-3]` 인용 링크 체계 도입

## 맥락 (Context)

- 에이전트가 3명 이상이고 라운드가 2회를 넘어가면 단순 시간순 피드만으로는 토론 흐름을 추적하기 어렵습니다. 카드마다 "Round N" 배지만 존재하고 접기/펼치기 단위가 개별 카드 한 장에 불과하여, 이전 라운드들을 접어두고 현재 진행 중인 라운드만 집중해서 검토하기 어려웠습니다.
- 발언과 쟁점을 명확하게 가리킬 고유 식별자도 부재했습니다. 쟁점은 ADR-051을 통해 고정 식별 번호를 확보했으나 발언에는 식별자가 없었습니다. `round_number`는 턴마다 1부터 다시 시작하지만 에이전트는 세션 전체 기록을 참조하므로, `R2-3` 같은 상대적 라벨은 다중 턴 환경에서 지칭 대상이 모호해집니다.
- 검토한 선택지:
  - **(턴, 라운드, 순번) 라벨** — 사람이 읽기는 좋지만 모델이 틀리게 쓰기 쉽고, 재실행·재개·병렬에서 순번이 흔들립니다.
  - **메시지 id 의 앞자리** — 고정되지만 읽을 수 없고 모델이 옮겨 쓰다 틀립니다.
  - **대화 안에서 늘어나는 정수** — 짧고, 한 번 붙으면 바뀌지 않으며, 모델이 그대로 옮겨 씁니다. 이것을 택합니다.
  - 라운드 묶음 대신 **쟁점별 스레드 보기** — 쟁점 번호가 생긴 뒤에야 가능하고 범위가 큽니다. 후속 과제로 미룹니다.

## 결정 (Decision)

**발언에 세션 내 고유 일련번호를 부여합니다** (`messages.speech_no`, `DebateMessage.tag` → `S14`).

- 전문가 및 오케스트레이터의 실제 발언(`SpeechRunner.speak`)에만 부여되며, 사용자 발언과 시스템 메모(발언자 지명, 작업 분배, 조건 판정 등)에는 부여하지 않습니다.
- 턴 내에서 최초로 번호를 발급할 때 카운터를 `max(DB 내 messages.speech_no 최댓값, 현재 턴 초안 예약 번호, 메모리 내 카운터)`로 1회 동기화하며(`turns.ensure_speech_counter`), 이후에는 메모리 상에서 순차 증가합니다. 단일 세션에서는 턴이 순차 실행되므로 동시성 충돌은 없습니다. 조회 트랜잭션은 즉시 커밋하여 커넥션을 풀에 반환합니다(ADR-041).
- 발언 초안(ADR-025)에 예약 번호를 저장해 두고, 초안에서 이어가는 발언은 해당 번호를 그대로 사용합니다. 따라서 신규 발언 번호는 초안의 번호보다 커야 충돌을 방지할 수 있습니다. 예약만 되고 저장되지 않은 번호(초안 생성 전 중단된 발언 등)는 어떤 프롬프트에도 노출된 적이 없으므로 재사용되어도 안전합니다.
- 동시에 병렬 실행되는 발언들은 시작 시점이 비동기적으로 엇갈릴 수 있으므로, 병렬 라운드는 배정 순서, 그래프 워크플로는 노드 활성화 순서에 따라 사전에 번호를 예약합니다.
- 실패한 발언도 번호를 보존합니다 (결번 허용). 재생성(ADR-036) 시에는 기존 번호를 그대로 유지하며, 세션 분기 시에는 번호 레코드를 그대로 복제합니다.

**프롬프트 대화 기록 헤더에 발언 번호를 포함합니다** (`[System Architect (역할) · S14]:`, `DebateMessage.speaker_label`).

- 발언 맥락, 장부·요약 입력(`render_message`), 합성 전사와 대체 보고서, 그래프 입력, 서브 토론 발언·결론이 같은 머리줄을 씁니다.
- 번호는 메시지 자신에 저장된 값이라 라운드가 바뀌어도 앞부분이 같습니다(ADR-045 의 캐시 규칙). `recording.load_history` 도 번호를 실어, 다시 연 대화의 첫 턴에서도 머리줄이 같습니다.
- 인용 지시(`context_memory.CITE_INSTRUCTION`)를 발언·그래프 노드·서브 토론·합성 지시에 넣습니다. 다른 발언은 `[S14]`, 쟁점은 `[I-3]` 으로 가리키고, 발언 머리줄은 직접 쓰지 말라고 합니다. 발언 지시에서는 요지 지시 앞에 둡니다.
- 새 대화로 이어 가면(`continue_session`) 발언 번호가 1부터 다시 시작하므로 넘겨받는 장부에서 `[S…]` 를 지웁니다. 쟁점 번호는 남깁니다.

**전문가 피드는 카드를 라운드 묶음 아코디언으로 그룹화하고, 본문 내 인용 표기를 하이퍼링크로 렌더링합니다.** 초급자 및 체험 화면은 기존 구성을 유지하며 라벨이 일반 텍스트로 표시됩니다.

- 묶음 식별 키는 (턴 ID, 라운드 번호)입니다 (그래프 워크플로는 "Step N"). 사용자 요청, 계획, 최종 결론 등 턴의 시작과 끝을 장식하는 카드와 턴 외부 작업은 묶음에서 제외하여, 모든 묶음이 접힌 상태에서도 전체 흐름의 목표와 결과를 한눈에 파악할 수 있습니다. 묶음 헤더에는 발언 및 도구 실행 횟수와 해당 라운드의 결정 장부 상태 변화량(ADR-051의 `round_deltas`)을 요약 표시합니다.
- 신규 라운드 묶음은 항상 펼쳐진 상태로 생성하며, 레이아웃 안정성을 위해 애니메이션은 비활성화합니다(`duration=0`). 자동 스크롤 추적 중에는 새 라운드가 시작될 때 직전 묶음을 자동으로 접되, 사용자가 수동으로 펼친 묶음이나 현재 스트리밍 중인 카드가 포함된 묶음은 접지 않습니다. 세션을 다시 로드할 때는 완료된 이전 턴의 묶음은 모두 접고, 진행 중인 턴의 마지막 묶음만 펼쳐진 상태로 초기화합니다.
- 펼침 후 스크롤(`reveal_js`)은 상위 아코디언 컨테이너의 인라인 height가 해제되고 대상 요소의 위치와 크기가 2프레임 연속 안정화된 후 실행합니다. Quasar의 슬라이드 전환 특성상 즉시 스크롤하면 부정확한 위치로 이동하는 문제를 방지하기 위함입니다.
- 카드 헤더에 `S14` 칩을 표시하고, 본문 내 `[S14]`, `[I-3]` 표기를 `#mado-ref-…` 앵커 링크로 변환합니다. 변환 처리는 수식 플레이스홀더 치환 후 일반 텍스트 영역에 대해서만 수행하므로 코드 블록 및 수식 내부는 안전하게 보호됩니다. 앞뒤 문맥 검사를 통해 일반 마크다운 링크나 이스케이프 표기는 변환에서 제외하며, 행 머리의 `[S14]:` 표기는 링크로 변환하여 markdown2 파서에 의해 참조 정의로 오인 삭제되는 현상을 방지합니다.
- 링크 클릭 시 document 위임 리스너가 브라우저 기본 해시 이동을 즉시 차단(`preventDefault()`)하고 서버로 커스텀 이벤트를 전달합니다. 발언 참조인 경우 해당 카드의 묶음을 펼치고 뷰포트 중앙으로 스크롤하며, 쟁점 참조인 경우 요약 띠의 쟁점 칩을 일시 강조하고, 세션 내에 존재하지 않는 번호는 경고 토스트로 안내합니다.

## 결과 (Consequences)

**장점 (Positive Consequences)**

- 긴 토론 피드를 라운드 단위로 컴팩트하게 접어두고, 헤더 요약만으로 라운드별 결정 및 쟁점 해소 현황을 한눈에 파악할 수 있습니다. 새로고침 후에도 상태가 일관되게 보존됩니다.
- 에이전트가 "아키텍트의 앞선 제안"과 같은 모호한 서술 대신 `[S14]`로 명확히 인용하며, 사용자는 해당 링크를 클릭하여 원문으로 즉시 이동할 수 있습니다. 마크다운 내보내기 문서 헤더에도 동일한 발언 번호가 반영됩니다.
- 발언 번호가 메시지 레코드에 불변으로 영속화되므로 후속 라운드에서도 프롬프트 캐시 접두부를 온전히 보존할 수 있습니다 (ADR-045).

**비용 및 제약 (Negative Consequences)**

- 모든 발언 머리줄이 몇 토큰 길어지고, 발언 지시에 인용 지시가 한 줄 늘어납니다.
- 접힌 묶음 안의 글은 브라우저 찾기(Ctrl+F)에 걸리지 않습니다. 앱 검색은 묶음을 펴고 갑니다.
- 모델이 `[S14]` 를 지어내거나 틀린 번호를 쓸 수 있습니다. 없는 번호는 눌렀을 때 알릴 뿐 바로잡지 않습니다.
- 옛 대화의 발언에는 번호가 없고 채워 넣지 않습니다(배포 전이라 하위호환을 두지 않습니다).
- 요약으로 접힌 옛 발언은 번호를 잃어도 됩니다. 요약 글에 번호를 보존하지 않습니다.

**이후에 따라올 결정**

- 쟁점별 스레드 보기, 접힌 묶음을 처음 펼칠 때 그리기(지연 렌더링), 쟁점 팝오버는 후속 과제입니다.
