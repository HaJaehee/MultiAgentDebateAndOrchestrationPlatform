# ADR-035. 멀티모달 파일 입력을 지정된 에이전트의 LLM 요청 시점에 동적으로 주입한다

> [ADR 목록](README.md) · 이전: [ADR-034](ADR-034-adaptive-graph-and-sub-debates.md)

## 상태 (Status)

채택됨 · 2026-10-31 · 관련: [ADR-025](ADR-025-resume-speeches-by-tool-step.md), [ADR-027](ADR-027-designate-skills-from-the-input-bar.md)

## 맥락 (Context)

- 기존의 @언급 및 파일 업로드는 파일의 절대/상대 경로 문자열만을 전달했습니다. 사용자 메시지는 모든 발언자의 대화 전사(Transcript) 및 최종 합성 단계에 매 라운드 복제되므로, 파일 내용 전체를 메시지에 직접 포함할 경우 컨텍스트 윈도우가 급격히 포화되기 때문입니다.
- 그 결과 UI 목업 이미지, 설계도 사진, 샌드박스가 생성한 차트 등 시각적 자료를 비전 모델이 탑재된 에이전트가 직접 분석할 수 있는 경로가 존재하지 않았습니다.
- 도구 실행 결과 또한 텍스트만을 지원했습니다. MCP 서버가 `ImageContent`를 반환하더라도 `str()`로 문자열 변환되어 수십만 자의 BASE64 데이터가 일반 텍스트 형태로 모델, 화면, 데이터베이스 전체에 그대로 전파되는 비효율이 있었습니다.
- 모델마다 지원하는 멀티모달 형식(이미지, 음성, 비디오, 문서 등)이 서로 다르며, 사설 LLM 게이트웨이나 vLLM 등 커스텀 엔드포인트의 지원 여부는 라이브러리 메타데이터만으로 완벽히 판별하기 어렵습니다.
- 매 턴의 메시지 시퀀스는 데이터베이스에 초안으로 저장되고(ADR-025), 토큰 계측 및 감사 로그에 기록됩니다. 메시지 페이로드에 수십 MB의 멀티모달 바이너리가 직접 잔류할 경우 시스템 전반의 I/O 및 데이터베이스 부하가 심각해집니다.

## 결정 (Decision)

### 1. 입력 모달리티(Modalities)는 에이전트 카드에서 사용자가 명시적으로 활성화한다

에이전트 카드의 `도구`, `스킬` 버튼 하단에 `모달` 설정 버튼을 추가하고, 이미지·음성·동영상·문서 체크박스를 제공합니다 (`agents.<key>.allowed_modalities`). 체크가 비어 있는 기본 상태에서는 기존과 완전히 동일하게 텍스트 및 파일 경로만 전달됩니다. 도구/스킬 할당과 동일한 잠금 규칙이 적용되며, 대화 세션이 시작되면 불변 스냅샷으로 고정됩니다.

### 2. 세션 메시지에는 파일 포인터만 유지하고, BASE64 페이로드는 요청 직전에 동적으로 생성한다

시스템 내부 메시지 블록(`mado_attachment`)에는 파일 경로, MIME 타입, 파일 크기 메타데이터만 보존합니다. `_complete_unthrottled`가 실제 LLM API 요청 페이로드를 조립할 때 `materialize_attachments`가 백그라운드 스레드에서 파일을 읽어 실제 공급자 규약에 맞는 멀티모달 블록으로 변환하며, API 호출이 완료되면 즉시 메모리에서 해제합니다. 따라서 데이터베이스 세션 초안에는 가벼운 파일 경로만 유지되며, 중단된 발언을 재개할 때도 동일한 포인터에서 최신 파일을 다시 읽어옵니다.

### 3. 첨부 파일은 턴 단위로 라이프사이클을 관리하며, 목표 에이전트 메시지에만 주입한다

언급된 파일은 해당 턴의 첫 번째 사용자 프롬프트 메시지에만 주입됩니다. 프롬프트 캐시의 일관성을 유지할 수 있는 고정 위치입니다. 언급된 파일 정보는 스킬 지정과 동일하게 턴 메타데이터(`MentionReport.attachment_paths`)로 영구 기록됩니다. 본문에 표시되는 `[@파일명]` 참조는 여전히 경로 문자열로 유지되며, 다음 턴에서 다시 분석이 필요한 경우 재언급할 수 있습니다.

### 4. 텍스트 형식 문서는 BASE64 인코딩 없이 순수 텍스트 블록으로 주입한다

txt, md, csv, html, json, xml 등의 텍스트 기반 문서는 불필요한 BASE64 변환을 배제하고 인라인 텍스트 블록으로 주입합니다. 많은 상용 API 공급자(예: Anthropic Claude 등)는 텍스트 파일을 BASE64 문서 블록으로 전송할 경우 API 오류를 반환하기 때문입니다. PDF를 비롯한 바이너리 파일에 한해서만 표준 BASE64 블록으로 인코딩합니다.

### 5. 멀티모달 미지원 오류(REJECTED) 발생 시 텍스트 전용으로 안전하게 폴백한다

첨부 파일이 포함된 LLM 요청이 모델 측에서 거절될 경우(`REJECTED`), 첨부 내용을 "미지원 형식으로 인한 제외" 텍스트 안내로 대체하여 동일 모델로 즉시 재시도하고 발언 상단에 시스템 경고를 표시합니다. 단순한 모달리티 불일치로 인해 긴 토론 발언 전체가 유실되는 현상을 방지하며, 모델에게도 파일 미수신 사실을 명시하여 환각(Hallucination)을 방지합니다.

### 6. 도구 실행 결과로 반환된 미디어 파일 처리

`ImageContent`, `AudioContent` 등의 MCP 멀티모달 리소스를 텍스트와 분리하여 처리합니다 (`ToolOutput` 클래스). 반환된 미디어 파일은 `.mado/tool_media/` 작업 디렉터리에 안전하게 저장한 뒤 차기 턴의 사용자 메시지로 첨부하며, 멀티모달 수신이 비활성화된 에이전트에게는 요약 텍스트만을 전달합니다.

## 결과 (Consequences)

**이점**

- 모달리티가 활성화된 에이전트는 UI 목업, 차트 이미지, PDF 기술 문서를 직접 시각적으로 분석할 수 있으며, 비활성화된 타 에이전트의 프롬프트와 토큰 비용에는 전혀 영향을 주지 않습니다.
- 세션 메시지 초안과 도구 로그에 대용량 BASE64 데이터가 잔류하지 않으므로, 고용량 멀티모달 파일을 첨부하더라도 데이터베이스 용량과 UI 렌더링 성능이 가볍게 유지됩니다.
- 도구 실행으로 생성된 그래프 및 차트 이미지가 텍스트 파싱 오류 없이 모델에게 정확한 비전 입력으로 전달됩니다.
