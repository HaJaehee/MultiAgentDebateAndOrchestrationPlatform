# ADR-035. 파일 내용은 카드에서 고른 에이전트에게만, 요청을 보내는 순간에만 싣는다

> [ADR 목록](README.md) · 이전: [ADR-034](ADR-034-adaptive-graph-and-sub-debates.md)

## 상태 (Status)

채택됨 · 2026-10-31 (v1.5.1) · 관련: [ADR-025](ADR-025-resume-speeches-by-tool-step.md), [ADR-027](ADR-027-designate-skills-from-the-input-bar.md)

## 맥락 (Context)

- @언급과 업로드는 파일 경로만 전달합니다. 사용자 메시지는 모든 발언자의 전사와 합성에 라운드마다 복사되므로, 거기 내용을 붙이면 컨텍스트가 포화됩니다.
- 그래서 UI 목업, 화이트보드 사진, 샌드박스가 그린 차트를 에이전트가 직접 볼 길이 없었습니다. 모델이 볼 수 있는데도 경로만 받습니다.
- 도구 결과도 글만 다뤘습니다. MCP 서버가 `ImageContent` 를 돌려주면 `str()` 로 뭉개져 BASE64 수십만 자가 "글" 이 되어 모델, 화면, DB 로 갔습니다.
- 어떤 모델이 무엇을 받는지는 Provider 마다 다르고, LiteLLM 의 모델 표로도 다 알 수 없습니다 (사설 게이트웨이, vLLM, 표에 없는 모델). 표의 값도 음성·동영상은 대개 비어 있습니다.
- 메시지 목록은 판마다 초안으로 DB 에 남고(ADR-025), 토큰을 세고, 거절되면 지문으로 로그에 남습니다. 메시지에 수십 MB 가 들어가면 이 모두가 함께 느려집니다.

## 결정 (Decision)

### 1. 받을 형식은 사람이 에이전트 카드에서 고른다

카드의 `도구`, `스킬` 아래에 `모달` 버튼을 두고, 이미지·음성·동영상·문서 체크박스를 보여 줍니다 (`agents.<key>.allowed_modalities`). 모두 비어 있으면 요청은 지금까지와 똑같습니다 — 글과 파일 경로뿐입니다. 도구·스킬 할당과 같은 잠금을 쓰고, 대화가 시작되면 스냅샷으로 고정됩니다.

모델 표로 자동 판정하지 않습니다. 표에 없는 모델이 많고, 사설 엔드포인트는 사람이 더 잘 압니다.

### 2. 메시지에는 파일을 가리키는 블록만 두고, BASE64 는 요청 직전에 만든다

앱 내부 블록 `mado_attachment` 에는 경로·형식·크기만 있습니다. `_complete_unthrottled` 가 요청을 만들 때 `materialize_attachments` 가 이벤트 루프 밖에서 파일을 읽어 실제 블록으로 바꾸고, 요청이 끝나면 버립니다. 초안에는 경로만 남으므로 끊긴 발언은 같은 블록에서 파일을 다시 읽습니다. 토큰은 크기로 어림합니다 (토크나이저는 모르는 블록에서 예외를 올리고, 첨부는 글자 수로 셀 수 없습니다).

### 3. 첨부는 턴 단위이고, 목표 메시지에 싣는다

언급한 턴의 발언마다 첫 사용자 메시지에 실립니다. 두 자르기가 모두 남기는 자리이고, 매번 같은 자리라 프롬프트 캐시도 깨지 않습니다. 언급한 파일은 스킬 지정처럼 값으로 넘겨(`MentionReport.attachment_paths`) 턴 기록에 고정하고, 개입 메모로 더할 수 있습니다. 글에 남는 `[@참조]` 는 그대로 경로입니다. 다음 턴에 다시 보여 주려면 다시 언급합니다.

### 4. 글자 문서는 글자 그대로 싣는다

txt, md, csv, html, json, xml 은 BASE64 대신 글 블록으로 싣습니다. 요청은 "BASE64 로 직접 전달" 이지만, 글자를 BASE64 문서로 받지 않는 Provider 가 많습니다 (Anthropic 은 PDF 만 받습니다). 글은 어느 모델이나 읽으므로 인코딩이 얻는 것 없이 거절만 부릅니다. 나머지 형식은 모두 BASE64 입니다.

### 5. 모델이 거절해도 발언을 잃지 않는다

첨부가 든 요청이 거절되면(`REJECTED`) 첨부를 "받지 못했다" 는 글로 바꿔 같은 모델에게 다시 묻고, 발언 앞에 경고를 남깁니다. 체크박스가 모델 능력과 어긋난 것뿐인데 발언을 통째로 잃으면, 대화가 시작된 뒤에는 모달이 고정되어 있어 사람이 바로 고칠 수도 없습니다. 모델에게도 받지 못했다고 적어 내용을 지어내지 않게 합니다.

### 6. 도구가 돌려준 파일은 다음 사용자 메시지로 싣는다

`ImageContent` · `AudioContent` · blob 리소스를 글과 분리합니다 (`ToolOutput`, `str` 의 하위 클래스라 `(문자열, 상태)` 약속은 그대로입니다). 같은 체크를 따릅니다. 받는 에이전트에게는 파일을 `.mado/tool_media/` 에 풀어 판의 도구를 다 돌린 뒤 사용자 메시지로 붙이고, 아니면 무엇이 왔는지만 글로 적습니다. `role=tool` 에 싣지 않는 것은 OpenAI 호환 엔드포인트가 도구 결과로 글만 받기 때문이고, 도구 결과 사이에 끼우지 않는 것은 짝이 깨지면 400 이기 때문입니다.

샌드박스(v0.9.0 이상, 별도 체크아웃)는 새로 만든 래스터 그림을 `ImageContent` 로도 돌려줍니다. 호스트가 `SANDBOX_INLINE_IMAGES` 로 요청할 때만입니다 — 결과를 글로 뭉개는 호스트(AnythingLLM 등)에서는 BASE64 가 컨텍스트로 쏟아지므로 기본은 꺼 둡니다. MADO 는 자기가 띄우는 서버에 이 값을 줍니다.

### 하지 않기로 한 것

- **대화 내내 첨부를 유지하지 않습니다.** 라운드 × 발언자만큼 비용이 곱해지고, 사람이 고르지 않은 비용입니다. 경로가 글에 남으니 다시 언급하면 됩니다.
- **오케스트레이터의 짧은 호출(지명, 장부, 요약)에는 싣지 않습니다.** 발언(`SpeechRunner.speak`)만 싣습니다. 동료 자문의 상대도 받지 않습니다.
- **파일을 Provider 에 미리 올리지 않습니다** (Files API). 에어갭 사용처가 많고 Provider 마다 달라, 인라인 하나로 둡니다. 그래서 파일당 20 MB, 발언당 50 MB 상한이 있습니다.
- **채팅 화면에 미리보기를 넣지 않습니다.** 요청 범위 밖입니다. 보내는 순간 누구에게 무엇이 가는지 알림으로만 알립니다.

## 결과 (Consequences)

**좋아지는 점**

- 체크한 에이전트가 목업, 사진, 차트, PDF 를 직접 봅니다. 나머지 에이전트의 프롬프트는 한 글자도 달라지지 않습니다.
- 초안과 도구 기록에 BASE64 가 남지 않아, 첨부가 있어도 DB 와 화면의 무게가 그대로입니다.
- MCP 서버가 돌려준 그림이 더는 글자 더미로 모델에게 가지 않습니다 (모달을 끈 에이전트도 이득입니다).

**치르는 비용**

- 어떤 형식을 체크해도 되는지는 사람이 압니다. 못 받는 모델이면 발언마다 거절 한 번(스트리밍, 비스트리밍으로 두 번)을 치른 뒤 글로 이어 갑니다.
- 토큰은 어림값입니다. 실제 사용량은 Provider 가 정하고, 컨텍스트 몫(예산의 절반)도 이 어림으로 계산합니다.
- 언급한 뒤 파일이 바뀌면 다음 요청은 바뀐 내용을 봅니다. 같은 턴 안에서 발언마다 다른 파일을 볼 수 있지만, 파일을 복사해 고정해 두는 비용이 더 크다고 봤습니다.
- `.mado/tool_media/` 에 도구 결과 파일이 쌓입니다. 7일 지난 것은 저장할 때 지웁니다.
