# ADR-008. 토론 실행을 브라우저 화면에서 떼어 낸다

> [ADR 목록](README.md) · 이전: [ADR-007](ADR-007-no-simulated-answers.md) · 다음: [ADR-009](ADR-009-refuse-cross-workspace-debates.md)

## 상태 (Status)

채택됨 · 2026-08-28 · 관련: [ADR-001](ADR-001-python-single-process.md)

## 맥락 (Context)

초기 구현에서는 대화 입력창의 전송 버튼 클릭 이벤트 핸들러 내부에서 턴 실행 비동기 코루틴을 직접 `await` 호출했습니다. 즉, 토론 한 턴의 실행 수명 주기가 특정 브라우저 탭(NiceGUI 클라이언트 인스턴스) 하나에 직접 종속되어 있었습니다. 이로 인해 두 가지 치명적인 문제가 발생했습니다.

- **브라우저 새로고침 시 실행 중이던 토론이 강제 종료되었습니다.** 사용자가 브라우저를 새로고침하거나 페르소나 설정 페이지 등으로 라우팅을 이동하면 NiceGUI는 해당 클라이언트 객체를 메모리에서 즉시 파기합니다. 이때 토론 코루틴이 참조하고 있던 화면 슬롯의 상위 DOM 컨테이너가 소멸하면서, 후속 UI 갱신 시점에 "해당 슬롯의 부모 요소가 이미 삭제됨"이라는 런타임 예외가 발생했습니다. 이 예외가 턴 실행 함수의 최상위로 전파되어 기껏 진행되던 토론을 중도 중단시켰으며, 공교롭게도 토론이 마무리되려던 시점에 주로 발생했습니다.
- **페이지를 이탈했다가 다시 돌아와서 진행 상황을 확인할 방법이 없었습니다.** 토론 태스크가 백엔드에서 간신히 생존하더라도, 새로 열린 화면에서는 현재 진행 중인 토론의 스트리밍 상태를 구독할 수 없었습니다.

## 결정 (Decision)

토론 실행 수명 주기를 UI 계층에서 완전히 분리하여 **서버 프로세스가 직접 소유하는 백그라운드 태스크(Background Task)**로 이전하도록 합니다.

- 토론 실행기(Debate Runner)가 세션마다 독립된 비동기 태스크를 생성합니다. UI 화면 계층은 "해당 세션의 토론을 시작하라"는 비동기 신호만 발송하고 즉시 제어를 반환받습니다.
- 실행기는 세션별로 두 가지 핵심 상태를 관리합니다.
  - **정본 스냅샷 (Authoritative Snapshot)**: 해당 턴에서 생성된 모든 발언(실시간 스트리밍 중인 발언 포함), 활성 발언 ID, 현재 산출물, 진행 단계 안내 문구를 메모리에 유지합니다. 나중에 접속한 화면은 이 스냅샷을 읽어 UI를 복원합니다.
  - **구독 큐 (Subscription Queue)**: 연결된 브라우저 클라이언트마다 독립된 이벤트 큐를 배정합니다. 특정 클라이언트가 연결을 끊으면 해당 큐만 안전하게 폐기합니다.
- 토론 실행기는 구체적인 UI 위젯 요소를 일절 참조하지 않습니다. 신규 태스크는 비어 있는 UI 컨텍스트 슬롯 스택으로 기동되므로 실수로라도 화면 요소를 직접 생성할 수 없습니다.
- 처리 속도가 느려 큐가 가득 찬(Overflow) 클라이언트가 발생하면, 토론 실행 자체를 중단시키는 대신 지연된 해당 화면 클라이언트의 연결만을 강제 해제합니다.
- 턴이 완전히 종료된 이후의 인메모리 스냅샷은 참조하지 않습니다. 턴 종료 시점 이후부터는 SQLite 데이터베이스가 단일 정본 역할을 수행합니다. 종료 후에도 스냅샷을 지속 신뢰할 경우 지난 턴의 임시 데이터가 DB의 영속화 기록을 덮어쓰는 문제가 발생하기 때문입니다.
- 개별 UI 컴포넌트는 "자신이 속한 클라이언트가 현재 유효한가"를 자체 검증하며, 이미 소멸된 화면으로 지연 도달한 이벤트는 조용히 무시합니다.
- 애플리케이션 종료 또는 대화 세션 삭제 시에는 진행 중인 백그라운드 토론 태스크에 비동기 취소(`task.cancel()`) 신호를 전파하여 자원을 정리합니다.

## 결과 (Consequences)

**좋아지는 점**

- 브라우저 새로고침, 타 페이지 이동, 여러 탭에서의 동일 대화 동시 모니터링이 완벽하게 지원됩니다. 새로 접속한 브라우저 화면에서도 실시간 생성 중이던 발언 텍스트가 자연스럽게 이어서 스트리밍됩니다.
- "토론 도메인 계층은 UI 프리젠테이션 계층을 참조하지 않는다"는 명확한 단방향 의존성 규칙이 확립되었으며, 이는 시스템 전반의 계층 분리 기준이 되었습니다.

**치르는 비용**

- 새로고침하여 재접속한 화면은 **데이터베이스 영속 기록과 메모리의 실시간 스냅샷을 고유 ID 기준으로 정밀하게 병합**해야 합니다. 스트리밍 중이던 카드의 컨테이너 DOM도 다시 마운트해야만 후속 청크 데이터가 올바른 위치에 삽입될 수 있습니다.
- 데이터의 정본 소스가 시점에 따라 동적으로 전환됩니다 (턴 진행 중에는 메모리 스냅샷, 턴 종료 후에는 SQLite DB). 시스템 코드가 이 전환 타이밍을 정확히 인지하고 처리해야 합니다.
- 백그라운드 태스크의 취소 관리 책임이 메인 애플리케이션 수명 주기 관리자로 이전되었습니다. 이후 취소 신호를 삼켜버리는 방어 코드로 인해 서버 종료가 멈추는 장애가 발생하여, 취소 대기 시간에 20초의 엄격한 타임아웃 상한을 설정하게 되었습니다 ([ADR-014](ADR-014-tool-failure-is-observation.md)).
- 사용자 개입(토론 즉시 중지, 사용자 개입 메모 주입, 도구 예산 증액 승인 등)을 브라우저 화면에서 백그라운드 토론 태스크로 전달하기 위한 전용 채널이 필요해졌으며, 이를 위해 세션별 "턴 제어 우편함(Queue)" 메커니즘을 신설했습니다.

**함께 개선한 사항**

이 작업을 진행하는 과정에서, 턴 종료 시 호출되던 UI 갱신 로직이 툴팁 위젯을 **매번 중복 생성하고 있던 결함**도 함께 수정했습니다. 툴팁 생성 함수는 내부적으로 현재 활성 슬롯에 신규 DOM 요소를 추가하는데, 그 시점에는 이미 상위 슬롯 컨테이너가 파기된 상태였습니다. 이에 툴팁은 초기 컴포넌트 마운트 시 단 1회만 생성하고, 이후 갱신 시에는 텍스트 속성만 변경하도록 최적화했습니다. 서버 주도형(Server-driven) UI 환경에서는 "UI 요소를 생성하는 시점"이 언제인가가 심각한 수명 주기 버그의 직접적인 원인이 되기 쉽습니다.
