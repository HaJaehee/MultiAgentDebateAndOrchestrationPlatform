# ADR-055. Bench 는 결정적 검사와 판정 모델의 채점으로 품질을 숫자로 남기고, 두 실행을 견줘 나빠진 것을 짚는다

> [ADR 목록](README.md) · 이전: [ADR-054](ADR-054-model-conformance-check.md)

## 상태 (Status)

채택됨 · 2026-11-12 · 관련: [ADR-034](ADR-034-adaptive-graph-and-sub-debates.md), [ADR-048](ADR-048-token-and-time-mini-charts.md), [ADR-054](ADR-054-model-conformance-check.md)

## 맥락 (Context)

- MADO Bench(v1.5)는 한 요청을 여러 변형(전략·라운드·참여자·모델)으로 돌려 토큰·시간·미해결 쟁점·도구 실패를 표로 냅니다. **품질**은 사람이 비교 화면에서 👍/👎 를 매겨야만 남습니다.
- 폐쇄망에는 모델이 여럿 있고, 어느 모델을 어느 역할에 둘지를 정해야 합니다. 조합은 곱으로 늘어나는데(판정자 2종 × 코더 3종 …) 사람이 결론을 전부 읽고 매길 수는 없습니다. 모델이나 프롬프트를 바꾼 뒤 "나빠지지 않았는가" 도 지금은 표 둘을 눈으로 견줘야 합니다.
- 적합성 점검(ADR-054)은 모델이 **할 수 있는지**만 봅니다. **잘하는지**는 일을 시켜 봐야 압니다.
- LLM 판정을 도구 보안에 쓰는 것은 기각했습니다(tool-security §10: 판정자 자체가 주입될 수 있음). 여기서의 판정은 권한을 주지 않고 표의 한 칸을 채울 뿐이라 사정이 다릅니다.

## 결정 (Decision)

### 1. 결정적 검사 (`checks`) 가 먼저입니다

시나리오에 검사를 적으면 변형이 끝난 뒤 **그 변형의 작업 공간과 결론**에 돌립니다.

| 종류 | 통과 조건 |
| :--- | :--- |
| `file_exists` | 작업 공간에 그 파일이 있음 |
| `file_contains` | 그 파일에 `text` 가 있거나 `regex` 가 맞음 |
| `conclusion_contains` | 결론에 그 글이 있거나 `regex` 가 맞음 |
| `command` | `argv` 를 작업 공간에서 돌려 끝남 값이 `expect_exit`(기본 0), `stdout_contains` 가 있으면 출력에 그 글 |
| `max_open_issues` | 마지막 장부의 미해결 쟁점 수가 그 이하 |

- 같은 결과물에는 늘 같은 답입니다. 모델이 만든 스크립트를 실제로 돌려 보는 것(`command`)이 "만들었다고 보고했다" 와 "된다" 를 가릅니다.
- `command` 는 문자열 목록만 받고 셸을 거치지 않습니다. `{python}` 은 Bench 를 돌리는 인터프리터입니다. 시간 상한이 있습니다(기본 120초).
- 경로는 그 변형의 작업 공간 안만 봅니다. 밖을 가리키면 실패로 적습니다.
- 검사 하나가 터져도 나머지는 계속하고, 변형의 결과는 버리지 않습니다.

`command` 는 시나리오를 쓴 사람의 명령을 그 사람의 권한으로 돌립니다. 시나리오 파일은 `python -m app.bench` 를 치는 사람이 고른 것이라 스크립트를 직접 돌리는 것과 같은 신뢰입니다. 화면이나 REST 로 시나리오를 받는 길은 없습니다.

### 2. 판정 모델의 채점 (`rubric`) 은 선택입니다

`rubric.judge` 에 conf 의 에이전트 키를 적으면, 기준마다 척도의 한 단계를 고르게 합니다.

- 판정자가 결정 LLM(System 1)을 쓰는 에이전트면 기준마다 `score` 질문 하나를 한 번의 요청으로 보냅니다. 아니면 생성형 모델에게 `{"scores": {...}}` JSON 한 줄을 받습니다. 폐쇄망에서도 같은 방식입니다 — 판정자는 그 망의 모델입니다.
- **판정자는 요청과 결론만 봅니다.** 변형의 이름·전략·모델은 보내지 않습니다. 생성형 판정자는 도구와 단계적 사고 지침을 떼고 부릅니다.
- **읽지 못한 점수는 지어내지 않습니다.** 기준 하나라도 못 읽으면 그 변형의 점수는 비우고 "판정 실패" 와 사유를 적습니다 (ADR-007 과 같은 원칙).
- 점수는 `(단계 합) / (기준 수 × 최고 단계)` 로 0~1 입니다. 모델이 매긴 값이므로 절대값이 아니라 **같은 판정자가 매긴 변형끼리의 차이**로 읽습니다.
- 드라이런은 채점하지 않습니다 (결론이 대본입니다).
- 판정 호출의 토큰은 변형의 사용량에 넣지 않습니다. 변형이 일하는 데 쓴 값이 아닙니다.

### 3. 모델 행렬과 그래프 변형

- 변형에 `matrix: {에이전트 키: [모델 …]}` 를 적으면 목록들의 곱만큼 변형으로 펼칩니다. 이름은 `<원래 이름> · critic=qwen3-32b, coder=…` 입니다. 모델 이름만 바뀌고 연결(주소·키)은 conf 의 것이라, 한 게이트웨이가 여러 모델을 내는 폐쇄망에 맞습니다.
- 변형에 `graph: <그래프 id>` 를 적으면 그래프 토론을 돌립니다. 그래프는 여기서 만들지 않고 편집기로 저장해 둔 것을 고릅니다. `headless.create_session` 이 `graph_id` 를 받게 했고, REST·MCP 는 이 인자를 내보내지 않으므로 거기서는 예전처럼 거절됩니다.
- 설정에 없는 에이전트의 모델을 바꾸려는 변형은 시나리오를 읽을 때 거절합니다 (예전에는 조용히 무시했습니다).

### 4. 두 실행 견주기 (`diff`)

`python -m app.bench diff <이전 result.json> <새 result.json>` 은 변형 이름으로 맞춰 상태·검사·채점·토큰·시간을 견줍니다.

- **나빠짐**으로 치는 것: 끝났던 변형이 끝나지 못함, 통과한 검사 수가 줄어듦, 채점이 0.15 이상 내려감. 하나라도 있으면 끝남 값 1 입니다.
- 채점이 0.15 미만으로 움직인 것은 판정자의 흔들림으로 보고 알리지 않습니다. 토큰이 25% 넘게 는 것은 표에 적기만 합니다 — 품질이 오른 값일 수 있습니다.
- 두 실행의 요청이 다르면 그렇다고 적습니다.
- 파일 둘만 읽습니다. 설정도 DB 도 필요 없어, 폐쇄망에서 가져온 `result.json` 을 밖에서 견줄 수 있습니다.

### 하지 않는 것

- 리더보드·대시보드·점수 이력 화면. 표와 `diff` 까지입니다.
- 같은 변형을 여러 번 돌려 평균 내기. 필요하면 변형을 이름만 달리해 여러 개 적습니다.
- 판정자 여럿의 합의. 판정자를 바꿔 한 번 더 돌려 견주면 됩니다.
- 화면에서 시나리오를 만들고 돌리기.

## 결과 (Consequences)

**좋아지는 점**

- 모델·전략 조합을 사람이 읽지 않고도 줄 세울 첫 기준이 생깁니다. 사람은 위쪽 몇 개만 읽으면 됩니다.
- 모델이나 프롬프트를 바꾼 뒤의 회귀 확인이 명령 한 줄과 끝남 값입니다.

실제 확인(2026-11-11~12, 두 번 실행, `deepseek-v4-flash` 가 일하고 채점, `jev-1.13.0` 이 같은 결론을 한 번 더 채점): 작은 구현 시나리오에서 두 번 모두 검사 3개가 통과했습니다(모델이 만든 `summarize.py` 를 실제로 돌려 합계 350 을 확인). 생성형 판정자는 두 번 모두 0.50(요청 충족 충실 · 간결함 미흡), 결정 LLM 판정자는 0.50(둘 다 보통)과 0.75(충실 · 보통)를 줬습니다. 첫 실행에서는 생성형 판정 요청이 두 번 나갔습니다 — 첫 응답에서 추론이 `max_tokens` 1,500 을 다 써 본문이 비었고 앱이 답을 다시 청했습니다.

**치르는 비용**

- 채점은 모델의 의견입니다. 위 실행에서 두 판정자는 같은 결론에 기준별 단계를 다르게 매겼습니다. 판정자를 바꾸면 점수의 뜻이 바뀌므로, `diff` 는 같은 판정자의 두 실행에만 씁니다.
- 판정자가 작은 `max_tokens` 의 추론 모델이면 판정마다 요청이 더 나가거나 실패합니다. 판정자는 응답 한도가 넉넉한 에이전트로 고릅니다.
- 한 변형 한 번 실행의 점수입니다. 같은 변형을 다시 돌리면 달라질 수 있습니다.
- `matrix` 는 곱으로 늘어납니다. 3 × 3 × 3 은 27턴입니다.
