# ADR-055. Bench는 결정적 검사와 판정 모델의 채점으로 품질을 수치화하고, 두 실행 결과를 비교해 성능 저하를 검출한다

> [ADR 목록](README.md) · 이전: [ADR-054](ADR-054-model-conformance-check.md) · 다음: [ADR-056](ADR-056-per-connection-limits-fallback-chain-and-applying-advice.md)

## 상태 (Status)

채택됨 · 2026-11-12 · 관련: [ADR-034](ADR-034-adaptive-graph-and-sub-debates.md), [ADR-048](ADR-048-token-and-time-mini-charts.md), [ADR-054](ADR-054-model-conformance-check.md)

## 맥락 (Context)

- MADO Bench(v1.5)는 한 요청을 여러 변형(전략·라운드·참여자·모델)으로 실행해 토큰·소요 시간·미해결 쟁점·도구 실패를 표로 출력합니다. **품질**은 사용자가 비교 화면에서 👍/👎를 매겨야만 기록되었습니다.
- 폐쇄망에는 여러 모델이 배치되어 있어 어느 모델을 어느 역할에 둘지 정해야 합니다. 조합은 곱으로 늘어나는데(판정자 2종 × 코더 3종 …) 사람이 결론을 전부 읽고 평가할 수는 없습니다. 모델이나 프롬프트를 바꾼 뒤 "성능이 저하되지 않았는가"도 기존에는 표 두 개를 눈으로 비교해야 했습니다.
- 적합성 점검(ADR-054)은 모델이 **지원하는지**만 확인합니다. **잘 수행하는지**는 실제 작업을 시켜 봐야 압니다.
- LLM 판정을 도구 보안에 사용하는 방안은 기각했습니다(tool-security §10: 판정자 자체가 프롬프트 인젝션에 노출될 수 있음). 여기서의 판정은 권한을 주지 않고 표의 한 칸을 채울 뿐이므로 성격이 다릅니다.

## 결정 (Decision)

### 1. 결정적 검사(`checks`)가 먼저입니다

시나리오에 검사를 지정하면 변형이 끝난 뒤 **해당 변형의 작업 공간과 결론**을 대상으로 실행합니다.

| 종류 | 통과 조건 |
| :--- | :--- |
| `file_exists` | 작업 공간에 해당 파일이 있음 |
| `file_contains` | 해당 파일에 `text`가 있거나 `regex`가 일치함 |
| `conclusion_contains` | 결론에 해당 문자열이 있거나 `regex`가 일치함 |
| `command` | `argv`를 작업 공간에서 실행해 종료 코드가 `expect_exit`(기본값 0)이고, `stdout_contains`가 지정되면 출력에 해당 문자열이 포함됨 |
| `max_open_issues` | 마지막 장부의 미해결 쟁점 수가 지정한 상한 이하 |

- 동일한 결과물에는 항상 같은 판정이 나옵니다. 모델이 만든 스크립트를 실제로 실행해 보는 것(`command`)이 "작성했다고 보고함"과 "실제로 동작함"을 가릅니다.
- `command`는 문자열 목록만 허용하며 셸을 거치지 않습니다. `{python}`은 Bench를 실행 중인 인터프리터로 치환됩니다. 시간 제한이 있습니다(기본값 120초).
- 경로는 해당 변형의 작업 공간 내부만 허용합니다. 작업 공간 밖을 가리키면 실패로 기록합니다.
- 검사 하나에서 오류가 나도 나머지는 계속 실행하며, 변형의 결과는 버리지 않습니다.

`command`는 시나리오 작성자가 지정한 명령을 실행자의 권한으로 수행합니다. 시나리오 파일은 `python -m app.bench`를 실행하는 사용자가 직접 고른 것이므로 스크립트를 직접 실행하는 것과 신뢰 수준이 같습니다. 화면이나 REST API로 시나리오를 받는 경로는 두지 않습니다.

### 2. 판정 모델의 채점(`rubric`)은 선택 사항입니다

`rubric.judge`에 `conf.json`의 에이전트 키를 지정하면, 기준마다 척도의 한 단계를 선택하게 합니다.

- 판정자가 결정 LLM(System 1)을 쓰는 에이전트면 기준마다 `score` 질문 하나를 별도 요청으로 보냅니다. 생성형 모델이면 `{"scores": {...}}` JSON 한 줄을 응답받습니다. 폐쇄망에서도 방식은 같습니다 — 판정자는 해당 환경의 모델입니다.
- **판정자는 요청과 결론만 봅니다.** 변형의 이름·전략·모델은 보내지 않습니다. 생성형 판정자는 도구와 단계적 사고 지침을 제외하고 호출합니다.
- **파싱하지 못한 점수는 지어내지 않습니다.** 기준을 하나라도 파싱하지 못하면 해당 변형의 점수는 비우고 "판정 실패"와 사유를 적습니다 (ADR-007과 같은 원칙).
- 점수는 `(단계 합) / (기준 수 × 최고 단계)`로 0~1 범위입니다. 모델이 매긴 값이므로 절댓값이 아니라 **같은 판정자가 매긴 변형 간의 차이**로 해석합니다.
- 드라이런은 채점하지 않습니다 (결론이 고정 대본입니다).
- 판정 호출의 토큰은 변형의 사용량에 포함하지 않습니다. 변형이 작업을 수행하는 데 사용한 비용이 아닙니다.

### 3. 모델 행렬과 그래프 변형

- 변형에 `matrix: {에이전트 키: [모델 …]}`를 적으면 목록들의 곱만큼 변형으로 펼칩니다. 이름은 `<원래 이름> · critic=qwen3-32b, coder=…` 형식입니다. 모델 이름만 바뀌고 연결 정보(주소·키)는 `conf.json`의 설정을 쓰므로, 하나의 게이트웨이가 여러 모델을 제공하는 폐쇄망에 맞습니다.
- 변형에 `graph: <그래프 id>`를 적으면 그래프 토론을 실행합니다. 그래프는 여기서 만들지 않고 편집기로 저장해 둔 것을 지정합니다. `headless.create_session`이 `graph_id`를 받도록 했고, REST·MCP는 이 인자를 노출하지 않으므로 거기서는 예전처럼 거절됩니다.
- 설정에 없는 에이전트의 모델을 바꾸려는 변형은 시나리오를 읽을 때 거절합니다 (예전에는 조용히 무시했습니다).

### 4. 두 실행 비교 (`diff`)

`python -m app.bench diff <이전 result.json> <새 result.json>`은 변형 이름을 기준으로 맞춰 상태·검사·채점·토큰·시간을 비교합니다.

- **성능 저하**로 판정하는 조건: 완료되었던 변형이 완료되지 못함, 통과한 검사 수가 줄어듦, 채점이 0.15 이상 하락함. 하나라도 해당하면 종료 코드는 1입니다.
- 채점이 0.15 미만으로 움직인 것은 판정자의 변동 폭으로 보고 알리지 않습니다. 토큰이 25% 넘게 증가한 것은 표에 표시만 합니다 — 품질이 올라간 결과일 수 있습니다.
- 두 실행의 요청이 다르면 별도로 표시합니다.
- 파일 두 개만 읽습니다. 설정도 DB도 필요 없어, 폐쇄망에서 가져온 `result.json`을 외부 환경에서 비교할 수 있습니다.

### 하지 않는 것

- 리더보드·대시보드·점수 이력 화면. 표와 `diff`까지만 지원합니다.
- 같은 변형을 여러 번 실행해 평균 내기. 필요하면 변형을 이름만 달리해 여러 개 적습니다.
- 판정자 여럿의 합의. 판정자를 바꿔 한 번 더 실행해 비교하면 됩니다.
- 화면에서 시나리오를 만들고 실행하기.

## 결과 (Consequences)

**좋아지는 점**

- 모델·전략 조합을 사람이 일일이 읽지 않고도 줄 세울 첫 기준이 생깁니다. 사람은 상위 몇 개만 검토하면 됩니다.
- 모델이나 프롬프트를 바꾼 뒤의 회귀 확인이 명령 한 줄과 종료 코드로 끝납니다.

실제 확인(2026-11-11~12, 두 번 실행, `deepseek-v4-flash`가 작업과 채점을 맡고, `jev-1.13.0`이 같은 결론을 한 번 더 채점): 작은 구현 시나리오에서 두 번 모두 검사 3개가 통과했습니다(모델이 만든 `summarize.py`를 실제로 실행해 합계 350을 확인). 생성형 판정자는 두 번 모두 0.50(요청 충족 충실 · 간결함 미흡), 결정 LLM 판정자는 0.50(둘 다 보통)과 0.75(충실 · 보통)를 주었습니다. 첫 실행에서는 생성형 판정 요청이 두 번 나갔습니다 — 첫 응답에서 추론이 `max_tokens` 1,500을 다 써 본문이 비었고 앱이 응답을 다시 요청했습니다.

**치르는 비용**

- 채점은 모델의 평가 결과입니다. 위 실행에서 두 판정자는 같은 결론에 기준별 단계를 다르게 매겼습니다. 판정자를 바꾸면 점수의 의미가 달라지므로, `diff`는 같은 판정자의 두 실행에만 사용합니다.
- 판정자가 `max_tokens`가 작은 추론 모델이면 판정마다 요청이 더 나가거나 실패할 수 있습니다. 판정자는 응답 한도가 넉넉한 에이전트로 고릅니다.
- 한 변형 한 번 실행의 점수입니다. 같은 변형을 다시 실행하면 달라질 수 있습니다.
- `matrix`는 곱으로 늘어납니다. 3 × 3 × 3은 27턴입니다.
