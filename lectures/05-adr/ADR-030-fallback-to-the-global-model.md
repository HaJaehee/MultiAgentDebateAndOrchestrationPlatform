# ADR-030. 개별 모델의 연결이 실패하면, 켜 둔 배치에 한해 전역 기본 모델이 대신 답하고 그 사실을 남깁니다

> [ADR 목록](README.md) · 이전: [ADR-029](ADR-029-beginner-pages.md)

## 상태 (Status)

채택됨 · 2026-10-11 · 관련: [ADR-002](ADR-002-litellm-gateway.md), [ADR-011](ADR-011-session-config-snapshot.md), [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-025](ADR-025-resume-speeches-by-tool-step.md)

## 맥락 (Context)

- 에이전트마다 다른 모델을 붙일 수 있습니다. 그중 하나의 키가 만료되거나 서버가 내려가면 그 에이전트의 발언 자리에는 "연결 끊김" 안내만 남고, 토론은 한 사람이 빠진 채 끝납니다. 나머지 연결이 멀쩡해도 그렇습니다.
- 한편 이 프로젝트는 **응답을 지어내지 않는다**는 원칙을 갖고 있습니다. 예전의 내장 시뮬레이터는 엔드포인트가 500 을 돌려줘도 그럴듯한 페르소나 답변을 만들어 냈고, 그 답이 다음 에이전트의 입력과 최종 합성까지 오염시켰습니다. 그래서 실패는 `LLMUnavailableError` 로 올리고 그대로 적습니다.
- 전역 기본 모델이 대신 답하는 것은 지어내는 것이 아닙니다. 그러나 **조용히 바뀌면 같은 문제**가 됩니다. 여러 모델을 섞어 얻으려던 다양성이 사라졌는데 기록은 그대로이고, 개별 모델이 사내 모델·전역이 외부 API 인 배치에서는 대화와 작업 공간 내용이 의도하지 않은 곳으로 나갑니다.
- 발언은 한 번의 요청이 아니라 도구 루프입니다. 도중에 모델을 바꾸면 한 모델이 만든 도구 호출 기록(사고 블록·서명 포함)을 다른 모델에게 넘기게 되고, Provider 에 따라 거절합니다. 이미 화면에 흘러간 글이 있으면 같은 답이 두 번 붙습니다.
- 죽은 연결은 빨리 실패하지 않을 수 있습니다. `timeout` 과 `num_retries` 를 통째로 치르고 나서야 실패가 확정되므로, 발언마다 다시 기다리면 한 턴이 몇 분씩 늘어납니다.

## 결정 (Decision)

**`llm.fallback.enabled` 를 켠 배치에 한해, 자기 연결을 쓰는 에이전트의 호출이 연결 문제로 실패하면 전역 기본 연결(`llm`)로 같은 발언을 처음부터 다시 받습니다. 전환할 때마다 그 사실을 화면과 기록에 남깁니다.**

- **기본은 꺼둡니다.** 조용한 전환이 기본이 되어서는 안 되고, 외부로 나가는 경로가 될 수 있기 때문입니다. 에이전트마다 `allow_fallback: false` 로 막을 수 있습니다.
- **연결의 문제일 때만 물러섭니다.** 인증 실패, 모델 이름, 연결 실패, 응답 없음, 서버 오류입니다 (`model_status.classify`). 한도 초과(429)는 잠깐 뒤에 풀리고 폴백하면 요청이 전역 모델로 몰리므로 물러서지 않습니다. 요청 거절(400)과 컨텍스트 초과는 요청의 문제라 전역 모델도 같은 이유로 실패합니다.
- **모델이 아무것도 내놓기 전에만 물러섭니다.** 글이 한 조각이라도 흘렀거나 한 판 이상 받은 뒤(= 도구 호출 기록이 생긴 뒤), 그리고 끊긴 발언을 이어 가는 중([ADR-025](ADR-025-resume-speeches-by-tool-step.md))에는 물러서지 않습니다. 개별 모델의 연결 실패는 대부분 발언의 첫 요청에서 드러나므로 주된 경우는 이것으로 덮입니다.
- **판단은 `LLMCaller.call_agent` 한 곳에서 합니다.** 모든 LLM 호출이 이 함수를 지납니다. 엔진의 실패 처리부 여섯 곳은 손대지 않습니다.
- **바꾸는 것은 연결과 그 모델의 용량뿐입니다.** 페르소나·도구·스킬·온도는 에이전트 것 그대로입니다. 처음부터 다시 부르므로 시스템 프롬프트와 컨텍스트 자르기는 대체 모델의 한도로 다시 계산됩니다.
- **전역은 지금의 설정입니다.** 잠긴 대화의 스냅샷([ADR-011](ADR-011-session-config-snapshot.md))에는 전역 값이 따로 없고, 키를 바꾼 뒤에도 동작해야 합니다. 그래서 누가 실제로 답했는지는 스냅샷이 아니라 **발언마다** `messages.llm_meta` 에 적습니다.
- **실패한 연결은 잠깐 건너뜁니다.** `retry_after` 초 동안은 원래 모델을 부르지 않고 곧바로 전역 모델로 보내고, 지나면 한 번 다시 불러 봅니다. `모델 연결 상태` 창에서 응답을 확인하면 즉시 원래 모델로 돌아갑니다.
- **알림은 인자가 아니라 컨텍스트 변수로 받습니다** (`llm_fallback.listening`). `call_agent` 와 같은 모양으로 만든 호출기들이 인자 하나 때문에 깨지지 않게 하려는 것이고, `LLM_HOLDER` 가 이미 같은 방식입니다.
- **전역 모델도 실패하면 지어내지 않습니다.** 원래 에이전트의 실패로 올리고 두 이유를 함께 적습니다.

**다음은 하지 않습니다.**

- 엔진에서 발언을 통째로 다시 부르지 않습니다. 도구가 두 번 실행되고 실패 처리부 여섯 곳을 모두 고쳐야 합니다.
- LiteLLM 의 자체 폴백 옵션에 맡기지 않습니다. 누가 답했는지를 화면에 알릴 길과, 실패 갈래별 정책·차단기를 둘 자리가 없습니다.
- 기동할 때 한 번 확인해 설정을 바꿔 두지 않습니다. 연결 상태는 도중에 바뀝니다.
- 발언 도중(도구를 부른 뒤)의 전환은 넣지 않습니다. 필요해지면 그때 Provider 별 제약을 확인하고 따로 결정합니다.

## 결과 (Consequences)

**장점**

- 한 모델의 장애가 그 에이전트의 침묵으로 이어지지 않습니다. 토론은 전원의 발언으로 끝납니다.
- 전환은 드러납니다. 발언 카드의 `기본 모델로 응답` 배지, 발언 기록, 저장 문서, 턴 종료 알림과 요약 JSON 의 `fallback_agents` 가 같은 사실을 말합니다.
- 죽은 연결의 타임아웃을 한 번만 치릅니다.
- 꺼 둔 배치에서는 달라지는 것이 없습니다. 콜백을 감싸지도 않습니다.

**고려할 트레이드오프**

- 폴백 발언은 다른 모델이 쓴 것입니다. 모델을 섞어 얻으려던 관점의 차이는 그만큼 줄어듭니다. 실패로 세지는 않지만 턴이 끝날 때 사람에게 알립니다.
- 첫 요청이 실패한 발언은 처음부터 다시 부릅니다. 지정 스킬을 미리 부르는 단계와 컨텍스트 자르기가 한 번 더 돕니다 (화면과 기록에는 한 번만 남깁니다).
- 발언 도중에 끊긴 경우는 여전히 실패입니다. 사람이 "이어서 진행" 을 눌러야 하고, 그때도 원래 모델로 이어 갑니다.
- 차단기는 프로세스 메모리에 있습니다. 재기동하면 잊고 원래 모델부터 다시 부릅니다.
- 잠긴 대화가 스냅샷에 없는 모델의 답을 갖게 됩니다. 그 사실은 발언 기록에만 있습니다.
