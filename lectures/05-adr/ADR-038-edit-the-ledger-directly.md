# ADR-038. 토론 유휴 상태에서 결정 장부를 항목 단위로 직접 편집하고 변경 이력을 사용자 발언으로 기록한다

> [ADR 목록](README.md) · 이전: [ADR-037](ADR-037-tell-people-looking-elsewhere.md)

## 상태 (Status)

채택됨 · 2026-10-31 · 관련: [ADR-020](ADR-020-conversation-memory.md), [ADR-036](ADR-036-retry-one-speech-and-inline-comments.md)

## 맥락 (Context)

- 결정 장부(Decision Ledger)는 읽기 전용으로 제공되었으며, 잘못 기록된 기술 결정이나 오해된 요구사항을 바로잡으려면 채팅 프롬프트로 정정 요청을 보내야 했습니다. 이 정정이 장부에 반영되려면 다음 라운드 턴을 실행하여 장부 재작성 단계를 거쳐야 했고, 그동안 잘못된 결정이 모든 에이전트의 LLM 프롬프트에 지속적으로 주입되는 문제가 있었습니다. 미해결 쟁점 하나를 닫기 위해서도 불필요한 1턴의 LLM 비용이 소모되었습니다.
- 토론 엔진은 장부 상태를 메모리에 보관하다가 턴 종료 시점에 데이터베이스에 일괄 저장합니다(`persist_memory`). 실행 중인 턴 외부에서 임의로 DB 장부를 수정하면 턴 종료 시 무조건 덮어써지는 문제가 발생합니다.
- 마스터 오케스트레이터는 매 라운드마다 장부 전체를 새로 작성합니다. 사용자가 직접 수정한 항목이라는 사실을 인지하지 못하면 차기 갱신 단계에서 모델이 이를 임의로 되돌릴 위험이 있습니다.
- 수렴 판정, 서브 토론 개설 여부, 최종 합의 판정 로직이 장부의 마크다운 헤더(`## 제목`)와 목록 기호(`- 항목`) 구조를 정규식으로 파싱합니다 (`ledger_items`). 따라서 자유 형식 텍스트 편집을 허용하면 마크다운 서식이 훼손되어 시스템 기능이 오동작할 위험이 컸습니다.

## 결정 (Decision)

### 1. 자유 텍스트 편집 대신 항목(Item) 단위 구조화 편집 인터페이스를 제공한다

각 섹션별로 항목 단위 입력 필드를 제공하고, 미해결 쟁점 항목에는 상태 체크박스를 배치합니다. 체크박스를 해제하면 해당 쟁점을 '해결 완료'로 마킹하여 닫고, 빈 섹션은 `- 없음`으로 자동 서식화합니다. 사용자가 마크다운 서식을 직접 입력하지 않아도 시스템이 항상 유효한 헤더와 목록 구조로 안전하게 재생성하여 수렴 판정 파서의 정합성을 보장합니다.

### 2. 토론이 실행 중이지 않은 유휴(Idle) 상태에서만 편집을 허용한다

토론이 진행 중일 때는 편집 버튼을 비활성화하고, 편집 도중 다른 탭에서 토론이 시작되거나 장부가 갱신된 경우 낙관적 동시성 제어(Optimistic Concurrency Control)를 적용합니다 (`UPDATE … WHERE decision_ledger = :원본장부`). 충돌 발생 시 수정을 즉시 취소하고 최신 장부를 다시 불러오도록 안내합니다.

### 3. 장부 수정 이력을 사용자 권위의 발언 레코드로 타임라인에 영구 기록한다

장부 저장 시 `turn_meta.kind = ledger_edit` 메타데이터를 가진 시스템 안내 발언을 타임라인 끝에 생성하고, 프롬프트 조립 시 `build_user_record`가 이를 사용자 공식 발언과 동일한 우선순위로 포함합니다. 변경 기록에는 섹션별 삭제/추가 항목 및 닫힌 쟁점 목록이 명시됩니다. 이를 통해 모델이 차기 장부 재작성 시 사용자의 명시적 결정을 함부로 번복하지 못하도록 강력한 맥락 권위를 부여합니다.

### 4. 마지막 턴의 메모리 스냅샷도 동일하게 동기화한다

수정된 장부는 차기 턴의 시작 장부로 사용됩니다. 아울러 이전 발언 재생성이나 세션 분기(Fork)가 마지막 턴의 `turns.memory`를 참조하므로, 마지막 턴의 메모리 데이터도 수정된 장부 값으로 함께 동기화하여 시점 일관성을 유지합니다.

### 5. 토큰 한도 및 길이 상한 엄격 적용

장부 편집 저장 시에도 시스템의 정합성을 위해 턴별 장부 토큰 상한(`LEDGER_MAX_CHARS`) 검증을 거치며, 한도를 초과하는 비대칭 저장은 거부합니다.

## 결과 (Consequences)

**이점**

- 잘못된 기술 결정이나 오해를 추가 턴 실행 없이 즉각적으로 바로잡을 수 있어 토큰 비용과 시간을 대폭 절감할 수 있습니다.
- 해결된 쟁점을 원클릭으로 닫아 불필요한 논쟁 지속을 방지할 수 있습니다.
- 구조화된 UI를 통해 결정 장부의 마크다운 문법 정합성이 100% 보장됩니다.

**트레이드오프**

- 변경 이력 요약이 사용자 발언 컨텍스트 예산(`USER_RECORD_SHARE`)의 일부를 사용합니다.
- 토론이 시작되거나 동시 수정 충돌이 발생하면 작성 중이던 편집 내용이 취소될 수 있습니다.
