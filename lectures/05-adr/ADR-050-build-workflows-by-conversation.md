# ADR-050. 대화로 실행 그래프와 새 에이전트를 함께 설계하고, 쓰기 전에 모든 검사를 끝낸 뒤 한 번에 저장한다

> [ADR 목록](README.md) · 이전: [ADR-049](ADR-049-execution-grounded-diagnostician-and-stagnation-observer.md)

## 상태 (Status)

채택됨 · 2026-11-04 · 관련: [ADR-013](ADR-013-json-config.md), [ADR-021](ADR-021-graph-debate.md), [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-034](ADR-034-adaptive-graph-and-sub-debates.md)

## 맥락 (Context)

- 그래프 토론(ADR-021)은 병렬 분기, 합류, 판정 루프를 표현할 수 있지만, 비엔지니어 사용자가 캔버스에서 노드와 핀을 직접 잇는 일은 여전히 어렵습니다. 대화형 에이전트 빌더는 에이전트 **한 명**만 만들고, 적응형 그래프(ADR-034)는 턴마다 그래프를 그리되 **이미 있는 전문가만** 씁니다. "흐름을 말로 설명하면, 필요한 전문가까지 만들어 그래프로 저장한다"는 일은 어느 쪽으로도 할 수 없었습니다.
- 두 기능의 부품이 이미 있었습니다. 에이전트 빌더의 대화 루프(`BuilderChat.send`)와 설계도 역주입, 적응형 그래프의 노드·선 규격과 보정(`parse_draft`), 비용 상한 검사(`draft_report`), 편집기의 자동 배치(`auto_layout`)입니다. 새로 만들면 같은 규칙이 두 벌이 되어 서로 어긋납니다.
- 설계 검토에서 처음 초안의 결함이 드러났습니다.
  - **키 충돌**: 사전 검증이 `{**기존 풀, **새 에이전트}`로 합치면 겹치는 키가 가려집니다. 저장할 때 `agent_key_for`가 새 에이전트의 키를 `coder_2`로 바꾸는데 노드는 여전히 `coder`를 가리키므로, 검증을 통과한 뒤 **오류 없이 다른 에이전트가 발언**합니다.
  - **저장 잠금**: conf.json 을 막는 진짜 조건은 "어느 대화든 진행 중인가"입니다(에이전트 풀은 프로세스 전체가 하나). 초안은 이 대화의 `personas_locked`만 보았습니다.
  - **롤백**: 에이전트마다 `add_agent_to_conf_file`을 부르면 파일을 N번 다시 쓰고, 중간 실패 시 메모리 스냅샷으로 되돌리면 그 사이 다른 창이 고친 설정까지 지워집니다.
  - **편집기**: 편집 상태는 브라우저가 들고 '저장 안 됨'을 따로 셉니다. 창이 파일에 직접 쓰면 저장하지 않은 편집과 엇갈립니다.

## 결정 (Decision)

**대화로 워크플로 만들기를 추가합니다.** 도우미는 오케스트레이터의 연결 설정을 쓰는 도구 없는 사본이며, 답 끝에 ```` ```agents ````(새 에이전트 전체 목록)와 ```` ```graph ````(그래프 전체) 블록을 붙입니다. 코어는 `app/orchestration/workflow_builder.py`, 창은 `app/ui/components/graph_builder_dialog.py`입니다. 계층 규칙상 `app.agents`는 `app.orchestration`을 가져올 수 없으므로 코어는 orchestration 에 둡니다.

기존 부품을 재사용합니다:

- 그래프 규격 문장은 `graph_draft.GRAPH_FORMAT_GUIDE` 하나를 두 프롬프트가 함께 씁니다. `parse_draft`에서 "dict → GraphSpec" 부분을 `spec_from_draft`로 떼어 빌더도 같은 보정을 받습니다. 블록이 여럿인 답에서는 `parse_draft`의 탐욕 검색이 첫 `{`부터 마지막 `}`까지 잡으므로, 빌더는 펜스 블록을 먼저 잘라냅니다.
- 그래프 검사는 적응형 그래프와 같은 `draft_report`(검증 + 노드 12개·호출 40회 상한)입니다. 빌더는 여기에 새 에이전트 검사를 더합니다 — 이미 있는 키(꺼진 것과 `orchestrator` 포함)와 겹치면 **오류**입니다.
- 대화 흐름은 `BuilderChat.send`를 그대로 쓰고, 묻기·답 읽기를 훅(`user_entry`, `streaming_view`, `ask`, `take_reply`)으로 떼어 하위 클래스가 바꿉니다.
- 자동 배치는 `graph_canvas.auto_layout`을 고칩니다. 되돌림 선을 뺀 그래프에서 **최장 경로**로 열을 정해, 길이가 다른 갈래가 모이는 취합 노드가 긴 갈래 뒤에 놓입니다.

대화:

- 지금 설계도(`[지금 설계도]`)는 **가장 최근 사용자 말에만** 붙이고, 기록에는 블록 대신 한 줄을 남깁니다. 그래프와 여러 에이전트는 수 KB 라 턴마다 쌓으면 맥락 한도에 닿습니다.
- 이번 답이 만든 문제(읽지 못한 블록, 검사 오류)만 한 번 고쳐 받습니다. 사용자가 랙에서 고쳐 생긴 오류로는 다시 쓰게 하지 않습니다. 고쳐 받는 주고받기는 기록에 남기지 않습니다.
- 기존 에이전트의 설정 수정은 범위 밖입니다. 도우미는 로스터에서 고치도록 안내합니다.

저장 — **쓰기 전에 모든 검사를 끝냅니다** (`save_workflow`):

1. 새 에이전트가 있으면, 어느 대화든 진행 중일 때 거부합니다. 그래프만 저장할 때는 막지 않습니다(턴을 시작할 때 스냅샷으로 고정되므로).
2. 저장하는 지금 구성을 다시 읽어 최종 검사를 합니다. 대화하는 사이 같은 키가 생겼으면 새 키를 받고 **노드도 함께 바꿉니다**.
3. conf.json 에 새 에이전트를 **한 번에** 씁니다(`add_agents_to_conf_file`, 하나라도 틀리면 아무것도 쓰지 않음). 모델·API 키는 적지 않아 llm 기본 설정을 상속합니다.
4. 그래프를 내보냅니다. 그래프 쓰기가 실패해도 conf.json 은 되돌리지 않고, 에이전트는 등록되었다는 사실을 알립니다.

진입은 두 곳이며 결과를 내보내는 방식이 다릅니다:

- **대화 화면 로스터** — 새 그래프 파일(`ai-<날짜시간>`)로 저장하고 이 대화의 `graph_id`에 연결합니다. 전략은 바꾸지 않습니다(그래프 토론이면 실행 그래프, 적응형이면 기준 그래프). 이미 시작해 잠긴 대화는 첫 발언 때 고정한 구성으로 돌아 새 에이전트가 없으므로, 저장만 하고 연결하지 않습니다.
- **그래프 편집기** — 지금 캔버스(저장하지 않은 편집 포함)에서 시작하고, 결과는 캔버스에만 적용합니다. 파일은 편집기의 [저장]이 씁니다.

창의 미리보기는 읽기 전용입니다. 새 에이전트 노드는 점선 테두리로 구분합니다(`graph_canvas.js`만 고치므로 Vue Flow 번들은 다시 빌드하지 않습니다).

## 결과 (Consequences)

**좋아지는 점**

- 흐름을 말로 설명하면 그래프와 필요한 전문가가 함께 만들어지고, 만든 그래프는 사람이 그린 그래프와 똑같이 검증·동결·재개됩니다(ADR-021, ADR-024). 빌더는 실행 경로에 아무것도 더하지 않습니다.
- 그래프 규격, 보정, 비용 상한이 적응형 그래프와 한 벌이라, 한쪽을 고치면 다른 쪽도 따라옵니다.
- 키가 겹쳐 엉뚱한 에이전트가 발언하는 일, 쓰다 만 conf.json, 다른 창의 변경을 덮는 롤백이 구조적으로 생기지 않습니다.

**치르는 비용**

- 도우미 호출은 사용자 말 하나에 최대 2번(고쳐 받기 포함)입니다.
- 창 안에서는 노드를 옮기거나 속성을 고칠 수 없습니다. 속성 패널은 편집기 페이지 안의 지역 함수라, 세밀한 편집은 저장한 뒤 편집기에서 합니다.
- 그래프 저장이 실패하면 등록된 에이전트가 남습니다. 해는 없지만, 같은 설계도로 다시 저장하면 키가 겹쳐 새 키(`_2`)를 받습니다.
- 랙의 [빼기]로 뺀 키는 도우미에게 알리지만, 사용자가 다시 요청하면 도우미가 다시 만들 수 있습니다.
