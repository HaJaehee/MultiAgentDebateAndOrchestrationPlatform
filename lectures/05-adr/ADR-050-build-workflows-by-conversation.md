# ADR-050. 대화로 실행 그래프와 새 에이전트를 함께 설계하고, 쓰기 전에 모든 검사를 끝낸 뒤 한 번에 저장한다

> [ADR 목록](README.md) · 이전: [ADR-049](ADR-049-execution-grounded-diagnostician-and-stagnation-observer.md)

## 상태 (Status)

채택됨 · 2026-11-04 · 관련: [ADR-013](ADR-013-json-config.md), [ADR-021](ADR-021-graph-debate.md), [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-034](ADR-034-adaptive-graph-and-sub-debates.md)

## 맥락 (Context)

- 그래프 토론(ADR-021)은 병렬 분기, 합류, 판정 루프를 정밀하게 표현할 수 있지만, 일반 사용자가 캔버스에서 노드와 핀을 직접 연결하여 설계하는 데에는 여전히 진입 장벽이 높습니다. 대화형 에이전트 빌더는 에이전트 **한 명**만 생성할 수 있고, 적응형 그래프(ADR-034)는 턴마다 그래프를 동적으로 생성하되 **기존에 등록된 전문가만** 활용할 수 있습니다. "자연어로 업무 흐름을 설명하면 필요한 전문가까지 함께 정의하여 완성된 그래프로 저장한다"는 워크플로는 기존 기능만으로는 구현할 수 없었습니다.
- 이를 위한 기본 구성 부품들은 이미 존재하고 있었습니다. 에이전트 빌더의 대화 루프(`BuilderChat.send`)와 설계도 역주입 기법, 적응형 그래프의 노드·엣지 규격 및 자동 보정(`parse_draft`), 비용 상한 유효성 검사(`draft_report`), 그리고 그래프 편집기의 자동 레이아웃 알고리즘(`auto_layout`)이 그것입니다. 신규 기능을 완전히 새로 작성하면 동일한 규칙이 이중화되어 상호 불일치가 발생할 위험이 있었습니다.
- 초기 초안에 대한 설계 검토 과정에서 다음과 같은 결함이 확인되었습니다:
  - **키 충돌**: 사전 검증 시 `{**기존 풀, **새 에이전트}` 방식으로 병합하면 중복된 키가 가려집니다. 실제 저장 시점에 `agent_key_for`가 새 에이전트의 키를 `coder_2`로 변경하더라도 그래프 노드는 여전히 `coder`를 가리키므로, 유효성 검사를 통과한 뒤 **오류 없이 엉뚱한 에이전트가 발언하는 결함**이 발생합니다.
  - **저장 잠금**: `conf.json` 수정을 제한해야 하는 실질적 조건은 "어느 대화 세션이든 실행 중인가"입니다 (에이전트 풀 인스턴스는 프로세스 전역에서 단 하나만 존재하기 때문입니다). 초안에서는 현재 대화 세션의 `personas_locked` 여부만 검사하는 허점이 있었습니다.
  - **불완전한 롤백**: 에이전트마다 `add_agent_to_conf_file`을 반복 호출하면 파일을 N번 다시 쓰게 되며, 도중 실패 시 메모리 스냅샷으로 롤백하면 그 사이 다른 창에서 수정한 설정까지 유실됩니다.
  - **편집기 상태 불일치**: 그래프 편집기 화면의 편집 상태는 브라우저가 관리하며 미저장 변경 사항을 추적합니다. 대화창이 파일에 직접 기록해 버리면 사용자가 저장하지 않은 편집 내용과 충돌이 일어납니다.

## 결정 (Decision)

**대화형 워크플로 빌더를 도입합니다.** 도우미는 오케스트레이터의 LLM 설정을 활용하는 도구 없는 사본(`builder_agent`)이며, 응답 끝에 ```` ```agents ````(신규 에이전트 전체 목록)와 ```` ```graph ````(실행 그래프 전체 명세) 블록을 첨부합니다. 코어 로직은 `app/orchestration/workflow_builder.py`에, 대화창 UI는 `app/ui/components/graph_builder_dialog.py`에 구현합니다. 계층 규칙상 `app.agents`는 `app.orchestration`을 임포트할 수 없으므로 코어 모듈은 `orchestration` 패키지에 배치합니다.

기존 부품을 최대한 재사용하고 표준화합니다:

- 그래프 규격 안내 문구는 `graph_draft.GRAPH_FORMAT_GUIDE` 상수를 두 프롬프트가 공통으로 참조합니다. `parse_draft`에서 "dict → GraphSpec" 변환 로직을 `spec_from_draft`로 분리하여 빌더 역시 동일한 보정 규칙을 적용받도록 합니다. 여러 블록이 포함된 응답의 경우 `parse_draft`의 정규식이 첫 `{`부터 마지막 `}`까지 과도하게 매칭하므로, 빌더는 마크다운 펜스 블록을 사전에 정밀 분리합니다.
- 그래프 유효성 검사는 적응형 그래프와 동일한 `draft_report`(검증 + 노드 12개·호출 40회 상한)를 적용합니다. 빌더는 여기에 신규 에이전트 키 검증을 추가합니다 — 이미 존재하는 키(비활성화된 에이전트 및 `orchestrator` 포함)와 중복될 경우 **검증 오류**로 처리합니다.
- 대화 루프는 `BuilderChat.send`를 그대로 계승하되, 질의 및 응답 처리 로직을 훅 메서드(`user_entry`, `streaming_view`, `ask`, `take_reply`)로 분리하여 서브클래스에서 목적에 맞게 재정의할 수 있도록 합니다.
- 자동 레이아웃 알고리즘(`graph_canvas.auto_layout`)을 개선합니다. 역방향 선(되돌림 엣지)을 제외한 DAG 상에서 **최장 경로**를 기준으로 열을 계산하여, 길이가 서로 다른 병렬 갈래가 취합 노드(merge)로 합류할 때 취합 노드가 긴 갈래의 후속 위치에 자연스럽게 배치되도록 합니다.

대화 인터랙션 원칙:

- 현재 설계도(`[지금 설계도]`)는 **가장 최근 사용자 메시지에만** 첨부하며, 대화 기록에는 코드 블록 대신 한 줄 요약 안내 문구만 남깁니다. 그래프와 에이전트 명세는 용량이 수 KB에 달하므로 턴마다 누적하면 컨텍스트 한도에 빠르게 도달하기 때문입니다.
- 이번 응답으로 인해 발생한 오류(파싱 실패 블록, 유효성 검사 실패)에 대해서만 1회 자체 교정을 요청합니다. 사용자가 화면의 랙에서 직접 수정하여 발생한 오류에 대해서는 재작성을 유발하지 않습니다. 교정 과정의 왕복 메시지는 대화 이력에 남기지 않습니다.
- 기존 에이전트의 기본 설정 수정은 빌더의 작업 범위에서 제외합니다. 도우미는 에이전트 로스터 화면에서 직접 수정하도록 안내합니다.

저장 파이프라인 — **실제 쓰기 전에 모든 검증을 완료합니다** (`save_workflow`):

1. 새로 추가할 에이전트가 존재할 때, 현재 실행 중인 대화 세션이 하나라도 있다면 저장을 거부합니다. 그래프만 단독 저장할 경우에는 차단하지 않습니다 (턴 시작 시 스냅샷으로 고정되므로 안전합니다).
2. 저장 시점에 최신 시스템 구성을 다시 조회하여 최종 검증을 수행합니다. 대화 도중 동일한 키의 에이전트가 다른 곳에서 생성되었다면 새로운 대체 키를 발급받고 **그래프 노드의 참조 키도 함께 치환**합니다.
3. `conf.json`에 신규 에이전트들을 **한 번에 일괄 기록**합니다 (`add_agents_to_conf_file`, 전체 유효성 사전 검증 후 단 1회 기록). 모델 및 API 키는 지정하지 않아 기본 설정을 안전하게 상속받습니다.
4. 그래프 파일을 저장합니다. 그래프 파일 쓰기가 실패하더라도 `conf.json`의 변경 사항은 롤백하지 않으며, 에이전트 등록 사실과 그래프 저장 실패 원인을 사용자에게 투명하게 알립니다.

진입 경로는 두 곳이며 결과 반영 방식이 상이합니다:

- **대화 세션 화면 로스터** — 새 그래프 파일(`ai-<날짜시간>`)로 저장하고 현재 대화의 `graph_id`로 연결합니다. 실행 전략(strategy)은 임의로 변경하지 않습니다 (그래프 토론이면 실행 그래프, 적응형이면 기준 그래프로 연결). 이미 시작되어 잠긴 대화는 첫 발언 시 고정된 구성으로 진행되어 신규 에이전트가 반영되지 않으므로, 파일 저장만 수행하고 대화 연결은 건너뜁니다.
- **그래프 편집기** — 현재 캔버스 상태(저장되지 않은 편집 내용 포함)에서 시작하며, 결과는 캔버스에만 우선 반영합니다. 영구 파일 저장은 사용자가 편집기 상단의 [저장] 버튼을 눌러 명시적으로 수행합니다.

대화창의 미리보기 캔버스는 읽기 전용으로 제공됩니다. 아직 저장되지 않은 신규 에이전트 노드는 점선 테두리로 명확히 구분합니다 (`graph_canvas.js` 템플릿만 수정하여 추가 번들 빌드 없이 가볍게 동작합니다).

## 결과 (Consequences)

**긍정적 효과**

- 자연어로 요구 사항을 설명하는 것만으로 복합 그래프와 필요한 AI 전문가 에이전트가 동시에 생성되며, 생성된 그래프는 수동 설계된 그래프와 완전히 동일하게 검증·동결·재개 메커니즘을 지원합니다 (ADR-021, ADR-024). 빌더 로직은 실제 실행 런타임에 어떠한 부하도 주지 않습니다.
- 그래프 명세 규격, 보정 로직, 비용 상한 규칙이 적응형 그래프와 단일 소스로 통합 관리되므로, 향후 규격 변경 시 유지보수 정합성이 보장됩니다.
- 키 충돌로 인해 엉뚱한 에이전트가 발언하는 버그, 중간 실패로 불완전하게 기록된 `conf.json`, 그리고 다른 브라우저 세션의 변경 사항을 덮어쓰는 무분별한 롤백 문제가 구조적으로 방지됩니다.

**고려할 점 (트레이드오프)**

- 한 번의 사용자 발화당 도우미 호출이 최대 2회(자체 교정 포함) 발생할 수 있습니다.
- 대화창 내부에서는 노드 드래그 이동이나 상세 속성 편집이 제한됩니다. 속성 편집 패널은 편집기 페이지의 전용 UI이므로, 세밀한 파라미터 조정은 캔버스에 적용한 후 편집기에서 진행해야 합니다.
- 그래프 저장이 실패하더라도 이미 등록된 에이전트는 삭제되지 않습니다. 시스템에 장애를 유발하지는 않지만, 동일 설계도로 재저장할 경우 키 중복으로 인해 접미사(`_2`)가 붙을 수 있습니다.
- 에이전트 랙에서 [제거] 버튼으로 제외한 에이전트 키는 도우미 프롬프트에 배제 대상으로 전달되지만, 사용자가 대화로 다시 생성을 요구하면 도우미가 재생성할 수 있습니다.
