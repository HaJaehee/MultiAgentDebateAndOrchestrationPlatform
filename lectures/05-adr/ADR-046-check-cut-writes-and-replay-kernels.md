# ADR-046. 끊긴 쓰기는 디스크에서 확인하고, 커널 변수는 사람이 고를 때만 셀을 다시 실행해 되살린다

> [ADR 목록](README.md) · 이전: [ADR-045](ADR-045-claude-prompt-cache-markers.md)

## 상태 (Status)

채택됨 · 2026-11-01 (v1.5.1) · 관련: [ADR-014](ADR-014-tool-failure-is-observation.md), [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-025](ADR-025-resume-speeches-by-tool-step.md), [ADR-041](ADR-041-postgresql-compatibility.md), [ADR-043](ADR-043-code-diff-viewer.md), [ADR-044](ADR-044-runtime-queue-and-checkpoint-retention.md)

## 맥락 (Context)

[ADR-025](ADR-025-resume-speeches-by-tool-step.md)로 도구 단위 재개가 가능해졌지만, 서버 재시작으로 생기는 두 가지 틈이 남아 있었습니다.

- **실행 중이던 쓰기 호출의 결과를 모릅니다.** 모델은 `[결과 모름]`만 받습니다. `append_workspace_file`은 다시 부르면 같은 조각이 두 번 들어가고, `write_file`은 이미 끝났어도 다시 쓰느라 토큰을 씁니다. MCP 도구에는 멱등 키가 없어 서버에 물어볼 수도 없습니다.
- **커널 변수가 사라지는데 모델은 모릅니다.** 초안의 대화에는 변수를 만든 기록이 그대로 있어, 모델은 있다고 믿고 코드를 씁니다. 재개 안내에도 그 사실이 없어서 `NameError`를 보고서야 알게 됩니다.

해결책으로 "파일 쓰기 전후의 SHA-256을 기록하고, 성공한 셀을 턴 메타데이터에 적어 재개할 때 자동으로 다시 실행하거나 초기화를 고르게 하자"는 제안이 들어왔습니다. 방향은 맞지만 코드를 대조하니 세 가지를 바꿔야 했습니다.

- **셀 목록을 새로 적을 필요가 없습니다.** 도구 호출은 이미 실행 즉시 `tool_calls`에 인자와 결과까지 기록됩니다([ADR-024](ADR-024-resume-interrupted-turns.md)). 메타데이터에 또 적으면 같은 사실의 사본이 둘이 되어 어긋날 수 있습니다.
- **자동 재실행은 지금까지의 원칙과 충돌합니다.** "사람 없이 LLM 비용과 도구 실행이 시작되면 안 된다"([ADR-024](ADR-024-resume-interrupted-turns.md))가 재개의 전제입니다. 게다가 옛 셀에는 파일을 쓰는 코드가 들어 있을 수 있어, 다시 돌리면 **그 뒤에 고친 파일이 옛 내용으로 돌아갑니다.** 변수를 되살리려다 작업물을 잃는 것은 복구가 아니라 새 사고입니다.
- **"초기화"는 고를 필요가 없습니다.** 서버가 재시작되면 커널은 이미 비어 있습니다. 비우기만 하는 선택지는 하는 일이 없습니다. 의미 있는 선택은 "그대로 이어 가기"와 "다시 실행하고 이어 가기"입니다.

## 결정 (Decision)

### 1. 쓰기 도구를 부르기 직전에 해시를 초안에 남기고, 이어 갈 때 비교한다

보안 판정을 통과한 쓰기 호출은 실행 직전에 대상 파일의 SHA-256과 **호출이 성공하면 되어야 할 내용의 SHA-256**을 초안에 남깁니다(`open_writes`, `app/agents/write_probe.py`). 사람의 승인을 기다리는 동안 파일이 바뀔 수 있고 거부된 호출의 경로는 읽을 이유가 없으므로, 판정 뒤에 읽습니다.

이어 갈 때 지금 파일과 비교해, `[결과 모름]` 대신 다음 중 하나를 그 호출의 도구 결과로 넣습니다.

| 지금 파일 | 도구 결과 |
| :--- | :--- |
| 쓰려던 내용과 같음 | 이미 반영되었으니 되풀이하지 말 것 |
| 호출 전과 같음 | 반영되지 않았으니 필요하면 다시 부를 것 |
| 둘 다 아님 | 일부만 쓰였거나 다른 쪽이 고쳤으니 읽어서 확인할 것 |
| 호출 전과 다름 (`edit_file`처럼 결과를 미리 모르는 호출) | 바뀐 것은 맞으니 읽어서 확인할 것 |

`append_workspace_file`의 기대 해시는 호출 전 내용 뒤에 조각을 이은 값입니다. 파일 끝을 다시 읽지 않아도 해시 객체를 이어서 구할 수 있습니다.

호출이 끝나면 그 뒤의 해시도 남겨(`known_files`), 이어 갈 때 이 발언이 마지막으로 쓴 뒤 달라진 파일을 재개 안내에 적습니다. 끊긴 사이 사람이 고쳤거나 다른 에이전트가 덮어쓴 파일을 모델이 기억대로 믿지 않게 합니다.

다음은 확인하지 않고 예전처럼 `[결과 모름]`으로 둡니다.

- 인자 모양을 모르는 도구. 다루는 것은 `write_file`, `write_workspace_file`, `append_workspace_file`, `edit_file`뿐입니다.
- 원격 서버의 경로(이 PC의 파일이 아닙니다), 신뢰하지 않는 서버, 작업 공간 밖의 경로(모델이 정한 경로를 앱 권한으로 읽게 됩니다).
- 일반 파일이 아니거나 256MB를 넘는 파일. 장치 파일이나 파이프를 열면 끝나지 않습니다.

알리기만 하고 막지는 않습니다. 모델이 다시 부를 이유가 있을 수 있고, 판단은 관측을 읽는 쪽의 몫입니다([ADR-014](ADR-014-tool-failure-is-observation.md)).

### 2. 다시 실행할 셀은 도구 기록에서 고른다

`turns.kernel_cells`가 그 턴의 `tool_calls`에서 고릅니다. 저장 형식은 바뀌지 않습니다.

- `execute_python_code`, `run_python_file` 중 **끝까지 실행된 것만** 고릅니다. 서버는 코드가 실패해도 도구 호출은 성공으로 돌려주므로, 결과 첫 줄의 `execution_status: RAN_`을 봅니다.
- 커널이 비워진 뒤의 것만 남깁니다. `reset_kernel_state`가 성공했거나, 시간 초과로 커널이 다시 뜬 호출이 경계입니다.
- 네임스페이스별로 묶습니다. 커널은 대화와 에이전트마다 따로입니다.
- 앞서 다시 실행한 기록은 뺍니다. 다시 끊겨도 같은 셀을 두 번 세지 않습니다.

### 3. 재실행은 별도 버튼으로만 일어난다

끊긴 턴 안내 줄의 **이어서 진행**은 코드를 돌리지 않습니다. 셀이 있으면 **셀 재실행 후 이어서** 버튼(`mode="replay"`)이 함께 보입니다. 재개 방식을 값 하나로 더했으므로 세 화면(전문가·쉬운·체험)과 러너는 그대로 넘기기만 합니다.

재실행 자체는 다음을 지킵니다(`app/orchestration/kernel_replay.py`).

- **지금의 보안 설정을 받습니다.** 셀마다 도구 보안 판정을 거칩니다. 끊긴 사이 조인 규칙을 옛 기록으로 건너뛰지 않습니다([ADR-024](ADR-024-resume-interrupted-turns.md)). 막힌 호출도 감사 기록에 남습니다.
- **비우고 시작합니다.** 엔진 오류로 멈춘 턴은 커널이 살아 있을 수 있어, 그대로 돌리면 코드가 두 번 쌓입니다.
- **첫 실패에서 멈춥니다.** 뒤의 셀은 대개 앞의 셀에 기댑니다. 정지 요청도 셀 사이에서 받습니다.
- **연결을 쥐고 있지 않습니다.** 셀은 몇 분씩 걸릴 수 있어 읽은 트랜잭션을 닫고 시작합니다([ADR-041](ADR-041-postgresql-compatibility.md)).

### 4. 재실행이 바꾼 파일은 재실행 전으로 돌린다

재실행 직전에 작업 공간 스냅샷을 찍고, 끝나면 그 사이 바뀐 파일을 되돌립니다(`workspace_checkpoint.snapshot`, `revert`, [ADR-043](ADR-043-code-diff-viewer.md)). 스냅샷을 찍지 못하거나 같은 작업 공간에서 다른 턴이 도는 중이면 **실행하지 않습니다.** 그 턴이 그사이 쓴 파일까지 함께 되돌리게 되기 때문입니다.

검토 대안: 파일을 쓰는 셀을 코드 검사로 골라 건너뛰기 → 기각. 그 셀이 만든 변수가 뒤의 셀에 필요하고, `exec_scan`은 보안 경계도 정밀 분석기도 아니어서 놓치는 코드가 남습니다.

### 5. 모델과 사람에게 어디까지 되살렸는지 알린다

- 초안에서 이어 가는 발언의 재개 안내에 커널 상태를 적습니다. `continue`로 이어 간 재시작 턴은 변수가 사라졌다고, `replay`는 몇 개까지 되살렸고 어디서 왜 멈췄는지 적습니다. 엔진 오류로 멈춘 턴을 `continue`로 이으면 커널이 살아 있으므로 적지 않습니다.
- `replay`는 피드에 안내(`KIND_KERNEL_REPLAY`)를 남기고, 다시 실행한 도구 기록을 거기에 잇습니다. 무슨 코드를 돌렸고 무슨 파일을 되돌렸는지 사람이 봅니다. 다른 에이전트의 맥락에도 들어갑니다.

초안 형식이 바뀌므로 `SPEECH_STATE_VERSION`을 3으로 올립니다. 이전 형식의 초안은 발언을 처음부터 합니다.

## 결과 (Consequences)

**이점**

- 덧붙이기 호출이 끊겨도 같은 조각을 두 번 넣지 않습니다. 실제 샌드박스에서 `append_workspace_file` 직후 프로세스를 강제 종료하고 다시 띄웠을 때, 모델은 "이미 반영됨"을 받았고 파일은 한 번만 쓰인 채였습니다.
- 재개한 모델이 커널 상태를 처음부터 압니다. 같은 실험에서 `replay` 뒤 끊기기 전의 변수로 계산이 성공했고, 재실행이 덮어쓴 파일은 사람이 고친 내용으로 돌아갔습니다. `continue`는 `NameError`가 났습니다(이전과 같은 동작이며, 이제 재개 안내가 미리 알립니다).
- DB 스키마와 저장 형식을 늘리지 않습니다. 셀은 이미 있는 도구 기록에서 고릅니다.

**비용과 한계**

- 쓰기 호출마다 해시 계산과 초안 저장이 한 번씩 늘어납니다.
- **되살린 상태는 근사치입니다.** 난수·시각·외부 상태에 달린 값은 달라질 수 있고, 실패한 셀이 도중까지 만든 변수는 없습니다. `run_python_file`은 파일의 지금 내용을 실행합니다.
- **이번 턴의 셀만 다시 실행합니다.** 이전 턴에서 만든 변수에 기대는 셀은 실패하고 거기서 멈춥니다. 대화 전체를 다시 돌리면 비용과 부작용이 커지고, 그사이 커널이 몇 번 다시 떴는지도 기록에 없습니다.
- **작업 공간 밖으로 나간 일은 되돌릴 수 없습니다.** 네트워크 호출, 작업 공간 밖 파일, `.gitignore`에 든 파일, 스냅샷 제외 폴더가 그렇습니다. 검사에 걸린 코드는 처음 실행 때처럼 승인 카드를 띄웁니다. `auto` 모드는 묻지 않습니다.
- **재실행 도중 서버가 또 내려가면 파일이 되돌려지지 않습니다.** 다음 재개에서 자동으로 되돌리지 않는 이유는, 그사이 사람이 고친 파일까지 함께 되돌릴 수 있기 때문입니다. 변경 내역 화면에서 확인할 수 있습니다.
- 재실행이 도는 동안 사람이 작업 공간 파일을 고치면 그 변경도 되돌려집니다.
- 쓰기 확인은 앱이 경로를 푸는 방식(`policy.resolve_path`)이 서버와 같다는 전제입니다. 다르면 "반영 안 됨"으로 잘못 알려, 덧붙이기가 되풀이될 수 있습니다. 보안 판정도 같은 풀이를 쓰므로, 그런 서버는 이미 판정 대상이 틀린 상태입니다.
- 슬롯 양보([ADR-044](ADR-044-runtime-queue-and-checkpoint-retention.md))로 사라진 변수는 되살리지 않습니다. 턴이 끊긴 것이 아니라 도는 중이므로 물어볼 자리가 없습니다.

**구현하며 드러난 것**

- 샌드박스는 네임스페이스에서 영숫자와 `_`, `-`만 남기고 40자로 자르는데 대화 id가 36자라, 에이전트 키는 앞 세 글자만 남았습니다. `critic`과 `critic2`가 같은 커널을 썼고, 한글 키는 통째로 지워져 그 대화의 발언자가 한 커널에 모였습니다. 그대로 두면 뒤의 에이전트가 커널을 비울 때 앞의 복원까지 지웁니다. 그래서 `compose_scope`가 제한 안에 드는 이름을 만들도록 함께 고쳤습니다. 들어가지 않는 값은 대화 id 앞 27자와 해시 12자로 줄입니다. 커널은 저장되지 않으므로 이름이 바뀌어도 잃는 것이 없고, 지식 그래프의 스코프는 그대로입니다.
- 에이전트 설정은 대화에 고정되므로(`frozen_agents`), `conf.json`에서 에이전트의 서버 권한을 빼도 그 대화의 재실행은 일반 발언과 똑같이 고정된 값을 봅니다. 재실행만 다르게 보면 안 되므로 맞췄고, 시험도 고정된 값을 바꾸는 쪽으로 고쳤습니다.
