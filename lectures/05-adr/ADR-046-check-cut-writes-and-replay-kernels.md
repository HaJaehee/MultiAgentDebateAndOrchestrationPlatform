# ADR-046. 비정상 중단된 파일 쓰기 작업의 디스크 반영 여부를 검증하고 사용자 승인 시에만 커널 코드 셀을 선별 재실행한다

> [ADR 목록](README.md) · 이전: [ADR-045](ADR-045-claude-prompt-cache-markers.md)

## 상태 (Status)

채택됨 · 2026-11-01 · 관련: [ADR-014](ADR-014-tool-failure-is-observation.md), [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-025](ADR-025-resume-speeches-by-tool-step.md), [ADR-041](ADR-041-postgresql-compatibility.md), [ADR-043](ADR-043-code-diff-viewer.md), [ADR-044](ADR-044-runtime-queue-and-checkpoint-retention.md)

## 맥락 (Context)

[ADR-025](ADR-025-resume-speeches-by-tool-step.md)를 통해 도구 단위의 턴 재개 메커니즘을 구축했으나, 서버 비정상 종료(재시작) 시 두 가지 문제점이 여전히 존재했습니다.

- **실행 중이던 파일 쓰기 호출의 실제 디스크 반영 여부를 확인할 수 없습니다.** LLM 모델은 도구 결과로 `[결과 모름]`(Unknown Result)만을 전달받습니다. 이로 인해 `append_workspace_file`을 재호출할 경우 동일한 내용이 중복 추가되고, `write_file`이 이미 완료되었음에도 불필요하게 재작성하느라 토큰이 낭비됩니다. MCP 도구 프로토콜에는 멱등성 키(Idempotency Key)가 없어 서버에 직접 질의할 수도 없습니다.
- **샌드박스 커널 메모리의 변수가 소멸하지만 모델은 이를 인지하지 못합니다.** 초안 메시지 기록에는 변수를 정의한 코드가 정상 실행된 것으로 남아 있어, 모델은 해당 변수가 존재한다고 가정하고 후속 코드를 작성합니다. 재개 안내문에도 변수 소멸 사실이 명시되지 않아, 결국 런타임 `NameError`가 발생한 후에야 실패를 인지하게 됩니다.

이를 해결하기 위해 "파일 쓰기 전후의 SHA-256 해시를 기록하고, 성공한 코드 셀을 턴 메타데이터에 기록하여 재개 시 자동 재실행하거나 초기화 여부를 선택하도록 하자"는 제안이 있었습니다. 기본 방향성은 타당하나, 기존 아키텍처 원칙과의 정합성을 검토한 결과 다음 세 가지 수정이 필요했습니다.

- **코드 셀 목록을 별도로 중복 저장할 필요가 없습니다.** 도구 호출 이력은 이미 실행 즉시 `tool_calls`에 인자 및 결과와 함께 영속화됩니다([ADR-024](ADR-024-resume-interrupted-turns.md)). 메타데이터에 별도로 중복 기록할 경우 동일한 사실에 대한 데이터 불일치가 발생할 위험이 있습니다.
- **자동 재실행은 핵심 설계 원칙과 정면으로 충돌합니다.** "인간 사용자의 명시적 개입 없이 백그라운드에서 임의로 LLM 비용 및 도구 실행을 유발해서는 안 된다"([ADR-024](ADR-024-resume-interrupted-turns.md))는 원칙이 세션 복구의 전제 조건입니다. 더욱이 과거 실행된 코드 셀에 파일 쓰기 로직이 포함되어 있다면, 이를 무조건 재실행할 경우 **그 이후 시점에 수정된 최신 작업 공간 파일이 과거 내용으로 덮어써져 롤백되는 부작용**이 발생합니다. 메모리 변수를 복구하려다 실제 작업 결과물을 유실하는 것은 복구가 아니라 새로운 결함입니다.
- **"초기화" 옵션은 무의미합니다.** 서버가 재시작되면 인메모리 커널은 이미 완전히 비어 있는 초기화 상태입니다. 따라서 실질적으로 유효한 선택지는 "커널 재실행 없이 그대로 이어가기"와 "코드 셀 선별 재실행 후 이어가기"의 두 가지뿐입니다.

## 결정 (Decision)

### 1. 쓰기 도구 실행 직전 파일 해시를 초안에 기록하고 세션 재개 시 검증

보안 정책 판정을 통과한 파일 쓰기 도구 호출은 실행 직전에 대상 파일의 기존 SHA-256과 **호출 성공 시 예상되는 파일 내용의 SHA-256**을 발언 초안(`open_writes`, `app/agents/write_probe.py`)에 기록합니다. 사용자의 승인을 대기하는 동안 파일이 변경될 수 있으며, 거부된 호출의 경로는 파일 검증 대상이 아니므로 정책 판정 완료 직후에 해시를 산출합니다.

세션 재개 시 현재 디스크 상의 파일과 비교하여, 일률적인 `[결과 모름]` 대신 상황에 따라 다음 중 하나의 관찰 결과를 도구 반환값으로 전달합니다.

| 현재 디스크 파일 상태 | 모델에 전달되는 도구 실행 결과 안내 |
| :--- | :--- |
| 예상된 수정 내용과 일치함 | 이미 디스크에 정상 반영되었으므로 동일 쓰기 작업을 반복하지 말 것 |
| 호출 전 파일 상태와 일치함 | 디스크에 반영되지 않았으므로 필요 시 쓰기 도구를 재호출할 것 |
| 둘 다 일치하지 않음 | 쓰기 작업이 부분 반영되었거나 타 프로세스에 의해 변경되었으므로 파일 재조회 후 판단할 것 |
| 호출 전과 다름 (`edit_file` 등 사전 결과 예측이 불가능한 호출) | 파일 내용이 변경되었음은 확인되었으므로 파일 재조회 후 후속 작업을 진행할 것 |

`append_workspace_file`의 예상 해시는 호출 전 원본 데이터 뒤에 추가할 바이트 스트림을 연결하여 산출합니다. 파일 끝을 다시 읽지 않고도 해시 객체의 업데이트(`update`)를 통해 효율적으로 계산할 수 있습니다.

호출 완료 후 최종 해시 역시 기록(`known_files`)하여, 세션 재개 시 해당 발언이 마지막으로 쓰기를 완료한 이후 외부에서 변경된 파일 목록을 재개 안내문에 명시합니다. 세션이 중단된 동안 사용자가 직접 수정했거나 타 에이전트가 덮어쓴 파일을 모델이 과거 메모리 정보에 의존하여 오판하지 않도록 방지합니다.

다음 대상은 디스크 검증을 생략하고 기존과 동일하게 `[결과 모름]`으로 처리합니다.

- 파라미터 규격을 인식할 수 없는 도구. 검증 대상은 `write_file`, `write_workspace_file`, `append_workspace_file`, `edit_file`의 4종으로 한정합니다.
- 원격 서버 경로(로컬 호스트 디스크 파일이 아님), 비신뢰 서버, 작업 공간 외부 경로(LLM이 지정한 임의 경로를 애플리케이션 권한으로 읽게 되는 보안 위험 방지).
- 일반 파일이 아니거나 256MB를 초과하는 대용량 파일 (디바이스 파일 또는 명명된 파이프(FIFO) 참조 시 프로세스 블로킹 위험 방지).

상태를 사실대로 안내할 뿐 실행 자체를 강제 차단하지는 않습니다. 모델이 재호출을 판단할 정당한 맥락이 있을 수 있으며, 판단은 관찰 결과를 수신하는 주체의 몫입니다([ADR-014](ADR-014-tool-failure-is-observation.md)).

### 2. 재실행 대상 코드 셀의 선별 기준 수립

`turns.kernel_cells`가 해당 턴의 `tool_calls` 영속화 이력에서 재실행 대상 셀을 선별합니다. 기존 데이터베이스 스키마 및 저장 형식은 그대로 유지됩니다.

- `execute_python_code`, `run_python_file` 중 **정상 완료된 호출만** 선별합니다. 샌드박스 서버는 코드 실행 중 예외가 발생하더라도 도구 호출 자체는 성공 응답을 반환하므로, 도구 결과 페이로드 첫 줄의 `execution_status: RAN_` 접두사를 확인하여 판단합니다.
- 커널이 초기화된 이후의 코드 셀만 포함합니다. `reset_kernel_state`가 성공했거나 실행 시간 초과로 커널이 자동 재생성된 호출 지점이 경계선이 됩니다.
- 네임스페이스(스코프) 단위로 분리 그룹화합니다. 커널 인스턴스는 세션 및 에이전트별로 엄격히 격리됩니다.
- 이전에 재실행된 이력 셀은 중복 선별에서 제외합니다. 재개 도중 다시 중단되더라도 동일 셀이 중복 누적되지 않습니다.

### 3. 사용자 명시적 승인 버튼을 통한 재실행 제어

중단된 턴 안내 배너의 **이어서 진행** 버튼은 코드를 재실행하지 않고 대화 흐름만 복원합니다. 복구 가능한 코드 셀이 존재하는 경우에 한해 **셀 재실행 후 이어서** 버튼(`mode="replay"`)이 함께 노출됩니다. 재개 모드를 단일 파라미터로 확장했으므로 3개 UI 뷰(전문가 모드, 비엔지니어 모드, 간이 체험 모드) 및 백그라운드 러너는 해당 파라미터를 그대로 투과 전달합니다.

코드 셀 재실행 시 준수하는 핵심 불변식(`app/orchestration/kernel_replay.py`):

- **현재의 보안 정책을 엄격히 적용합니다.** 셀 단위로 최신 도구 보안 판정을 거치며, 중단 시점의 이전 승인 기록을 근거로 보안 검사를 우회하지 않습니다([ADR-024](ADR-024-resume-interrupted-turns.md)). 차단된 호출 역시 감사 로그에 기록됩니다.
- **커널 인스턴스를 초기화한 후 실행합니다.** 런타임 예외로 중단된 턴의 경우 커널 프로세스가 살아있을 수 있으므로, 기존 상태 위에 덧씌워 실행할 경우 변수 상태가 왜곡되는 문제를 방지합니다.
- **최초 실행 실패 시 즉시 중단합니다.** 후속 셀은 대부분 이전 셀이 정의한 변수에 의존하므로, 선행 셀 실패 시 후속 실행을 중단합니다. 사용자 정지 요청 역시 각 셀 실행 사이에서 즉시 감지하여 중단합니다.
- **데이터베이스 트랜잭션을 점유하지 않습니다.** 코드 셀 실행은 수 분 이상 소요될 수 있으므로, 세션 조회 트랜잭션을 신속히 커밋 및 종료한 후 실행합니다([ADR-041](ADR-041-postgresql-compatibility.md)).

### 4. 재실행에 의한 파일 변경 사항의 롤백 격리

재실행 직전에 작업 공간 체크포인트 스냅샷을 생성하고, 재실행 완료 즉시 그사이 변경된 작업 공간 파일을 스냅샷 시점 상태로 자동 롤백합니다(`workspace_checkpoint.snapshot`, `revert`, [ADR-043](ADR-043-code-diff-viewer.md)). 스냅샷 생성이 불가능하거나 동일 작업 공간에서 타 대화 세션의 턴이 실행 중인 경우에는 **재실행을 안전하게 거부**합니다. 타 턴이 작업 중인 파일까지 함께 롤백되는 데이터 손상을 방지하기 위함입니다.

검토 대안: 정적 코드 분석을 통해 파일 쓰기 로직이 포함된 셀만 선별 제외하는 방안 → 기각. 해당 셀이 생성한 변수가 후속 셀에서 필수적일 수 있으며, `exec_scan`은 보안 경계용 휴리스틱일 뿐 완전한 의미 분석기가 아니므로 우회 가능성이 상존합니다.

### 5. 커널 복구 범위 및 상태의 투명한 공시

- 초안을 기반으로 재개되는 발언의 프롬프트 안내문에 커널 복구 상태를 명시합니다. `continue` 모드로 재개된 세션에는 커널 변수가 소멸되었음을 고지하고, `replay` 모드에서는 몇 개의 셀이 복구되었으며 어디서 어떤 원인으로 중단되었는지를 명시합니다. 런타임 오류로 중단되어 커널이 보존된 세션을 `continue` 모드로 재개할 경우에는 커널이 살아있으므로 경고문을 생략합니다.
- `replay` 실행 시 피드에 시스템 이벤트 카드(`KIND_KERNEL_REPLAY`)를 게시하고, 재실행된 도구 호출 이력을 연결합니다. 사용자는 어떤 코드가 재실행되었고 어떤 파일이 원상 복구되었는지 투명하게 열람할 수 있으며, 이는 타 에이전트의 컨텍스트에도 정상적으로 반영됩니다.

초안 데이터 구조 확장에 따라 `SPEECH_STATE_VERSION`을 3으로 상향 조정합니다. 이전 버전 포맷의 미완료 초안은 안전을 위해 발언을 최초 단계부터 다시 시작합니다.

## 결과 (Consequences)

**도입 이점**

- 파일 내용 추가(`append_workspace_file`) 도중 중단되더라도 동일 텍스트 조각이 중복 추가되지 않습니다. 실제 샌드박스 환경에서 파일 덧붙이기 직후 프로세스를 강제 종료하고 재시작한 검증 결과, 모델은 "이미 반영됨" 상태를 정상 인지하였으며 파일 중복 쓰기가 발생하지 않았습니다.
- 세션을 재개한 LLM이 커널 변수 상태를 사전에 명확히 인지합니다. 동일 실험 환경에서 `replay` 모드 수행 시 중단 이전의 메모리 변수를 기반으로 후속 계산이 정상 완료되었으며, 코드 재실행 중 덮어써진 파일은 사용자가 직전에 수정한 최신 파일 내용으로 안전하게 복원되었습니다. `continue` 모드의 경우 기대대로 `NameError`가 발생하였으나, 사전 고지를 통해 원인을 모델이 즉시 파악할 수 있었습니다.
- 데이터베이스 스키마 확장 없이 기존 `tool_calls` 영속화 데이터만을 활용하여 복구 대상을 선별합니다.

**고려 사항 및 기술적 한계**

- 파일 쓰기 도구 호출 시마다 SHA-256 해시 연산 및 초안 영속화 오버헤드가 발생합니다.
- **복원된 커널 변수 상태는 근사치(Approximation)입니다.** 난수 생성, 타임스탬프, 외부 환경 상태에 의존적인 변수 값은 이전과 달라질 수 있으며, 도중 실패한 코드 셀이 생성하려 했던 변수는 복구되지 않습니다. `run_python_file`은 해당 스크립트 파일의 현재 디스크 내용을 기준으로 실행됩니다.
- **현재 턴에서 실행된 코드 셀만 재실행합니다.** 이전 턴에서 선언된 전역 변수에 의존하는 셀은 실패할 수 있으며 해당 지점에서 중단됩니다. 세션 전체의 모든 과거 셀을 재실행하는 것은 비용과 부작용이 지나치게 크며, 과거 라운드 동안 커널이 재시작된 정확한 시점 이력이 보존되지 않기 때문입니다.
- **작업 공간 외부의 부수 효과는 롤백할 수 없습니다.** 외부 네트워크 호출, 작업 공간 외부 파일 조작, `.gitignore` 등록 파일, 스냅샷 제외 디렉터리 내 변경 사항은 원상 복구되지 않습니다. 보안 검사에 지정된 도구는 최초 실행 시와 동일하게 사용자 승인 카드를 호출합니다(`auto` 모드에서는 자동 승인).
- **재실행 도중 서버가 다시 비정상 종료되면 파일 롤백이 누락될 수 있습니다.** 다음 세션 재개 시 자동 롤백을 수행하지 않는 이유는, 중단된 공백 기간 동안 사용자가 직접 수정한 작업 내용까지 함께 손실될 위험이 있기 때문입니다. 파일 변경 사항은 작업 공간 변경 내역(Diff) 뷰를 통해 확인 및 수동 조치할 수 있습니다.
- 재실행이 진행 중인 짧은 시간 동안 사용자가 작업 공간 파일을 수정할 경우 해당 수정 사항도 함께 스냅샷 시점으로 롤백될 수 있습니다.
- 디스크 쓰기 검증은 호스트 애플리케이션의 경로 해석 방식(`policy.resolve_path`)이 대상 샌드박스 서버와 완전히 일치한다는 전제에 기반합니다. 경로 해석이 불일치할 경우 "미반영"으로 오판하여 중복 쓰기가 유발될 수 있습니다. 다만 도구 보안 판정 역시 동일한 경로 해석기를 공유하므로, 이러한 서버는 이미 보안 정책 적용 단계에서 비정상으로 분류됩니다.
- 런타임 슬롯 양보([ADR-044](ADR-044-runtime-queue-and-checkpoint-retention.md))로 인해 초기화된 커널 변수는 복구 대상이 아닙니다. 비정상 중단이 아닌 정상 턴 실행 흐름 중 발생한 양보이므로 사용자 승인을 질의할 인터페이스가 존재하지 않습니다.

**구현 과정에서 도출된 추가 개선 사항**

- 내장 샌드박스 서버는 네임스페이스 문자열에서 영숫자와 `_`, `-`만 유지하고 40자로 자르는데, 세션 UUID가 이미 36자를 차지하여 에이전트 키는 앞 세 글자만 남는 결함이 발견되었습니다. 이로 인해 `critic`과 `critic2`가 동일한 커널 인스턴스를 공유하고 한글 키 에이전트는 키 문자열이 전량 제거되어 세션 내 모든 에이전트가 단일 커널로 수렴하는 문제가 있었습니다. 이는 후속 에이전트가 커널 초기화를 호출할 때 선행 에이전트의 변수 상태까지 일괄 소멸시키는 원인이 되었습니다. 이에 `compose_scope`가 최대 길이 제한을 준수하도록 세션 ID 앞 27자리와 해시 12자리의 결합 구조로 스코프 생성 규칙을 개선하였습니다. 커널 변수는 디스크에 영속화되지 않으므로 네임스페이스 규칙 변경에 따른 데이터 유실이 없으며 지식 그래프 격리 스코프는 온전히 유지됩니다.
- 에이전트 설정 스냅샷은 세션 시작 시점에 영속화(`frozen_agents`)되므로, 이후 `conf.json`에서 특정 에이전트의 MCP 서버 권한을 회수하더라도 해당 대화 세션의 재실행은 일반 발언과 동일하게 고정된 스냅샷 설정을 참조하도록 일관성을 유지하였습니다.
