# ADR-037. 사용자 입력을 대기하는 상태를 전역 알림으로 브로드캐스트하고 실행 런타임에서 최신 상태를 동기화한다

> [ADR 목록](README.md) · 이전: [ADR-036](ADR-036-retry-one-speech-and-inline-comments.md)

## 상태 (Status)

채택됨 · 2026-10-31 · 관련: [ADR-028](ADR-028-plan-approval-gate.md)

## 맥락 (Context)

- 계획 승인, 도구 실행 승인, 에이전트 질문 응답, 컨텍스트 한도 알림 등 사용자의 즉각적인 개입이 필요한 요청은 해당 대화 세션의 타임라인 내에만 표시되며, 3~10분의 타임아웃 제한이 있습니다. 사용자가 브라우저의 다른 탭이나 다른 대화 세션을 보고 있을 경우 승인 카드가 열린 사실을 인지하지 못해 타임아웃으로 턴이 중단되는 문제가 빈번했습니다.
- UI 세션의 실시간 이벤트 구독(`RunBinding`)은 현재 활성화된 단일 대화에만 바인딩되어 있으므로 타 세션의 대기 이벤트가 현재 탭으로 전달되지 않았습니다.
- 브라우저 데스크톱 알림(Web Notification)은 보안 컨텍스트(HTTPS 또는 localhost)에서만 동작합니다. 사내 폐쇄망이나 원격 평문 HTTP 환경에서는 해당 브라우저 API 호출이 차단됩니다.
- 체험 및 초급자 화면의 게스트 사용자 역시 동일한 서버에서 작업을 수행하므로, 게스트 세션의 승인 대기 상태가 메인 관리자의 브라우저에 알림으로 노출되는 노이즈를 방지해야 했습니다.

## 결정 (Decision)

### 1. 전역 이벤트 버스 채널에는 최소한의 세션 변경 신호만 브로드캐스트한다

`TurnRun.publish`는 승인 대기 상태가 변경될 수 있는 핵심 이벤트(`WAITING_EVENTS`) 발생 시 `WAITING_CHANNEL`로 해당 `session_id`만을 전송합니다. 각 브라우저 탭의 `WaitingWatcher`는 신호를 수신할 때 `DebateRunner.waiting_by_session()`을 재조회하여 정확한 대기 상태 목록을 동기화합니다. 이벤트를 큐에 쌓아 증분으로 처리하지 않고 런타임의 정본(Source of Truth)을 매번 직접 조회하므로, 네트워크 지연이나 메시지 유실이 발생하더라도 항상 최신의 대기 상태를 정확히 유지할 수 있습니다.

### 2. 승인 대기 상태의 정본은 `TurnRun`의 활성 요청 카드 목록이다

`waiting_requests()`는 현재 런타임에 활성화된 카드 목록에서 직접 산출합니다. 정상 종료되거나 취소된 실행은 빈 목록으로 처리됩니다. 운영체제 데스크톱 알림으로 전송되는 페이로드의 보안을 위해 `WaitingRequest` 객체에는 도구 인자의 세부 값이나 질문 본문을 포함하지 않고, 대화 세션 제목, 발언 에이전트 이름, 대상 도구 이름까지만 포함합니다.

### 3. 상황에 따른 3단계 알림 채널 제공

| 알림 경로 | 동작 조건 | 설명 |
| :--- | :--- | :--- |
| 브라우저 탭 제목 `(N) 승인 대기 — MADO` | 상시 | 모든 대화 세션의 대기 요청 총합을 탭 제목에 실시간 반영 |
| 사이드바 배지 `승인 대기 N` | 상시 | 대기 요청이 존재하는 대화 세션 항목 옆에 배지 표시 및 툴팁 제공 |
| 토스트(Toast) 팝업 | 현재 탭이 해당 세션을 보고 있지 않을 때 | 다른 대화 화면이나 백그라운드 탭에서 승인 요청 감지 시 즉시 토스트 표시 |
| 데스크톱 OS 알림 | 탭이 백그라운드 상태이고 알림 권한이 허용된 경우 | 클릭 시 해당 대화 세션 탭으로 즉시 포커스 이동 및 대화창 활성화 |

- 데스크톱 알림 권한 요청은 사용자의 명시적인 클릭 제스처가 필요하므로 헤더 영역의 알림 종 버튼(`DesktopAlertButton`) 핸들러에서 직접 호출합니다.
- 동일한 요청 ID에 대해 중복 알림이 발생하지 않도록 `tag` 속성에 요청 ID를 바인딩하여 단일 알림으로 통합합니다.
- 평문 HTTP 원격 접속 환경에서는 알림 버튼이 보안 컨텍스트 제약을 안내하고, 탭 제목 및 사이드바 배지를 통해 안정적으로 상태를 전달합니다.

### 4. 게스트 및 체험 사용자의 턴은 관리자 전역 알림에서 격리한다

체험 세션 및 초급자 화면의 게스트 세션 실행 시 `announce_waiting=False` 플래그를 설정하여 전역 버스 채널에 대기 신호를 브로드캐스트하지 않으며, 관리자의 `waiting_by_session()` 집계에서도 제외합니다.

## 결과 (Consequences)

**이점**

- 타 작업이나 다른 대화 탭을 조회 중인 상황에서도 승인 대기 상태를 즉시 인지하여 타임아웃으로 인한 작업 중단을 예방할 수 있습니다.
- 알림 클릭 한 번으로 승인이 필요한 해당 대화 세션으로 즉시 이동하여 결재를 신속하게 처리할 수 있습니다.
- 모든 승인 대기 파이프라인이 단일화되어 향후 새로운 유형의 승인 단계가 추가되더라도 일관된 전역 알림 혜택을 누릴 수 있습니다.
