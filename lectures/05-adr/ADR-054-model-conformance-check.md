# ADR-054. 새 모델은 토론에 넣기 전에 작은 요청 몇 건으로 점검하고, 결과는 설정을 바꾸지 않고 권고로만 낸다

> [ADR 목록](README.md) · 이전: [ADR-053](ADR-053-plan-speech-reads-only.md) · 다음: [ADR-055](ADR-055-bench-checks-and-judged-rubric.md)

## 상태 (Status)

채택됨 · 2026-11-11 · 관련: [ADR-007](ADR-007-no-simulated-answers.md), [ADR-030](ADR-030-fallback-to-the-global-model.md), [ADR-035](ADR-035-agent-input-modalities.md), [ADR-039](ADR-039-lazy-tool-schemas.md)

## 맥락 (Context)

- MADO 의 운영 환경은 폐쇄망이고, 그곳의 LLM 은 OpenAI 호환 엔드포인트(vLLM·사내 게이트웨이) 뒤의 오픈 모델 여럿과 결정 LLM(Jev·Laya)입니다. 개발 PC 에서는 DeepSeek 와 Jev 로 검증합니다.
- 모델과 서버 조합마다 다른 것이 많습니다. 지금까지는 전부 **토론이 터진 뒤에** 알았습니다. 도구 호출이 본문 글자로 새어 실행되지 않음(v0.7.0), 답이 `reasoning_content` 안에만 있어 빈 카드가 됨(v0.7.0), 같은 역할이 연달아 오면 400(v0.5.0), 도구 이력이 있는데 `tools` 를 빼면 400(v0.5.2), `max_context_window` 가 실제 창보다 커서 자르기 전에 서버가 먼저 거절(v0.5.3) — 릴리스 노트의 장애 기록이 이 목록입니다.
- `모델 연결 상태`(`model_status.probe`)는 `ping` 한 번으로 **응답하는지**만 봅니다. 응답하는 모델이 도구를 쓸 수 있는지는 말해 주지 않습니다.
- 폐쇄망에서는 장애가 나면 로그를 들고 나와야 원인을 볼 수 있습니다. 반입한 날 그 자리에서 알 수 있어야 합니다.

## 결정 (Decision)

### 1. 연결 하나에 짧은 요청 8건으로 모양을 확인합니다

`app/agents/model_check.py`. 생성형 연결은 아래를 차례로 봅니다 (모두 `max_tokens` 512 이하, 재시도 없음).

| 검사 | 보는 것 | 어긋나면 |
| :--- | :--- | :--- |
| 기본 응답 | 답이 오는가, 사용량을 보고하는가 | 실패 — 나머지는 묻지 않습니다 |
| 추론과 본문 | `reasoning_content` 가 갈라져 오는가, 본문이 비는가, `<think>` 가 본문에 섞이는가 | 주의 + `max_tokens` 권고 또는 서버 파서 안내 |
| 스트리밍 | `stream=True` 로 글 조각이 오는가 | 주의 — 발언마다 스트리밍 없이 다시 묻게 됩니다 |
| 잘림 알림 | 16 토큰에서 끊었을 때 `finish_reason='length'` 인가 | 주의 — 이어 쓰기와 잘림 안내가 동작하지 않습니다 |
| 연속된 user | 같은 역할 둘을 받는가 | 참고 — MADO 가 합쳐 보내므로 영향 없음 |
| 도구 호출 | `tool_calls` 로 오고 인자가 읽히는가, 본문으로 새는가(`find_leaked_tool_call`) | 실패(누출·거절) 또는 주의 |
| 도구 결과 뒤 마무리 | 도구 결과가 담긴 대화를 `tool_choice="none"` 으로 받는가 | 실패 또는 주의 |
| 도구 목록에서 불러오기 | 지연 로딩 목록(`catalog_tool`)을 읽고 `tools__load_tools` 를 부르는가 | 주의 + `tool_loading.enabled: false` 권고 |
| 이미지 입력 | 한 가지 색 그림을 받아 그 색을 답하는가 | 참고, 이미지를 켠 에이전트가 있으면 주의 |
| 컨텍스트 창 | `/models` 의 `max_model_len` 등이 에이전트 설정보다 작은가 | 실패 + `max_context_window` 권고 |

결정 LLM 은 요청 한 번에 noul·choice·score 세 질문을 보내 답의 모양을 봅니다.

### 2. 판정은 결정적입니다 — LLM 이 채점하지 않습니다

응답의 필드, 종료 사유, 표식, 정해 둔 낱말(`42`, `red`, 도구 결과의 낱말)만 봅니다. 모델이 일을 잘하는지는 재지 않습니다 (Bench 의 일). 판정 모델을 두면 폐쇄망마다 그 모델부터 믿을 수 있어야 하고, 같은 서버를 두 번 점검해 다른 결과가 나옵니다.

### 3. 요청은 실제 코드가 만드는 모양으로 보냅니다

- 연결 정보는 `probe_kwargs` (연결 확인과 같음), 도구 호출 풀이는 `ToolCallMixin._parse_tool_call`, 목록 도구와 상시 지침은 `catalog_tool` · `tool_loading_guidance` 를 그대로 씁니다. 점검이 통과하면 토론에서도 통과해야 뜻이 있습니다.
- **도구 결과 뒤 마무리의 assistant 턴은 지어내지 않고, 방금 모델이 낸 것을 `_assistant_turn` 으로 되돌려 넣습니다.** 첫 구현은 손으로 만든 턴을 보냈고, 실제 DeepSeek(thinking mode)에서 "`reasoning_content` must be passed back" 400 으로 거절되어 멀쩡한 모델이 '실패' 로 나왔습니다. 모델이 도구를 부르지 않았으면 이 검사는 건너뜁니다.
- 스트림의 사용량 유무는 보지 않습니다. LiteLLM 이 서버가 보내지 않아도 마지막 조각에 토크나이저로 센 값을 채워 넣어, 서버가 보고한 것인지 가를 수 없습니다 (1.98 · 1.105 에서 확인).

### 4. 결과는 권고입니다. 런타임은 결과에 따라 달라지지 않습니다

검사마다 `통과 · 참고 · 주의 · 실패 · 건너뜀` 과 한 줄 설명, 그리고 권장 설정(`Suggestion`)을 냅니다. conf 로 고칠 수 있는 것은 설정 이름과 값을 함께 담고(`max_context_window`, `max_tokens`, `tool_loading.enabled`, `allowed_modalities.image`), 서버 쪽에서 고칠 것(vLLM 의 `--tool-call-parser`, `--reasoning-parser`)은 글로만 냅니다. conf 는 사람이 고칩니다.

프로파일을 읽어 요청을 다르게 만드는 분기는 두지 않습니다. 그런 분기는 "점검을 돌린 서버" 와 "돌리지 않은 서버" 에서 같은 conf 가 다르게 동작하게 만들고, 장애가 났을 때 무엇이 나갔는지 conf 만으로 알 수 없게 됩니다.

### 5. 어디서 돌리는가

- 콘솔: `python -m app.modelcheck [--agent KEY …] [--json] [--config …]`. 서버를 띄우기 전에 돌릴 수 있고, 실패한 검사가 있으면 끝남 값이 1 입니다.
- 화면: `모델 연결 상태` 창의 줄마다 `적합성 점검` 단추. 주인의 화면에만 있고(요청이 여러 건 나갑니다), 연결된 줄에서만 눌리며, 한 번에 한 연결만 돕니다.
- 둘 다 `data/modelcheck/<연결 id>.json` 에 남깁니다. 기록에는 상태와 크기, 키를 가린 오류 원문 한두 줄만 있고 모델이 쓴 글은 없습니다.
- 서버 전체의 동시 요청 상한(`app.llm_concurrency`)을 지킵니다. 연결 확인과 달리 자리가 날 때까지 기다립니다 (사람이 눌러 시작한 일입니다).

### 하지 않는 것

- 실제 창 크기를 넘치는 요청을 보내 재는 일. 128k 토큰을 한 번 보내는 것은 단일 GPU 서버에 큰 부하이고, vLLM 은 `/models` 로 알려 줍니다. 서버가 말해 주지 않으면 건너뜀으로 두고 모델 카드의 값을 적으라고 안내합니다.
- 음성·동영상·문서 입력 점검, 프롬프트 캐시 점검.
- 점검 결과로 conf 를 자동으로 고치는 일.

## 결과 (Consequences)

**좋아지는 점**

- 새 모델을 들인 날, 그 모델로 MADO 의 어느 기능이 되고 안 되는지를 1분 안에 표로 봅니다. 릴리스 노트의 장애 다섯 갈래가 각각 검사 한 줄입니다.
- 폐쇄망에서 들고 나올 것이 로그가 아니라 `data/modelcheck/*.json` 한 파일입니다. 내용 없이 상태만 있습니다.

실제 확인(2026-11-11): `deepseek/deepseek-v4-flash` 는 요청 8건에 10개 검사 모두 통과, `jev/jev-1.13.0` 은 요청 1건에 4개 모두 통과했습니다.

**치르는 비용**

- 요청 한 건의 결과입니다. 열 번에 한 번 도구 호출이 새는 모델은 통과로 나올 수 있습니다.
- 도구를 부르라는 지시를 따르지 않는 모델은 '주의' 이고, 그 뒤의 마무리 검사는 건너뜁니다.
- 컨텍스트 창은 서버가 말한 값을 믿습니다. 게이트웨이가 `/models` 를 막으면 알 수 없습니다.
- LiteLLM 이 짝이 맞는 `<think>…</think>` 를 스스로 갈라 주므로(1.98), 본문에 섞인 추론은 닫는 표식만 온 경우에만 드러납니다.
