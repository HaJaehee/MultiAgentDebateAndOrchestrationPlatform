# ADR-004. 저장소는 SQLite 파일 하나로 한다

> [ADR 목록](README.md) · 이전: [ADR-003](ADR-003-mcp-tool-protocol.md) · 다음: [ADR-005](ADR-005-long-lived-mcp-sessions.md)

## 상태 (Status)

채택됨 · 2026-08-26 (초기 설계) · 관련: [ADR-011](ADR-011-session-config-snapshot.md), [ADR-017](ADR-017-never-lose-a-write.md)

## 맥락 (Context)

- 영속화해야 할 데이터는 대화 세션, 발언 내역, 도구 실행 로그, 최종 산출물, 그리고 세션별 고정된 에이전트 설정 스냅샷입니다.
- 특정 대화 세션에 데이터를 기록하는 주체는 사실상 해당 세션을 실행 중인 단일 백그라운드 토론 태스크뿐이므로, 동시성 쓰기 경합의 빈도가 매우 낮습니다.
- 시스템 관리자가 1인인 소규모 운영 환경이며, 별도의 외부 데이터베이스 서버(PostgreSQL, MySQL 등)를 구축 및 관리할 리소스가 부족합니다.
- 소프트웨어를 인터넷이 단절된 폐쇄망으로 이전하거나 데이터를 백업할 때, 단일 파일 단위로 관리할 수 있는 편의성이 매우 큽니다.
- 애플리케이션 전체가 Python `asyncio` 기반으로 동작하므로, DB I/O 대기 시간 동안 비동기 이벤트 루프가 차단(Block)되어서는 안 됩니다.

## 결정 (Decision)

모든 대화 및 세션 기록을 **단일 SQLite 로컬 데이터베이스 파일**에 영속화하도록 합니다.

- SQLAlchemy 2.0의 비동기 ORM과 `aiosqlite` 드라이버를 결합하여 데이터베이스 접근 계층을 구현합니다.
- 데이터베이스 연결 주소(Connection URI)는 설정 파일에서 주입받도록 구성합니다. 향후 엔터프라이즈 환경에서 외부 DBMS로 전환할 때 드라이버 연결 문자열만 교체하여 대응할 수 있도록 여지를 둡니다.
- 별도의 스키마 마이그레이션 도구(Alembic 등)는 의존성에 포함하지 않습니다. 애플리케이션 기동 시 누락된 테이블을 자동 생성하고, "추가된 컬럼 목록" 메타데이터와 실제 DB 스키마를 비교하여 빠진 컬럼만 동적으로 `ALTER TABLE ADD COLUMN`을 수행합니다. 데이터베이스 스키마는 **추가(Append-only)** 방식으로만 관리합니다.
- 대화 세션을 삭제할 경우 그에 종속된 발언, 도구 기록, 산출물, 에이전트 스냅샷이 연쇄 삭제(Cascade Delete)되도록 외래키 관계를 설정합니다.

## 결과 (Consequences)

**좋아지는 점**

- 별도의 데이터베이스 서버 설치, 사용자 계정 권한 설정, 네트워크 포트 개방과 같은 운영 관리 부담이 전무합니다.
- 과거 버전에서 생성된 SQLite 데이터베이스 파일을 상위 버전의 애플리케이션으로 복사해 와도 정상적으로 인식 및 기동됩니다. 복잡한 마이그레이션 스크립트를 폐쇄망에 별도 반입할 필요가 없습니다.
- 데이터 백업 및 복구 작업이 단순한 로컬 파일 복사 명령 하나로 완결됩니다.

**치르는 비용**

- **Windows 운영체제의 파일 잠금(Locking) 메커니즘에 취약합니다.** 초기 기본 설정 상태로 운영하던 중, 사용자 세션이 잠겨 있는 사이 백신 프로그램의 실시간 파일 검사가 SQLite 파일을 독점 점유하여 최종 종합 보고서 저장 트랜잭션이 실패하는 사고가 발생했습니다. 이는 [ADR-017](ADR-017-never-lose-a-write.md)에서 잠금 타임아웃 증액, WAL 모드 적용, 재시도 로직, 비상 로컬 파일 덤프 메커니즘을 도입하여 보완했습니다.
- **스키마 변경이 추가 작업으로만 엄격히 제한됩니다.** 기존 컬럼의 이름을 변경하거나 데이터 타입을 수정하려면 정식 마이그레이션 도구가 필요합니다. 따라서 신규 컬럼을 추가할 때 그 명칭과 도메인 의미를 사전에 매우 신중하게 결정해야 합니다. 일례로 발언 발생 시각은 기존 레코드 생성 시각(`created_at`) 컬럼의 의미를 재정의하지 않고, 명시적인 신규 컬럼으로 추가했습니다.
- **데이터가 평문으로 저장됩니다.** 대화 구성 스냅샷에 모델 제공자의 API 키가 포함되면서 ([ADR-011](ADR-011-session-config-snapshot.md)), 로컬 SQLite 파일에 대한 파일 시스템 접근 권한 관리가 핵심적인 보안 관리 대상이 되었습니다.
- **다중 노드 수평 확장이 불가능합니다.** 동시에 쓰기를 시도하는 주체가 많아지면 파일 락 경합이 급격히 증가합니다. 연결 주소를 설정 파일로 분리해 둔 것은 향후 외부 DBMS 이전이 필요할 때를 대비한 최소한의 확장점입니다.
- **싱글턴 엔진 인스턴스가 자동화 테스트 환경을 오염시켰습니다.** 엔진 인스턴스를 먼저 초기화한 테스트 케이스의 DB 파일 경로가 전역 싱글턴에 고정되어, 실행 순서에 따라 테스트 실행기가 개발자의 실제 로컬 DB 파일에 테스트 대화를 기록하는 문제가 발생했습니다. 이는 모든 단위 테스트 격리 시 메모리 SQLite(`:memory:`)를 우선 바인딩하도록 테스트 하네스를 수정하여 방지했습니다.
