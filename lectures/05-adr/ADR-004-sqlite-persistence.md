# ADR-004. 저장소는 SQLite 파일 하나로 한다

> [ADR 목록](README.md) · 이전: [ADR-003](ADR-003-mcp-tool-protocol.md) · 다음: [ADR-005](ADR-005-long-lived-mcp-sessions.md)

## 상태 (Status)

채택됨 · 2026-08-26 (초기 설계) · 관련: [ADR-011](ADR-011-session-config-snapshot.md), [ADR-017](ADR-017-never-lose-a-write.md)

## 맥락 (Context)

- 저장할 것은 대화, 발언, 도구 실행 기록, 산출물, 대화별 에이전트 설정입니다.
- 대화 하나에 기록하는 주체는 사실상 그 대화의 토론 태스크 하나입니다. 동시 쓰기가 적습니다.
- 운영자는 한 명이고 DB 서버를 따로 운영할 여력이 없습니다.
- 폐쇄망으로 옮기거나 백업할 때 파일 하나만 다루면 편합니다.
- 앱 전체가 asyncio 위에서 돌므로 DB 대기가 이벤트 루프를 막으면 안 됩니다.

## 결정 (Decision)

**SQLite 파일 하나**에 모든 대화 기록을 저장한다.

- SQLAlchemy 2.0의 비동기 ORM과 aiosqlite 드라이버를 쓴다.
- 접속 주소는 설정값으로 둔다. 나중에 다른 DB로 옮길 때 드라이버 문자열만 바꾸게 한다.
- 스키마 이관 도구는 쓰지 않는다. 기동할 때 없는 테이블을 만들고, "나중에 추가된 컬럼" 표와 실제 테이블을
  비교해 빠진 컬럼만 추가한다. 스키마는 **더하기만** 한다.
- 대화를 지우면 딸린 발언, 도구 기록, 산출물, 에이전트 설정이 함께 지워지게 관계를 건다.

## 결과 (Consequences)

**좋아지는 것**

- 운영 부담이 없습니다. 설치도, 계정도, 포트도 필요 없습니다.
- 옛 DB 파일을 들고 새 버전으로 옮겨도 그대로 열립니다. 폐쇄망에 이관 도구를 반입할 필요가 없습니다.
- 백업이 파일 복사입니다.

**치르는 비용**

- **Windows 파일 잠금에 약합니다.** 기본 설정 그대로 쓰다가, 화면이 잠긴 사이 백신 검사가 파일을 잡아 최종
  보고서 저장이 실패했습니다. [ADR-017](ADR-017-never-lose-a-write.md)에서 대기 시간, WAL, 재시도, 파일 보존으로
  보완했습니다.
- **스키마를 더하기만 할 수 있습니다.** 컬럼 이름이나 타입을 바꾸려면 정식 이관 도구가 필요합니다. 그래서
  컬럼을 추가할 때 이름과 의미를 신중하게 정하게 됩니다. 예컨대 발언 시각은 기존 생성 시각 컬럼을 재활용하지
  않고 새 컬럼으로 추가했습니다.
- **평문 저장입니다.** 대화 구성 스냅샷에 API 키가 들어가면서([ADR-011](ADR-011-session-config-snapshot.md))
  DB 파일 권한이 보안 문제가 되었습니다.
- **여러 대로 늘릴 수 없습니다.** 쓰는 주체가 늘면 잠금 경합이 커집니다. 접속 주소를 설정값으로 둔 것이 그때를
  위한 여지입니다.
- **싱글턴 엔진이 테스트를 오염시켰습니다.** 엔진을 먼저 만든 쪽의 경로가 고정되어, 순서가 나쁜 테스트가
  개발자의 실제 DB에 대화를 썼습니다. 테스트마다 메모리 DB로 엔진을 먼저 만들어 막았습니다.
