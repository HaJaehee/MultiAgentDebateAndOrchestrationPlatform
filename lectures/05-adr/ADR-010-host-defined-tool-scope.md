# ADR-010. 도구 상태의 격리 경계는 호스트가 정한다

> [ADR 목록](README.md) · 이전: [ADR-009](ADR-009-refuse-cross-workspace-debates.md) · 다음: [ADR-011](ADR-011-session-config-snapshot.md)

## 상태 (Status)

채택됨 · 2026-08-28 · 관련: [ADR-005](ADR-005-long-lived-mcp-sessions.md), [ADR-016](ADR-016-per-workspace-mcp-runtime.md), [ADR-020](ADR-020-conversation-memory.md)

## 맥락 (Context)

- MCP 세션을 프로세스 수명 주기에 맞춰 장기간 유지하게 되면서 ([ADR-005](ADR-005-long-lived-mcp-sessions.md)), 단일 도구 서버 프로세스를 시스템 내의 모든 대화 세션이 함께 공유하게 되었습니다.
- 공식 지식 그래프(Memory) 서버는 **단일 프로세스당 하나의 그래프 데이터베이스 파일**을 사용합니다. 그러자 **새로운 대화 세션이 이전 대화 세션의 기억을 그대로 읽어 들이는 문제**가 발생했습니다. 데이터 격리의 논리적 단위가 비즈니스 도메인 규칙이 아니라 하위 전송 계층의 물리적 특성(단일 프로세스 수명)에 종속되어 있었던 것입니다. 긴 토론 과정에서 컨텍스트 창이 축소되더라도 핵심 결정을 안전하게 보존하기 위해 도입한 지식 베이스가, 엉뚱하게도 다른 대화의 결정을 뒤섞는 결과를 낳았습니다.
- 샌드박스 실행 커널 역시 세션 간에 공유되었습니다. 도구의 세부 실행 기록은 타 에이전트의 입력 컨텍스트에 포함되지 않으므로, 커널 상태를 무분별하게 공유할 경우 리뷰어 에이전트가 출처를 알 수 없는 전역 변수(예: 3라운드 전 다른 에이전트가 선언한 오래된 데이터프레임)를 그대로 물려받아, 그것을 현재 유효한 데이터로 착각하고 잘못된 검토 의견을 작성하게 됩니다.
- 대화 세션 ID를 도구 파라미터로 노출하여 LLM 모델이 직접 전달하도록 하는 방안도 검토되었습니다. 그러나 모델이 단 한 번이라도 세션 ID 입력을 누락하거나 오기입하면 다른 세션의 데이터를 오염시키게 되며, 이는 해결하고자 했던 본래 결함을 전혀 방어하지 못합니다.

## 결정 (Decision)

해당 도구 호출이 어떤 대화 세션에 귀속되는지는 오직 호스트 오케스트레이터만이 정확히 알고 있습니다. 따라서 **호스트가 모든 도구 호출의 요청 메타데이터(`_meta`) 영역에 대화 세션 ID를 직접 주입하도록 합니다.** 서버 구현체마다 참조하는 키 명칭이 상이하므로 여러 호환 키 이름으로 함께 전송합니다.

도구 상태의 격리 정책은 호스트 계층의 단일 진실 공급원에서 일괄 정의하도록 합니다.

| 상태 데이터 | 격리 경계 | 격리 사유 |
| :--- | :--- | :--- |
| 작업 공간 디렉터리 | 모든 에이전트 공유 | 에이전트 상호 간의 파일 및 코드 전달(인계) 채널 |
| 지식 그래프 (메모리) | 대화 세션 단위 격리 | 합의된 사실은 해당 세션의 모든 참가자가 공유하되 세션 간에는 격리 |
| 샌드박스 실행 커널 | 대화 세션 × 발언자 단위 격리 | 커널 내부 변수는 세션 기록에 남지 않으므로, 에이전트 간 전달은 오직 명시적 파일을 통해서만 수행 |

지식 그래프 서버는 공식 오픈소스 리포지토리를 **최소한의 침습으로 포크(Fork)**하여 커스터마이징합니다.

- 도구 처리 비즈니스 함수는 원본 코드를 그대로 보존하고, 라우팅 등록 부분만을 래핑하여 매 요청마다 해당 요청의 격리된 그래프 컨텍스트 내에서 실행되도록 합니다. 향후 공식 서버의 신규 버전 업데이트를 손쉽게 병합하기 위함입니다.
- 요청 처리 시 전역 변수를 조작하지 않고, Python `contextvars` 기반의 요청별 독립 컨텍스트를 사용합니다. 두 대화 세션의 도구 호출이 비동기 `await` 지점에서 교차 실행되더라도 내부 상태가 뒤섞이지 않도록 방어합니다.
- 참조할 그래프 스코프를 결정하는 우선순위는 **메타데이터(`_meta`) > 도구 인자(Fallback) > `unscoped-<프로세스ID>`** 순으로 엄격히 강제합니다. 호스트 메타데이터가 모델 인자보다 항상 우선하므로, 모델이 임의로 타 세션의 그래프 ID를 인자로 넘기더라도 타 세션의 데이터에 절대 접근할 수 없습니다.
- 메타데이터에 스코프가 누락되었을 때 **공용(Default) 그래프로 폴백하지 않도록 합니다.** 공용 그래프로 떨어뜨리면 향후 메타데이터 주입 로직이 깨졌을 때 원래의 데이터 누출 버그가 조용히 재발하기 때문입니다.

샌드박스 서버는 별도로 포크하지 않습니다. 원래부터 도구 인자보다 메타데이터를 우선 검사하도록 설계되어 있었으며, 단지 호스트가 메타데이터를 전송하지 않고 있었을 뿐이었습니다.

## 결과 (Consequences)

**좋아지는 점**

- 대화 세션 간에 지식 그래프 기억과 샌드박스 커널 상태가 완벽히 격리됩니다.
- 모델이 도구 인자에 어떠한 값을 입력하더라도 호스트가 설정한 격리 경계를 결코 월경할 수 없습니다. 보안 및 격리의 완결성이 모델의 신뢰성에 의존하지 않습니다.

**치르는 비용**

- **정상적인 업무상 경계 횡단이 필요할 때도 엄격한 격리가 적용됩니다.** 과거의 긴 대화를 새로운 대화 세션으로 이어받을 때 "이전 세션의 기억을 참고하라"는 프롬프트 지시가 동작하지 않습니다. 따라서 세션 이어받기 기능 구현 시, 호스트가 이전 대화의 그래프 파일을 새로운 세션 ID 명의로 **명시적으로 파일 복사**해 주는 로직을 별도로 구축해야 했습니다. 경계를 설정한 주체가 경계 간 데이터 이동 책임도 함께 져야 합니다.
- 포크된 서버 코드를 지속적으로 유지보수해야 합니다. 실제 실행 번들은 Node 패키지 디렉터리에 상주해야 하므로, 메인 앱이 기동할 때마다 원본 포크 파일을 설정 경로로 자동 복사 및 동기화합니다.
- 샌드박스 커널 프로세스 수가 "동시 토론 세션 수 × 샌드박스를 사용하는 에이전트 수"에 비례하여 증가합니다. 이에 따라 커널 최대 허용치 기본값을 8개에서 16개로 상향 조정했으며, 초과 시 LRU(가장 오래 미사용된 커널 우선 회수) 알고리즘으로 정리하도록 조치했습니다.
- 요청 메타데이터 전달을 지원하지 않는 구버전 MCP SDK 환경에서는 경고 로그를 남기고 스코프 없이 호출을 시도하게 되므로 완벽한 격리가 보장되지 않습니다.

**교훈**

- 데이터의 격리 경계는 해당 경계의 **전체 맥락을 정확히 인지하고 있는 상위 주체(호스트)**가 결정해야 합니다. 개별 서버는 호출이 어느 비즈니스 세션의 것인지 알 수 없으며, 언어 모델은 언젠가 지침을 누락하기 마련입니다.
- 장애 대비용 폴백 메커니즘은 과거의 버그를 은밀히 재현하지 않는 방식으로 설계해야 합니다. `unscoped-...` 파일이 파일 시스템에 생성되면 그것 자체가 호스트 연동 이상을 알리는 시각적 경고 신호가 됩니다.
