# ADR-011. 시작한 대화는 에이전트 설정 전체를 고정한다

> [ADR 목록](README.md) · 이전: [ADR-010](ADR-010-host-defined-tool-scope.md) · 다음: [ADR-012](ADR-012-agent-owned-debate-order.md)

## 상태 (Status)

채택됨 · 2026-08-30 (v0.1) · 관련: [ADR-004](ADR-004-sqlite-persistence.md), [ADR-012](ADR-012-agent-owned-debate-order.md), [ADR-013](ADR-013-json-config.md)

## 맥락 (Context)

- 초기부터 대화 세션별 페르소나(이름, 역할, 시스템 프롬프트)는 첫 사용자 메시지 기록 시점에 고정했습니다. 토론 도중에 에이전트의 성격과 지침이 변경되면 동일한 발언자가 앞뒤로 모순된 주장을 펼치게 되고, 오케스트레이터가 누가 어떤 논점에 동의했는지 추적할 수 없기 때문입니다.
- 웹 UI 화면에서 에이전트를 동적으로 추가하거나 삭제할 수 있도록 기능을 확장하려던 시점이었습니다. 이전까지는 설정 파일(`conf.json`)을 직접 편집한 뒤 애플리케이션을 재기동해야 했습니다.
- 그러나 에이전트 **실행 인스턴스 자체**는 매 턴마다 전역 설정 파일에서 동적으로 읽어오고 있었습니다. 이로 인해 설정 파일에서 특정 에이전트를 삭제하면, 해당 에이전트가 이미 활발히 참여하고 있던 기존 대화 세션에서도 에이전트가 조용히 증발해 버렸습니다. 데이터베이스에 보존된 페르소나 텍스트만으로는 에이전트를 되살릴 수 없었습니다. 모델 정보, 엔드포인트 URL, API 키가 영속화되지 않았기 때문입니다.
- 화면에서 에이전트 설정을 손쉽게 변경할 수 있게 될수록 이러한 데이터 유실 사고가 빈번히 발생할 것이 명백했습니다.

## 결정 (Decision)

첫 사용자 메시지가 시스템에 기록되는 순간, 해당 세션에 참여하는 모든 에이전트의 **설정 전체를 대화 레코드에 불변 스냅샷(Immutable Snapshot)으로 저장하도록 합니다.** 그 시점 이후부터 해당 대화 세션은 외부 설정 파일을 전혀 참조하지 않습니다.

- 스냅샷에는 모델명, 엔드포인트 URL, API 키, 샘플링 파라미터, 허용된 도구 권한, 순차적 사고 설정, 페르소나 텍스트가 모두 포함됩니다. 이후 기능 확장을 통해 추가된 발언 순서, 토론 진영, UI 카드 색상 및 아바타 아이콘도 함께 영속화됩니다.
- 이미 시작되어 고정된 대화 세션의 로스터 및 페르소나 UI는 전역 에이전트 풀이 아닌 **해당 세션의 스냅샷 데이터를 기반으로 렌더링하도록 합니다.** 시스템 설정에서는 삭제되었으나 과거 대화에만 남아 있는 에이전트에는 "이 대화 전용" 뱃지를 부착하여 표시합니다.
- UI 카드의 표시 순서를 결정론적(Deterministic)으로 정렬합니다 (오케스트레이터 우선, 설정 파일 등록 순서, 대화 전용 에이전트 순). 스냅샷 레코드들은 단일 DB 트랜잭션에서 일괄 커밋되어 생성 시각이 동일하므로, 정렬 기준이 없으면 무작위 UUID 순서로 뒤섞여 화면을 열 때마다 카드 배치가 뒤바뀌는 문제가 있었기 때문입니다.
- 관리자를 위한 예외 갱신 통로(비상구)로 **'설정 동기화(Refresh Config)'** 기능을 제공합니다. 현재의 최신 시스템 설정을 기반으로 런타임 설정을 다시 고정하되, 기존 페르소나 텍스트는 보존합니다.
- 스냅샷 컬럼이 NULL인 구버전 대화 세션은 기능 도입 이전에 시작된 레거시 세션으로 간주하고, 기존처럼 설정 파일을 참조하도록 하위 호환성을 유지합니다.
- 페르소나 외부 조회 REST API는 내부 자격 증명이 포함된 스냅샷 전체를 절대 외부에 노출하지 않습니다.

## 결과 (Consequences)

**좋아지는 점**

- 수개월 전의 과거 대화 세션을 열더라도 당시의 발언자가 당시의 모델과 프롬프트 설정 그대로 일관되게 발언합니다. 전역 설정 파일을 안심하고 수정하거나 리팩터링할 수 있습니다.

| 설정 파일의 변경 사항 | 이미 시작된 대화 세션의 동작 |
| :--- | :--- |
| 신규 에이전트 추가 | 기본 체크 해제 상태로 표시되며, 사용자가 수동 활성화해야 참여 |
| 기존 에이전트 삭제 또는 비활성화 | 기존에 고정된 스냅샷 설정으로 변함없이 토론 참여 |
| 모델명, 엔드포인트, API 키, 도구 권한 변경 | 기존 세션에는 일절 영향 없음 |
| MCP **서버** 프로세스 자체의 On/Off | **직접적인 영향 있음** (도구 서버 프로세스는 전역 애플리케이션의 물리적 자원) |

**치르는 비용**

- **민감한 API 키가 로컬 SQLite 파일에 평문으로 저장됩니다.** 시스템의 완전한 자기완결성을 확보하기 위해 치러야 하는 보안상 대가입니다. 운영 가이드에 DB 파일의 파일 시스템 접근 권한 관리를 강조하고, REST API 엔드포인트가 스냅샷 데이터를 외부로 유출하지 않는지 회귀 테스트로 검증합니다.
- 외부 API 키를 갱신하거나 게이트웨이 주소를 이전했을 때, 과거 대화 세션은 이미 고정된 무효한 엔드포인트로 요청을 시도하게 됩니다. 이 경우 대화 세션마다 '설정 동기화' 버튼을 수동으로 실행해 주어야 합니다.
- 시스템 전역에서 에이전트 도구 권한을 수정하더라도 기존 대화 세션에는 자동 반영되지 않습니다. "도구 권한 변경 사항이 기존 대화에도 즉시 적용된다"고 안내하던 UI 문구를 정직하게 전면 수정해야 했습니다.

**이후에 따라온 결정**

- 세션 스냅샷을 단일 기준점(SSOT)으로 삼으면서 프로그램이 설정 파일을 안전하게 다시 저장(덮어쓰기)하는 빈도가 급증했고, 이는 TOML 포맷의 한계를 드러내어 JSON으로 전환하는 계기가 되었습니다 ([ADR-013](ADR-013-json-config.md)).
- 발언 순서와 토론 진영 정보를 에이전트의 일급 속성으로 분리하면서 이 정보 역시 스냅샷에 함께 고정되도록 개선했습니다 ([ADR-012](ADR-012-agent-owned-debate-order.md)).
- '대화 이어받기'로 생성된 신규 세션은 원본 세션의 스냅샷을 복사하여 계승합니다. 따라서 원본 대화에서 이미 삭제된 에이전트라도 새 세션에서 자연스럽게 발언을 이어갈 수 있습니다.

**교훈**

"시작된 대화는 외부 설정을 결코 참조하지 않는다"와 같은 엄격한 불변 원칙을 수립할 때는, 반드시 관리자가 의도적으로 상태를 갱신할 수 있는 안전한 예외 통로('설정 동기화')를 함께 설계해야 합니다. 예외 갱신 통로가 마련되어 있지 않으면 사용자는 규칙 자체를 해킹하거나 우회하려 시도합니다.
