# ADR-011. 시작한 대화는 에이전트 설정 전체를 굳힌다

> [ADR 목록](README.md) · 이전: [ADR-010](ADR-010-host-defined-tool-scope.md) · 다음: [ADR-012](ADR-012-agent-owned-debate-order.md)

## 상태 (Status)

채택됨 · 2026-08-30 (v0.1) · 관련: [ADR-004](ADR-004-sqlite-persistence.md), [ADR-012](ADR-012-agent-owned-debate-order.md), [ADR-013](ADR-013-json-config.md)

## 맥락 (Context)

- 처음부터 대화별 페르소나(이름, 역할, 시스템 프롬프트)는 첫 메시지에 굳혔습니다. 토론 도중 인격이 바뀌면 같은
  화자가 앞뒤로 모순된 말을 하게 되고, 오케스트레이터가 누가 무엇에 동의했는지 추적할 수 없습니다.
- 에이전트를 화면에서 추가하고 삭제할 수 있게 하려는 참이었습니다. 이전에는 설정 파일을 직접 고치고 앱을 다시
  띄워야 했습니다.
- 그런데 에이전트 **객체 자체**는 여전히 매 턴 설정에서 가져왔습니다. 설정에서 에이전트를 지우면 그 에이전트는
  이미 그를 쓰던 대화에서도 조용히 사라졌습니다. 저장된 페르소나로는 되살릴 수 없었습니다. 모델도, 엔드포인트도,
  키도 없었으니까요.
- 화면에서 설정을 쉽게 바꿀 수 있게 되면 이런 일이 훨씬 자주 생길 것이 분명했습니다.

## 결정 (Decision)

첫 사용자 메시지가 기록되는 순간, 참여하는 에이전트의 **설정 전체**를 대화에 스냅샷으로 저장한다. 그때부터
그 대화는 설정 파일을 읽지 않는다.

- 스냅샷에는 모델, 엔드포인트, API 키, 샘플링 값, 도구 권한, 단계적 사고 설정, 페르소나가 들어간다. 이후에
  추가된 발언 순서와 진영, 카드 색과 아이콘도 함께 굳는다.
- 잠긴 대화의 로스터와 페르소나 화면은 에이전트 풀이 아니라 **스냅샷을 그린다.** 설정에서 사라졌지만 이 대화에만
  남은 에이전트에는 "이 대화 전용" 표시를 붙인다.
- 카드 순서를 결정적으로 정한다(오케스트레이터, 설정 파일 순서, 이 대화 전용 순). 스냅샷 행들은 한 커밋에
  들어가 생성 시각이 같아서, 정렬이 무작위 ID로 떨어져 카드가 열 때마다 바뀌었다.
- 비상구로 **설정 갱신**을 둔다. 현재 설정으로 운영 설정을 다시 굳히되 페르소나는 건드리지 않는다.
- 스냅샷 컬럼이 비어 있는(NULL) 대화는 이 컬럼이 생기기 전에 잠긴 대화로 보고, 예전처럼 설정 파일을 따른다.
- 페르소나 조회 API는 스냅샷을 절대 내보내지 않는다.

## 결과 (Consequences)

**좋아지는 것**

- 한 달 전 대화를 열어도 그때의 화자가 그때의 설정으로 말합니다. 설정 파일을 마음 놓고 고칠 수 있습니다.

| 설정 파일의 변화 | 이미 시작한 대화 |
| :--- | :--- |
| 에이전트 추가 | 체크 해제 상태로 보임, 켜야 참여 |
| 에이전트 삭제, 비활성 | 굳힌 설정으로 계속 발언 |
| 모델, 엔드포인트, 키, 도구 권한 변경 | 영향 없음 |
| MCP **서버** 켜고 끄기 | **영향 있음** (프로세스는 앱 전체의 성질) |

**치르는 비용**

- **API 키가 평문 SQLite에 들어갑니다.** 자기완결성의 대가입니다. DB 파일 권한 점검을 운영 문서에 적고, API가
  스냅샷을 노출하지 않는다는 것을 테스트로 확인합니다.
- 키를 교체하거나 게이트웨이를 옮기면 옛 대화는 죽은 엔드포인트를 두드립니다. 대화마다 "설정 갱신"을 눌러야 합니다.
- 도구 권한을 바꿔도 시작한 대화에는 반영되지 않습니다. 화면에서 "도구 할당이 시작한 대화에도 적용된다"고
  말하던 문구를 모두 고쳐야 했습니다.

**이후에 따라온 결정**

- 스냅샷을 정본으로 삼자 설정을 되쓰는 일이 늘었고, TOML 되쓰기의 한계가 드러났습니다([ADR-013](ADR-013-json-config.md)).
- 발언 순서와 진영을 에이전트 속성으로 옮기면서 그것도 스냅샷에 함께 굳게 되었습니다([ADR-012](ADR-012-agent-owned-debate-order.md)).
- 이어받기로 만든 새 대화는 스냅샷을 복사해 가져갑니다. 원래 대화에서 삭제된 에이전트도 새 대화에서 계속 발언할 수
  있습니다. 설정에 아직 있는 에이전트는 다음 잠금 때 현재 설정으로 다시 굳으므로, 대화 사이의 모델 교체는 반영됩니다.

**교훈**

강한 규칙("시작한 대화는 설정을 읽지 않는다")을 세울 때는 비상구("설정 갱신")를 함께 설계합니다. 비상구가 없으면
사람들은 규칙 자체를 우회합니다.
