# ADR-041. SQLite와 동일한 동작 보증 하에 PostgreSQL 호환성을 지원하고 다중 인스턴스 확장의 데이터베이스 계층을 준비한다

> [ADR 목록](README.md) · 이전: [ADR-040](ADR-040-compact-stale-file-reads.md)

## 상태 (Status)

채택됨 · 2026-10-31 (v1.5.1) · 관련: [ADR-001](ADR-001-python-single-process.md), [ADR-004](ADR-004-sqlite-persistence.md), [ADR-017](ADR-017-never-lose-a-write.md), [ADR-024](ADR-024-resume-interrupted-turns.md)

## 맥락 (Context)

- 기존 문서는 `db_url` 설정만 변경하면 PostgreSQL로 원활히 전환할 수 있다고 기술했으나, 실제로는 세션 검색 기능이 SQLite 전용 가상 테이블인 FTS5에 강하게 결합되어 있었습니다.
- 검색 엔진 외에도 SQLite와 PostgreSQL 간의 엄격함 차이로 인한 잠재적 결함이 다수 존재했습니다. SQLite는 기본적으로 외래 키 제약 조건, 문자열 길이 상한(`String(n)`), NUL 문자 포함 여부를 엄격히 검사하지 않으므로, PostgreSQL 전환 시 숨어 있던 런타임 오류가 대거 발생할 위험이 있었습니다.
- 인메모리 SQLite 기반의 전체 테스트 스위트를 PostgreSQL 16.9 환경으로 리다이렉션하여 전수 실행했습니다 (`tests/pg_redirect.py`). 수정 전에는 2,743개 테스트 중 25건이 실패했으며, 분석 결과 15건은 실제 애플리케이션의 데이터베이스 호환성 결함이었습니다. 호환성 개선 후에는 2,794개 테스트가 모두 정상 통과했습니다 (인메모리 SQLite 전용 테스트 1건 및 Windows 심볼릭 링크 권한 관련 2건 건너뜀).

| 식별된 결함 | SQLite 환경 | PostgreSQL 환경 |
| :--- | :--- | :--- |
| 체험/초급자 테이블 외래 키에 `ON DELETE` 누락 | 부모 삭제 후에도 자식 행 잔류 | 관리자 화면에서 대화 세션 삭제 시 외래 키 위반 에러 발생 |
| 보안 감사 집계 쿼리의 `PARTITION BY arguments` (JSONB) | 암묵적 문자열 비교 처리 | JSONB 동등 비교 불가로 보안 감사 화면 전체 쿼리 실패 |
| `String(n)` 길이 제약 | 컬럼 길이 무시하고 저장 | 긴 역할 설명이 포함된 에이전트의 발언 기록 시 INSERT 실패 |
| 문자열 내부 NUL 바이트 | 그대로 저장 허용 | `cannot contain NUL (0x00) characters` 오류로 발언 기록 실패 |
| 타임존 없는 Datetime | UTC로 해석 (`as_utc`) | asyncpg 드라이버가 로컬 시각으로 읽어 9시간 오차 발생 |
| `_ADDED_COLUMNS` 마이그레이션 | 정상 작동 | `PRAGMA`, `DATETIME`, `DEFAULT 0` 문법 오류로 마이그레이션 실패 |
| 비밀번호가 포함된 `db_url` | 로컬 파일 경로이므로 해당 없음 | 서버 기동 로그에 DB 접속 비밀번호가 평문 노출 |

- 단위 테스트로 드러나지 않는 트랜잭션 수명 주기도 실측했습니다. PostgreSQL에서 순차 토론 턴을 실행한 결과 **LLM API 호출 6회 중 5회에서 DB 커넥션이 `idle in transaction` 상태로 장시간 유지되는 심각한 커넥션 점유 결함**이 발견되었습니다. 발언 직전 인라인 코멘트를 조회하면서 트랜잭션을 연 채로 LLM 응답을 수 분간 대기했기 때문입니다. 동시 실행 턴 수가 늘어나면 커넥션 풀 고갈로 전체 시스템이 정지될 수 있었습니다.

## 결정 (Decision)

### 1. 단일 비즈니스 규칙 하에 데이터베이스별 최적화 검색 엔진 분리

검색 규칙은 "지정된 모든 키워드가 대소문자 구분 없이 부분 문자열(Substring)로 포함된 발언 검색"으로 일원화합니다. 한글 합성어("분산캐시")나 조사가 결합된 어휘("캐시를")를 정확히 매칭하기 위함입니다. `SearchBackend` 추상 계층을 통해 데이터베이스별 고유 인덱스와 쿼리 파이프라인을 캡슐화하며, `search_sessions` API 인터페이스는 완전히 동일하게 유지됩니다.

### 2. PostgreSQL을 위한 3단계 계층적 검색 파이프라인

| 순서 | 검색 방식 | 타임아웃 상한 | 최적 케이스 |
| ---: | :--- | ---: | :--- |
| 1 | `pg_trgm` GIN 인덱스 기반 `ILIKE` (3글자 이상 키워드) | 1초 | 희귀 어휘 검색 |
| 2 | `created_at` 인덱스 기반 역순 스캔 (시간 상한 도달 시 조기 종료) | 3초 | 빈출 어휘 및 2글자 이하 단문 |
| 3 | `tsvector` GIN 인덱스 기반 접두사 검색 (`partial`) | 3초 | 희귀 2글자 단문 |

흔한 단어 검색 시 쿼리 플래너가 모든 매칭 행을 수집하느라 발생하는 성능 저하를 방지하기 위해 2단계 인덱스 스캔을 도입하고 쿼리 타임아웃을 트랜잭션 `SAVEPOINT` 수준에서 격리 제어합니다.

### 3. 데이터베이스 정합성 및 타입 호환성 정비

- PostgreSQL에서 `String(n)` 컬럼은 길이 제약 없는 `TEXT`로 매핑하여 불필요한 데이터 절단을 방지합니다.
- NUL 바이트는 쿼리 실행 직전(`before_cursor_execute`) 자동으로 제거하며, 타임존 없는 Datetime은 명시적 UTC로 일괄 보정합니다.
- `sessions.id`를 참조하는 모든 외래 키에 `ON DELETE CASCADE`를 적용하여 데이터 정합성을 보장합니다.
- 스키마 동적 패치(`_ADDED_COLUMNS`)는 SQLAlchemy 인스펙터를 사용하여 RDBMS 종류에 맞는 DDL을 동적으로 생성하도록 개선했습니다.
- 접속 문자열의 비밀번호는 로그 출력 시 마스킹 처리합니다.

### 4. 긴 외부 I/O 대기 전 커넥션 조기 반환

`SpeechRunner.speak`는 외부 LLM API 호출 직전에 트랜잭션을 명시적으로 커밋하고 커넥션을 풀로 반환합니다. SQLAlchemy 세션은 커밋 후에도 객체 속성을 유지하도록 구성되어 있으므로 후속 로직에 영향이 없습니다. 이를 통해 외부 API 대기 시간 동안 커넥션이 불필요하게 점유되는 현상을 원천 차단했습니다.

### 5. 다중 프로세스 수평 확장을 위한 DB 계층 선제 준비

- 분산 기동 시 동시 스키마 변경 충돌을 방지하기 위해 트랜잭션 권고 잠금(`pg_advisory_xact_lock`)을 적용했습니다.
- 프로세스 생명주기 동안 공유 권고 잠금을 유지하여 단일 인스턴스 전제 작업(비정상 종료 턴 정리 등)의 안전성을 확보했습니다.
- 연결 풀 설정(`db_pool_size`, `db_max_overflow`, `pool_pre_ping`)을 환경 설정으로 완전히 분리했습니다.

## 결과 (Consequences)

**이점**

- `db_url` 설정만으로 SQLite와 PostgreSQL 간의 완전한 무중단 호환성을 확보했습니다.
- 복잡한 검색 쿼리도 최대 3~4초 이내에 완료되도록 엄격한 상한이 적용되어 데이터베이스 락 경합을 방지합니다.
- LLM 호출 중 커넥션을 점유하지 않아 적은 커넥션 풀 크기(`db_pool_size=10`)로도 다수의 동시 토론 세션을 원활히 처리할 수 있습니다.
- 데이터베이스 비밀번호가 로그에 노출되지 않아 엔터프라이즈 보안 요구사항을 충족합니다.
