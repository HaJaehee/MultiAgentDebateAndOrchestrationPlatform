# ADR-009. 작업 공간이 다른 토론은 동시에 돌리지 않는다

> [ADR 목록](README.md) · 이전: [ADR-008](ADR-008-background-debate-runner.md) · 다음: [ADR-010](ADR-010-host-defined-tool-scope.md)

## 상태 (Status)

**대체됨** · 2026-08-28 채택 · 2026-09-09 [ADR-016](ADR-016-per-workspace-mcp-runtime.md)으로 대체

이 결정은 더 이상 유효하지 않습니다. 가용성과 정직성이 부딪혔을 때 이 프로젝트가 무엇을 골랐는지 보여 주는
기록으로 남깁니다.

## 맥락 (Context)

- 에이전트들이 파일을 주고받는 **작업 공간** 폴더를 대화마다 다르게 지정할 수 있게 하려 했습니다. 작업 공간은
  대화의 설정이지 배포 설정이 아니므로, 설정 파일은 건드리지 않고 대화에 저장합니다.
- MCP 서버는 자기가 볼 폴더를 **기동할 때** 받습니다. 파일 시스템 서버는 명령행 인자로, 샌드박스는 환경변수로
  받습니다. 실행 중에는 바꿀 방법이 없습니다.
- 당시 앱에는 MCP 매니저가 하나뿐이었고, 모든 대화가 같은 서버 프로세스를 썼습니다. 작업 공간을 바꾸려면 서버를
  다시 띄워야 했습니다.
- 그러면 A 대화가 토론하는 도중 B 대화가 다른 폴더로 토론을 시작할 때, 서버가 B의 폴더로 다시 뜨면서 **A의 도구가
  B의 파일을 읽고 쓰게** 됩니다. 오류는 나지 않습니다. 결과만 조용히 틀립니다.

## 결정 (Decision)

**조용히 틀리느니 거절한다.**

- 이미 다른 작업 공간의 토론이 진행 중이면, 새 토론 시작을 "작업 공간 충돌" 오류로 거절한다.
- 토론 중에는 작업 공간 변경을 막는다.
- 작업 공간을 바꿀 때는 이미 치환된 명령행 인자에서 경로를 찾아 바꾸지 않고, **치환하기 전의 원래 서버 설정을
  새 경로로 다시 치환**해 서버를 다시 띄운다.

## 결과 (Consequences)

**좋아지는 것**

- 한 대화의 도구가 다른 대화의 파일을 건드리는 일이 원천적으로 없어졌습니다.
- 사용자는 왜 시작할 수 없는지 분명한 메시지를 받았습니다.

**치르는 비용**

- **여러 대화를 동시에 돌릴 수 없었습니다.** 원격 사용자와 서버 PC 주인이 각자 다른 프로젝트 폴더로 토론하는
  사용 방식이 막혔습니다.

**대체된 이유**

열흘 뒤, 작업 공간마다 MCP 서버 묶음을 따로 띄우는 런타임 풀이 들어오면서 이 거절은 필요 없어졌습니다
([ADR-016](ADR-016-per-workspace-mcp-runtime.md)). 거절 규칙 자체는 형태를 바꿔 남았습니다. 이제 거절하는 이유는
"두 폴더를 동시에 열 수 없다"가 아니라 "지금 서버 묶음을 하나 더 띄울 예산이 없다"입니다. 남의 폴더를 조용히
읽고 쓰느니 시작을 막는다는 원칙은 그대로입니다.

**이 ADR에서 배울 점**

- 제대로 된 해결책(런타임 풀)을 당장 만들 수 없을 때, **틀린 결과 대신 명시적인 거절**을 택하는 것도 설계입니다.
- 임시 결정도 기록할 가치가 있습니다. 나중에 대체될 때, 무엇을 지켜야 하는지(여기서는 "남의 폴더를 건드리지
  않는다")가 기록에 남아 있어야 새 설계가 그것을 잃지 않습니다.
