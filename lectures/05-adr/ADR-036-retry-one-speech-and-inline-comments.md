# ADR-036. 단일 발언 재생성(Retry) 및 특정 문장에 대한 인라인 코멘트 전달 기능을 추가한다

> [ADR 목록](README.md) · 이전: [ADR-035](ADR-035-agent-input-modalities.md)

## 상태 (Status)

채택됨 · 2026-10-31 (v1.5.1) · 관련: [ADR-024](ADR-024-resume-interrupted-turns.md), [ADR-025](ADR-025-resume-speeches-by-tool-step.md)

## 맥락 (Context)

- 특정 전문가 에이전트 1명의 발언 내용이 논점에서 벗어나거나 기대와 다르게 작성된 경우에도, 기존에는 턴 전체를 롤백하여 다시 실행하거나 후속 턴에서 추가 요청으로 정정해야만 했습니다.
- 시스템 개입 메모(Intervention note)는 발언 사이에 삽입되어 모든 에이전트의 컨텍스트에 전역으로 공유되었기 때문에, 특정 에이전트의 특정 문장을 지목하여 피드백을 전달할 수 있는 세밀한 수단이 없었습니다.

## 결정 (Decision)

### 1. 발언 레코드는 인플레이스(In-place)로 갱신하고, 이전 버전은 `messages.revisions`로 보존한다

기존 메시지의 ID, 생성 시각 정렬 순서, 라운드 인덱스를 그대로 유지합니다. 이를 통해 결정 장부 반영 시점, 계획 승인 상태, 그래프 구조, 전체 텍스트 검색 색인을 일체 수정할 필요가 없습니다. 이전 버전에서 실행했던 도구 호출 이력은 `message_id` 외래 키 연결을 안전하게 분리하여 감사 로그를 유실하지 않고 버전 단위로 추적할 수 있도록 합니다.

### 2. 전문가 에이전트의 완료된 턴 발언에 한해서만 재생성을 허용한다

계획 수립, 쟁점 취합, 조건부 판정, 최종 합성 등 오케스트레이션 단계는 후속 워크플로의 토대가 되는 메타 발언이므로 단독 재생성을 허용하지 않습니다. 또한 토론이 진행 중인 상태에서는 재생성을 시작할 수 없습니다. 재생성 실행은 러너의 표준 파이프라인을 그대로 활용하여 도구 승인, 사용자 질문, 새로고침 인터페이스를 동일하게 지원합니다.

### 3. 발언 당시 시점의 컨텍스트를 충실히 복원하여 재실행한다

재생성 시 주입되는 프롬프트 맥락은 해당 턴이 시작될 때의 기억과 해당 발언 직전까지의 대화 이력으로 구성됩니다. 병렬 또는 그래프 실행 단계에서 동시에 발언한 동료 에이전트의 발언은 맥락에서 제외합니다. 턴 지침은 발언 당시 기록된 `turn_meta.prompt_tail`을 그대로 복원합니다. 작업 공간 파일 변경은 비가역적이므로 현재 작업 공간 상태를 프롬프트에 명시하고, 이전 버전에서 실행되었던 도구 호출 결과는 관찰 메모로 제공합니다.

### 4. 후속 발언은 자동 재생성하지 않으며, 결정 장부의 일관성은 투명하게 유지한다

단일 발언이 재생성되더라도 이후에 이어진 타 전문가의 발언들은 자동으로 재생성되지 않습니다. 대신 타임라인 끝에 시스템 안내 메시지를 남기고, 결정 장부의 항목들을 새 버전의 발언 내용에 맞게 동기화합니다.

### 5. 인라인 코멘트는 독립 테이블(`speech_comments`)로 관리하며, 발언 기록 커밋 시 전달 완료로 전환한다

인라인 코멘트는 턴 외부에서도 자유롭게 작성할 수 있고 다음 턴 발언 시점까지 대기할 수 있어야 하므로, 인메모리 큐가 아닌 영구 테이블로 관리합니다. 코멘트는 해당 에이전트의 차기 발언 프롬프트 최하단에만 단독으로 주입되며, 공용 대화 기록이나 결정 장부에는 노출되지 않습니다.

## 결과 (Consequences)

**이점**

- 턴 전체를 재실행하지 않고 문제가 된 단일 발언만 신속하게 재생성할 수 있어 토큰 비용과 대기 시간을 획기적으로 절감할 수 있습니다.
- 특정 에이전트의 특정 문장을 드래그하여 직관적으로 코멘트를 작성하고 맞춤형 지침을 전달할 수 있습니다.

**트레이드오프**

- 재생성된 발언 이후에 이미 작성된 후속 발언들은 이전 버전의 논의를 기반으로 남아 있을 수 있으므로, 큰 맥락 전환이 필요한 경우 사용자가 후속 요청으로 정렬해야 합니다.
