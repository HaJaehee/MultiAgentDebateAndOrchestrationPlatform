# MADO로 배우는 멀티 에이전트 시스템 설계

본 강의 자료는 MADO(Multi-Agent Debate & Orchestration Platform)를 기반으로 하여 멀티 에이전트 LLM 애플리케이션을 설계하고 운영하는 실무적인 방법을 다룹니다. MADO는 여러 LLM 에이전트가 MCP 도구를 활용해 사실 관계를 검증하며 토론하고, 그 결과를 코드, 문서, 다이어그램으로 합성해 내는 Python 기반 웹 애플리케이션입니다.

단순히 코드를 한 줄씩 따라 읽는 방식의 강의가 아닙니다. 구체적인 구현 세부 사항은 요구사항에 따라 달라질 수 있지만, "왜 이러한 아키텍처 구조를 선택했는가"에 대한 고민과 해법은 다른 프로젝트에도 범용적으로 적용할 수 있습니다. 따라서 본 강의에서는 핵심 개념을 일반화하여 설명하고, 실제 개발 과정에서 발생했던 다양한 장애와 그때 내린 아키텍처 의사결정을 중심으로 내용을 구성했습니다. 약 한 달 동안 누적된 커밋 기록, 릴리스 노트, 기술 위키가 이 자료의 바탕이 되었습니다.

## 수강 대상

- Python으로 웹 백엔드를 개발해 보신 분
- LLM API를 직접 호출해 본 경험이 있으신 분
- 에이전트나 도구 호출(Function Calling) 개념은 접해 보았으나, 여러 에이전트를 유기적으로 연계해 본 경험이 없으신 분

`asyncio`와 SQL의 기초 개념을 알고 계시면 한결 수월하게 학습하실 수 있습니다. 설령 익숙하지 않으시더라도 전체적인 구조와 흐름을 파악하시는 데에는 지장이 없습니다.

## 권장 학습 순서

처음 학습하시는 분이라면 1강부터 순서대로 학습하시기를 권장합니다. 3강 아키텍처와 5강 ADR은 서로 긴밀하게 상호 참조하고 있습니다. 아키텍처 다이어그램을 확인하시다가 "왜 이러한 구조로 설계되었을까?"라는 의문이 생기시면, 연결된 해당 ADR 문서를 먼저 살펴보신 뒤 돌아오시는 학습 방식을 추천합니다.

이미 멀티 에이전트 시스템을 구축해 보신 경험이 있으시다면, 5강의 ADR부터 먼저 살펴보신 후 세부 구현 기법이 궁금한 항목에 대해 4강의 해당 절을 찾아보시는 방식도 효과적입니다.

## 다이어그램 표기 및 작성 기준

- 본 자료의 다이어그램은 Mermaid로 작성했습니다. GitHub, VS Code(Markdown Preview Mermaid Support 확장 프로그램), Obsidian 등에서 정상적으로 렌더링되어 확인하실 수 있습니다.
- C4 다이어그램은 Mermaid의 플로우차트 문법에 C4 표기법(요소 이름, 종류, 기술, 설명)을 적용하여 작성했습니다. 세부 범례는 [3강 안내](03-architecture/README.md#c4-표기-범례)를 참고하시기 바랍니다.
- 설정 키(`max_rounds`, `debate_priority` 등)는 사용자가 직접 정의하고 수정하는 항목이므로 실제 명칭을 그대로 표기했습니다. 반면 내부 함수나 소스 파일 명칭은 가급적 배제하고 시스템 내 역할 위주로 서술했습니다.
- 본 자료의 기술 내용은 **v0.9.1(2026-09-23)** 버전을 기준으로 작성되었습니다. 이후 버전에서 달라진 변경 사항은 저장소의 릴리스 노트를 확인해 주시기 바랍니다.
