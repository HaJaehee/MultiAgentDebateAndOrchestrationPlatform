# MADO로 배우는 멀티 에이전트 시스템 설계

이 자료는 MADO(Multi-Agent Debate & Orchestration Platform)를 교재 삼아 멀티 에이전트
LLM 애플리케이션을 어떻게 설계하고 운영하는지 다룹니다. MADO는 여러 LLM 에이전트가
MCP 도구로 사실을 확인해 가며 토론하고, 그 결과를 코드와 문서, 다이어그램으로 합성하는
파이썬 웹 애플리케이션입니다.

코드를 한 줄씩 따라 읽는 강의는 아닙니다. 구현 세부는 바뀌지만, 왜 이런 구조가 되었는지는
다른 프로젝트에도 그대로 옮겨 쓸 수 있습니다. 그래서 설명은 되도록 일반화했고, 대신 실제로
있었던 장애와 그때 내린 결정을 많이 실었습니다. 한 달 남짓한 개발 기간 동안 쌓인 커밋 기록,
릴리스 노트, 기술 위키가 이 자료의 원재료입니다.

## 누구를 위한 자료인가

- 파이썬으로 웹 백엔드를 만들어 본 개발자
- LLM API를 한 번이라도 직접 호출해 본 사람
- 에이전트나 도구 호출(function calling)을 들어는 봤지만, 여럿을 엮어 본 적은 없는 사람

asyncio와 SQL의 기초를 알면 읽기 편합니다. 몰라도 흐름을 따라가는 데는 지장이 없습니다.

## 읽는 순서

처음이라면 1강부터 차례대로 읽으세요. 3강과 5강은 서로를 자주 가리킵니다. 아키텍처 그림에서
"왜 이렇게 생겼지?" 싶은 곳이 나오면 해당 ADR로 건너갔다가 돌아오는 방식이 잘 맞습니다.

이미 멀티 에이전트 시스템을 만들어 본 사람이라면 5강 ADR부터 읽고, 궁금한 결정이 생길 때
4강의 해당 절을 찾아보는 것도 좋습니다.

## 표기와 기준

- 다이어그램은 Mermaid로 그렸습니다. GitHub, VS Code(Markdown Preview Mermaid Support 확장),
  Obsidian 등에서 그림으로 보입니다.
- C4 다이어그램은 Mermaid의 순서도 문법에 C4 표기법(요소 이름, 종류, 기술, 설명)을 얹어
  그렸습니다. 범례는 [3강 안내](03-architecture/README.md#c4-표기-범례)에 있습니다.
- 설정 키(`max_rounds`, `debate_priority` 등)는 사용자가 직접 만지는 값이라 그대로 적었습니다.
  반면 함수나 파일 이름은 되도록 쓰지 않고 역할로 불렀습니다.
- 내용은 **v0.9.1(2026-09-23)** 기준입니다. 이후 버전에서 달라진 부분은 저장소의 릴리스 노트를
  확인하세요.
