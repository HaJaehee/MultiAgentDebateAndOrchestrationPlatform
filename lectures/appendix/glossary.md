## 토론의 구성

| 용어 | 뜻 |
| :--- | :--- |
| 에이전트 | 이름, 역할, 모델, 시스템 프롬프트, 쓸 수 있는 도구를 가진 LLM 참가자 |
| 오케스트레이터 | 유일한 필수 에이전트. 계획, 경로 결정(지명, 분배, 게이트, 장부), 최종 합성을 맡는다. 라운드 안에서는 발언하지 않는다 |
| 전문가 | 오케스트레이터가 아닌 에이전트. 아키텍트, 엔지니어, 리뷰어 등 |
| 세션(대화) | 사이드바의 대화 하나. 여러 턴이 쌓인다 |
| 턴 | 사용자 요청 하나가 계획, 토론, 합성을 거쳐 산출물이 되기까지 |
| 라운드 | 한 턴 안에서 전문가들이 한 바퀴 발언하는 단위. 상한은 `max_rounds` |
| 발언 | 에이전트가 한 번 말하는 것. 안에서 도구를 여러 번 부를 수 있다 |
| 도구 루프 | 발언 하나 안에서 "도구 호출 요청 → 실행 → 관찰 결과 전달"을 반복하는 과정 |
| 관찰 결과 (observation) | 도구 실행 결과나 오류 문구. 모델이 읽고 다음 행동을 정한다 |
| 합성 | 토론이 끝난 뒤 오케스트레이터가 결론과 종합 다이어그램을 쓰는 단계 |
| 산출물 | 턴마다 남는 결론 문서, 다이어그램, 전문가 코드, 토론 요약 |
| 합의 | 발언하지 못한 에이전트가 없고, 도중에 끊지 않았고, 합성이 비지 않은 턴 |

## 토론 전략

| 용어 | 뜻 |
| :--- | :--- |
| 토론 전략 | 라운드마다 누가, 어떤 순서로, 어떤 지침을 받고 말할지 정하는 규칙 |
| 순차 토론 | 발언 우선순위 순서로 모두 말하고, 각자 바로 앞 사람의 결론을 이어받는다 |
| 디베이트 | 제안 진영과 비판 진영을 번갈아 세우고 중립은 마지막 |
| 오케스트레이터 지명 | 매 라운드 오케스트레이터가 필요한 사람만 지명 |
| 병렬 지시 | 오케스트레이터가 과업을 나눠 주고 동시에 실행한 뒤 중간 취합 |
| 그래프 토론 | 사람이 그린 그래프(노드와 연결선)대로 흐름을 정한다 |
| 발언 우선순위 (`debate_priority`) | 라운드 안의 순서. 작을수록 먼저 |
| 진영 (`debate_stance`) | 제안, 비판, 중립. 디베이트 전략이 쓴다 |
| 슈퍼스텝 | 그래프 토론에서 새 입력을 받은 노드들이 함께 도는 한 단계 |
| 게이트 | 그래프의 예/아니오 판정 노드. 검토 루프를 닫는다 |
| 대체 경로 | 지명, 분배, 판정이 실패했을 때 물러서는 기본 동작. 물러서면 반드시 기록한다 |
| 개입 메모 | 토론 도중 사람이 보내는 말. 다음 발언자의 맥락에 들어간다 |
| 정지 | 진행 중인 발언은 끝까지 받고 합성으로 넘어간다 |
| 긴급 종료 | 즉시 끊고 이번 턴이 만든 것을 지운다. 보낸 글은 입력창으로 돌아온다 |
| 도구 예산 | 발언 하나에서 허용하는 도구 루프 횟수. 소진되면 사람에게 확장을 묻는다 |

## 에이전트 설정과 상태

| 용어 | 뜻 |
| :--- | :--- |
| 로스터 | 화면 위쪽의 에이전트 카드와 토론 설정 패널 |
| 페르소나 | 이름, 역할, 시스템 프롬프트, 카드 겉모습 |
| 구성 스냅샷 | 첫 메시지 때 대화에 굳힌 에이전트 설정 전체. 이후 그 대화의 정본 |
| 설정 갱신 | 잠긴 대화의 운영 설정만 현재 설정 파일로 다시 굳히는 기능. 페르소나는 유지 |
| 이 대화 전용 | 설정 파일에서는 사라졌지만 스냅샷으로 그 대화에만 남은 에이전트 |
| 정본 (source of truth) | 여러 사본 중 기준이 되는 것. 배포 설정은 설정 파일, 대화는 DB, 진행 중인 턴은 실행기 스냅샷 |
| 작업 공간 | 에이전트들이 파일을 주고받는 폴더. git 저장소. 대화마다 지정 가능 |

## 도구 (MCP)

| 용어 | 뜻 |
| :--- | :--- |
| MCP | Model Context Protocol. LLM 애플리케이션과 도구 서버 사이의 공개 규격 |
| 호스트 | LLM 애플리케이션. MADO 자체 |
| 클라이언트 | 호스트 안에서 도구 서버 하나와의 연결을 맡는 부분 |
| 서버 | 도구를 제공하는 프로그램 |
| stdio 전송 | 호스트가 서버를 자식 프로세스로 띄우고 표준 입출력으로 통신 |
| Streamable HTTP | 이미 떠 있는 서버에 주소로 붙는 전송 방식 |
| 도구 이름공간 | `서버__도구` 형식의 이름. 서버 사이의 이름 충돌을 막는다 |
| 스코프 (`_meta`) | 호스트가 모든 도구 호출에 싣는 대화 ID. 도구 서버 안의 상태를 대화별로 나눈다 |
| 지식 그래프 | memory 서버가 대화별로 유지하는 엔티티와 관계. 컨텍스트가 잘려도 남는 기억 |
| 샌드박스 | 상태가 유지되는 파이썬 커널에서 코드를 실행하는 서버. 커널은 대화 × 발언자 단위 |
| MCP 런타임 | 작업 공간 하나를 위한 도구 서버 프로세스 묶음 |
| 런타임 풀 | 작업 공간별 런타임을 빌려 주고, 참조를 세고, 유휴 런타임을 정리하는 구성 요소 |

## LLM과 컨텍스트

| 용어 | 뜻 |
| :--- | :--- |
| 컨텍스트 창 | 모델이 한 요청에서 읽을 수 있는 최대 토큰 수 (`max_context_window`) |
| 컨텍스트 예산 | 창에서 출력 한도, 여유분, 도구 정의를 뺀 입력 한도 |
| 응답 한도 (`max_tokens`) | 모델이 한 응답에서 생성할 수 있는 최대 토큰 수. 도구 호출 인자와 보이지 않는 추론도 포함 |
| 요청 모양 정리 | 공급자별 대화 규칙(역할 교대 등)에 맞게 메시지를 자르고 합치는 과정 |
| 이어 쓰기 | 응답 한도에서 잘린 답변을 구분자 없이 이어 붙이게 다시 요청하는 것 (`max_continuations`) |
| 요청 지문 | 호출이 실패했을 때 남기는 요청의 모양(역할 순서, 토큰, 도구 수, 큰 메시지). 크기만 남긴다 |
| 사고 흔적 | 단계적 사고의 중간 과정. 사람에게는 보여 줄 수 있지만 다른 에이전트의 프롬프트에는 넣지 않는다 |
| `show_steps` | 사고 과정을 **사람에게** 보여 줄지 정하는 설정 |
| 프롬프트 캐시 | 요청 앞부분이 이전과 같을 때 공급자가 싸고 빠르게 처리하는 기능. 자주 바뀌는 것은 뒤에 둔다 |
| 사용자 발언 기록 | 세션의 모든 사용자 발언을 잘리지 않는 목표 메시지에 고정한 것 |
| 결정 장부 | 오케스트레이터가 라운드마다 갱신하는 요구사항, 결정, 기각안, 쟁점, 담당 목록 |
| 요지 | 발언 끝의 3~5줄 요약. 오래된 긴 발언은 이것만 전달된다 |
| 코드 참조 | 긴 코드 블록을 줄 수, 언어, 첫 줄, 관련 파일로 바꾼 한 줄 |
| 누적 요약 | 창을 넘을 때 오래된 발언을 접어 만든 요약 |
| 이어받기 | 가득 찬 대화에서 기록만 비우고 나머지를 물려주는 새 대화를 만드는 기능 |
| 인수인계 노트 | 이어받은 대화의 첫 메시지. 넘어온 것과 넘어오지 못한 것을 적는다 |

## 배포와 운영

| 용어 | 뜻 |
| :--- | :--- |
| 폐쇄망 | 인터넷과 분리된 망 |
| 전체 번들 | 포터블 런타임, wheel, 도구 서버 설치본까지 담은 패키지. 처음 반입할 때 |
| 소스 갱신 패키지 | 소스와 설명서만 담은 수백 KB 패키지. 코드만 바뀌었을 때 |
| 허용 목록 (allow-list) | 담을 것을 명시한 목록. 목록에 없는 것은 자동으로 빠진다 |
| 루프백 | 같은 PC 안의 접속(`127.0.0.1`, `::1`). MADO는 인증 없이 허용 |
| 접근 토큰 | 원격 접속을 여는 24자 토큰. `.env`에 보관 |
| 닫히는 쪽으로 실패 (fail-closed) | 설정이 잘못되었을 때 접근을 여는 대신 막는 것 |
| WAL | SQLite의 저널 모드. 쓰기마다 저널 파일을 만들지 않고 읽기가 쓰기를 막지 않는다. 네트워크 드라이브에서는 쓰지 않는다 |

## 아키텍처 문서

| 용어 | 뜻 |
| :--- | :--- |
| 정적 뷰 | 구성 요소, 의존, 데이터 구조를 멈춰 놓고 본 모습 |
| 동적 뷰 | 실행 중에 무엇이 어떤 순서로 일어나는지 |
| 배포 뷰 | 어떤 기계, 어떤 런타임, 어떤 프로세스에서 도는지 |
| C4 모델 | 컨텍스트, 컨테이너, 컴포넌트, 코드의 네 단계로 확대해 가며 그리는 방식 |
| C4 컨테이너 | 따로 실행되거나 따로 데이터를 담는 단위. 도커 컨테이너와 다르다 |
| ADR | 아키텍처 결정 기록. 상태, 맥락, 결정, 결과로 이루어진 짧은 문서 |
| 품질 속성 | 기능이 아니라 시스템의 모양을 정하는 요구(신뢰성, 이식성, 격리 등) |
