# 부록 A. 용어집

> [강의 안내](../README.md) · [부록 B. 실습과 토론 과제](exercises.md)

가나다순이 아니라 주제별로 체계화하여 구성했습니다. 생소한 아키텍처 용어나 시스템 개념이 나오면 이 용어집을 참고하시기 바랍니다.

---

## 토론의 구성

| 용어 | 정의 |
| :--- | :--- |
| 에이전트 | 고유 이름, 역할 페르소나, 대상 언어 모델, 시스템 프롬프트, 인가된 도구 권한을 보유한 LLM 토론 참가자입니다. |
| 오케스트레이터 | 시스템의 유일한 필수 시스템 에이전트입니다. 사전 계획 수립, 실행 경로 제어(동적 지명, 태스크 분배, 품질 게이트 평가, 결정 장부 관리), 최종 종합 보고서 작성을 전담하며, 라운드 내부의 일반 토론에는 직접 발언자로 참여하지 않습니다. |
| 전문가 | 오케스트레이터를 제외한 전문 도메인 에이전트들입니다. 소프트웨어 아키텍트, 시니어 엔지니어, 보안 리뷰어 등이 포함됩니다. |
| 세션(대화) | 웹 UI 사이드바에 표시되는 독립된 대화 단위입니다. 내부에 여러 회차의 턴(Turn)이 순차적으로 누적됩니다. |
| 턴 | 단일 사용자 요청이 접수되어 사전 계획 수립, 다자간 토론, 최종 종합 보고서 생성 단계를 거쳐 최종 산출물로 완결되기까지의 전체 실행 주기입니다. |
| 라운드 | 단일 턴 내부에서 참여 전문가 에이전트들이 한 차례씩 발언을 주고받는 순환 단위입니다. 최대 실행 횟수는 `max_rounds` 설정으로 제한됩니다. |
| 발언 | 특정 에이전트가 자신의 차례에 생성하는 단일 응답 단위입니다. 발언 생성 과정에서 도구를 여러 차례 호출할 수 있습니다. |
| 도구 루프 | 단일 발언 생성 과정에서 "도구 호출 요청 → 호스트 실행 → 관찰 결과 주입"을 반복 수행하는 피드백 루프입니다. |
| 관찰 결과 (Observation) | 도구 실행의 반환 데이터 또는 오류 메시지입니다. 언어 모델이 이를 읽고 후속 판단이나 추가 도구 호출 여부를 결정합니다. |
| 합성 | 다자간 토론이 마무리된 후 오케스트레이터가 핵심 아키텍처 결정 사항과 종합 Mermaid 다이어그램을 정리하는 최종 작성 단계입니다. |
| 산출물 | 매 턴마다 시스템에 영속화되는 최종 결론 보고서, 아키텍처 다이어그램, 전문가 코드 발췌본, 토론 요약본의 총칭입니다. |
| 합의 | 통신 실패로 발언하지 못한 응답 누락(미응답) 에이전트가 없고, 사용자가 중도 취소하지 않았으며, 최종 종합 응답이 정상 생성된 완전한 턴을 의미합니다. |

## 토론 전략

| 용어 | 정의 |
| :--- | :--- |
| 토론 전략 | 매 라운드마다 어떤 에이전트가 어떤 순서로, 어떠한 맥락 지침(Guidance)을 부여받아 발언할지를 통제하는 오케스트레이션 알고리즘입니다. |
| 순차 토론 | 발언 우선순위 순서대로 모든 전문가가 순차 발언하며, 직전 발언자의 이름을 호명하고 그의 논거와 결론을 이어받아 발전시키는 전략입니다. |
| 디베이트 | 제안 진영과 비판 진영을 번갈아 교차 배치하여 상호 논박을 유도하고, 중립 진영을 최종 검토자로 배치하는 전략입니다. |
| 오케스트레이터 지명 | 매 라운드마다 오케스트레이터가 지금까지의 토론 흐름을 분석하여 가장 적합한 전문가를 동적으로 선별 호출하는 전략입니다. |
| 병렬 지시 | 오케스트레이터가 전문가들에게 세부 태스크를 분배하고 동시 병렬로 실행을 유도한 뒤, 중간 산출물을 취합하여 진행하는 전략입니다. |
| 그래프 토론 | 사용자가 시각적으로 저작한 유향 그래프(DAG 및 게이트 루프)의 토폴로지에 따라 발언 흐름과 분기를 실행하는 전략입니다. |
| 발언 우선순위 (`debate_priority`) | 단일 라운드 내부에서 발언 순서를 결정하는 정수 속성입니다. 수치가 작을수록 우선순위가 높습니다. |
| 진영 (`debate_stance`) | 에이전트가 취하는 토론 입장(제안, 비판, 중립)을 나타내는 속성이며, 디베이트 전략에서 진영별 순서를 편성할 때 활용됩니다. |
| 슈퍼스텝 | 그래프 토론에서 새로운 입력을 수신한 모든 활성 노드들이 동시 병렬로 실행되는 단일 이산 실행 단위입니다. |
| 게이트 | 그래프 토론에서 조건 분기를 평가하는 Yes/No 판정 노드이며, 피드백 루프의 종료 조건을 결정합니다. |
| 대체 경로 | 발언자 지명, 태스크 분배, 게이트 판정 파싱 등이 실패했을 때 시스템이 안전하게 후퇴하여 동작하는 기본 폴백 경로입니다. 시스템은 대체 경로 전환 사실을 반드시 기록합니다. |
| 개입 메모 | 토론 진행 도중 사용자가 실시간으로 주입하는 피드백 메시지입니다. 즉시 다음 발언자의 입력 컨텍스트에 반영됩니다. |
| 정지 | 현재 발언 중인 에이전트의 응답까지만 정상 수신하고, 후속 라운드를 중단한 채 즉시 최종 종합 단계로 전환하는 명령입니다. |
| 긴급 종료 | 실행 중인 모든 비동기 태스크를 즉시 강제 취소하고, 이번 턴에서 생성된 불완전한 임시 데이터를 삭제하는 명령입니다. 입력했던 메시지는 입력창에 그대로 복원됩니다. |
| 도구 예산 | 단일 발언 내에서 허용되는 도구 호출 루프의 최대 상한선입니다. 예산이 소진되면 사용자에게 승인을 요청하거나 호출을 차단합니다. |

## 에이전트 설정과 상태

| 용어 | 정의 |
| :--- | :--- |
| 로스터 | 웹 UI 상단에 위치한 에이전트 카드 목록 및 토론 전략 설정 패널입니다. |
| 페르소나 | 에이전트의 고유 명칭, 담당 역할, 전문 도메인 시스템 프롬프트, UI 시각 스타일의 총칭입니다. |
| 구성 스냅샷 | 첫 사용자 메시지가 기록되는 순간 세션 레코드에 영구 고정되는 참여 에이전트들의 불변 설정 전체입니다. 해당 세션의 단일 기준점(SSOT)이 됩니다. |
| 설정 갱신 | 고정된 대화 세션의 엔드포인트 및 API 키 설정을 최신 설정 파일(`conf.json`)의 내용으로 다시 동기화하는 비상구 기능입니다. 기존 페르소나 내용은 안전하게 보존됩니다. |
| 이 대화 전용 | 시스템 전역 설정 파일에서는 삭제되었으나, 과거 대화 세션의 스냅샷 데이터에 보존되어 해당 세션에서만 활성화되는 에이전트입니다. |
| 단일 기준점 (Single Source of Truth, SSOT) | 시스템 내 여러 데이터 사본 중 최종 판단 기준이 되는 신뢰할 수 있는 단일 원천입니다. 시스템 배포 설정은 설정 파일, 대화 이력은 SQLite DB, 턴 진행 중 실시간 상태는 실행기 인메모리 스냅샷이 단일 기준점 역할을 수행합니다. |
| 작업 공간 | 에이전트들이 도구를 통해 소스 코드와 문서 파일을 읽고 쓰는 실제 디렉터리입니다. 내부적으로 Git 저장소로 초기화되며, 대화 세션별로 독립 지정할 수 있습니다. |

## 도구 (MCP)

| 용어 | 정의 |
| :--- | :--- |
| MCP | Model Context Protocol의 약어로, LLM 호스트 애플리케이션과 외부 도구 서버 간의 표준 통신 프로토콜 규격입니다. |
| 호스트 | MCP 클라이언트를 내장하여 도구를 호출하고 오케스트레이션을 총괄하는 메인 애플리케이션이며, MADO 자체가 이에 해당합니다. |
| 클라이언트 | 호스트 내부에서 특정 MCP 도구 서버와의 1:1 연결 및 세션 수명 주기를 전담 관리하는 어댑터 컴포넌트입니다. |
| 서버 | 파일 시스템, 코드 샌드박스, 지식 그래프 등 실제 도구 기능을 구현하여 외부에 제공하는 독립 프로그램 프로세스입니다. |
| stdio 전송 | 호스트가 외부 서버를 자식 프로세스로 직접 기동하고, 표준 입출력(stdin/stdout) 스트림을 통해 JSON-RPC 메시지를 교환하는 전송 방식입니다. |
| Streamable HTTP | 이미 외부 네트워크에 독립 기동 중인 원격 MCP 서버에 URL 엔드포인트를 통해 비동기 연결하는 최신 전송 방식입니다. |
| 도구 네임스페이스 | `서버명__도구명` 형식으로 부여되는 고유 식별자입니다. 서로 다른 서버 간의 도구 명칭 충돌을 원천 방지합니다. |
| 스코프 (`_meta`) | 호스트가 모든 도구 호출의 메타데이터 영역에 주입하는 대화 세션 ID입니다. 도구 서버 프로세스 내부의 상태를 세션별로 안전하게 논리 격리합니다. |
| 지식 그래프 | memory MCP 서버가 대화 세션별로 영속화하는 엔티티와 관계망 데이터입니다. 모델의 컨텍스트 창이 축소되더라도 핵심 기억을 유지해 줍니다. |
| 샌드박스 | 상태가 격리 유지되는 파이썬 커널에서 코드를 안전하게 실행하는 도구 서버입니다. 실행 커널은 "대화 세션 × 발언자" 단위로 정밀 격리됩니다. |
| MCP 런타임 | 특정 작업 공간 디렉터리에 바인딩되어 기동하는 외부 도구 서버 프로세스들의 단일 묶음 인스턴스입니다. |
| 런타임 풀 | 작업 공간별로 독립된 MCP 런타임 프로세스 묶음을 동적으로 대여하고, 참조를 추적하며, 유휴 자원을 안전하게 회수하는 자원 관리자 컴포넌트입니다. |

## LLM과 컨텍스트

| 용어 | 정의 |
| :--- | :--- |
| 컨텍스트 창 | 모델이 단일 API 요청에서 처리할 수 있는 최대 토큰 한도(`max_context_window`)입니다. |
| 컨텍스트 예산 | 전체 컨텍스트 창 크기에서 최대 출력 한도, 안전 마진, 등록된 도구 스키마 정의 토큰을 제외한 순수 대화 입력 허용 토큰 한도입니다. |
| 응답 한도 (`max_tokens`) | 모델이 단일 응답에서 생성할 수 있는 최대 토큰 수입니다. 본문 텍스트뿐만 아니라 도구 호출 인자 및 보이지 않는 추론 토큰까지 포함됩니다. |
| 요청 모양 정제 | 상용 공급자별 고유한 대화 포맷 규약(연속된 user 메시지 금지 등)을 충족하도록 메시지 시퀀스를 안전하게 다듬고(트리밍) 병합하는 전처리 과정입니다. |
| 이어 쓰기 (Continuation) | 출력 토큰 한도 도달로 인해 중도에 잘린(Truncated) 응답을 문맥 구분자 없이 매끄럽게 이어서 작성하도록 모델에 추가 요청하는 기능입니다 (`max_continuations`). |
| 요청 핑거프린트 (요청 지문) | API 호출 실패 시 원인 규명을 위해 기록하는 요청의 메타 규격 정보(역할 순서, 토큰 비율, 도구 수, 최대 메시지 바이트 등)입니다. 본문 내용은 배제하고 크기 정보 중심으로 기록합니다. |
| 중간 추론 과정 (Reasoning Trace) | 순차적 사고 모델이 생성하는 중간 사고(추론) 과정입니다. UI 화면을 통해 사람에게는 시각화할 수 있으나, 컨텍스트 오염을 막기 위해 타 에이전트의 프롬프트에는 주입하지 않습니다. |
| `show_steps` | 에이전트의 중간 사고 과정을 브라우저 화면에 표시할지 여부를 제어하는 사용자 전용 디스플레이 설정 플래그입니다. |
| 프롬프트 캐시 | 모델 공급자 측에서 요청 메시지 시퀀스의 앞부분(Prefix)이 이전과 일치할 때 비용을 할인하고 응답 속도를 가속하는 캐싱 메커니즘입니다. 캐시 적중률을 높이기 위해 가변 데이터는 요청의 최하단에 배치합니다. |
| 사용자 발언 고정 | 세션 내의 모든 사용자 지시 발언을 컨텍스트 축소 시에도 절대 잘리지 않는 최상단 목표 메시지 영역에 상시 유지하는 보호 장치입니다. |
| 결정 장부 | 오케스트레이터가 매 라운드 종료 시점마다 갱신하는 요구사항, 확정 결정, 기각 대안, 미해결 쟁점, 담당 태스크 목록의 5대 구조화 기록입니다. |
| 요지 | 모든 에이전트가 발언 말미에 작성하도록 강제되는 3~5줄 분량의 요약 블록입니다. 오래된 과거 발언은 이 요지 블록만을 컨텍스트로 전달합니다. |
| 코드 참조 | 장문의 소스 코드 블록을 줄 수, 프로그래밍 언어, 첫 라인 미리보기, 관련 파일 경로로 축약한 1줄짜리 참조 텍스트입니다. |
| 누적 요약 | 컨텍스트 윈도우 한도를 초과할 때 오래된 대화 이력을 점진적으로 압축하여 생성하는 장기 메모리 요약문입니다. |
| 대화 이어받기 | 컨텍스트가 임계치까지 누적된 대화 세션에서 기존 상세 메시지 로그만을 비우고, 확정된 결정 장부와 지식 그래프 상태를 계승하여 신규 대화를 생성하는 기능입니다. |
| 세션 인계 노트 | 세션 이어받기로 생성된 신규 대화의 첫 번째 시스템 메시지이며, 이전 세션으로부터 정상 승계된 자산과 계승되지 못한 한계 사항을 정직하게 명시합니다. |

## 배포와 운영

| 용어 | 정의 |
| :--- | :--- |
| 폐쇄망 | 외부 공용 인터넷과 물리적 또는 논리적으로 완전히 격리된 고보안 오프라인 네트워크 환경입니다. |
| 전체 번들 | 포터블 CPython 인터프리터, 오프라인 wheel 모음, 사전 설치된 도구 서버 배포본까지 모두 패키징한 아티팩트이며, 최초 시스템 구축이나 런타임 업그레이드 시 반입합니다. |
| 소스 갱신 패키지 | 애플리케이션 비즈니스 소스 코드와 정적 에셋만을 선별하여 구성한 수백 KB 단위의 경량 패치 아카이브입니다. |
| 허용 목록 (Allow-list) | 패키징 대상 파일을 명시적으로 선별한 화이트리스트입니다. 목록에 명시되지 않은 임시 파일이나 비밀 키는 패키징에서 자동 배제됩니다. |
| 로컬 루프백 | 서버 머신 자체 내부에서의 접속(`127.0.0.1`, `::1`)을 의미하며, MADO는 물리적 콘솔 접근으로 신뢰하여 추가 인증 없이 허용합니다. |
| 접근 토큰 | 외부 네트워크에서 인입되는 원격 접속을 인가하기 위해 관리자가 발급하는 24자리 비밀 키입니다. 환경 파일(`.env`)에 안전하게 보관됩니다. |
| 안전 우선 차단 (Fail-closed) | 보안 설정이 누락되거나 비정상적인 오류가 발생했을 때, 접근을 임의로 허용하는 대신 완전히 차단하는 보수적 방어 설계 철학입니다. |
| WAL (Write-Ahead Logging) | SQLite의 고성능 저널 모드입니다. 트랜잭션마다 파일 시스템 저널 파일을 생성하지 않으며 읽기 작업이 쓰기 작업을 차단하지 않도록 지원합니다. 단, 네트워크 파일 시스템에서는 비활성화합니다. |

## 아키텍처 문서

| 용어 | 정의 |
| :--- | :--- |
| 정적 뷰 | 소프트웨어 시스템의 컴포넌트 구성, 계층 간 의존 관계, 데이터 영속화 모델을 정지된 구조적 관점에서 조망한 아키텍처 뷰입니다. |
| 동적 뷰 | 시스템 기동부터 사용자 턴 실행, 도구 피드백 루프, 시스템 종료까지 런타임 상에서 일어나는 실행 흐름과 상태 전이를 시간 순서로 기술한 뷰입니다. |
| 배포 뷰 | 소프트웨어가 실제 물리 머신의 어떤 운영체제, 어떤 프로세스 격리 구조, 어떤 네트워크 토폴로지 상에서 구동되는지를 정의한 뷰입니다. |
| C4 모델 | 소프트웨어 아키텍처를 시스템 컨텍스트(Context), 컨테이너(Containers), 컴포넌트(Components), 코드(Code)의 4단계 줌 레벨로 점진 확대하며 시각화하는 표기 프레임워크입니다. |
| C4 컨테이너 | 물리적 Docker 컨테이너와 구별되며, 독립적으로 실행되거나 자체적인 데이터 영속화 저장소를 보유한 고수준의 단일 배포/실행 단위를 의미합니다. |
| ADR | 아키텍처 결정 기록(Architecture Decision Record)의 약어로, 시스템의 중대한 기술적 결정의 상태, 맥락, 결정 내용, 결과를 간결하게 남기는 의사결정 문서입니다. |
| 품질 속성 | 시스템의 개별 기능(Functionality)을 넘어 성능, 신뢰성, 이식성, 보안성, 유지보수성 등 전체 아키텍처의 비기능적 품질 척도를 정의하는 요구사항입니다. |
