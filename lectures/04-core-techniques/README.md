# 4강. 핵심 기술

> 이전: [3-3. 배포 뷰](../03-architecture/03-deployment-view.md) · 다음: [4-1. 설정](01-configuration.md)

3강이 "무엇이 어디에 있는가"를 봤다면, 4강은 "그것을 어떻게 만들었는가"를 봅니다. 각 절은 한 가지
기술 주제를 다루고, 주제마다 처음에 어떻게 만들었는지, 무엇이 깨졌는지, 어떻게 고쳤는지의 순서로
설명합니다. 특정 파일이나 함수보다 다른 프로젝트에 가져갈 수 있는 기법에 초점을 맞췄습니다.

| 절 | 주제 | 가져갈 수 있는 기법 |
| :--- | :--- | :--- |
| [4-1](01-configuration.md) | 설정을 읽고, 검증하고, 되쓰기 | 원문 되쓰기, 원자적 교체, 주석을 데이터로 다루기, 바꾼 값만 기록 |
| [4-2](02-llm-integration.md) | 여러 공급자의 LLM을 한 인터페이스로 | 요청 모양 정리층, 컨텍스트 예산 계산, 잘림 복구와 이어 쓰기, 요청 지문 |
| [4-3](03-mcp-host.md) | MCP 호스트 만들기 | 장수 세션과 소유 태스크, 호스트가 정하는 스코프, 작업 공간별 런타임 풀 |
| [4-4](04-orchestration.md) | 토론을 조율하는 엔진 | 순수한 전략 객체, 대체 경로 기록, 병렬 라운드, 그래프 실행, 산출물 합성과 다이어그램 수리 |
| [4-5](05-context-memory.md) | 컨텍스트 창과 대화 기억 | 사용자 발언 고정, 결정 장부, 버리기 전에 요약, 발언 요지 전달, 프롬프트 캐시를 고려한 배치 |
| [4-6](06-persistence.md) | 영속화와 스냅샷 | 구성 스냅샷, 정렬 키와 시각 분리, 도구 없는 스키마 이관, 기록을 잃지 않는 저장 |
| [4-7](07-failure-design.md) | 실패를 설계하기 | 실패 경계, 취소와 예외 계층, 정직한 대체 경로, 조용한 실패 찾기 |

4-7은 앞의 여섯 절을 가로지르는 주제입니다. 앞 절들을 읽으면서 "실패하면 어떻게 되지?"라는 질문이
계속 떠오른다면, 4-7에서 한꺼번에 정리됩니다.

## 이 강을 읽는 요령

각 절에는 실제 사고 사례가 많이 나옵니다. 사례를 읽을 때 다음 세 가지를 스스로 물어보세요.

1. **이 문제는 오류 메시지를 냈는가?** 대부분 내지 않았습니다. 결과가 조금 나빠지거나 조용히
   사라졌습니다.
2. **처음 설계에서 이 문제를 예측할 수 있었는가?** 어떤 것은 예측할 수 있었고, 어떤 것은 실제
   엔드포인트나 실제 Windows 환경을 만나기 전에는 알 수 없었습니다.
3. **고친 방법이 증상을 가렸는가, 원인을 없앴는가?** 이 프로젝트는 원인을 없애지 못할 때 최소한
   증상을 드러내는 쪽을 택했습니다.
