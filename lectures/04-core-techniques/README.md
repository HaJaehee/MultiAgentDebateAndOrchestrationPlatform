# 4강. 핵심 기술

> 이전: [3-3. 배포 뷰](../03-architecture/03-deployment-view.md) · 다음: [4-1. 설정](01-configuration.md)

3강에서 전체적인 아키텍처 구조를 조망했다면, 4강에서는 실제 시스템을 지탱하는 세부 핵심 기술과 실무 구현 기법들을 심도 있게 살펴봅니다. 각 절은 하나의 기술 주제를 집중적으로 다루며, 초기 구현 방식에서 마주했던 기술적 한계와 장애, 그리고 이를 극복해 낸 최종 설계의 순서로 설명합니다. 특정 프레임워크나 파일에 종속된 설명보다는 다른 엔지니어링 프로젝트에도 범용적으로 적용할 수 있는 핵심 설계 패턴에 초점을 맞추었습니다.

| 세부 절 | 핵심 주제 | 실무에 적용 가능한 아키텍처 기법 |
| :--- | :--- | :--- |
| **[4-1](01-configuration.md)** | 설정을 읽고, 검증하고, 되쓰기 | 원본 보존 기반 안전한 되쓰기, 원자적 파일 교체, 주석의 데이터화, 변경분 선택적 갱신 |
| **[4-2](02-llm-integration.md)** | 여러 공급자의 LLM을 단일 인터페이스로 통합 | 요청 구조 정리 계층(Sanitization), 컨텍스트 예산 산출, 응답 잘림 복구 및 이어 쓰기, 요청 지문 로깅 |
| **[4-3](03-mcp-host.md)** | 견고한 MCP 호스트 구축 | 장기 지속 세션과 프로세스 수명 관리, 호스트 주도형 세션 스코프 주입, 작업 공간별 런타임 풀 |
| **[4-4](04-orchestration.md)** | 멀티 에이전트 토론 오케스트레이션 | 순수 전략 객체 분리, 대체 경로의 투명한 기록, 동시성 병렬 라운드, DAG 그래프 스케줄링, 다이어그램 자기 수리 |
| **[4-5](05-context-memory.md)** | 컨텍스트 윈도우와 장기 대화 기억 | 핵심 사용자 지침 핀 고정, 누적 결정 장부, 컨텍스트 압축 자동 요약, 발언 요지 추출, 프롬프트 캐시 최적화 |

4-7절은 앞선 6개 절 전체를 관통하는 핵심 아키텍처 철학을 다룹니다. 앞선 절들을 학습하시면서 "만약 이 단계에서 예외가 발생하면 시스템은 어떻게 반응할까?"라는 의문이 생기신다면, 4-7절에서 체계적으로 정리하실 수 있습니다.

## 본 강의를 효과적으로 학습하는 요령

각 절에는 개발 및 운영 과정에서 겪었던 생생한 실제 장애 사례들이 다수 등장합니다. 이러한 사례들을 살펴보실 때 다음 3가지 관점을 염두에 두고 분석해 보시기 바랍니다.

1. **이 장애는 시스템에 명시적인 에러 메시지를 출력했는가?**  
   대부분 명시적인 오류를 출력하지 않았습니다. 겉보기에는 정상 동작하는 것처럼 보이지만 결과물의 품질이 서서히 저하되거나 데이터가 조용히 유실되는 잠재적 결함이었습니다.
2. **초기 설계 단계에서 이러한 문제를 사전에 예측할 수 있었는가?**  
   사전 설계로 예측 가능한 결함도 있었지만, 실제 상용 엔드포인트의 미세한 동작 차이나 폐쇄망 Windows 환경의 파일 잠금 특성에 직접 부딪히기 전에는 파악하기 어려웠던 현실적 문제들이 많았습니다.
3. **적용된 해결책이 단순한 임시방편(증상 완화)인가, 근본적인 구조 개선인가?**  
   근본 원인을 즉각 제거하기 어려운 제약 조건 속에서는, 문제를 은폐하기보다 시스템 실패를 가시화하여 투명하게 드러내는 설계를 선택했습니다.
