# Mermaid 다이어그램 작성 지침

다이어그램은 산출물 뷰어에서 직접 렌더링됩니다. 문법이 어긋나면 최종 합성 완료 후 검사기에서 반려되어 다시 작성해야 하므로, 처음부터 아래의 규칙을 준수해 주시기 바랍니다.

## 기본 구성 규칙

- 코드 블록은 ` ```mermaid `로 시작하며, **첫 줄에 다이어그램 종류를 반드시 선언**합니다: `flowchart TD`, `flowchart LR`, `sequenceDiagram`, `classDiagram`, `stateDiagram-v2`, `erDiagram`.
- 다이어그램 하나에는 단일 종류의 문법만 사용합니다. 순서도(`flowchart`) 내에 시퀀스 문법(`Note right of`, `participant`, `loop`, `alt`, `->>`)을 혼용하지 마십시오. 부가 설명이 필요한 경우 점선으로 연결된 노드를 사용합니다: `api -.- note1["재시도는 3회까지"]`.
- 노드 ID는 영문과 숫자의 조합으로 간결하게 작성하고(`api`, `db1`), 화면에 표시될 명칭은 라벨에 기재합니다: `api["주문 API"]`.

## 라벨 표기

- **괄호가 포함된 라벨은 반드시 큰따옴표로 감싸야 합니다**: `pg["결제 대행사 (PG)"]`. 큰따옴표가 없는 `pg[결제 대행사 (PG)]`는 문법 오류로 처리됩니다. 다른 특수문자가 섞여 있는 경우에도 큰따옴표로 감싸면 안전합니다.
- 라벨 내부에는 큰따옴표를 중복해서 사용하지 마십시오. 필요한 경우 `&quot;`를 사용합니다.
- 연결선 라벨 표기: `a -->|요청| b` 또는 `a -- 요청 --> b` 형식을 사용합니다.

## subgraph

- `subgraph 아이디["제목"]` … `end` 형식으로 작성합니다. 큰따옴표가 누락된 `subgraph 아이디 "제목"` 형식은 거부됩니다.
- 열린 `subgraph`의 개수와 닫는 `end`의 개수를 반드시 일치시켜 주십시오.
- 소문자 `end`는 예약어이므로 노드 식별자로 사용할 수 없습니다 (`done`, `END` 등으로 변경합니다).

## 스타일 지정

- `style` 및 `classDef`에서 사용하는 색상 코드는 `#1f77b4`와 같이 16진수(HEX)로 작성합니다. `rgb(...)` 형식은 쉼표 구분자로 인해 구문 분석 오류가 발생합니다.

## 시퀀스 다이어그램

- 화살표는 `->>`, `-->>`, `->`, `-->`, `-x`, `-)`만 지원됩니다. `==>`는 지원되지 않습니다.
- 참여자 명칭에 공백이나 특수문자가 포함된 경우 별칭(Alias)을 정의하여 사용합니다: `participant PG as 결제 대행사`.

## 최종 점검

다이어그램을 발언이나 결론에 포함하기 전에 `reference.md`의 체크리스트를 확인해 주시기 바랍니다. 자주 발생하는 오류 유형과 올바른 수정 예시가 정리되어 있습니다.
