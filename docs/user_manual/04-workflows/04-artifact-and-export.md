# 산출물 생성과 내보내기

> 상위: [워크플로우 개관](README.md) · 이전: [로스터 편집](03-roster-editing.md) · 다음: [폐쇄망 배포](05-airgap-deployment.md)
>
> 파일: `app/orchestration/engine.py` (추출) · `app/ui/components/artifact_viewer.py` (렌더링) · `app/export.py` (내보내기)

토론이 끝나면 두 가지가 남습니다. **산출물**(결론·다이어그램·코드)과
**대화 기록 전체**입니다. 둘은 다른 경로로 나갑니다.

오케스트레이터가 쓰는 것은 **최종 결론과 종합 다이어그램까지**입니다. 소스 코드는 다시 쓰지
않습니다 — 코드 산출물은 이번 턴 전문가 발언에서 모읍니다. 예전에는 합성이 전문가 코드를
통째로 다시 출력해 응답 한도를 채웠고, 그 합성이 다음 턴 전사에 다시 들어가 컨텍스트가 빠르게
찼습니다.

---

## 산출물 파이프라인

```text
오케스트레이터 합성 응답 (결론 + 종합 다이어그램)      이번 턴 전문가 발언
   │                                                   │
   ▼                                                   ▼
_extract_artifacts_from_synthesis() ◀──────────────────┘
   │  결론 → 보고서 탭, ```mermaid → 다이어그램 탭
   │  전문가마다 가장 최근에 낸 코드 → 코드 탭
   ▼
ArtifactItem  ─── DB(ArtifactModel) 저장
   │
   ▼
artifacts_synthesized 이벤트 ──▶ 산출물 뷰어에 **덧붙임**
```

### 한 턴이 남기는 탭

제목 앞에 턴이 끝난 시각(`MM-DD HH:MM`)이 붙습니다. 탭은 턴마다 쌓이므로 어느 턴의 것인지
보여야 합니다.

| 탭 | 출처 |
| :--- | :--- |
| `09-14 10:32 최종 결론` | 합성 본문 (끝에 완료 시각·총 경과) |
| `09-14 10:32 종합 다이어그램` | 합성의 ```mermaid. 없으면 이번 턴 발언에서 가장 최근 다이어그램 |
| `09-14 10:32 python · Senior Python Engineer R2` | 전문가마다 이번 턴에 가장 최근 코드를 낸 발언. 같은 코드는 한 번, 최대 12개 |
| `09-14 10:32 토론 요약 (JSON)` | 참여자·라운드·실패·합의 여부 |

이전 턴의 코드는 그 턴의 탭으로 이미 남아 있어 다시 올리지 않습니다.

### 합성이 비었거나 실패했을 때

오케스트레이터가 엔드포인트에 못 닿았거나(`합성 실패 (LLM 연결 끊김)`), 연결은 됐는데 결론이
비어 있으면(`합성 실패 (빈 응답)` — 컨텍스트가 가득 찼거나, 답을 사고 안에만 썼거나, 응답
한도를 사고에 다 쓴 경우) 빈 보고서를 정상 결론으로 저장하지 않습니다. 대신 **LLM 없이 모은
전문가별 마지막 발언**을 그 탭에 담습니다. 한도·빈 답변을 알리는 꼬리표(`> ⚠️ ...`)만 붙은 답도
빈 답으로 봅니다. 이 턴은 합의에 이르지 않은 것으로 기록됩니다.

결론이 필요하면 같은 대화에서 "결론만 다시 정리해 줘" 처럼 요청하세요.

## 작업 공간 파일 다운로드

토론이 작업 공간에 만든 파일(코드, 문서, 올린 파일)을 받아 갑니다. 같은 망의 다른 PC 에서 쓸 때는
이것이 결과물을 가져가는 길입니다.

| 여는 곳 | 버튼 |
| :--- | :--- |
| 에이전트 설정 패널, 작업 공간 입력란 바로 아래 | `작업 공간 파일 다운로드` (적용된 폴더가 있을 때만 켜짐) |
| 산출물 뷰어의 보고서(마크다운) 탭 머리 | `작업 공간 파일` |
| 보고서 본문 끝 | `이 작업 공간의 파일 다운로드` |

```text
WorkspaceDownloadDialog.open()
   │  목록을 새로 훑음 (에이전트가 방금 만든 파일 포함), 최근 수정 순
   ▼
고르기 ── 1개 ──▶ 그 파일
      └─ 여러 개 ─▶ build_workspace_zip() ── 이벤트 루프 밖에서 zip 생성
   ▼
serve_once(): 한 번만 쓰이는 새 주소, 캐시 안 함 ──▶ 브라우저 다운로드
```

| 안전장치 | 내용 |
| :--- | :--- |
| 경로 재확인 | 화면이 보낸 경로를 받기 직전에 `plan_download()` 가 다시 풀어 작업 공간 밖·없는 파일은 뺌 |
| 한도 | 한 번에 5,000개, 압축 전 1 GB. 넘으면 만들지 않고 알림 |
| 압축 보관 | `data/downloads/` (작업 공간 밖이라 에이전트 목록에 안 섞임), 1시간 뒤 삭제 |
| 오래된 내용 방지 | NiceGUI 기본 다운로드는 파일 경로로 주소를 만들고 1시간 캐시해, 고친 파일을 다시 받으면 예전 내용이 나왔음 → 받을 때마다 새 주소, `max-age=0`, 한 번 받으면 주소 삭제 |

> 접속 인증은 아직 없습니다. 외부에 열면 누구나 받을 수 있으니, 토큰 인증이 들어가기 전에는
> `127.0.0.1` 로만 여세요.

## 산출물 뷰어

각 산출물이 탭 하나입니다. 턴이 끝나면 그 턴의 탭이 **뒤에 붙고**, 가장 최근 보고서가 열립니다.
이전 턴의 탭은 그대로 남습니다. 토론 중에 페이지를 새로 고쳐도 DB 에 저장된 탭과 진행 중인
턴의 탭을 합쳐 보여 줍니다.

> 예전에는 턴이 끝날 때 뷰어를 그 턴의 산출물로 **통째로 바꿨습니다.** 라운드가 쌓인
> 세션에서 최근 턴 것만 남았고, 합성이 빈 답을 낸 턴이면 빈 보고서 하나만 남아 토론 결과가
> 사라진 것처럼 보였습니다 (DB 에는 남아 있었습니다).

탭마다:

| 조작 | 동작 |
| :--- | :--- |
| **복사** | 클립보드로 (`app/ui/clipboard.py`) |
| **다운로드** | 종류에 맞는 확장자로 파일 저장 |

### Mermaid 렌더링

Mermaid 블록은 다이어그램으로 그립니다. 문법 오류가 있으면 **오류를 표시하고
원본 소스를 보여줍니다** — 빈 상자를 남기지 않습니다. LLM 이 만든 Mermaid 는
문법이 어긋나는 일이 흔하므로, `normalize_mermaid()` 가 흔한 문제(따옴표,
줄바꿈, 노드 라벨의 특수문자)를 먼저 정리합니다.

**순서도에 섞인 시퀀스 다이어그램 문법 (v0.8.1).** 모델이 `flowchart` 안에 `Note right of X: …`,
`loop …`, `participant …` 같은 시퀀스 다이어그램 문법을 넣으면 렌더러가 통째로 거부합니다
(`Expecting 'SEMI', … got 'NODE_STRING'`).

| 경우 | 처리 |
| :--- | :--- |
| `Note right of/left of/over X: 글` | LLM 없이 `X -.- mado_note_1["글"]` 로 바꿈 (점선으로 붙인 노트 노드) |
| `loop`·`alt`·`participant`·`->>` 등 | 검사 규칙 `sequence-syntax-in-flowchart` 에 걸림 → 합성이면 오케스트레이터에게 수선 요청 |
| 수선 뒤에도 틀림, 또는 전문가 발언에서 가져온 다이어그램이 틀림 | 탭 제목 앞에 `⚠` |

전문가 발언에서 가져온 다이어그램(합성에 다이어그램이 없거나 합성이 실패한 턴)은 LLM 수선을
거치지 않으므로 기계적 수선과 `⚠` 표시가 전부입니다. `Note` 를 노드 이름으로 쓴 경우
(`Note --> B`)나 시퀀스·상태·클래스 다이어그램의 `note` 는 정상이라 건드리지 않습니다.

## 대화 기록 내보내기

`app/export.py` 가 대화 하나를 **마크다운 문서 한 장**으로 만듭니다.

```text
# {대화 제목}

| 항목 | 값 |
| --- | --- |
| 생성 | 2026-08-30 14:22 |
| 최종 수정 | 2026-08-30 15:07 |
| 토론 전략 | 순차 토론 (Sequential Debate) |
| 최대 라운드 | 3 |
| 참여 에이전트 | orchestrator, architect, coder, critic |
| 작업 공간 | D:\work\project-a |

## 세션 전용 지침
...

## 발언 기록
### 🙋 사용자
### 🧭 오케스트레이터  (Round 0)
### 🤖 System Architect  (Round 1)
   └ 🔧 filesystem__read_text_file  ▸ 인자 / 결과
### ⚠️ 실패 — Security & Quality Critic

## 최종 산출물
...
```

| 표지 | 발언 종류 |
| :--- | :--- |
| 🙋 사용자 | `user` |
| 🧭 오케스트레이터 | `orchestrator` |
| 🤖 에이전트 | `agent` |
| ⚠️ 실패 | `error` |
| ⚙️ 시스템 | `system` |

**누가 무슨 자격으로 말했는지가 한눈에 보여야** 합니다. 실패도 기록에 남으므로,
문서를 읽는 사람이 "네 명이 합의했다" 와 "두 명이 침묵했다" 를 구분할 수 있습니다.

### 설계 두 가지

**순수 함수입니다.** DB 를 모릅니다. 화면이 읽어 온 값을 넘기기만 하고, 이
파일은 그것을 문서로만 바꿉니다. 그래서 테스트가 DB 없이 돕니다.

**전략 이름은 지금 값을 씁니다.**

```python
("토론 전략", get_strategy(session.get("strategy")).display_name)
```

저장된 키가 아니라 **이 대화가 실제로 도는 전략**의 이름을 적습니다. 예전
이름(`free_debate`)으로 저장된 대화는 이어서 진행하면 지금 전략으로 돌아가므로,
문서에 없어진 키를 남겨 두면 **그 문서가 거짓말을 하게 됩니다.**

### 도구 기록의 중복 방지

도구 실행 기록은 보통 발언에 붙어 나옵니다. 어느 발언에서 나왔는지 기록이 남지
않은 항목만 문서 끝에 따로 모읍니다 — 발언에 붙은 것을 여기서 또 보여주면 같은
내용이 두 번 나옵니다.

### 파일 이름

```python
safe_filename("JWT 인증 설계", when=created_at)
# → "JWT_인증_설계_20260830-1422.md"
```

Windows 에서 쓸 수 없는 문자를 걸러내고, 제목이 비어도 날짜로 이름이 남습니다.

## 시각 처리

DB 에는 **UTC 로 저장**하고(`utc_now()`), 문서에 쓸 때 로컬로 옮깁니다
(`to_local()`). 파일 이름의 타임스탬프도 같은 값을 씁니다 — 문서 안의 시각과
파일 이름이 어긋나면 안 됩니다.

## 산출물은 어디에 남는가

| 위치 | 무엇 | 세션 삭제 시 |
| :--- | :--- | :--- |
| DB `artifacts` | 합성된 코드·문서·다이어그램 | 함께 삭제 |
| 작업 공간 폴더 | 에이전트가 MCP 로 **실제로 만든 파일** | **남음** |
| 내보낸 마크다운 | 사용자가 저장한 위치 | 무관 |

작업 공간 파일이 남는 이유: 에이전트가 만든 파일은 대화 기록과 별개의
산출물이고, 여러 대화가 같은 폴더를 공유할 수도 있습니다. git MCP 서버를 켜
두었다면 라운드별 변화가 커밋으로도 남습니다.
