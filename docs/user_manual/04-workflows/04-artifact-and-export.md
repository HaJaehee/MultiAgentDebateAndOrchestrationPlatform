# 산출물 생성과 내보내기

> 상위: [워크플로우 개관](README.md) · 이전: [로스터 편집](03-roster-editing.md) · 다음: [폐쇄망 배포](05-airgap-deployment.md)
>
> 관련 소스: `app/orchestration/engine.py` (추출) · `app/ui/components/artifact_viewer.py` (렌더링) · `app/export.py` (내보내기)

토론 턴이 완료되면 시스템에는 두 가지 핵심 자산이 영속화됩니다: 정제된 **산출물(Artifacts)**(종합 결론 보고서, 아키텍처 다이어그램, 소스 코드)과 **전체 대화 및 도구 실행 기록(Transcript)**입니다. 두 데이터는 목적에 따라 서로 다른 파이프라인을 통해 제공됩니다.

오케스트레이터 모델이 직접 작성하는 산출물은 **최종 결론 보고서와 종합 Mermaid 다이어그램까지**로 엄격히 한정됩니다. 전문 에이전트들이 작성한 소스 코드를 합성 단계에서 중복 작성하지 않으며, 코드 산출물은 이번 턴 전문가 발언 내의 코드 블록에서 자동으로 수집합니다. 과거에는 오케스트레이터가 전문가 코드를 본문에서 전부 재출력하여 LLM 응답 토큰 한도를 소진했을 뿐만 아니라, 거대한 코드 덤프가 다음 턴의 프롬프트 전사에 누적 주입되어 컨텍스트 창이 조기 포화되는 심각한 비효율이 발생했기 때문입니다.

## 산출물 추출 및 렌더링 파이프라인

```text
오케스트레이터 합성 응답 (결론 + 종합 다이어그램)      이번 턴 전문가 에이전트 발언들
   │                                                   │
   ▼                                                   ▼
_extract_artifacts_from_synthesis() ◀──────────────────┘
   │  결론 텍스트 → 보고서 탭, ```mermaid → 종합 다이어그램 탭
   │  전문가별 가장 최근 작성된 코드 블록 추출 → 개별 코드 탭
   ▼
ArtifactItem 인스턴스 생성 ─── DB(ArtifactModel) 영구 저장
   │
   ▼
artifacts_synthesized 웹소켓 이벤트 ──▶ 산출물 뷰어 패널에 신규 탭으로 **누적 덧붙임**
```

### 한 턴이 생성하는 탭 구성

탭 제목 접두사에는 해당 턴이 완료된 타임스탬프(`MM-DD HH:MM`)가 표시됩니다. 여러 턴이 진행되면서 탭이 지속적으로 누적되므로 어느 턴에서 도출된 결과물인지 명확히 식별할 수 있어야 합니다.

| 탭 명칭 예시 | 데이터 출처 및 수집 기준 |
| :--- | :--- |
| `09-14 10:32 최종 결론` | 오케스트레이터 합성 본문 (말미에 턴 완료 시각 및 총 소요 시간 기록) |
| `09-14 10:32 종합 다이어그램` | 합성 본문의 ```mermaid 블록 (부재 시 이번 턴 전문가 발언 중 최신 다이어그램) |
| `09-14 10:32 python · Senior Python Engineer R2` | 전문가 에이전트별 이번 턴 최신 코드 블록 (중복 코드 제거, 최대 12개) |
| `09-14 10:32 토론 요약 (JSON)` | 참여 에이전트 목록, 진행 라운드 수, 실패 에이전트, 전원 합의 여부 메타데이터 |

이전 턴의 산출물은 기존 탭으로 영구 보존되므로 현재 턴에서 중복 생성하지 않습니다.

### 최종 합성이 비어 있거나 실패했을 때의 폴백 처리

오케스트레이터가 외부 엔드포인트 연결 장애(`합성 실패 (LLM 연결 끊김)`)를 겪었거나, 연결은 성공했으나 결론 본문이 비어 있는 경우(`합성 실패 (빈 응답)` — 컨텍스트 한도 초과, 사고 블록 내에만 답변 작성, 응답 토큰을 사고 과정에서 전량 소진 등) 빈 보고서를 정상 결론으로 저장하지 않습니다.
대신 **별도의 LLM 호출 없이 이번 턴 각 전문가 에이전트의 마지막 발언을 취합**하여 보고서 탭에 안전하게 보존합니다. 한도 도달이나 빈 답변 알림 꼬리표(`> ⚠️ ...`)만 존재하는 응답 역시 비어 있는 것으로 간주합니다. 이 경우 해당 턴은 전원 합의에 도달하지 못한 상태(`is_consensus_reached = False`)로 기록됩니다.

만약 결론 도출이 반드시 필요한 경우, 동일한 대화 세션에서 "앞선 논의를 바탕으로 최종 결론만 간결히 요약해 주세요"와 같이 후속 요청을 전송하여 보완할 수 있습니다.

## 작업 공간(Workspace) 파일 다운로드 기능

토론 과정에서 에이전트들이 작업 공간 디렉터리에 실제로 생성하거나 수정한 소스 코드, 문서 파일, 사용자가 업로드한 첨부 파일 등을 웹 브라우저를 통해 손쉽게 다운로드할 수 있습니다. 동일 네트워크의 다른 PC에서 원격 접속하여 작업할 때 최종 산출물을 로컬 장비로 반출하는 표준 경로입니다.

| UI 위치 | 다운로드 진입 버튼 |
| :--- | :--- |
| 로스터 패널, 작업 공간 경로 입력란 바로 하단 | `작업 공간 파일 다운로드` (유효한 폴더가 바인딩된 경우 활성화) |
| 산출물 뷰어의 보고서(마크다운) 탭 상단 헤더 | `작업 공간 파일` 버튼 |
| 산출물 보고서 본문 최하단 | `이 작업 공간의 파일 다운로드` 링크 |

```text
WorkspaceDownloadDialog.open()
   │  작업 공간 파일 목록 실시간 스캔 (에이전트가 방금 생성한 파일 즉시 반영, 최신 수정순)
   ▼
사용자 선택 ── 단일 파일 ──▶ 해당 단일 파일 즉시 전송
             └── 다중 파일 ──▶ build_workspace_zip() ── 별도 스레드에서 zip 압축 생성
   ▼
serve_once(): 1회용 고유 임시 URL 발급, 브라우저 캐시 무효화 ──▶ 브라우저 다운로드 실행
```

| 안전장치 및 최적화 | 상세 구현 내용 |
| :--- | :--- |
| **경로 유효성 재검증** | 프론트엔드가 요청한 파일 경로를 디스크에서 읽기 직전 `plan_download()`가 절대 경로로 재해석하여, 작업 공간 외부 경로(`..`)나 존재하지 않는 파일은 다운로드 목록에서 사전에 원천 배제합니다. |
| **용량 및 파일 수 제한** | 1회 다운로드 시 최대 5,000개 파일, 압축 전 원본 기준 최대 1GB로 엄격히 제한됩니다. 한도를 초과하면 zip 생성을 즉시 중단하고 사용자에게 경고를 표시합니다. |
| **임시 압축 파일 격리** | 생성된 zip 파일은 `data/downloads/` 디렉터리에 저장됩니다. 작업 공간 외부 폴더이므로 에이전트의 파일 검색이나 자동완성 목록에 불필요하게 섞이지 않으며, 1시간 경과 시 백그라운드에서 자동 삭제됩니다. |
| **오래된 캐시 방지 (Cache Busting)** | NiceGUI 기본 정적 다운로드는 고정 파일 URL을 생성하고 브라우저가 1시간 동안 캐시하므로, 에이전트가 파일을 수정한 후 다시 다운로드했을 때 구버전 파일이 다운로드되는 버그가 있었습니다. MADO는 매 다운로드 요청마다 일회성 고유 URL(`serve_once()`), `Cache-Control: max-age=0, no-cache`, 1회 다운로드 완료 즉시 URL 메모리 해제 방식을 적용하여 항상 가장 최신의 파일을 안전하게 제공합니다. |

> [!NOTE]
> 외부 PC에서 접속하는 경우 원격 접속 토큰(REMOTE_ACCESS_TOKEN)으로 인증된 사용자만 파일 다운로드 기능을 이용할 수 있습니다 ([conf.json 설정 가이드](../02-getting-started/02-configuration.md#보안-및-원격-접속) 참고).

## 산출물 뷰어 컴포넌트

각 산출물은 개별 탭으로 구성됩니다. 새로운 토론 턴이 완료되면 해당 턴의 탭들이 **기존 탭 목록의 뒤에 순차적으로 추가**되며, 가장 최근에 생성된 종합 보고서 탭이 자동으로 열립니다. 이전 턴들의 산출물 탭은 그대로 안전하게 유지됩니다. 토론 진행 도중 사용자가 브라우저를 새로고침하더라도 데이터베이스에 영속화된 기존 탭과 메모리에서 진행 중인 턴의 탭을 정합성 있게 병합하여 렌더링합니다.

> [!NOTE]
> 과거 버전에서는 새로운 턴이 완료될 때마다 뷰어의 탭 목록을 해당 턴의 결과물로 **통째로 교체**했습니다. 이로 인해 다중 턴으로 진행된 세션에서 이전 턴의 산출물을 다시 확인할 수 없었고, 만약 특정 턴에서 합성 실패가 발생하면 뷰어 전체가 빈 화면으로 전환되어 기존 작업 결과가 모두 사라진 것처럼 오인되는 문제가 있었습니다. 현재는 모든 턴의 산출물이 영구 누적 보존됩니다.

| 탭 상단 조작 버튼 | 동작 |
| :--- | :--- |
| **복사** | 해당 탭의 본문 텍스트 전체를 운영체제 클립보드로 복사합니다 (`app/ui/clipboard.py`). |
| **다운로드** | 산출물 유형에 적합한 확장자(`.md`, `.mermaid`, `.py`, `.json` 등)로 로컬에 파일로 저장합니다. |

### Mermaid 다이어그램 실시간 렌더링 및 자동 보정

마크다운 내의 Mermaid 코드 블록은 시각적 다이어그램으로 자동 변환 렌더링됩니다. 문법 오류가 발생할 경우 **에러 메시지와 함께 원본 소스 코드를 표시**하여 빈 상자로 방치되는 현상을 방지합니다. LLM이 생성하는 Mermaid 문법은 사소한 오타나 따옴표 누락이 잦으므로, `normalize_mermaid()` 전처리기가 일반적인 오류(잘못된 따옴표, 불필요한 줄바꿈, 노드 라벨 내 특수문자 등)를 1차적으로 자동 교정합니다.

**플로우차트 내 시퀀스 다이어그램 문법 혼용 자동 보정 (v0.8.1)**:
LLM 모델이 `flowchart` 정의 내에 `Note right of X: …`, `loop …`, `participant …`와 같은 시퀀스 다이어그램 전용 문법을 무의식중에 혼용하여 작성하면 Mermaid 파서가 전체 렌더링을 거부하는 문제가 발생합니다 (`Expecting 'SEMI', … got 'NODE_STRING'`).

| 발생 상황 | 자동 처리 및 보정 메커니즘 |
| :--- | :--- |
| `Note right of/left of/over X: 설명` | LLM 재호출 없이 `X -.- mado_note_1["설명"]` 형태로 즉시 치환 (점선으로 연결된 노트 노드 변환) |
| `loop`, `alt`, `participant`, `->>` 등 시퀀스 키워드 혼용 | `sequence-syntax-in-flowchart` 유효성 검사 트리거 → 최종 합성 단계인 경우 오케스트레이터에게 수선 재작성 요청 |
| 수선 이후에도 오류가 지속되거나 전문가 발언에서 가져온 다이어그램 오류 | 탭 제목 앞에 `⚠` 경고 아이콘을 부착하고 원문 텍스트와 함께 렌더링 |

전문가 발언에서 가져온 다이어그램(합성에 다이어그램이 없거나 합성이 실패한 턴)은 LLM 수선을 거치지 않으므로 기계적 수선과 `⚠` 표시가 적용됩니다. `Note`를 일반 노드 식별자로 사용하는 올바른 순서도 문법(`Note --> B`)이나 시퀀스/상태/클래스 다이어그램 내의 표준 `note` 구문은 정상적인 문법이므로 임의로 수정하지 않습니다.

## 대화 기록 마크다운 내보내기

`app/export.py` 모듈은 단일 대화 세션의 모든 논의 과정과 산출물을 **완전한 단일 마크다운(.md) 보고서 문서**로 변환합니다.

```text
# {대화 세션 제목}

| 메타데이터 항목 | 설정값 |
| --- | --- |
| 세션 생성 시각 | 2026-08-30 14:22 |
| 최종 수정 시각 | 2026-08-30 15:07 |
| 적용 토론 전략 | 순차 토론 (Sequential Debate) |
| 최대 라운드 수 | 3 |
| 참여 에이전트 | orchestrator, architect, coder, critic |
| 작업 공간 경로 | D:\work\project-a |

## 세션 전용 커스텀 지침
...

## 전체 발언 기록
### 🙋 사용자
### 🧭 오케스트레이터  (Round 0 계획 수립)
### 🤖 System Architect  (Round 1)
   └ 🔧 filesystem__read_text_file  ▸ 호출 인자 및 관측 결과
### ⚠️ 발언 실패 — Security & Quality Critic (엔드포인트 연결 불가)

## 최종 산출물 모음
...
```

| 식별 표지 | 발언 주체 및 메시지 유형 |
| :--- | :--- |
| 🙋 **사용자** | `user` (초기 요청 및 토론 도중 개입 메모) |
| 🧭 **오케스트레이터** | `orchestrator` (목표 계획 수립, 발언자 지명, 라운드 취합, 최종 합성) |
| 🤖 **전문가 에이전트** | `agent` (각 도메인 전문가 에이전트의 정규 발언) |
| ⚠️ **발언 실패** | `error` (네트워크 장애나 타임아웃으로 인한 연결 실패 알림) |
| ⚙️ **시스템** | `system` (시스템 상태 안내 및 이벤트) |

**누가 어떤 자격으로 발언했는지를 한눈에 식별할 수 있어야 합니다.** 실패 상태 역시 문서에 투명하게 기록되므로, 보고서를 검토하는 사람이 '모든 전문가가 정상 합의한 결과'인지 '일부 전문가의 응답 불가로 인한 부분 합의'인지를 명확히 판별할 수 있습니다.

### 내보내기 엔진의 두 가지 핵심 설계

1. **데이터베이스 의존성이 없는 순수 함수 구조**: `export_session_markdown()`은 DB 계층과 완전히 분리된 순수 함수입니다. UI나 서비스 레이어가 조회해 온 데이터 딕셔너리만을 입력받아 마크다운 텍스트로 변환하므로, 단위 테스트 작성 시 데이터베이스 모킹 없이도 신속하고 안정적인 검증이 가능합니다.
2. **현재 유효한 전략 명칭 표기**:
   ```python
   ("토론 전략", get_strategy(session.get("strategy")).display_name)
   ```
   과거 버전의 레거시 식별자(`free_debate` 등)로 DB에 저장되어 있더라도, 내보내기 문서에는 **현재 시스템에서 실제로 동작하는 정규화된 전략 명칭**(`순차 토론 (Sequential Debate)`)을 명시합니다. 대화를 재개했을 때 실제로 실행되는 동작과 내보낸 문서의 설명이 불일치하는 정보 왜곡을 방지하기 위함입니다.

### 도구 실행 이력의 중복 출력 방지

각 도구 실행 이력은 원칙적으로 이를 호출한 해당 에이전트의 발언 블록 하단에 트리 형태로 인라인 첨부됩니다. 호출 발언 정보가 누락된 예외적인 도구 실행 기록만 문서 말미의 '독립 도구 실행 이력' 섹션에 모아 출력함으로써 동일한 내용이 문서 내에서 중복 노출되는 현상을 깔끔하게 방지합니다.

### 안전한 파일명 생성 규칙

```python
safe_filename("JWT 인증 설계", when=created_at)
# → "JWT_인증_설계_20260830-1422.md"
```

Windows를 포함한 모든 운영체제에서 파일 시스템 금지 문자를 안전한 언더스코어(`_`)로 치환하며, 세션 제목이 비어 있는 경우에도 타임스탬프 기반으로 유일한 파일명을 자동 생성합니다.

## 타임존(시각) 일관성 처리

모든 시간 데이터는 데이터베이스에 **철저히 UTC 기준으로 저장**되며(`utc_now()`), 내보내기 문서를 생성할 때 비로소 로컬 시간대로 안전하게 변환됩니다(`to_local()`). 문서 파일명에 포함되는 날짜/시간 스탬프 역시 본문과 동일한 로컬 시간을 사용하여 문서 내외의 시간 정보 불일치를 원천 차단합니다.

## 산출물 영속화 위치 및 생애주기

| 보관 위치 | 저장되는 데이터 내용 | 세션 삭제 시 동작 |
| :--- | :--- | :--- |
| 데이터베이스 `artifacts` 테이블 | 최종 합성된 마크다운 보고서, 다이어그램, 소스 코드, 요약 JSON | 세션과 함께 영구 삭제 |
| 작업 공간(Workspace) 디렉터리 | 에이전트들이 MCP 도구를 통해 **디스크에 직접 생성한 실제 소스 코드 파일** | **삭제되지 않고 보존됨** |
| 로컬 다운로드 마크다운 파일 | 사용자가 로컬 PC로 내보내기 하여 저장한 `.md` 문서 | 세션 삭제와 무관하게 보존됨 |

작업 공간 폴더 내부의 소스 파일들이 세션 삭제 시에도 안전하게 보존되는 이유는, 에이전트가 작성한 코드는 대화 세션과 독립된 사용자의 실제 개발 자산이며 복수의 세션이 동일한 작업 폴더를 공유할 수 있기 때문입니다. MCP git 서버를 활성화해 두었다면 각 토론 라운드별 파일 변경 내역이 로컬 git 커밋 이력으로도 영구 보존됩니다.
