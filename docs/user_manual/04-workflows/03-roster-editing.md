# 로스터 편집

> 상위: [워크플로우 개관](README.md) · 이전: [세션 생애주기](02-session-lifecycle.md) · 다음: [산출물 생성과 내보내기](04-artifact-and-export.md)
>
> 관련 구현: [설정 레이어](../03-core/01-config-layer.md) · 파일: `app/ui/components/roster.py` (1,851줄)

에이전트는 원래 `conf.json` 에만 존재했습니다. 하나 추가하거나, 도구를 주거나,
순서를 바꾸려면 편집기를 열고 앱을 다시 띄워야 했습니다. 로스터 패널이 그
전부를 화면에서 처리하고 **결과를 `conf.json` 에 되씁니다.**

---

## 무엇이 어디에 저장되는가

```text
┌─────────────────────────────┐   ┌──────────────────────────────┐
│ 이 대화의 설정 (DB)          │   │ 전역 배포 설정 (conf.json)     │
│                             │   │                              │
│ · 참여 토글                  │   │ · 에이전트 추가 / 삭제         │
│ · 토론 전략                  │   │ · 비활성화                    │
│ · 최대 라운드                │   │ · 발언 순서 (debate_priority) │
│ · 커스텀 지침                │   │ · 진영 (debate_stance)        │
│ · 작업 공간                  │   │ · 도구 권한                   │
│                             │   │ · MCP 서버 추가/삭제/on-off    │
│ 이 대화에만 적용             │   │ 아직 시작 안 한 모든 대화에 적용 │
└─────────────────────────────┘   └──────────────────────────────┘
```

화면이 이 둘을 시각적으로 나눠 두는 이유입니다. 오른쪽 것을 바꾸면 경고 문구가
뜹니다.

> ⚠️ 에이전트 추가·삭제와 진영·발언 순서·도구 변경은 conf.json 에 저장되어
> 앞으로 만드는 모든 대화에 적용됩니다.

---

## 조작 대응표

| 하고 싶은 것 | 어디서 | `conf.json` 에 생기는 일 |
| :--- | :--- | :--- |
| 에이전트 추가 | 헤더의 **에이전트 추가** | `agents` 에 새 항목 |
| 카드 색·아이콘 | **에이전트 추가** 다이얼로그 / **페르소나 편집** | `card_color` · `icon` (올린 그림은 `data/agent_icons/` 로 복사) |
| 발언 순서 변경 | 카드를 **드래그** | `debate_priority` 를 10, 20, 30… 으로 재부여 |
| 진영 배정 | 카드 ⋮ → 진영 | `debate_stance` |
| 도구 권한 | 카드 ⋮ → 도구 | `allowed_mcp_servers` |
| 비활성화 | 카드 ⋮ → 비활성화 | `"enabled": false` |
| 삭제 | 카드 ⋮ → 삭제 | 그 에이전트 객체 제거 |
| MCP 서버 추가 | MCP 영역의 **추가** | `mcp_servers` 에 새 항목 |
| MCP 서버 on/off | 상태 칩 토글 | `"enabled"` 변경 |
| 설정 다시 읽기 | **conf.json 다시 읽기** | (읽기만) |

## 잠금 규칙

**이 하나가 `conf.json` 을 고치는 조작 전부를 막습니다.**

```text
잠기는 조건 (둘 중 하나라도)
  ① 이 대화의 페르소나가 이미 고정됨 (첫 메시지를 보냄)
  ② 어느 대화든 토론이 진행 중
```

②가 놀라운 지점입니다. **다른 대화에서 토론이 돌고 있으면 지금 보고 있는 빈
대화에서도** 에이전트를 추가할 수 없습니다. 에이전트 풀은 프로세스 전체가
하나를 공유하므로, 갈아 끼우면 진행 중인 턴의 발언자 목록이 바뀝니다.

잠긴 동안에는 **창이 아예 열리지 않습니다** — 열어 놓고 저장할 때 거절하면
사용자가 입력을 다 하고 나서 버려집니다.

작업 공간·라운드 수·전략은 이 잠금과 무관합니다 (대화 하나의 설정).

## 에이전트 추가

폼은 LLM 항목 전부를 미리 채워 보여줍니다 — 모델, API URL, 키, provider, 온도,
컨텍스트 창, 응답 토큰, 타임아웃, 재시도, 도구 루프 한도. 값은
`agent_defaults_from_llm()` 이 계산한 **현재 유효 기본값**입니다
(`llm` 값이 있으면 그것, 없으면 `AgentConfig` 기본값).

### 그대로 둔 항목은 파일에 적히지 않습니다

```python
overrides = prune_agent_overrides(submitted, defaults)   # 기본값과 같은 것 제거
```

```json
"data_analyst": {
  "name": "Data Analyst",
  "role": "Data & Metrics Analysis",
  "temperature": 0.15,
  "allowed_mcp_servers": ["filesystem", "git"],
  "system_prompt": "..."
}
```

`temperature` 만 사용자가 바꿨습니다. 나머지는 없으므로 `llm` 을 상속합니다.

**이유 둘:**

1. **비밀값.** 화면이 보여주는 것은 환경변수가 *해석된* 값입니다. 그대로 되쓰면
   평문 API 키가 `conf.json` 에 박힙니다
2. **상속.** 적지 않은 항목은 계속 `llm` 을 따르므로, `.env` 를 바꾸면 이
   에이전트도 함께 움직입니다

같은 창에서 페르소나, 도구 할당, 단계적 사고 모드, 토론 진영도 정합니다.

## 발언 순서 — 카드 드래그

카드를 끌어다 놓으면 `debate_priority` 가 10, 20, 30… 으로 다시 매겨집니다.
사이에 자리를 남기는 것은 나중에 한 명을 둘 사이에 끼워 넣을 때 나머지를 다시
쓰지 않기 위해서입니다.

**놓을 자리는 커서 위치가 정합니다** — 카드의 왼쪽 절반이면 그 앞, 오른쪽
절반이면 그 뒤. 이걸 커서로 정하지 않으면 "오른쪽으로 한 칸" 과 "맨 뒤로" 를
표현할 방법이 없습니다.

> 드래그 처리는 **브라우저 안에서** 합니다. `dragover` 에 파이썬 핸들러를 달면
> NiceGUI 가 그 이벤트를 서버로 보내는데, `dragover` 는 커서가 움직이는 내내
> 초당 수십 번 발생합니다. 카드 위를 지나가기만 해도 웹소켓 메시지가 쏟아져
> 드래그가 끊겼습니다.

## 비활성화 vs 삭제

둘 다 풀에서 빠지지만(`AgentPool.reload()` 가 `"enabled": false` 를 건너뜀)
복구 가능성이 다릅니다.

| | 비활성화 | 삭제 |
| :--- | :--- | :--- |
| `conf.json` | `"enabled": false` 추가 | 객체 제거 |
| 설정·프롬프트 | 남음 | 사라짐 |
| 화면에서 복구 | 가능 (**꺼둔 에이전트** 칩) | 불가 |
| 시작한 대화 | 영향 없음 | 영향 없음 |

비활성화된 에이전트는 풀에 없어서 카드로 보이지 않습니다. 그래서 로스터가
**별도의 칩 줄**로 그립니다. 이것이 없으면 한 번 끄면 화면에서 다시 켤 방법이
사라져 `conf.json` 을 직접 열어야 합니다.

**오케스트레이터는 끌 수도 지울 수도 없습니다.** 계획과 합성을 맡고,
`RootConfig` 가 그것 없이는 검증을 통과시키지 않습니다.

## MCP 서버 관리

상태 칩이 서버별 연결 상태를 보여줍니다.

| 칩 | 뜻 |
| :--- | :--- |
| 🟢 연결됨 | 도구 사용 가능 |
| 🔴 실패 | 툴팁에 자식 프로세스 stderr |
| ⚪ 비활성 | `"enabled": false` |

추가·삭제·on/off 는 `conf.json` 에 저장되고 **지금 열려 있는 모든 대화에
영향을 줍니다.** 서버는 프로세스 전체가 공유하기 때문입니다.

> 서버를 추가하는 것만으로는 아무도 쓰지 않습니다. 쓸 에이전트의
> `allowed_mcp_servers` 에 이름을 넣어야 합니다.

**도구 할당은 서버를 다시 띄우지 않습니다.** 서버 구성이 바뀐 것이 아니므로
재기동은 몇 초를 버리는 일입니다.

## 설정 반영 흐름

```text
화면 조작
   │
   ▼
conf.json 쓰기 (검증 → 원문 읽기 → 딕셔너리 수정 → 원자적 쓰기)
   │
   ├─ 실패 ──▶ 토스트로 알림. 실행 중 구성은 그대로
   │
   ▼
get_config(reload=True)
   │
   ├─ reload_agent_pool()          제자리에서 풀 갱신
   └─ mcp.reload_from_config()     서버 구성이 바뀐 경우에만
   │
   ▼
화면 다시 그리기 (refresh_agent_cards)
```

에이전트만 바뀌었으면 MCP 서버를 다시 띄우지 않습니다. **깨진 `conf.json` 은
실행 중 구성을 건드리지 않습니다** — 읽지도 못한 설정으로 풀을 다시 만들면
안 됩니다.

**conf.json 다시 읽기** 버튼은 편집기로 파일을 직접 고쳤을 때 같은 결과를
만듭니다.
