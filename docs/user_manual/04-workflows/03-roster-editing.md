# 로스터 편집

> 상위: [워크플로우 개관](README.md) · 이전: [세션 생애주기](02-session-lifecycle.md) · 다음: [산출물 생성과 내보내기](04-artifact-and-export.md)
>
> 관련 구현: [설정 레이어](../03-core/01-config-layer.md) · 소스 파일: `app/ui/components/roster.py` (1,851줄)

초기 시스템에서 에이전트 설정은 오직 `conf.json` 파일에만 존재했습니다. 새로운 에이전트를 추가하거나 도구 권한을 부여하고 발언 순서를 변경하려면 텍스트 에디터를 열어 수동 편집한 뒤 서버를 재기동해야 했습니다. 현재 MADO의 로스터 패널은 이 모든 작업을 웹 UI 화면에서 직관적으로 처리하며, **그 결과를 `conf.json` 파일에 실시간으로 안전하게 역반영**합니다.

---

## 세션별 설정(DB)과 전역 배포 설정(conf.json)의 분리

```text
┌─────────────────────────────┐   ┌──────────────────────────────┐
│ 이 대화의 세션 설정 (DB)    │   │ 전역 배포 설정 (conf.json)   │
│                             │   │                              │
│ · 참여 여부 토글            │   │ · 신규 에이전트 추가 / 삭제  │
│ · 토론 전략 선택            │   │ · 에이전트 비활성화          │
│ · 최대 라운드 수            │   │ · 발언 우선순위(debate_priority)│
│ · 세션 커스텀 지침          │   │ · 토론 진영(debate_stance)   │
│ · 세션 작업 공간 경로       │   │ · MCP 도구 권한 매핑         │
│                             │   │ · MCP 서버 추가/삭제/on-off  │
│ 해당 대화 세션에만 적용     │   │ 향후 생성될 모든 대화에 기본 적용│
└─────────────────────────────┘   └──────────────────────────────┘
```

로스터 화면은 이 두 가지 성격의 설정을 시각적으로 명확히 분리하여 제공합니다. 전역 배포 설정에 영향을 주는 작업을 수행할 때는 사용자 주의 경고가 표시됩니다:

> [!WARNING]
> 에이전트 추가/삭제, 진영 배정, 발언 우선순위, 도구 권한 변경은 전역 `conf.json` 파일에 직접 영구 기록되며, 향후 새롭게 생성되는 모든 대화 세션에 기본값으로 적용됩니다.

## 로스터 주요 조작 및 반영 매핑

| 사용자 작업 | 조작 위치 | `conf.json` 반영 내용 |
| :--- | :--- | :--- |
| 신규 에이전트 추가 | 로스터 상단 헤더의 **에이전트 추가** 버튼 | `agents` 객체에 신규 항목 추가 |
| 대화로 에이전트 만들기 | **에이전트 추가** 모달 상단의 **에이전트 만들기** → 도우미와 대화 → **양식에 채우기** | 모달의 **추가** 버튼으로 저장 (위 행과 동일) |
| 카드 색상 및 아이콘 지정 | **에이전트 추가** 모달 / **페르소나 편집** 화면 | `card_color`, `icon` (업로드된 이미지는 `data/agent_icons/`로 복사) |
| 발언 순서 변경 | 에이전트 카드를 마우스로 **드래그 앤 드롭** | `debate_priority`를 10, 20, 30 단위로 순차 재부여 |
| 토론 진영 배정 | 에이전트 카드 우측 상단 더보기(⋮) → 진영 선택 | `debate_stance` 값 갱신 (`proponent` / `critic` / `neutral`) |
| 도구 권한 설정 | 에이전트 카드 우측 상단 더보기(⋮) → 도구 설정 | `allowed_mcp_servers` 권한 배열 갱신 |
| 스킬 할당 | 에이전트 카드의 **스킬 N** 버튼 | `allowed_skills` 배열 갱신 (MCP 도구 권한과 동일한 잠금 규칙 적용) |
| 에이전트 비활성화 | 에이전트 카드 우측 상단 더보기(⋮) → 비활성화 | `"enabled": false` 속성 부여 |
| 에이전트 영구 삭제 | 에이전트 카드 우측 상단 더보기(⋮) → 삭제 | 해당 에이전트 JSON 객체 완전 제거 |
| MCP 서버 등록 | MCP 관리 영역의 **서버 추가** 버튼 | `mcp_servers` 객체에 신규 서버 정의 추가 |
| MCP 서버 on/off 토글 | MCP 서버 상태 칩 클릭 토글 | 해당 서버의 `"enabled"` 불리언 값 변경 |
| 스킬 활성화/비활성화 토글 | 로스터 패널 **스킬** 영역의 칩 스위치 (토론 중에도 전환 가능) | `skills.disabled` 목록 변경. 진행 중인 대화 세션에도 다음 발언부터 즉시 적용 |
| 설정 수동 동기화 | 로스터 하단의 **conf.json 다시 읽기** 버튼 | 디스크의 `conf.json`을 런타임 메모리로 재로드 |

## 전역 설정 편집 잠금 규칙

**다음 두 가지 조건 중 하나라도 만족하면 `conf.json`을 수정하는 모든 UI 조작이 엄격히 차단됩니다:**

```text
전역 편집 잠금 발생 조건 (둘 중 하나라도 해당 시)
  ① 현재 대화 세션의 페르소나가 이미 고정됨 (첫 사용자 메시지를 전송함)
  ② 시스템 내의 어느 대화 세션이든 백그라운드 토론이 실행 중임
```

2번 조건에 특히 주목해야 합니다. **다른 대화 세션에서 토론이 진행 중이라면, 현재 열려 있는 빈 대화 세션에서도** 신규 에이전트를 추가하거나 삭제할 수 없습니다. 에이전트 풀은 프로세스 전체가 단일 인스턴스를 공유하므로, 풀을 재로드하면 다른 세션에서 진행 중인 토론 턴의 발언자 목록과 모델 구성이 변경되는 심각한 결함이 발생하기 때문입니다.

잠금 상태에서는 **편집 대화상자 자체가 열리지 않습니다.** 사용자가 폼에 모든 입력을 마친 후 저장 시점에 요청이 거부되어 입력 내용이 유실되는 문제를 방지하기 위함입니다.

단, 작업 공간 경로, 라운드 수, 토론 전략은 개별 세션 데이터베이스 컬럼이므로 이 전역 잠금의 영향을 받지 않습니다.

## 신규 에이전트 등록

추가 폼은 전역 `llm` 기본 설정을 기반으로 모든 필드(모델명, API URL, 인증 키, 공급자, 온도, 컨텍스트 창, 최대 토큰, 타임아웃, 재시도 횟수, 도구 루프 한도)를 미리 계산하여 자동으로 채워줍니다 (`agent_defaults_from_llm()`).

### 기본값과 동일한 항목은 파일에 기록되지 않습니다

```python
overrides = prune_agent_overrides(submitted, defaults)   # 기본값과 동일한 필드 제거
```

```json
"data_analyst": {
  "name": "Data Analyst",
  "role": "Data & Metrics Analysis",
  "temperature": 0.15,
  "allowed_mcp_servers": ["filesystem", "git"],
  "system_prompt": "..."
}
```

위 예시에서는 사용자가 `temperature`만 기본값과 다르게 수정했습니다. 나머지 필드는 파일에 기록되지 않고 상위 `llm` 전역 설정을 지속적으로 상속받습니다.

**이렇게 처리하는 두 가지 핵심 이유**:

1. **보안성(Secrets)**: UI 화면에 표시되는 값은 환경변수가 이미 *해석된 실제 값*입니다. 이를 그대로 저장하면 실제 API 키가 `conf.json` 파일에 평문으로 영구 노출됩니다.
2. **설정 상속(Inheritance)**: 생략된 항목은 상위 전역 `llm` 설정을 지속적으로 상속받으므로, 차후 `.env` 파일의 설정을 변경했을 때 해당 에이전트의 동작도 자연스럽게 함께 갱신됩니다.

동일한 모달 창 내에서 페르소나, MCP 도구 권한, 단계적 사고 모드, 토론 진영도 한 번에 설정할 수 있습니다.

## 발언 순서 변경 (카드 드래그 앤 드롭)

에이전트 카드를 드래그하여 원하는 위치에 놓으면 `debate_priority`가 10, 20, 30 단위로 자동 재부여됩니다. 10 단위 간격을 두는 이유는 향후 두 에이전트 사이에 새로운 에이전트를 삽입할 때 전체 목록을 매번 재기록하지 않기 위함입니다.

**카드를 배치할 정확한 위치는 마우스 커서의 상대적 위치로 결정됩니다.** 카드의 좌측 절반에 커서가 위치하면 해당 카드의 앞쪽에 삽입되고, 우측 절반에 위치하면 뒤쪽에 삽입됩니다. 커서 위치를 계산하지 않으면 '오른쪽으로 한 칸 이동'과 '맨 뒤로 이동'을 명확히 구분할 수 없기 때문입니다.

> [!NOTE]
> 드래그 앤 드롭 이벤트 처리는 **웹 브라우저 클라이언트 내부에서 순수 JavaScript로 처리**됩니다. 만약 `dragover` 이벤트를 NiceGUI 서버 핸들러로 전달하면, 마우스 커서가 움직이는 동안 초당 수십 회의 웹소켓 메시지가 서버로 쏟아져 드래그 동작이 끊기고 서버 부하가 급증하기 때문입니다.

## 에이전트 비활성화와 삭제의 차이점

두 작업 모두 런타임 에이전트 풀에서 에이전트를 제외하지만(`AgentPool.reload()` 시 `"enabled": false` 항목 건너뜀), 복구 가능성에서 명확한 차이가 있습니다:

| 비교 항목 | 에이전트 비활성화 (Disable) | 에이전트 영구 삭제 (Delete) |
| :--- | :--- | :--- |
| `conf.json` 반영 | `"enabled": false` 속성 추가 | 해당 에이전트 JSON 객체 완전 제거 |
| 프롬프트 및 설정 보존 | 파일 내에 그대로 보존됨 | 완전히 소실됨 |
| UI 화면에서의 복구 | **비활성화 에이전트 칩**을 클릭하여 즉시 복구 가능 | UI에서 복구 불가 (재등록 필요) |
| 이미 잠긴 대화 세션 | 영향 없음 (스냅샷으로 계속 참여) | 영향 없음 (스냅샷으로 계속 참여) |

비활성화된 에이전트는 풀에서 제외되어 일반 카드 목록에는 보이지 않지만, 로스터 패널 상단에 **별도의 '비활성화된 에이전트' 칩 목록**으로 표시됩니다. 이를 통해 UI 화면에서 언제든 원클릭으로 다시 활성화할 수 있습니다.

**오케스트레이터 에이전트는 비활성화하거나 삭제할 수 없습니다.** 전체 토론의 목표 계획과 최종 합성을 전담하는 핵심 시스템 구성 요소이며, Pydantic `RootConfig` 유효성 검사에서도 오케스트레이터의 부재는 즉시 설정 오류로 거부됩니다.

## 실시간 MCP 서버 관리

상태 칩이 서버별 연결 상태를 실시간으로 표시합니다.

| 상태 칩 | 의미 |
| :--- | :--- |
| 🟢 **연결됨** | 프로세스 기동 및 초기 핸드셰이크 완료, 도구 호출 즉시 가능 |
| 🔴 **실패** | 서버 기동 또는 연결 실패. 마우스 오버 툴팁에 자식 프로세스 stderr 원인 노출 |
| ⚪ **비활성** | `conf.json` 설정에서 `"enabled": false`로 명시된 상태 |

MCP 서버의 추가, 삭제, on/off 토글은 `conf.json`에 저장되며 **현재 실행 중인 모든 대화 세션에 즉각적인 영향을 미칩니다.** 도구 서버 프로세스는 세션 작업 공간마다 격리되어 실행되지만, 서버 기동 정의 자체는 `conf.json` 단일 파일이 통제하기 때문입니다. 설정을 변경하면 현재 활성 상태인 모든 런타임 서버 묶음이 안전하게 재기동됩니다.

> [!IMPORTANT]
> 신규 MCP 서버를 추가하는 것만으로는 에이전트가 도구를 사용할 수 없습니다. 반드시 해당 도구를 사용해야 하는 에이전트의 `allowed_mcp_servers` 권한 배열에 서버 이름을 명시적으로 추가해야 합니다.

**에이전트에 도구 권한을 할당하는 작업은 MCP 서버를 재기동하지 않습니다.** 서버 프로세스 구성 자체가 변경된 것이 아니므로 불필요한 재기동 지연(수 초)을 방지합니다.

## 설정 저장 및 런타임 갱신 파이프라인

```text
UI 화면 조작 발생
   │
   ▼
conf.json 원자적 쓰기 (사전 검증 → 원본 읽기 → 딕셔너리 수정 → 임시 파일 os.replace)
   │
   ├─ 검증 또는 저장 실패 시 ──▶ UI 토스트 알림 표시, 기존 실행 중 구성 유지
   │
   ▼
get_config(reload=True)
   │
   ├─ reload_agent_pool()          기존 인스턴스 제자리에서 에이전트 풀 갱신
   └─ mcp.reload_from_config()     서버 프로세스 구성이 변경된 경우에만 선별 재기동
   │
   ▼
UI 화면 재렌더링 (refresh_agent_cards)
```

에이전트 속성만 변경된 경우에는 MCP 서버를 재기동하지 않고 에이전트 풀만 제자리에서 갱신합니다. **문법 오류 등으로 손상된 `conf.json`은 실행 중인 기존 런타임 구성을 절대 건드리지 않습니다.** 정상적으로 읽지도 못한 비정상 설정으로 풀을 덮어쓰는 치명적인 사고를 원천 방지합니다.

UI의 **conf.json 다시 읽기** 버튼은 외부 텍스트 에디터로 설정 파일을 직접 수정한 경우 런타임에 즉시 동기화할 수 있는 수단을 제공합니다.
