## 세 단계

```text
  ① 생성                    ② 첫 메시지                   ③ 그 뒤
     │                          │                            │
  ┌──▼───────────────┐   ┌──────▼──────────┐   ┌─────────────▼──────────┐
  │ 🟢 편집 가능      │   │ 🔒 잠금          │   │ 🔒 잠긴 상태로 계속      │
  │ · 페르소나 초안   │──▶│ 모든 에이전트의   │──▶│ session_agents 만 읽음  │
  │ · 참여 에이전트   │   │ AgentConfig 전체 │   │ conf.json 과 무관       │
  │ · 전략 / 라운드   │   │ 를 DB 에 굳힘     │   │                        │
  │ · 작업 공간       │   │                  │   │ 작업 공간은 계속 변경 가능│
  └──────────────────┘   └──────────────────┘   └────────────────────────┘
```

## ① 새 대화 만들기

좌측 사이드바의 **+ New Chat**.

```python
SessionModel(
    title="New Debate Session",
    strategy="sequential_debate",
    max_rounds=3,
    active_agents=[...],      # 켜 둔 에이전트
    known_agents=[...],       # 그때 존재하던 전부
    personas_locked=False,
)
```

이 시점에 정할 수 있는 것:

| 항목 | 위치 | 잠긴 뒤 |
| :--- | :--- | :--- |
| 참여 에이전트 (토글) | 로스터 카드 | 고정 |
| 토론 전략 | 로스터 선택 상자 | 변경 가능 |
| 최대 라운드 | 로스터 슬라이더 | 변경 가능 |
| 커스텀 지침 | 로스터 텍스트 영역 | 변경 가능 |
| 작업 공간 | 로스터 입력 칸 | **변경 가능** |
| 페르소나 (이름·역할·프롬프트) | `/personas/{id}` | **고정** |

### `known_agents` 가 필요한 이유

`active_agents` 는 켜 둔 것만 담는 허용 목록입니다. 목록에 없는 키가 "사용자가
끈 것" 인지 "그때는 없던 것" 인지 구분할 수 없습니다. 그래서 `conf.json` 에
에이전트를 새로 추가하면 기존 대화에서 **전부 꺼진 것처럼** 보였습니다.
그때 무엇이 있었는지를 함께 적어 두면 둘을 가릴 수 있습니다.

## ② 페르소나 편집 (첫 메시지 전)

`/personas/{session_id}` 에서 대화별 인격을 정합니다.

| 편집 가능 | 편집 불가 |
| :--- | :--- |
| `name` — 화면에 뜨는 이름 | `model`, `api_base`, `api_key` |
| `role` — 역할 | `allowed_mcp_servers` |
| `system_prompt` — 기본 지시 | `temperature`, `max_tokens` … |
| `card_color`, `icon` — 카드 색과 아이콘 | |

운영 설정은 `conf.json` 이 정본입니다. 대화의 성격을 바꾸는 것은 인격이지
엔드포인트가 아닙니다.

저장한 값은 `session_agents` 에 **초안**으로 들어가고, 동시에 `conf.json` 의
전역 기본값에도 반영됩니다. 손대지 않은 에이전트는 `conf.json` 기본값을 씁니다.

**되돌리기**: 초안을 지우면 `conf.json` 기본값으로 돌아갑니다.

## ③ 잠금 (첫 사용자 메시지)

```text
사용자가 첫 메시지를 보냄
        │
        ▼
prepare_agents_for_turn(db, session_model, pool, active_keys)
        │
        ├─ 모든 활성 에이전트에 대해:
        │     초안이 있으면 그것을, 없으면 conf.json 기본값을
        │     session_agents 에 기록
        │     └─ config_snapshot = AgentConfig 전체
        │          (모델·엔드포인트·키·샘플링·도구 권한)
        │
        └─ sessions.personas_locked = True
```

이 순간부터 **이 대화는 `conf.json` 을 읽지 않습니다.**

> 잠금이 풀리는 경우가 하나 있습니다. 첫 요청을 **긴급 종료**로 되돌려 대화에 남은
> 발언이 하나도 없게 되면, 이 대화는 아직 시작하지 않은 것이 되어 잠금이 풀립니다
> (`discard_turn`). 굳혀 둔 `session_agents` 는 남고, 다음 첫 메시지에서 그때의
> `conf.json` 으로 다시 굳습니다.
> → [토론 한 턴의 생애주기](01-debate-turn.md#정지와-긴급-종료)

### 잠긴 뒤 전역 설정을 바꾸면

| `conf.json` 에 한 일 | 이 대화 | 아직 시작 안 한 대화 |
| :--- | :--- | :--- |
| 에이전트 삭제 | 영향 없음 (스냅샷으로 계속 참여) | 사라짐 |
| 에이전트 비활성화 | 영향 없음 | 참여 안 함 |
| 모델·엔드포인트 변경 | 영향 없음 | 새 값 적용 |
| API 키 변경 | 영향 없음 | 새 값 적용 |
| 도구 권한 변경 | 영향 없음 | 새 값 적용 |
| 에이전트 추가 | 참여 안 함 | 참여 |

### 왜 이렇게 하는가

이것이 없으면 **어제 끝난 대화를 오늘 다시 열었을 때 다른 시스템이 됩니다.**
기록에 남은 "System Architect" 가 지금은 다른 모델을 쓰고 다른 도구를 갖고
있는데, 그 대화를 이어서 진행하면 앞뒤가 맞지 않습니다.

토론 기록은 **그때 그 구성으로 만들어진 것**이고, 이어서 하는 발언도 같은
구성이어야 합니다.

## ④ 재개

세션을 다시 열면:

```text
sidebar 에서 대화 선택
   │
   ├─ 발언 기록·도구 기록·산출물을 DB 에서 로드
   ├─ session_agents 의 스냅샷으로 에이전트 구성
   └─ 진행 중인 토론이 있으면 TurnRun 스냅샷으로 화면 복원
```

브라우저를 새로고침하거나 다른 페이지에 다녀와도 토론은 계속 돕니다
(`DebateRunner` 가 브라우저와 무관한 태스크로 돌리기 때문).
새로 붙는 화면은 정본 스냅샷을 그대로 그립니다.

### 이 대화에만 남은 에이전트

`conf.json` 에서 지워졌지만 이 대화의 스냅샷에는 남아 있는 에이전트는 로스터에
표시되고 계속 참여합니다. 발언자 정렬은 이 순서입니다.

```text
1. 오케스트레이터
2. conf.json 순서
3. 이 대화에만 남은 에이전트
```

## 탈출구 — 설정 갱신

스냅샷이 고정이면 곤란한 경우가 있습니다.

- 사내 게이트웨이 주소가 바뀌었습니다
- API 키가 만료되었습니다
- 그 대화가 쓰던 모델이 서비스 종료되었습니다

로스터의 **설정 갱신** 버튼이 스냅샷을 지금 `conf.json` 값으로 다시 굳힙니다.

```text
갱신되는 것          갱신되지 않는 것
· 모델              · 이름 (name)
· 엔드포인트         · 역할 (role)
· API 키            · 시스템 프롬프트
· 도구 권한
· 샘플링 값
```

**인격은 건드리지 않으므로 기록의 화자는 그대로입니다.** `conf.json` 에 더 이상
없는 에이전트는 손대지 않습니다.

## ⑤ 삭제

사이드바에서 명시적으로 삭제합니다. `cascade="all, delete-orphan"` 이라
발언·도구 기록·산출물·페르소나가 함께 사라집니다.

작업 공간 폴더는 **지워지지 않습니다.** 에이전트가 만든 파일은 대화 기록과
별개의 산출물이고, 여러 대화가 같은 폴더를 공유할 수도 있기 때문입니다.

---

## 작업 공간

대화마다 다른 폴더를 쓸 수 있습니다. 로스터의 **작업 공간** 칸에 경로를 넣으면
그 대화의 MCP 서버(filesystem / git / sandbox / memory)가 그 폴더를 봅니다.

- 값은 `sessions.workspace_dir` 에 저장되고 **`conf.json` 은 바뀌지 않습니다**
- 비워 두면 `conf.json` 의 `WORKSPACE_DIR` 기본값
- **페르소나와 달리 잠기지 않습니다** — 토론 도중에도 바꿀 수 있어야 합니다
- 다른 작업 공간의 토론이 돌고 있으면 시작이 거부됩니다
  (`WorkspaceConflictError`)
