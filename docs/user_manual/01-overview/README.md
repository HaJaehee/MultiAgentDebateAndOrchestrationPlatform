# 시스템 개요

> 상위: [MADO 사용 설명서](../README.md) · 다음: [기술 스택](01-tech-stack.md)

---

## 한 문장으로

**여러 LLM 에이전트가 서로의 발언을 이어받아 토론하고, MCP 도구로 사실을 검증하며, 합의된 결과를 실행 가능한 산출물로 종합하는 웹 애플리케이션입니다.**

---

## 무엇이 다른가

단일 LLM에게 "이 시스템을 설계해 주십시오"라고 요청하면 언뜻 그럴듯한 답변 하나가 생성됩니다. 그러나 이를 비판적으로 검토한 주체가 없고, 작성된 코드가 실제로 정상 동작하는지 검증된 적도 없습니다.

MADO는 그 자리에 **서로 다른 전문 역할을 수행하는 다자간 에이전트**를 배치합니다.

```text
   유저 요청
        │
        ▼
  ┌───────────────┐
  │ 오케스트레이터 │  목표를 분해하고 발언권을 배분
  └───────┬───────┘
          │
     ┌────┴────┬─────────┬─────────┐
     ▼         ▼         ▼         ▼
  아키텍트  엔지니어   리뷰어   (추가한 전문가…)
   설계      구현       검증
     │         │         │
     └────┬────┴─────────┘
          │  각 에이전트는 MCP 도구를 실제로 실행합니다
          │  (파일 읽기/쓰기, 코드 실행, git, 지식 그래프, 웹 fetch)
          ▼
  ┌───────────────┐
  │ 오케스트레이터 │  토론 전체를 종합해 최종 산출물 합성
  └───────┬───────┘
          ▼
   코드 · 문서 · 다이어그램
```

핵심은 **주장과 검증이 명확히 분리**된다는 점입니다. 엔지니어 에이전트가 "이 코드는 정상 동작합니다"라고 주장하면, 리뷰어 에이전트가 샌드박스 MCP 도구를 활용하여 해당 코드를 실제 런타임에서 직접 실행하고 결과를 엄밀히 판정할 수 있습니다.

---

## 네 가지 설계 원칙

### 1. 설정이 곧 시스템 구성

에이전트 목록, 모델, 엔드포인트 URL, 인증 자격 증명, 도구 권한, 발언 순서, 토론 진영 등 모든 시스템 요소가 [`conf.json`](../02-getting-started/02-configuration.md) 파일 하나에 정의됩니다. 새로운 전문가 에이전트를 추가하기 위해 소스 코드를 수정할 필요가 없습니다. 웹 UI 화면에서도 손쉽게 추가할 수 있으며, 그 결과는 `conf.json`에 원자적으로 다시 영속화됩니다.

### 2. 시작한 대화는 자기완결적

첫 유저 메시지가 시스템에 기록되는 순간, 참여 에이전트들의 **설정 전체**(페르소나, 모델, 엔드포인트, API 키, 도구 권한)가 데이터베이스에 불변 스냅샷으로 고정 및 잠금 처리됩니다. 그 이후 시스템 설정 파일(`conf.json`)에서 특정 에이전트를 삭제하거나 모델을 교체하더라도, **해당 대화 세션은 최초 시작 시점의 설정 구성 그대로** 변함없이 진행됩니다. → [세션 생애주기](../04-workflows/02-session-lifecycle.md)

### 3. 없는 것을 지어내지 않는다

네트워크 단절 등으로 엔드포인트에 접속할 수 없는 에이전트의 차례는 `LLMUnavailableError` 예외와 함께 정상 실패 처리되며, 토론 이력에 **통신 실패 사실이 투명하게 기록됩니다.** 임의의 그럴듯한 문장을 지어내어 결측을 위장하지 않습니다. 최종 종합 오케스트레이터 역시 "어떤 에이전트가 통신 실패로 발언하지 못했는지"를 정확히 인지한 상태에서 보고서를 작성합니다. → [LLM 통합](../03-core/03-llm-integration.md)

### 4. 폐쇄망에서 완벽 동작

외부 인터넷이 원천 차단된 오프라인 폐쇄망에 반입하여 운용하는 것을 전제로 설계되었습니다. 포터블 파이썬 런타임, `node.exe` 단일 바이너리, 오프라인 wheel 모음, 사전 설치된 MCP 서버 배포본까지 한 번에 묶어주는 자동화 패키징 스크립트를 제공합니다. 또한 설정 파일의 모든 경로가 `${변수:-기본값}` 환경변수 치환을 지원하여 개발 PC와 오프라인 배포 번들이 동일한 설정 파일을 안전하게 공유합니다. → [폐쇄망 배포](../04-workflows/05-airgap-deployment.md)

## 화면 구성

| 영역 | 담당 기능 및 역할 |
| :--- | :--- |
| **좌측 사이드바** | 과거 대화 세션 목록 조회, 신규 세션 생성, 세션 이름 변경 및 삭제를 지원합니다. |
| **상단 로스터 패널** | 에이전트 카드(참여 여부 토글, 드래그 앤 드롭을 통한 발언 순서 조정, ⋮ 메뉴를 통한 진영 설정·비활성화·삭제), 최대 라운드 수, 토론 전략 선택, MCP 서버 상태 칩 모니터링, 작업 공간 디렉터리 지정을 제어합니다. |
| **중앙 토론 피드** | 유저, 오케스트레이터, 전문가 에이전트의 발언을 고유 색상과 아바타로 구분하여 실시간 렌더링합니다. MCP 도구 실행 내역은 접이식 아코디언으로 표시되며, 완료된 과거 발언은 3줄 요약 카드로 컴팩트하게 접힙니다. |
| **산출물 뷰어** | 턴마다 생성된 최종 결론, 종합 Mermaid 다이어그램, 전문가 코드 발췌본을 상단 탭으로 누적 관리합니다. 원클릭 클립보드 복사 및 로컬 파일 다운로드를 지원합니다. |
| **헤더 ⓘ 정보 버튼** | 소프트웨어 개발자 정보, 문의 이메일, 릴리스 버전, 라이선스 안내 모달을 띄우며, 지원 요청용 한 줄 시스템 정보 복사 기능을 제공합니다. |
| **페르소나 편집 페이지** | `/personas/{session_id}` 경로를 통해 세션별 에이전트의 역할과 시스템 프롬프트를 상세 편집할 수 있습니다. |
