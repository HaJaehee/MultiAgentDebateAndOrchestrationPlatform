# 동료 자문 (peers)

> 상위: [핵심 기술 개관](README.md) · 이전: [스킬](09-skills.md)
>
> 관련 소스: `app/agents/consultation.py` · `app/config/schema.py` (`PeerConsultationConfig`) ·
> `app/ui/components/roster/agent_dialogs.py` (도구 할당 창의 '에이전트 선택')

토론 중 한 전문가가 다른 전문가에게 **발언 도중에 바로 물어보는** 고급 기능입니다. 예를 들어
아키텍트가 설계를 확정하기 전에 보안 리뷰어에게 인증 방식의 취약점을 묻고, 받은 답을 자기 발언에
반영합니다. 다음 라운드까지 기다리지 않아도 됩니다.

> [!NOTE]
> 전문가 화면(`/`)에서 설정하는 기능입니다. 체험 화면(`/trial`)과 쉬운 화면(`/trial/easy`)에는
> 설정 화면이 없습니다.

---

## 어떻게 동작하는가

`peers` 는 MCP 서버가 아니라 **앱에 내장된 호스트 도구**입니다. 해당 기능을 활성화한 전문가에게는 발언 시
`peers__consult_agent` 도구가 제공되며, 모델이 이 도구를 통해 대상 에이전트와 질문을 지정하면 MADO 가 대상
에이전트를 직접 호출하여 답변을 전달합니다. 별도 프로세스를 기동하지 않으므로 `conf.json` 의 `mcp_servers`
에는 등록하지 않습니다.

| 항목 | 규칙 |
| :--- | :--- |
| 쓸 수 있는 단계 | 토론 라운드 (계획·합성 단계에는 주어지지 않음) |
| 쓰는 쪽 | `peers` 를 켠 전문가. **오케스트레이터는 쓰지 않습니다** |
| 묻는 상대 | 기본: 이번 턴에 참여한 다른 전문가 전원 / 고르면: 고른 전문가만 (아래) |
| 깊이 | 1단계. 자문받는 쪽은 다시 다른 전문가에게 묻지 못합니다 |
| 자문받는 쪽의 도구 | 묻는 쪽이 정한 상한까지 (기본 3회, 0 이면 도구 없이 답함) |
| 시간 제한 | 따로 없습니다. 턴의 정지·긴급 종료가 그대로 적용됩니다 |
| 도구 보안 | 자문 호출 자체는 판정하지 않고, 자문받는 쪽의 도구 호출은 평소대로 판정합니다 |

자문받는 쪽은 질문과(있으면) 배경 맥락만 받습니다. 토론 전사 전체를 읽지는 않으므로, 묻는 쪽이
필요한 맥락을 질문에 담아야 합니다.

---

## 켜기

1. 로스터에서 그 전문가 카드의 **도구 N** 버튼을 누릅니다.
2. 도구 할당 창에서 `peers` (`내장`) 를 체크합니다.
3. **저장** 을 누릅니다.

`conf.json` 에서는 해당 에이전트의 `allowed_mcp_servers` 에 `"peers"` 를 추가하는 것과 동일합니다.
설정 패널의 MCP 서버 영역에 상시 표시되는 `peers` 칩에 마우스를 올리면, 해당 대화에서 자문 기능을 활성화한 에이전트 목록이 툴팁으로 안내됩니다.

---

## 물을 상대와 도구 상한 고르기

도구 할당 창에서 `peers` 를 체크하면 옆의 **에이전트 선택** 버튼이 켜집니다.

```text
☑ peers [내장]  [에이전트 선택]  고른 2명 · 도구 3회
```

**에이전트 선택** 창에서 정하는 것:

| 항목 | 설명 |
| :--- | :--- |
| 이번 턴에 참여한 다른 전문가 전원 (기본) | 이번 턴에 실제로 참여하는 전문가 전원을 자문 대상으로 지정합니다 (체크박스 선택 또는 그래프 노드에 배치된 에이전트) |
| 아래에서 고른 전문가만 | 체크한 전문가에게만 묻습니다. **토론에 참여하지 않는 전문가도 고를 수 있어**, 토론 본체에서는 제외하고 전문 자문역으로만 활용할 때 유용합니다 |
| 후보 목록 | 자기 자신과 오케스트레이터를 뺀 로스터의 모든 에이전트가 아이콘·색과 함께 나오고, `토론 참여` / `토론 불참` 표시가 붙습니다 |
| 자문받는 쪽 도구 호출 상한 | 자문 한 번에 상대가 쓸 수 있는 도구 호출 수입니다. 기본 3, 0 이면 도구 없이 답합니다. 상대 자신의 `max_tool_iterations` 를 넘지는 않습니다 |

**확인** 을 누르면 도구 할당 창의 요약이 바뀌고, 도구 할당 창의 **저장** 을 눌러야 `conf.json` 에
기록됩니다.

- 고른 상대가 하나도 없으면 `peers` 도구가 주어지지 않습니다 (요약에 "고른 상대 없음").
- `conf.json` 에서 꺼 둔(`enabled: false`) 에이전트는 후보에 없습니다. 다시 켜면 나타납니다.
- 지정한 에이전트가 이후 삭제되거나 비활성화되면 해당 에이전트는 자문 대상 목록에서 자동으로 제외됩니다.

## 언제 적용되고, 대화마다 어떻게 다른가

도구 할당과 같은 규칙을 따릅니다.

1. 저장한 값은 `conf.json` 에 기록되어 **아직 시작하지 않은 대화**와 앞으로 만드는 대화에 적용됩니다.
2. 대화의 **첫 발언**이 시작되면, 다른 에이전트 설정과 함께 그 대화의 스냅샷(DB 의
   `session_agents.config_snapshot`)에 **고정**됩니다.
3. 이미 시작한 대화는 그 뒤 `conf.json` 을 어떻게 바꿔도 고정한 값을 그대로 씁니다. 그래서 대화마다
   자문 상대와 상한이 다를 수 있습니다.

시작한 대화에서는 도구 버튼이 잠겨 있습니다 (다른 구성 변경과 같은 잠금).

토론에 직접 참여하지 않는 에이전트에게 자문을 요청하더라도, 해당 에이전트는 **이 대화에 스냅샷으로 고정된 설정**(모델·프롬프트·도구)을 바탕으로 답변합니다.

## conf.json

```json
"architect": {
  "name": "System Architect",
  "allowed_mcp_servers": ["filesystem", "peers"],
  "peer_consultation": {
    "targets": ["critic", "security_advisor"],
    "max_tool_iterations": 5
  }
}
```

| 키 | 타입 | 기본값 | 설명 |
| :--- | :--- | :--- | :--- |
| `peer_consultation.targets` | list[str] \| 없음 | 없음 | 물을 수 있는 에이전트 키. 없으면 이번 턴에 참여한 다른 전문가 전원 |
| `peer_consultation.max_tool_iterations` | int (0~130) | `3` | 자문받는 쪽의 도구 호출 상한. 0 이면 도구 없이 답함 |

두 설정이 모두 기본값인 경우, 설정 저장 시 `peer_consultation` 블록을 생략하여 설정 파일을 간결하게 유지합니다.
`peers` 는 예약된 이름이라 같은 이름의 MCP 서버는 등록할 수 없습니다 (`skills` 와 같음).
