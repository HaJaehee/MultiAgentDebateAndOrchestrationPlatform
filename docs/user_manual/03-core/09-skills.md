## 스킬이란

**스킬**은 에이전트가 작업 내용에 부합할 때만 동적으로 불러와 참조하는 작업 지침 및 보조 스크립트 묶음입니다. 다이어그램 작성 규칙, 보고서 양식, 코드 검토 체크리스트처럼 조직 차원에서 표준화한 작업 방식을 `system_prompt`에 상시 적재하지 않고, 필요한 순간에만 선택적으로 활용하도록 지원합니다.

스킬 하나는 하나의 디렉터리에 대응합니다.

```text
skills/
  mermaid-diagrams/
    SKILL.md        ← 머리말(name, description) + 본문 지침
    reference.md    ← 부속 문서 (본문에서 참조할 때만 조회)
  csv-profile/
    SKILL.md
    scripts/profile_csv.py   ← 실행 스크립트 (작업 공간에 복사 후 샌드박스로 실행)
```

기본 제공 스킬은 두 가지입니다.

- `mermaid-diagrams` — MADO의 Mermaid 문법 검사기가 거부하는 구문을 사전에 회피하도록 돕는 지침입니다. 다이어그램을 작성하는 에이전트에 할당하면 산출물 합성 후 재생성해야 하는 오류를 방지할 수 있습니다.
- `csv-profile` — 작업 공간 내의 CSV 파일을 컬럼별 데이터 타입, 결측치, 값의 범위, 최빈값 등으로 요약 프로파일링하는 스크립트 스킬입니다 (UTF-8 및 CP949 인코딩 지원). 샌드박스 실행 도구(`run_python_file`)를 보유한 에이전트에 할당합니다.

## 에이전트가 스킬을 활용하는 순서 (점진적 공개)

| 단계 | 모델이 확인하는 정보 | 노출 시점 |
| :--- | :--- | :--- |
| 목록 | 스킬별 `- 이름: 설명` 요약 한 줄 (`skills__load_skill` 도구의 설명 내부) | 모든 LLM 요청 시점 |
| 본문 | YAML 머리말을 제외한 SKILL.md 본문 및 부속 파일 목록 | `skills__load_skill` 도구를 호출한 후 |
| 부속 파일 | 특정 부속 파일의 텍스트 전문 | `skills__read_skill_file` 도구를 호출한 후 |

등록된 스킬이 10개에 달하더라도 매 발언마다 소비되는 프롬프트 비용은 스킬 설명 10줄에 불과합니다. 모델은 요약 설명만 보고 호출 여부를 결정하므로, `description` 필드에는 **해당 스킬을 언제 호출해야 하는지** 명확히 기술해야 합니다.

스킬 도구를 보유한 에이전트의 시스템 프롬프트에는 "적합한 스킬이 있다면 답변을 작성하기 전에 먼저 호출하여 따르십시오"라는 상시 지침이 세션 맞춤 지침 앞에 자동으로 추가됩니다. 스킬이 할당되지 않은 에이전트의 프롬프트에는 해당 문구가 일체 추가되지 않습니다.

불러온 본문 지침은 해당 발언의 도구 루프 컨텍스트 내에서만 유지됩니다. 다음 차례 발언자의 컨텍스트에는 이전 발언자의 도구 실행 결과가 포함되지 않으므로, 다음 발언자가 동일한 지침을 참조해야 할 경우 다시 호출하여 사용합니다.

## MCP 서버가 아닌 호스트 레벨 도구

두 스킬 도구는 모델 관점에서는 일반 MCP 도구와 동일한 방식으로 제공됩니다 (`서버__도구` 명명 체계, 동일한 도구 루프, 접이식 카드 및 실행 로그 표시). 그러나 실제 실행은 외부 MCP 서버 프로세스가 아닌 MADO 호스트 엔진이 직접 수행합니다.

- 에이전트마다 가시적인 스킬 목록이 상이하며, 애플리케이션 실행 중에도 스킬 목록이 실시간으로 변경될 수 있습니다. 고정된 도구 카탈로그만 반환하는 외부 MCP 서버 아키텍처로는 이러한 동적 할당을 처리하기 어렵습니다.
- 스킬 폴더는 MADO 설치 디렉터리 내에 위치하므로 에이전트의 일반 파일 도구 접근이 원천 차단됩니다 (고정 보호 정책). MADO 엔진이 대리로 파일을 읽되, 지정된 스킬 폴더 내부로 조회를 엄격히 한정합니다. 상위 디렉터리 참조(`..`), 절대 경로, 숨김 파일, 폴더 외부를 가리키는 심볼릭 링크는 모두 거부됩니다.

이러한 설계에 따라 `skills`는 MCP 서버 이름으로 등록할 수 없습니다 (설정 유효성 검사 및 웹 UI의 **서버 추가** 시 거부됩니다).

또한 스킬 도구는 **도구 보안 판정(승인 카드)을 거치지 않습니다.** 운영자가 사전에 준비한 안전한 작업 지침 파일만을 조회하며, 접근 권한 역시 `allowed_skills` 및 활성화 여부로 통제되기 때문입니다. 따라서 도구 호출 로그에는 보안 판정 행이 표시되지 않습니다.

## 실시간 동적 반영

대화 세션이 시작되면 해당 세션의 에이전트 설정 스냅샷이 고정됩니다 ([에이전트 풀과 페르소나](02-agent-pool.md)). 스킬은 MCP 서버 활성화/비활성화와 마찬가지로 실시간 변경이 허용되는 설정입니다.

| 변경 항목 | 이미 진행 중인 대화 세션 | 아직 시작하지 않은 대화 세션 |
| :--- | :--- | :--- |
| SKILL.md 및 부속 파일 내용 수정 | **다음 발언부터** 변경된 내용 즉시 적용 | 즉시 적용 |
| 스킬 폴더 추가 및 삭제 | **다음 발언부터** 즉시 반영 | 즉시 적용 |
| 스킬 활성화/비활성화 (`skills.disabled`) | **다음 발언부터** 즉시 반영 (호출 시점 재검증 시 거부됨) | 즉시 적용 |
| 에이전트별 `allowed_skills` 할당 변경 | 영향 없음 (대화 시작 시 스냅샷에 고정됨) | 즉시 적용 |

스킬 목록은 매 발언마다 스킬 폴더를 다시 스캔하여 동적으로 구성합니다. 폴더 목록과 파일 메타데이터(크기, 수정 시각)만 확인하고, SKILL.md 파일은 변경이 감지된 경우에만 다시 파싱하므로 오버헤드가 극히 적습니다.

## 스킬 작성 규칙

```markdown
---
name: report-writing
description: 의사결정 보고서를 작성할 때 사용합니다. 결론을 서두에 배치하고, 추진 근거와 잔여 쟁점을 후반부에 기술합니다.
---

# 의사결정 보고서 작성 지침

1. 첫 단락에는 핵심 결론과 기대 효과를 요약하십시오. ...
```

| 규칙 항목 | 설계 근거 |
| :--- | :--- |
| **폴더 이름**이 고유 스킬 식별자입니다 (영문, 숫자, `_`, `-`, 최대 64자, 영문이나 숫자로 시작). YAML 머리말의 `name`은 화면 표시용 타이틀입니다. | `allowed_skills` 설정과 LLM 도구 파라미터에 스킬 폴더명이 그대로 전달됩니다. |
| `description` 필드는 필수 입력 항목입니다 (연속 공백은 단일 공백으로 치환되며 최대 1,024자까지 허용됩니다). | 모델이 스킬을 호출하기 전에 확인하는 유일한 단서입니다. |
| 본문 지침은 비어 있을 수 없으며, SKILL.md 파일은 UTF-8 인코딩으로 최대 256KB까지 허용됩니다. | 스킬을 호출하면 본문 전문이 모델 컨텍스트에 주입됩니다. 장문의 참고 자료는 부속 파일로 분리하십시오. |
| 부속 파일은 숨김 파일, `__pycache__`, `node_modules`, 가상환경, 심볼릭 링크를 제외한 폴더 내 파일입니다 (최대 200개까지 표시). | `read_skill_file` 도구는 최대 256KB 크기의 UTF-8 텍스트 문서를 지원합니다. |

YAML 머리말은 내장 경량 파서를 통해 파싱됩니다 (`key: value`, 따옴표, `|` 및 `>` 블록 스칼라, 들여쓰기된 연속 줄 지원).
폐쇄망 배포 환경에서 불필요한 서드파티 의존성을 추가하지 않기 위함입니다. `name`, `description` 이외의 메타데이터 키는 안전하게 무시됩니다.

작성 규칙을 위반한 스킬은 오류 사유와 함께 목록에 유지되며 (로스터 패널의 빨간색 칩 표시, `/api/skills`의 `problem` 필드), 어떤 에이전트에게도 제공되지 않습니다.

## 스크립트가 포함된 스킬

부속 파일 중 `*.py` 파일은 실행 가능한 파이썬 스크립트로 인식됩니다. 스킬 디렉터리는 MADO 설치 경로 내에 위치하여 에이전트가 해당 위치에서 직접 코드를 실행할 수 없으므로, 다음과 같은 생명주기로 동작합니다.

1. 실행 도구(`run_python_file`, 주로 `sandbox` MCP 서버)를 보유한 에이전트가 스킬을 호출합니다.
2. MADO 엔진이 스킬 디렉터리를 **해당 대화 세션의 작업 공간** 내 `.mado/skills/<이름>/` 경로로 복사하고, 반환되는 지침 하단에 실행 경로와 호출 방법(`sandbox__run_python_file`, `file_path=".mado/skills/<이름>/scripts/…"`)을 안내합니다.
3. 에이전트가 스크립트를 실행합니다. 이는 일반적인 샌드박스 도구 실행과 동일하므로 도구 보안 정책의 사전 코드 검사 및 보안 판정을 거칩니다. 기본 모드에서는 검사를 통과한 스크립트가 별도 확인 없이 실행되며, 검토 모드에서는 사용자 승인을 요청하고, 읽기 전용 모드에서는 실행이 거부됩니다.

| 규칙 항목 | 설계 근거 |
| :--- | :--- |
| 실행 도구를 보유하지 않은 에이전트에게는 스크립트를 복사하지 않으며, "실행 도구를 보유한 에이전트에게 위임하십시오"라는 안내만 전달합니다. | 불필요한 파일 복사로 작업 공간이 오염되는 것을 방지합니다. |
| 스킬 호출 시마다 **변경된 파일만** 선별적으로 복사합니다 (크기 및 수정 시각 비교). 에이전트가 복사본을 임의로 수정하더라도 원본으로 복원됩니다. 원본에 없는 추가 생성 파일은 삭제하지 않습니다. | 스킬 수정 사항이 즉시 반영되며, 스크립트 실행 결과물 파일은 안전하게 보존됩니다. |
| 단일 스킬당 최대 500개 파일, 총 용량 20MB로 제한됩니다. 한도 초과 시 복사 실패 안내와 함께 본문 지침만 전달됩니다. | 스킬은 경량 작업 지침 및 보조 유틸리티 도구로 운용되어야 합니다. |
| `.mado/` 디렉터리는 파일 @멘션 자동완성 목록 및 작업 공간 다운로드 대상에서 자동으로 제외됩니다. | 시스템 내부 관리용 디렉터리이기 때문입니다. |

**스크립트는 명령줄 인자 없이 단독 실행됩니다.** `run_python_file`은 `sys.argv`에 스크립트 경로만 전달하며 현재 작업 디렉터리(cwd)를 작업 공간 루트로 설정합니다. 따라서 스킬 스크립트는 필요한 입력을 작업 공간 내의 파일에서 읽어오고 결과물 역시 작업 공간 내에 저장하도록 작성하며, 대상 파일명은 SKILL.md 지침에 명시해야 합니다. 예를 들어 `csv-profile` 스킬은 선택적 입력 파일인 `csv-profile.targets.txt`를 읽고 결과 보고서를 `csv-profile.md` 파일로 작성합니다.

**스크립트 내부의 문자열도 보안 검사 대상에 포함됩니다.** 사전 정적 분석기는 실행 전 코드 내 경로 형태의 문자열을 잠재적 파일 접근으로 판정합니다. 따라서 건너뛸 디렉터리 목록에 `.memory-graphs`와 같은 문자열을 하드코딩하기만 해도 "대화별 지식 그래프 접근 시도"로 간주되어 고정 보호 정책에 의해 실행이 즉각 차단됩니다. 숨김 디렉터리를 건너뛰어야 하는 경우 특정 폴더명을 명시하는 대신 첫 글자(`.`) 패턴을 기준으로 필터링하십시오.

## 설정 방법

```json
"skills": {
  "dir": "${SKILLS_DIR:-skills}",
  "disabled": []
},
"agents": {
  "architect": {
    "allowed_skills": ["mermaid-diagrams"]
  }
}
```

- `skills.dir` — 스킬 디렉터리 경로입니다 (프로젝트 루트 기준 상대 경로). 소스 코드 업데이트 패키지는 기본 `skills/` 디렉터리를 통째로 교체하므로 (`trial_templates/`와 동일), 사용자 정의 스킬을 보존하시려면 별도 디렉터리를 지정해 주십시오.
- `skills.disabled` — 비활성화할 스킬 목록입니다. 여기에 등록되지 않은 스킬은 활성화 상태로 유지되며, 디렉터리를 추가하는 것만으로 즉시 설치됩니다.
- `agents.<키>.allowed_skills` — 해당 에이전트가 불러 사용할 수 있는 스킬 목록입니다. 비워 두면 스킬 도구가 제공되지 않습니다.

고정 형식 응답을 요구하는 호출에서는 MCP 도구와 마찬가지로 스킬 도구 역시 제공되지 않습니다. 발언자 지명, 과업 분배, 결정 장부 작성, 요약 정리, Mermaid 문법 복구 및 체험 서버의 게스트 참여자 등이 이에 해당합니다.

| UI 영역 | 기능 설명 |
| :--- | :--- |
| 로스터 패널의 **스킬** 영역 | 스킬별 상태 칩과 활성화/비활성화 스위치, `N/M 켜짐` 배지를 제공합니다. 유효하지 않은 스킬은 빨간색 칩에 오류 사유가 표시되며, 스크립트가 포함된 스킬에는 *스크립트* 배지가 부착됩니다. 재기동할 백그라운드 프로세스가 없으므로 토론 진행 중에도 잠기지 않으며, 스킬 폴더가 변경되면 5초 이내에 자동 갱신됩니다. |
| 에이전트 카드의 **스킬 N** 버튼 | 해당 에이전트의 `allowed_skills` 목록을 편집합니다. **도구 N** 버튼과 동일한 잠금 규칙 및 설정 생명주기를 따릅니다. 디렉터리에서 삭제된 스킬은 선택을 해제할 때까지 *폴더에 없음* 상태로 유지됩니다. |
| **에이전트 추가** 대화상자 | MCP 서버 선택 영역 하단에 *사용할 스킬* 선택 영역이 제공됩니다. |

오케스트레이터에게 전달되는 전문가 목록에도 각 에이전트가 현재 사용할 수 있는 스킬 이름이 함께 표시됩니다 (`· 스킬: mermaid-diagrams`). 오케스트레이터가 작업 분배 시 "누구에게 다이어그램 작성을 위임할지" 판단하는 근거로 활용됩니다.
