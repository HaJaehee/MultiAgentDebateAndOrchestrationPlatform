# 스킬

> 상위: [핵심 기술 개관](README.md) · 이전: [도구 보안](08-tool-security.md)
>
> 관련 소스: `app/agents/skills.py` · `app/config.py` (`SkillsConfig`, `allowed_skills`)

---

## 스킬이란

**스킬**은 에이전트가 일이 맞을 때만 불러 읽는 작업 지침 묶음입니다. 다이어그램 규칙, 보고서 양식,
검토 목록처럼 조직이 정해 둔 방식을 `system_prompt` 에 늘 싣지 않고 필요할 때만 꺼내 쓰게 합니다.

스킬 하나는 폴더 하나입니다.

```text
skills/
  mermaid-diagrams/
    SKILL.md        ← 머리말(name, description) + 본문 지침
    reference.md    ← 부속 문서 (본문이 가리킬 때만 읽음)
  csv-profile/
    SKILL.md
    scripts/profile_csv.py   ← 스크립트 (작업 공간에 복사해 샌드박스로 실행)
```

기본 스킬은 둘입니다.

- `mermaid-diagrams` — MADO 의 Mermaid 문법 검사기가 거부하는 모양을 피하는 규칙입니다. 다이어그램을 그리는
  에이전트에게 주면 합성 뒤 다시 그리는 일이 줄어듭니다.
- `csv-profile` — 작업 공간의 CSV 를 열마다 종류·빈 값·범위·많이 나온 값으로 요약하는 스크립트 스킬입니다
  (UTF-8·CP949). 샌드박스(`run_python_file`)를 가진 에이전트에게 줍니다.

---

## 에이전트가 스킬을 쓰는 순서 (점진적 공개)

| 단계 | 모델이 보는 것 | 언제 |
| :--- | :--- | :--- |
| 목록 | 스킬마다 `- 이름: 설명` 한 줄 (`skills__load_skill` 도구의 설명 안) | 모든 요청 |
| 본문 | 머리말을 뗀 SKILL.md 와 부속 파일 목록 | `skills__load_skill` 을 부른 뒤 |
| 부속 파일 | 파일 하나의 글 | `skills__read_skill_file` 을 부른 뒤 |

스킬이 열 개여도 발언마다 드는 비용은 설명 열 줄입니다. 모델은 설명만 보고 부를지 정하므로, 설명에는
**언제 쓰는지**를 적어야 합니다.

스킬 도구를 가진 에이전트의 시스템 프롬프트에는 "맞는 스킬이 있으면 먼저 불러 따르라"는 두 줄이
세션 지침 앞에 붙습니다. 스킬이 없는 에이전트의 프롬프트는 한 글자도 늘지 않습니다.

불러온 본문은 그 발언의 도구 루프 안에만 있습니다. 다음 발언자의 맥락에는 도구 결과가 들어가지
않으므로, 다음 차례에 또 필요하면 다시 부릅니다.

---

## MCP 서버가 아니라 호스트 도구

두 도구는 모델에게 MCP 도구와 똑같이 보입니다(`서버__도구` 이름, 같은 도구 루프, 같은 접이식 카드와
기록). 하지만 서버 프로세스가 아니라 MADO 가 직접 실행합니다.

- 에이전트마다 볼 수 있는 스킬이 다르고, 앱이 도는 중에도 목록이 바뀝니다. MCP 서버의 도구 목록은
  기동할 때 한 번 받고 부르는 쪽과 무관해서 이것을 담을 수 없습니다.
- 스킬 폴더는 MADO 설치 폴더 안에 있어 에이전트의 도구가 닿지 않습니다(고정 보호). MADO 가 대신
  읽되, 그 스킬의 폴더 안으로만 읽습니다. `..`, 절대 경로, 숨김 파일, 폴더 밖을 가리키는 링크는 거부합니다.

그래서 `skills` 는 MCP 서버 이름으로 쓸 수 없습니다(설정 검증과 **서버 추가** 가 거부합니다).

스킬 도구는 **도구 보안 판정을 거치지 않습니다.** 운영자의 지침 파일을 읽을 뿐이고, 누가 쓸지는
`allowed_skills` 와 켜기·끄기로 이미 정했기 때문입니다. 호출 기록에는 판정 줄이 없습니다.

## 실시간 반영

시작한 대화는 에이전트 설정 전체를 굳힙니다([에이전트 풀과 페르소나](02-agent-pool.md)). 스킬은 MCP 서버
켜기·끄기에 이은 두 번째 예외입니다.

| 바꾼 것 | 이미 시작한 대화 | 아직 시작하지 않은 대화 |
| :--- | :--- | :--- |
| SKILL.md 나 부속 파일 수정 | **다음 발언부터** 새 내용 | 같음 |
| 스킬 폴더 추가·삭제 | **다음 발언부터** | 같음 |
| 스킬 켜기·끄기 (`skills.disabled`) | **다음 발언부터**. 이미 나간 요청에서 부르면 그 순간 거부 | 같음 |
| 에이전트의 `allowed_skills` | 영향 없음 (도구 할당처럼 굳음) | 바로 적용 |

목록은 발언마다 스킬 폴더를 다시 훑어 만듭니다. 폴더 목록과 파일 정보만 보고, SKILL.md 는 바뀐 것만
다시 읽으므로 가볍습니다.

## 스킬 만들기

```markdown
---
name: report-writing
description: 결정 보고서를 쓸 때 씁니다. 결론을 먼저, 근거와 남은 쟁점을 뒤에 둡니다.
---

# 결정 보고서

1. 첫 문단에 결론 ...
```

| 규칙 | 이유 |
| :--- | :--- |
| **폴더 이름**이 스킬 이름입니다 (영문·숫자·`_`·`-`, 64자까지, 영문이나 숫자로 시작). 머리말의 `name` 은 화면에만 보입니다. | `allowed_skills` 와 도구 인자에 그대로 적힙니다. |
| `description` 은 필수입니다 (공백은 한 칸으로, 1024자에서 자름). | 모델이 부르기 전에 보는 유일한 글입니다. |
| 본문은 비어 있으면 안 되고, SKILL.md 는 UTF-8 에 256KB 까지입니다. | 부르면 본문 전체가 모델에게 갑니다. 긴 자료는 부속 파일로 나눕니다. |
| 부속 파일은 숨김 파일·`__pycache__`·`node_modules`·가상환경·링크를 뺀 폴더 안의 파일입니다 (200개까지 목록에 보임). | `read_skill_file` 은 256KB 까지의 글 파일을 읽습니다. |

머리말은 YAML 의 부분 집합(`key: value`, 따옴표, `|`·`>` 블록, 들여 쓴 이어짐 줄)만 직접 읽습니다.
폐쇄망 번들에 YAML 라이브러리를 더하지 않기 위해서입니다. `name`·`description` 밖의 키는 읽고 버립니다.

규칙을 어긴 스킬은 이유와 함께 목록에 남고(로스터의 빨간 칩, `/api/skills` 의 `problem`), 어느 에이전트에게도
주지 않습니다.

## 스크립트가 든 스킬

부속 파일 중 `*.py` 는 스크립트로 봅니다. 스킬 폴더는 설치 폴더 안이라 에이전트가 그 자리에서 실행할 수
없으므로, 이렇게 돕니다.

1. 실행 도구(`run_python_file`, 보통 `sandbox` 서버)를 가진 에이전트가 스킬을 불러옵니다.
2. MADO 가 스킬 폴더를 **그 대화의 작업 공간** `.mado/skills/<이름>/` 으로 복사하고, 불러온 본문 끝에 실행할
   경로와 호출 방법(`sandbox__run_python_file`, `file_path=".mado/skills/<이름>/scripts/…"`)을 붙입니다.
3. 에이전트가 실행합니다. 이것은 여느 샌드박스 호출이라 도구 보안의 코드 검사와 판정을 거칩니다. 기본 모드에서는
   검사를 통과한 스크립트가 묻지 않고 돌고, 검토 모드는 묻고, 읽기 전용 모드는 거부합니다.

| 규칙 | 이유 |
| :--- | :--- |
| 실행 도구가 없는 에이전트에게는 복사하지 않고, "실행할 수 있는 에이전트에게 맡기라" 고 알립니다. | 복사하는 까닭이 실행입니다. 아무도 못 돌릴 파일로 작업 공간을 어지럽히지 않습니다. |
| 불러올 때마다 **바뀐 파일만** 다시 복사합니다(크기·수정 시각 비교). 에이전트가 고친 복사본은 원본으로 돌아갑니다. 원본에 없는 파일은 지우지 않습니다. | 스킬 수정은 다음 불러오기에 닿고, 스크립트가 옆에 남긴 결과물은 지켜집니다. |
| 한 스킬에 500개·20MB 까지. 넘으면 복사하지 못했다는 안내와 함께 본문만 줍니다. | 스킬은 지침과 작은 도구 묶음입니다. |
| `.mado/` 는 @언급 목록과 작업 공간 다운로드에 보이지 않습니다. | MADO 가 쓰는 작업 공간 안의 자리입니다. |

**스크립트는 인자 없이 돕니다.** `run_python_file` 은 `sys.argv` 에 파일 경로만 넣고, 작업 폴더(cwd)를 작업
공간으로 둡니다. 그래서 스킬 스크립트는 입력을 작업 공간의 파일에서 읽고 결과도 거기 쓰도록 만들고, 어떤 파일인지는
SKILL.md 에 적습니다. `csv-profile` 은 선택 입력 `csv-profile.targets.txt` 를 읽고 `csv-profile.md` 를 씁니다.

**스크립트 안의 글자도 검사를 받습니다.** 코드 검사는 실행 전에 경로처럼 보이는 문자열을 "읽기"로 봅니다.
건너뛸 폴더 목록에 `.memory-graphs` 라고 적기만 해도 "대화별 지식 그래프를 읽는다" 로 보고 고정 보호가 실행을
막습니다. 숨김 폴더는 이름 대신 첫 글자(`.`)로 건너뛰세요.

## 설정

```json
"skills": {
  "dir": "${SKILLS_DIR:-skills}",
  "disabled": []
},
"agents": {
  "architect": {
    "allowed_skills": ["mermaid-diagrams"]
  }
}
```

- `skills.dir` — 스킬 폴더. 상대 경로면 프로젝트 루트 기준입니다. 소스 갱신 패키지는 기본 `skills/` 를
  통째로 바꾸므로(`trial_templates/` 와 같음), 직접 만든 스킬을 지키려면 다른 폴더를 가리키세요.
- `skills.disabled` — 꺼 둔 스킬. 여기 없는 스킬은 켜져 있습니다. 폴더를 넣는 것이 곧 설치입니다.
- `agents.<키>.allowed_skills` — 이 에이전트가 불러 쓸 수 있는 스킬. 비어 있으면 스킬 도구가 없습니다.

도구를 떼는 곳에서는 스킬도 뗍니다. 발언자 지명·과업 분배·결정 장부·요약·Mermaid 복구처럼 정해진 형식의
답을 받는 호출과, 체험 서버의 참여자가 그렇습니다.

## 화면

| 위치 | 하는 일 |
| :--- | :--- |
| 로스터 패널의 **스킬** 칸 | 스킬마다 칩과 켜기·끄기 스위치, `N/M 켜짐` 배지. 깨진 스킬은 빨간 칩에 이유가 뜨고, 스크립트가 든 스킬에는 *스크립트* 배지가 붙습니다. 토론 중에도 잠기지 않고(다시 띄울 서버가 없음), 스킬 폴더가 바뀌면 5초 안에 다시 그립니다. |
| 에이전트 카드의 **스킬 N** 버튼 | 그 에이전트의 `allowed_skills` 를 고릅니다. **도구 N** 과 같은 잠금·같은 의미입니다. 폴더에서 사라진 스킬은 체크를 풀 때까지 *폴더에 없음* 으로 남습니다. |
| **에이전트 추가** 대화상자 | MCP 서버 옆에 *사용할 스킬* 줄이 있습니다. |

오케스트레이터가 보는 전문가 목록에는 에이전트마다 지금 쓸 수 있는 스킬 이름이 붙습니다
(`· 스킬: mermaid-diagrams`). "다이어그램은 누구에게" 를 정할 때 씁니다.
