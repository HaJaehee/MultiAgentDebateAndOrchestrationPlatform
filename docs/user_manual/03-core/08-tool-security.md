# 도구 보안

> 상위: [핵심 기술 개관](README.md) · 이전: [데이터베이스와 세션 스냅샷](07-persistence.md)
>
> 관련 소스: `app/mcp/policy.py` · `app/mcp/exec_scan.py` · `app/orchestration/tool_gate.py` · `app/orchestration/control.py`

에이전트가 MCP 도구를 부르면, 실행하기 전에 **허용 · 묻기 · 거부** 가운데 하나로 판정합니다. 묻기가 나오면 채팅 피드 위에 승인 카드가 뜨고, 사람이 답할 때까지 그 발언만 기다립니다. 판정 방식은 Claude Code, Zed, Google Antigravity의 도구 권한 설계를 참고했고, 여러 에이전트가 사람 없이 오래 토론하는 MADO의 사정에 맞게 고쳤습니다.

---

## 도구가 아니라 행위에 규칙을 겁니다

규칙을 도구 이름에 걸면 우회로가 생깁니다. filesystem 도구로 `.env` 읽기를 막아도, sandbox에 `open('.env').read()` 한 줄을 보내면 같은 파일이 읽힙니다. Antigravity도 파일 도구로 막은 `.env`를 터미널의 `cat`으로 읽힌 적이 있습니다.

그래서 MADO는 호출을 먼저 **행위**로 바꾼 뒤 판정합니다.

| 행위 | 뜻 | 예 |
| :--- | :--- | :--- |
| `read(경로)` · `write(경로)` · `delete(경로)` | 파일 읽기·쓰기·삭제 | `filesystem__write_file` → `write(src/app.py)` |
| `exec(코드)` | sandbox 코드 실행 | `execute_python_code` → `exec` + 코드에서 찾은 경로·호스트 |
| `net(호스트)` | 네트워크 | `fetch` → `net(docs.python.org)` |
| `mcp(서버/도구)` | 도구 그 자체 | 모든 호출 |

sandbox 코드는 실행 전에 구문 트리로 읽어서 경로, URL, 삭제, 프로세스 실행을 찾아냅니다. `subprocess`, `eval`, 셸 명령(`!ls`)처럼 무엇을 할지 읽을 수 없는 코드는 안전하다고 짐작하지 않고 사람에게 묻습니다. 이 검사는 실수와 흔한 주입을 거르는 그물이지 보안 경계가 아닙니다. Python은 마음먹으면 무엇이든 숨길 수 있기 때문입니다.

## 판정 순서

**고정 보호 → 거부(deny) → 묻기(ask) → 허용(allow) → 모드 기본값** 순서로 보고, 먼저 걸린 쪽이 이깁니다. 구체적인 허용 규칙도 넓은 거부 규칙을 뚫지 못합니다.

| 위험 등급 | 읽기 전용 | 기본 | 검토 | 자동 |
| :--- | :---: | :---: | :---: | :---: |
| 읽기, 대화 상태(memory) | 허용 | 허용 | 허용 | 허용 |
| 작업 공간 안 쓰기 | 거부 | 허용 | 묻기 | 허용 |
| 작업 공간 밖 접근 | 거부 | 묻기 | 묻기 | 허용 |
| 삭제 | 거부 | 묻기 | 묻기 | 허용 |
| 코드 실행 (검사 통과) | 거부 | 허용 | 묻기 | 허용 |
| 검사에 걸린 코드, 패키지 설치 | 거부 | 묻기 | 묻기 | 허용 |
| 네트워크, 다른 호스트의 원격 서버 | 거부 | 묻기 | 묻기 | 허용 |
| 등급을 모르는 도구 | 거부 | 묻기 | 묻기 | 허용 |

"기본" 모드가 작업 공간 쓰기를 묻지 않는 이유는 쓰기마다 멈추면 토론이 진행되지 않기 때문입니다. 작업 공간은 앱이 git 저장소로 만들어 두므로 바뀐 내용을 확인하고 되돌릴 수 있습니다.

모드는 대화마다 로스터 패널의 **도구 보안**에서 고릅니다. 토론 중에 바꾸면 다음 도구 호출부터 바로 적용됩니다. 인자와 상관없이 늘 거부되는 도구(예: 읽기 전용 모드의 쓰기 도구)는 모델에게 넘기는 도구 목록에서 아예 뺍니다.

## 승인 카드

묻기로 판정된 호출은 채팅 피드 위쪽에 하늘색 카드로 뜹니다. 카드에는 에이전트, 도구, 위험 등급, 묻는 이유, 실행할 코드나 인자, 남은 시간이 나옵니다.

| 버튼 | 동작 |
| :--- | :--- |
| 이번만 허용 | 이 호출만 실행합니다. |
| 이 대화에서 허용 | 범위를 이 대화에 저장합니다. 그 범위의 호출은 다음부터 묻지 않고 실행합니다. |
| 항상 허용 | 범위를 `conf.json`의 `tool_security.allow`에 저장합니다. **서버 PC에서 연 화면에만** 보입니다. |
| 거부 | 이 호출을 막습니다. 사유를 적으면 에이전트에게 그대로 전달됩니다. |
| 이 대화에서 거부 | 범위를 이 대화에 저장합니다. 그 범위의 호출은 다음 턴에도 묻지 않고 거부합니다. |
| 항상 거부 | 범위를 `conf.json`의 `tool_security.deny`에 저장합니다. **서버 PC에서 연 화면에만** 보입니다. 기본 거부 목록은 그대로 남습니다. |

- 범위는 한 줄에 규칙 하나이고, 이 호출을 가리키는 가장 좁은 규칙이 미리 채워져 있습니다. '이 대화에서'와 '항상' 버튼이 허용·거부 모두 이 범위를 씁니다.
- 고친 범위가 쓸모없으면 받지 않고 이유를 알려 줍니다. 허용 범위가 지금 호출을 덮지 못하거나, 거부 범위가 지금 호출을 막지 못하는 경우입니다.
- 정해진 시간(기본 180초) 안에 답이 없으면 거부합니다. 토론을 정지하면 떠 있는 카드는 모두 거부됩니다.
- 같은 에이전트가 이번 턴에 이미 거부된 호출을 똑같이 다시 하면, 카드를 다시 띄우지 않고 거부합니다.
- 묻기 규칙(`ask`)에 걸린 카드에는 허용을 기억하는 버튼이 없습니다. 묻기 규칙이 허용 규칙보다 앞서므로 저장해도 효과가 없기 때문입니다. 거부는 기억할 수 있습니다.

### 이 대화의 규칙 보기와 지우기

로스터 패널의 **도구 보안** 옆 **대화 규칙** 버튼을 누르면, 이 대화에서 허용하거나 거부한 규칙이 나옵니다. 휴지통 버튼으로 하나씩 지울 수 있고, 다음 도구 호출부터 다시 모드와 설정대로 판정합니다. 토론 중에 지워도 됩니다. '항상' 규칙은 여기 나오지 않으며, `conf.json`의 `tool_security.allow`·`deny`에서 고칩니다. 대화를 새 대화로 이어받을 때 모드는 따라가지만 이 규칙들은 따라가지 않습니다.

## 고정 보호

어떤 모드, 규칙, 승인으로도 풀리지 않습니다.

1. **MADO 설치 폴더**: 작업 공간을 뺀 전부가 보호 대상입니다. 권한 규칙이 든 `conf.json`, 원격 접속 토큰과 API 키가 든 `.env`, 모든 대화가 든 DB, 앱 코드가 여기 있습니다. 세션 작업 공간을 설치 폴더로 잡아도 이 파일들에는 닿지 않습니다.
2. **`.memory-graphs`**: 대화마다 나뉜 지식 그래프입니다. 파일 도구로 직접 열면 다른 대화의 기억을 읽게 되므로 memory 도구만 씁니다.
3. **`.git` 안 쓰기**: `hooks/`는 다음 git 명령 때 실행되는 코드입니다. 저장소는 git 도구로만 바꿉니다.
4. **비밀 환경변수**: MCP 서버 프로세스는 MADO의 토큰과 API 키를 물려받지 않습니다. 서버에 비밀이 필요하면 `conf.json`의 그 서버 `env`에 명시합니다.

## 설정

```json
"tool_security": {
  "mode": "default",
  "approval_timeout": 180,
  "deny":  ["read(**/.env)", "read(**/.ssh/**)", "net(webhook.site)"],
  "ask":   ["mcp(git/git_checkout)"],
  "allow": ["net(docs.python.org)"],
  "agents": { "critic": { "mode": "read_only" } }
}
```

- 경로 규칙은 작업 공간 기준 glob입니다. `**`는 폴더를 넘나들고, 폴더 전체는 `src/**`처럼 적습니다.
- 막는 규칙은 위로 번지고(읽기를 막으면 쓰기도 막힘), 허용은 아래로 번집니다(쓰기를 허용하면 읽기도 허용).
- `deny`를 적으면 기본 거부 목록(비밀 파일, 유출용 수신 서비스)을 **대신합니다**. 기본 목록을 지우려는 게 아니라면 그대로 두고 필요한 줄만 더하십시오.
- 에이전트별 설정(`agents`)은 조이기만 합니다. 모드는 대화 모드와 비교해 더 엄격한 쪽이 쓰이고, 허용 규칙은 받지 않습니다. 에이전트 설정은 대화가 시작될 때 굳지만, 보안 설정은 굳지 않도록 `agents.<키>`가 아니라 여기에 둡니다.

## 기록

도구 기록마다 판정이 남습니다(`tool_calls`의 `decision`, `risk`, `rule`, `approver`). "이 대화에서 허용·거부" 규칙은 세션의 `tool_grants`, `tool_denials`에 저장됩니다. 채팅 피드의 도구 아코디언에는 Security 줄이 붙고, 막힌 호출은 "🛡️ Blocked" 제목으로 보입니다. 세션 저장 파일에도 호출마다 판정 한 줄이 남습니다.

자세한 설계와 다음 단계 계획은 개발 위키의 `wiki/mcp/tool-security.md`에 있습니다.
