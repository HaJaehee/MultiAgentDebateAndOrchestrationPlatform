# 도구 보안

> 상위: [핵심 기술 개관](README.md) · 이전: [데이터베이스와 세션 스냅샷](07-persistence.md) · 다음: [스킬](09-skills.md)
>
> 관련 소스: `app/mcp/policy.py` · `app/mcp/exec_scan.py` · `app/orchestration/tool_gate.py` · `app/orchestration/control.py`

에이전트가 MCP 도구를 호출하면, 실제 실행에 앞서 **허용(Allow) · 확인(Ask) · 거부(Deny)** 중 하나로 정책을 판정합니다. 확인(Ask) 판정이 내려지면 채팅 피드 상단에 승인 요청 카드가 표시되며, 사용자가 응답할 때까지 해당 발언만 대기 상태로 전환됩니다. 보안 판정 아키텍처는 Claude Code, Zed, Google Antigravity의 도구 권한 모델을 참고하였으며, 여러 에이전트가 사용자 개입 없이 자율적으로 심층 토론을 수행하는 MADO의 환경에 맞게 고도화되었습니다.

---

## 도구명이 아닌 행위(Action) 기반 보안 규칙

보안 정책을 단순 도구 함수명에만 바인딩하면 우회 경로가 쉽게 발생합니다. 예를 들어 파일시스템 도구에서 `.env` 파일 읽기를 차단하더라도, 코드 실행 샌드박스 도구에 `open('.env').read()` 한 줄을 전달하면 동일한 파일이 노출될 수 있습니다.

따라서 MADO는 도구 호출을 먼저 표준화된 **행위(Action)** 단위로 변환한 후 보안 정책을 판정합니다.

| 행위 유형 | 의미 및 대상 | 예시 |
| :--- | :--- | :--- |
| `read(경로)` · `write(경로)` · `delete(경로)` | 파일 읽기 · 쓰기 · 삭제 | `filesystem__write_file` → `write(src/app.py)` |
| `exec(코드)` | 샌드박스 내 코드 실행 | `execute_python_code` → `exec` + AST 분석을 통해 추출한 경로·호스트 |
| `net(호스트)` | 외부 네트워크 통신 | `fetch` → `net(docs.python.org)` |
| `mcp(서버/도구)` | 특정 도구 호출 자체 | 모든 MCP 호출 |

샌드박스 실행 코드는 실제 실행에 앞서 추상 구문 트리(AST) 분석을 거쳐 파일 경로, URL, 파일 삭제, 하위 프로세스 호출을 정적으로 추출합니다. `subprocess`, `eval`, 셸 명령어(`!ls`)처럼 정적 분석으로 행위를 사전에 파악할 수 없는 동적 코드는 임의로 안전하다고 간주하지 않고 사용자 확인(`ask`) 대상으로 전환합니다. 단, 이 정적 검사는 에이전트의 우발적인 실수나 정형화된 인젝션을 걸러내는 1차 안전망(Heuristic Filter)이며, 동적 언어의 리플렉션이나 난독화까지 완벽히 방어하는 절대적 보안 경계(Security Boundary)는 아닙니다.

## 판정 순서 및 우선순위

보안 정책은 **고정 보호(Hardcoded Protection) → 거부(Deny) → 확인(Ask) → 허용(Allow) → 모드 기본값(Mode Default)** 순서로 엄격하게 평가되며, 먼저 매칭된 규칙이 즉시 적용됩니다. 아무리 구체적인 허용 규칙이 존재하더라도 상위의 광범위한 거부 규칙을 무효화할 수 없습니다.

| 위험 등급 및 행위 유형 | 읽기 전용 (read_only) | 기본 모드 (default) | 검토 모드 (review) | 자동 모드 (auto) |
| :--- | :---: | :---: | :---: | :---: |
| 파일 읽기, 세션 상태 메모리 (`memory`) | 허용 | 허용 | 허용 | 허용 |
| 작업 공간 내부 파일 쓰기 | 거부 | 허용 | 확인(Ask) | 허용 |
| 작업 공간 외부 파일 접근 | 거부 | 확인(Ask) | 확인(Ask) | 허용 |
| 파일 및 디렉터리 삭제 | 거부 | 확인(Ask) | 확인(Ask) | 허용 |
| 코드 실행 (정적 검사 통과) | 거부 | 허용 | 확인(Ask) | 허용 |
| 검사 경고 코드, 패키지 동적 설치 | 거부 | 확인(Ask) | 확인(Ask) | 허용 |
| 네트워크 통신, 외부 호스트 원격 서버 | 거부 | 확인(Ask) | 확인(Ask) | 허용 |
| 위험 등급 미분류 도구 | 거부 | 확인(Ask) | 확인(Ask) | 허용 |

"기본(default)" 모드에서 작업 공간 내부 쓰기를 매번 사용자에게 확인하지 않는 이유는, 파일 생성·수정 작업마다 토론 흐름이 중단되면 생산성이 크게 저하되기 때문입니다. 작업 공간은 애플리케이션이 Git 저장소로 관리하므로 변경 내역을 언제든 확인하고 안전하게 롤백할 수 있습니다.

보안 모드는 세션별로 로스터 관리 패널의 **도구 보안** 드롭다운에서 선택합니다. 토론 진행 도중 모드를 변경하더라도 다음 도구 호출부터 즉시 반영됩니다. 인자와 무관하게 해당 모드에서 원천 거부되는 도구(예: '읽기 전용' 모드에서의 파일 쓰기 도구)는 LLM에 전달되는 도구 정의 목록(Tools Schema)에서 사전에 제외됩니다.

## 사용자 승인 카드

확인(`ask`)으로 판정된 도구 호출은 채팅 피드 상단에 하늘색 승인 요청 카드로 표시됩니다. 카드에는 호출 에이전트, 도구명, 위험 등급, 확인 사유, 실행할 인자 또는 코드 본문, 남은 응답 대기 시간이 명시됩니다.

| 승인 옵션 | 동작 설명 |
| :--- | :--- |
| **이번만 허용** | 해당 도구 호출 1회에 한해 실행을 허용합니다. |
| **이 대화에서 허용** | 해당 행위 범위를 현재 세션에 저장하여, 이후 동일 범위의 호출은 사용자 확인 없이 자동 허용합니다. |
| **항상 허용** | 해당 행위 범위를 `conf.json`의 `tool_security.allow`에 저장하여 전역 허용합니다. **서버 호스트(Local) 화면에서만** 노출됩니다. |
| **거부** | 해당 도구 호출 실행을 즉시 차단합니다. 사유를 입력하면 에이전트에게 오류 메시지로 그대로 전달됩니다. |
| **이 대화에서 거부** | 해당 행위 범위를 현재 세션에 저장하여, 이후 동일 범위의 호출은 다음 턴에도 사용자 확인 없이 즉시 차단합니다. |
| **항상 거부** | 해당 행위 범위를 `conf.json`의 `tool_security.deny`에 저장하여 전역 차단합니다. **서버 호스트(Local) 화면에서만** 노출됩니다. 기본 거부 목록은 그대로 유지됩니다. |

- 규칙 범위는 한 줄당 하나의 패턴으로 정의되며, 현재 호출을 정확히 지정하는 가장 구체적인 최소 범위의 규칙이 기본값으로 자동 입력됩니다. '이 대화에서' 및 '항상' 옵션 모두 이 규칙 패턴을 기준으로 저장됩니다.
- 사용자가 수정한 규칙 범위가 유효하지 않으면 등록이 반려되고 안내 메시지가 표시됩니다. 예를 들어 허용 규칙이 현재 호출을 포함하지 못하거나, 거부 규칙이 현재 호출을 차단하지 못하는 모순된 패턴을 지정한 경우입니다.
- 지정된 제한 시간(기본 180초) 내에 사용자의 응답이 없으면 타임아웃으로 자동 거부 처리됩니다. 사용자가 토론을 일시 중단하거나 강제 종료할 경우 대기 중인 모든 승인 카드는 일괄 거부됩니다.
- 동일한 에이전트가 현재 턴에서 이미 거부된 호출과 완전히 동일한 인자로 재호출을 시도할 경우, 승인 카드를 다시 표시하지 않고 즉시 거부(Auto-reject)합니다.
- 명시적 확인 규칙(`ask`)에 의해 유발된 승인 카드에는 영구 허용 버튼이 표시되지 않습니다. 규칙 평가 순서상 확인(`ask`)이 허용(`allow`)보다 우선하므로 허용 목록에 추가해도 효력이 없기 때문입니다 (거부 규칙 저장은 가능).

### 세션별 동적 규칙 조회 및 삭제

로스터 관리 패널의 **도구 보안** 옆 **세션 규칙** 버튼을 클릭하면, 현재 대화 세션에서 동적으로 등록한 허용/거부 규칙 목록을 확인할 수 있습니다. 휴지통 아이콘을 클릭하여 개별 규칙을 삭제할 수 있으며, 삭제 즉시 다음 도구 호출부터 기본 보안 모드와 전역 설정에 따라 판정됩니다. 토론 진행 도중에도 안전하게 삭제할 수 있습니다. 전역 '항상' 규칙은 이 창에 표시되지 않으며 `conf.json`의 `tool_security.allow` 및 `deny`에서 직접 관리합니다. 세션 분기(Fork) 시 보안 모드는 승계되지만, 세션별 동적 규칙은 복사되지 않고 초기화됩니다.

## 고정 보호 영역 (Hardcoded Protection)

어떠한 보안 모드, 세션별 규칙, 사용자 개별 승인으로도 결코 우회하거나 해제할 수 없는 절대적 보안 경계입니다.

1. **MADO 설치 디렉터리**: 세션 작업 공간을 제외한 애플리케이션 루트 전체가 보호 대상입니다. 권한 정책이 정의된 `conf.json`, 원격 접속 토큰 및 API 키가 저장된 `.env`, 전체 대화 이력이 담긴 데이터베이스, 애플리케이션 소스 코드가 포함됩니다. 세션 작업 공간 경로를 설치 디렉터리로 잘못 지정하더라도 이 핵심 파일들에는 절대 접근할 수 없습니다.
2. **`.memory-graphs`**: 세션별로 격리된 지식 그래프 데이터입니다. 일반 파일 도구로 직접 조작할 경우 다른 대화 세션의 메모리가 오염되거나 누출될 수 있으므로 전용 메모리 도구를 통해서만 접근할 수 있습니다.
3. **`.git` 내부 쓰기 제한**: `.git/hooks/` 등은 Git 명령 실행 시 임의 코드가 실행될 수 있는 취약 경로입니다. 따라서 저장소 조작은 안전한 Git 전용 도구를 통해서만 수행할 수 있습니다.
4. **환경변수 격리**: MCP 서버 하위 프로세스는 MADO 본체의 민감한 마스터 토큰 및 업스트림 LLM API 키를 상속받지 않습니다. 특정 MCP 서버에 인증 정보가 필요할 경우 `conf.json` 내 해당 서버의 `env` 섹션에 명시적으로 주입해야 합니다.

## 설정 예시

```json
"tool_security": {
  "mode": "default",
  "approval_timeout": 180,
  "deny":  ["read(**/.env)", "read(**/.ssh/**)", "net(webhook.site)"],
  "ask":   ["mcp(git/git_checkout)"],
  "allow": ["net(docs.python.org)"],
  "agents": { "critic": { "mode": "read_only" } }
}
```

- 경로 규칙은 작업 공간 기준의 Glob 패턴을 사용합니다. `**`는 모든 하위 디렉터리를 포함하며, 디렉터리 전체를 지정할 때는 `src/**`와 같이 기술합니다.
- 차단 규칙은 상위 행위로 전파되고(예: 읽기를 차단하면 쓰기도 자동 차단), 허용 규칙은 하위 행위로 전파됩니다(예: 쓰기를 허용하면 읽기도 자동 허용).
- `conf.json`에서 `deny` 목록을 명시하면 내장 기본 거부 목록(비밀 환경변수 파일, 외부 유출용 웹훅 서비스 등)을 **대체(Override)**합니다. 기본 차단 대상을 유지하려면 기본 규칙을 보존한 상태에서 추가 규칙을 기술해야 합니다.
- 에이전트별 보안 설정(`agents`)은 정책을 강화(Restrict)하는 방향으로만 동작합니다. 보안 모드는 세션 모드와 에이전트 모드 중 더 엄격한 기준이 적용되며, 전역보다 완화된 허용 규칙은 부여할 수 없습니다. 에이전트의 일반 설정은 세션 잠금 시점에 스냅샷으로 고정되지만, 보안 정책은 동적 관리를 위해 `agents.<key>`가 아닌 본 `tool_security` 섹션에서 독립적으로 관리됩니다.

## 감사 로그 및 실행 이력

모든 도구 실행 이력에는 보안 판정 결과가 상세히 기록됩니다 (`tool_calls` 테이블의 `decision`, `risk`, `rule`, `approver`). 세션 수준의 "이 대화에서 허용/거부" 규칙은 `sessions` 테이블의 `tool_grants`, `tool_denials` 필드에 JSON으로 영구 저장됩니다. 채팅 피드의 도구 실행 카드에서는 다음 두 가지 핵심 정보를 제공합니다:

- **결과 배지**: 카드 제목 영역 우측에 표시됩니다. `성공`(정상 실행 완료), `실패`(도구 실행 중 오류 반환), `차단`(실행 전 보안 정책에 의해 거부됨) 중 하나로 표시되며, 차단된 도구 호출에는 방패 아이콘이 부여됩니다.
- **판정 근거**: 카드 본문 상단에 `[결정 주체] · [판정 근거] · [승인 환경]` 형식으로 노출됩니다. 결정 주체에는 `자동 허용`, `사용자 승인`, `규칙 차단`, `모드 차단`, `고정 보호`, `사용자 거부`, `응답 시간 초과` 등이 기록됩니다 (예: `사용자 거부 · 세션 등록 규칙 write(design.md) · 서버 호스트`).

세션 내보내기 문서 및 JSON 백업 파일에도 도구 호출마다 동일한 보안 판정 이력이 완전하게 보존됩니다.
