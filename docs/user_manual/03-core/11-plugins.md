# 플러그인 (토론 전략 · 호스트 도구)

> 상위: [핵심 기술 개관](README.md) · 이전: [동료 자문 (peers)](10-peer-consultation.md)
>
> 관련 소스: `app/plugins.py` · `app/agents/host_tools.py` · `app/orchestration/strategies.py` · 예제: `docs/examples/plugins/`

---

애플리케이션 코드를 직접 수정하지 않고 신규 토론 전략과 호스트 도구를 플러그인 형태로 확장할 수 있습니다. 호스트 도구는 외부 MCP 서버처럼 별도 독립 프로세스로 분리되지 않고 애플리케이션 런타임 내부에서 직접 실행되는 도구입니다. 내장된 `skills`, `peers`, `ask`, `tools` 또한 동일한 메커니즘으로 동작합니다.

도구가 외부 프로세스로 격리되어 실행되어도 무방하다면 [MCP 서버](04-mcp-host.md) 형태로 개발하는 것을 권장합니다. 프로세스가 물리적으로 분리되어 있어 애플리케이션에 미치는 부하와 장애 전파를 최소화할 수 있습니다. 반면 호스트 도구는 현재 발언 차례의 에이전트 인스턴스나 작업 공간(workspace) 컨텍스트에 직접 접근해야 하는 경우에 주로 사용합니다.

> [!WARNING]
> **플러그인은 메인 애플리케이션과 동일한 시스템 권한으로 실행되는 파이썬 코드입니다.** 플러그인 디렉터리에 파일을 배치하는 것은 파이썬 패키지를 시스템에 설치하는 것과 동일한 보안 책임을 수반합니다. 코드 내용을 면밀히 검토하고 신뢰할 수 있는 코드만 추가하십시오.

---

## 플러그인 예제 적용해 보기

[`docs/examples/plugins/`](../../examples/plugins/README.md) 경로에 복사하여 즉시 테스트할 수 있는 예제 파일들이 준비되어 있습니다.

| 예제 파일 | 제공 기능 |
| :--- | :--- |
| [`strategies/consensus_voting.py`](../../examples/plugins/strategies/consensus_voting.py) | 1라운드에서는 제안을 발의하고, 2라운드부터는 발언 순서를 역순으로 뒤집어 교차 투표하는 전략 |
| [`host_tools/glossary.py`](../../examples/plugins/host_tools/glossary.py) | 위험 등급(read)을 명시하여 확인 없이 자동 실행되는 도구 및 시스템 프롬프트 지침 주입 |
| [`host_tools/ticket.py`](../../examples/plugins/host_tools/ticket.py) | 위험 등급 미지정으로 실행 시 승인 카드가 표시되는 도구 및 작업 공간 파일 작성 |

**1. 파일을 복사합니다.** 프로젝트 루트 디렉터리에 대상 폴더를 생성하고 파일을 배치합니다.

```text
MultiAgentDebateOrchestration/
├── strategies/
│   └── consensus_voting.py
└── host_tools/
    ├── glossary.py
    └── ticket.py
```

**2. 서버를 재시작합니다.** 플러그인은 서버 시작 시점에 1회만 정적으로 로드됩니다.

**3. 로드 결과를 확인합니다.** 로스터 패널의 MCP 서버 목록에 `glossary`와 `ticket` 칩이 추가되고, 토론 전략 선택 메뉴에 `합의 투표` 항목이 표시됩니다.

**4. 에이전트에 도구를 할당합니다.** 에이전트 카드의 `도구` 설정 패널에서 `glossary`와 `ticket`을 활성화합니다. 대화의 도구 구성은 첫 메시지를 보낼 때 고정되므로 **새 대화를 생성하여** 확인합니다.

**5. 토론을 실행합니다.** 전략을 `합의 투표`로 선택하고 최대 라운드를 2 이상으로 설정합니다.

- 라운드 1에서는 우선순위 순서대로 제안을 발표하고, 라운드 2에서는 역순으로 투표를 진행합니다.
- 모델이 `glossary__lookup`을 호출하면 별도 승인 절차 없이 즉시 실행되며 결과 도구 카드가 기록됩니다.
- 모델이 `ticket__create`를 호출하면 사용자 승인 요청 카드가 표시되며, 승인 시 작업 공간에 `tickets.md` 파일이 생성됩니다.

도구의 실제 호출 여부는 LLM이 판단합니다. 프롬프트에 "용어집에서 MADO의 뜻을 조회하고 티켓을 하나 생성해 주세요"와 같이 명시하면 쉽게 동작을 확인할 수 있습니다.

### 패키지 업데이트 시 유의사항

소스 업데이트 패키지는 `strategies/`와 `host_tools/` 디렉터리를 덮어쓰지 않고 영구 보존합니다. 단, 폐쇄망 전체 번들을 새로 빌드할 때는 해당 디렉터리가 기본 번들에 포함되지 않으므로 수동으로 백업 및 이전해야 합니다.

## 토론 전략 플러그인 작성법

`BaseDebateStrategy` 기본 클래스를 상속받아 구현합니다. [예제 코드](../../examples/plugins/strategies/consensus_voting.py)를 기반으로 수정하여 작성하는 것을 권장합니다.

| 속성 / 메서드 | 필수 여부 | 설명 |
| :--- | :--- | :--- |
| `name` | 필수 | 대화 세션에 저장되는 고유 식별자입니다. 영문·숫자·`_`·`-`만 사용 가능하며, 내장 전략 및 기존 별칭과의 중복은 허용되지 않습니다. |
| `display_name` | 필수 | UI 전략 선택 메뉴에 표시될 명칭입니다. |
| `get_speakers_for_round(active_agents, round_num, state)` | 필수 | 해당 라운드에 참여할 발언자 목록을 순서대로 반환합니다. |
| `turn_instruction(agent, speakers, index, state)` | 선택 | 해당 발언 차례에 주입할 프롬프트 지침 문자열을 반환합니다. |
| `orchestrator_selects_speakers` | 선택 | `True` 설정 시 오케스트레이터가 매 라운드 후보군 중에서 발언자를 동적으로 지명합니다. |
| `orchestrator_dispatches_parallel` | 선택 | `True` 설정 시 하위 작업을 분배하여 병렬 실행한 후 취합합니다. |

세부 개발 규약은 [토론 전략 구현 가이드](06-debate-strategies.md#신규-토론-전략-구현-가이드)를 준수하십시오. 전략 로직 내부에서 직접 LLM API를 호출하거나 무거운 파일 I/O를 수행하지 마십시오. 매 라운드 이벤트 루프 상에서 동기로 실행되므로 토론 엔진과 UI 전체가 블로킹될 수 있습니다.

## 호스트 도구 플러그인 작성법

`HostToolProvider` 기본 클래스를 상속받아 구현합니다. 필수적으로 정의해야 하는 속성 및 메서드는 `prefix`, `tails`, `tools_for`, `run`입니다.

```python
from app.agents.host_tools import HostToolProvider


class WeatherTools(HostToolProvider):
    prefix = "weather"          # 도구 이름의 앞부분
    tails = ("today",)          # 전체 이름은 weather__today
    risk = "read"               # 도구 보안 판정에 쓰는 등급

    def tools_for(self, agent):
        return [self.definition("today", "오늘 날씨를 알려 줍니다.", {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        })]

    async def run(self, call):
        return f"{call.arguments.get('city')}: 맑음", "success"
```

### 주요 속성 및 메서드 명세

| 속성 / 메서드 | 기본값 | 설명 |
| :--- | :--- | :--- |
| `prefix` | 필수 | 도구 이름의 고유 접두사이자 활성화 식별자입니다. 소문자로 시작하며 소문자·숫자·`-`·`_`만 허용되고 `__`는 사용할 수 없습니다. 내장 도구 및 타 플러그인, 등록된 MCP 서버와 중복될 수 없습니다. |
| `tails` | 필수 | 접두사 뒤에 붙는 세부 도구 식별자 튜플입니다. |
| `label` | 접두사 기반 자동 생성 | 동일한 이름의 MCP 서버 충돌 시 경고 안내에 표시되는 라벨입니다. |
| `summary` | 없음 | 에이전트 도구 설정 패널 및 칩 툴팁에 표시되는 요약 설명입니다. |
| `risk` | `unknown` | 도구 보안 정책 판정에 사용되는 기본 위험 등급입니다. 하단 [도구 보안](#도구-보안)을 참조하십시오. |
| `gated` | `True` | `False` 설정 시 보안 정책 검증을 생략합니다. 보안상 검증 생략이 완전히 안전한 사유가 있을 때만 사용하십시오. |
| `assignable` | `True` | `allowed_mcp_servers`를 통해 에이전트에 직접 할당 가능한 도구인지 여부입니다. |
| `tools_for(agent)` | 필수 | 발언 차례에 모델에게 주입할 도구 JSON 스키마 목록을 반환합니다. |
| `run(call)` | 필수 | 단일 도구 호출을 실행하고 `(결과 문자열, 상태)` 튜플을 반환합니다. 상태는 `"success"` 또는 `"error"`입니다. |
| `guidance(tools)` | `None` | 시스템 프롬프트에 동적 주입할 지침 텍스트입니다. |
| `definition(tail, description, parameters)` | 기본 제공 | 도구 스키마 생성을 지원하는 헬퍼 메서드입니다. |
| `enabled_for(agent)` | 자동 확인 | 특정 에이전트에게 도구 권한을 부여할지 검사합니다. |
| `risk_of(tool_name)` | `risk` 반환 | 개별 도구별로 서로 다른 위험 등급을 적용할 때 오버라이드합니다. |

`run` 메서드에 전달되는 `call` 객체 필드:

| 필드 | 설명 |
| :--- | :--- |
| `call.agent` | 도구를 호출한 에이전트 인스턴스 |
| `call.name` | 모델이 호출한 전체 도구 식별자 |
| `call.arguments` | 도구 인자 딕셔너리 (모델이 생성한 값이므로 철저한 유효성 검증 필요) |
| `call.session_id` | 현재 대화 세션의 UUID |
| `call.workspace` | 현재 세션의 작업 공간 디렉터리 경로 (미지정 시 None) |
| `call.tools` | 현재 턴에 주입된 도구 스키마 목록 |

### 플러그인 개발 시 준수 사항

- **상태의 세션 격리**: 플러그인 객체는 싱글턴으로 모든 대화 세션이 공유합니다. 인스턴스 속성에 세션 가변 상태를 저장하지 마십시오.
- **비동기 논블로킹 실행**: `run` 메서드는 메인 이벤트 루프에서 실행됩니다. 파일 I/O나 네트워크 통신 등 블로킹 연산은 반드시 `await asyncio.to_thread(...)`를 사용하여 백그라운드 스레드로 오프로드하십시오.
- **예외의 관찰 변환**: 도구 실패 시 예외를 직접 발생시키지 말고 `("실패 사유", "error")` 튜플로 반환하여 모델이 오류를 관찰하고 자가 교정할 수 있도록 유도하십시오.
- **출력 크기 자동 축약**: 도구 반환 결과가 지나치게 길 경우 시스템 상한에 맞춰 자동으로 앞뒤 일부만 요약 축약됩니다.
- **도구 식별자 네임스페이스 준수**: `tools_for`가 반환하는 스키마의 이름은 `접두사__tail` 형식이어야 하고, `tail`은 `tails`에 포함되어 있어야 합니다. 형식이 맞지 않는 스키마는 발언마다 도구 목록에서 제외되며 서버 로그에 경고가 기록됩니다. 플러그인 등록 자체는 정상 처리되므로, 도구가 보이지 않으면 로그를 확인하십시오. `definition()` 헬퍼를 사용하면 이름이 올바르게 생성됩니다.

## 도구 보안

플러그인 도구 호출은 일반 MCP 도구와 동일하게 [도구 보안 정책](08-tool-security.md)의 엄격한 판정을 거칩니다.

| `risk` | 읽기 전용 | 기본 | 검토 | 자동 |
| :--- | :--- | :--- | :--- | :--- |
| `read`, `state` | 실행 | 실행 | 실행 | 실행 |
| `write`, `exec` | 거부 | 실행 | 묻기 | 실행 |
| `outside`, `delete`, `exec_flagged`, `net` | 거부 | 묻기 | 묻기 | 실행 |
| `unknown` (밝히지 않음) | 거부 | 묻기 | 묻기 | 실행 |

사용자가 상주하지 않는 환경(헤드리스 API, 내장 MCP 서버)에서는 '묻기' 정책이 '거부'로 자동 전환됩니다.

보안 규칙은 `mcp(접두사/도구이름)` 형식으로 지정합니다.

```json
"tool_security": {
  "deny": ["mcp(ticket/*)"],
  "allow": ["mcp(glossary/lookup)"]
}
```

**보안 게이트의 한계 인식**: 도구 보안 정책은 도구 호출의 실행 허용 여부만을 판단하며, 플러그인 내부 파이썬 코드의 세부 동작까지 감시하지는 못합니다. 파일 경로 인자 검증이나 시스템 파일 보호는 플러그인 구현체 내부에서 자체적으로 엄격히 방어해야 합니다.

### 디렉터리 보호 규칙

- 에이전트의 파일 조작 도구는 플러그인 디렉터리에 대한 파일 읽기/쓰기가 전면 차단됩니다.
- 기본 작업 공간(Workspace) 내부의 경로는 플러그인 디렉터리로 등록할 수 없습니다. 에이전트가 코드를 실행하여 해당 디렉터리에 파일을 생성한 후 차기 기동 시 임의 코드가 실행되는 보안 위협을 방지하기 위함입니다.

## 문제 해결 및 진단

로드에 실패한 플러그인이 있더라도 메인 서버 기동이 중단되지 않습니다. 실패 원인은 토론 전략 선택 메뉴 옆의 주황색 경고 아이콘, [`GET /api/plugins`](../05-reference/01-http-api.md) API 응답, 서버 기동 로그에서 확인할 수 있습니다.

| 현상 | 원인 및 해결 방법 |
| :--- | :--- |
| 파일을 추가했는데 목록에 나타나지 않음 | 서버를 재시작했는지 확인하십시오. 파일명이 `_`로 시작하거나 `plugins.disabled` 목록에 등록되어 있는지 확인하십시오. |
| `구체 클래스를 찾지 못했습니다` 에러 | `BaseDebateStrategy` 또는 `HostToolProvider`를 올바르게 상속했는지, 필수 속성(`name`, `display_name` 등)이 구현되었는지 확인하십시오. |
| `이미 쓰입니다` 에러 | 내장 전략 이름이나 기존 별칭, 타 플러그인과 중복된 식별자입니다. 이름을 변경하십시오. |
| `MCP 서버 이름과 겹칩니다` 에러 | `conf.json`의 `mcp_servers`에 동일한 접두사 이름이 존재합니다. 플러그인 접두사나 MCP 서버 이름을 변경하십시오. |
| `기본 작업 공간 안의 폴더는 읽지 않습니다` 에러 | 플러그인 디렉터리 위치를 기본 작업 공간 외부의 독립 디렉터리로 변경하십시오. |
| 도구를 활성화했으나 모델이 인식하지 못함 | 대화의 에이전트 구성(도구 할당 포함)은 해당 대화의 첫 턴이 시작될 때 고정됩니다. 이미 메시지를 보낸 대화에는 변경된 할당이 적용되지 않으므로 새 대화 세션을 생성하여 확인하십시오. |
| 타임라인에 `[발언자 지명 실패]` 메시지 발생 | 전략 메서드 실행 중 예외가 발생했거나 발언자가 선정되지 않았습니다. 해당 라운드는 우선순위 순서로 안전하게 대체 진행되었습니다. |
| 플러그인 삭제 후 대화 세션의 전략이 변경됨 | 알 수 없는 전략으로 지정된 세션은 기본 전략(순차 토론)으로 자동 폴백합니다. 웹 화면에서 해당 대화를 열거나 설정을 변경하거나 메시지를 전송하면 기본 전략 이름이 대화 레코드에 저장되므로, 플러그인을 복원해도 이전 전략으로 자동 복귀하지 않을 수 있습니다. 복원한 뒤 전략 선택 메뉴에서 다시 선택하십시오. |
