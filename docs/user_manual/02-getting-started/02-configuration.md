# conf.json 설정

> 상위: [시작하기](README.md) · 이전: [설치와 첫 실행](01-installation.md)

`conf.json`은 MADO 시스템의 **배포 설정 단일 정본(Source of Truth)**입니다. 에이전트 목록, 모델 지정, 엔드포인트 URL, 자격 증명, 도구 권한, 발언 순서, MCP 도구 서버 목록이 모두 이곳에 선언됩니다.

구현 메커니즘과 원리는 [설정 레이어](../03-core/01-config-layer.md) 문서를 참고하시기 바랍니다. 본 문서는 각 설정 항목을 "무엇을 어떻게 작성해야 하는가"를 안내합니다.

---

## 전체 구조

```json
{
  "app":         { },
  "llm":         { "sequential_thinking": { } },
  "mcp_servers": { "<서버이름>": { } },
  "agents":      { "<에이전트키>": { "sequential_thinking": { } } }
}
```

---

## JSON 에 없는 두 가지 규칙

### 주석 — `//` 로 시작하는 키

표준 JSON 사양에는 주석 문법이 정의되어 있지 않습니다. MADO 시스템은 **객체 키가 `//` 접두사로 시작할 경우 개발자 설명 주석으로 간주하고 파싱 시 안전하게 필터링**합니다. 값은 단일 문자열 또는 여러 줄을 표현하는 문자열 배열 형태로 작성할 수 있습니다.

```json
"// filesystem": [
  "공용 작업 공간 파일 I/O (공식 서버, 도구 14종).",
  "지정한 디렉터리 밖 경로는 서버가 자체적으로 차단합니다."
],
"filesystem": { "command": "${NODE_BIN:-node}", "enabled": true }
```

설명 주석 자체가 유효한 JSON 키-값 데이터의 일부이므로, 웹 UI 화면에서 에이전트를 추가하거나 삭제하더라도 파일 내의 주석이 지워지지 않고 안전하게 보존됩니다.

### 여러 줄 글 — 문자열 배열 활용

`system_prompt`나 `prompt_template`과 같은 장문의 프롬프트는 문자열 배열 형태로 줄 단위로 나누어 작성할 수 있으며, 시스템이 읽어 들일 때 개행 문자(`\n`)로 자동 결합합니다. 장문의 지침을 `\n` 이스케이프 문자로 한 줄에 뭉개어 작성하지 않아도 되므로 사람이 직접 읽고 편집하기에 매우 용이합니다.

```json
"system_prompt": [
  "당신은 수석 소프트웨어 아키텍트입니다.",
  "확장성과 유지보수성을 고려하여 구조를 제안하세요."
]
```

## `app` — 서버 기동

```json
"app": {
  "host": "${APP_HOST:-${HOST:-127.0.0.1}}",
  "port": "${APP_PORT:-${PORT:-8000}}",
  "db_url": "${APP_DB_URL:-sqlite+aiosqlite:///./multiagent.db}",
  "debug": true
}
```

| 키 | 타입 | 기본값 | 설명 |
| :--- | :--- | :--- | :--- |
| `host` | str | `127.0.0.1` | Uvicorn 바인딩 호스트 주소입니다. |
| `port` | int | `8000` | HTTP 서비스 포트입니다 (문자열로 입력해도 정수로 자동 변환됩니다). |
| `db_url` | str | `sqlite+aiosqlite:///./multiagent.db` | 비동기 SQLAlchemy 연결 URI입니다. |
| `debug` | bool | `true` | 코드 변경 감지 자동 재시작 및 상세 DB 쿼리 로깅 활성화 여부입니다. |

### 원격 접속 토큰 (다른 PC 에서 접근 시)

MADO는 기본적으로 로컬 루프백(`127.0.0.1`) 환경에서만 인입 요청을 허용합니다. 동일 폐쇄망 내의 다른 PC에서 원격 접속하여 협업하려면 `APP_HOST=0.0.0.0`으로 개방하고, **서버 머신의 관리자(소유자)가 발급한 토큰을 통해 로그인**하도록 통제합니다.

| 접속 유형 | 접근 제어 규칙 |
| :--- | :--- |
| 서버 머신 로컬 접속 (`127.0.0.1`, `::1`) | 추가 인증 없이 즉시 이용 가능합니다. 우측 상단 정보(ⓘ) 버튼 옆에 관리용 **열쇠 아이콘**이 표시됩니다. |
| 외부 네트워크 원격 접속 | `/login` 페이지에서 관리자 토큰 입력 필수. 인증 성공 시 세션 쿠키가 **7일간** 유지됩니다. 우측 상단에 로그아웃 버튼이 제공됩니다. |
| 토큰 누락 또는 형식 오류 시 | 외부 네트워크 인입 접속을 **전면 차단**합니다 (보수적 실패 방어: 토큰 설정을 실수로 누락하더라도 외부로 문이 열리지 않습니다). |

**하위 호환 — 외부에 개방된 서버인데 `.env`에 토큰이 누락된 경우:** 토큰 기능 도입 전부터 `0.0.0.0`으로 운용하던 인스턴스는 업데이트 직후 토큰이 부재합니다. 서버 머신에서 **최초로 화면을 여는 순간** 신규 난수 토큰을 자동 생성하여 `.env`에 저장 및 적용하고 팝업으로 알립니다: "외부 유저 인증 토큰이 없어 새 토큰(`토큰`)으로 서버를 시작했습니다. `.env`에 저장하였습니다." 그 전까지 외부 PC의 접근은 엄격히 차단됩니다. 단, `127.0.0.1`로만 개방된 서버, 이미 유효한 토큰이 존재하는 경우, 혹은 `.env`에 **값이 기재되어 있으나 형식이 잘못된 경우**(소유자의 의도적 설정을 임의 덮어쓰지 않음)에는 자동 생성하지 않습니다.

- **토큰 규격**: `.env` 파일의 `MADO_ACCESS_TOKEN` 설정값입니다. 영문 대소문자와 숫자로 구성된 **정확히 24자리 문자열**이어야 합니다. `.env` 파일은 Git 버전 관리와 폐쇄망 배포 번들에서 철저히 제외됩니다.
- **열쇠 관리 창 (서버 머신 로컬 전용)**: ① `.env` 파일의 토큰 반영 — 수동 편집한 토큰을 서버 재기동 없이 즉시 메모리에 적용합니다. ② 신규 난수 토큰 생성 후 `.env` 저장 — 암호학적 난수로 새 토큰을 생성하여 파일 저장에 성공했을 때만 메모리에 반영하며 모달 창에 단 1회 표시합니다. 어느 쪽이든 **기존의 모든 원격 세션이 일괄 만료**되어 로그인 페이지로 리다이렉트됩니다.
- **잠긴 IP 해제 기능 (서버 로컬 전용)**: 무차별 대입 실패로 차단된 IP 목록과 잔여 시간을 확인하고, `해제` 또는 `모두 해제` 버튼을 통해 15분의 타임아웃을 즉시 해제할 수 있습니다.
- **보안 감사 로그**: 인증 잠금 및 해제 이력은 `data/security/login_audit.jsonl` 파일에 구조화되어 영구 기록됩니다. **사용자가 입력했던 토큰 평문은 절대 기록하지 않습니다.** 파일 크기가 5MB를 초과하면 로테이션을 수행합니다.
- **차단 메커니즘**: 모든 페이지, 웹소켓 채널, `/api/*` 경로, 파일 다운로드를 최외곽에서 검증하는 단일 보안 미들웨어(`app/security.py`)가 전담합니다. 5회 연속 인증 실패 시 해당 IP를 15분간 차단하며, 로컬 루프백 요청에 대해서도 Host 및 Origin 헤더를 엄격히 검증하여 악성 웹사이트의 CSRF/DNS 리바인딩 공격을 원천 차단합니다.

> ⚠️ **기본 통신에 HTTPS 암호화가 적용되어 있지 않습니다.** 동일 내부망에서 패킷 스니핑이 가능한 사용자가 존재할 경우 로그인 토큰과 쿠키가 탈취될 수 있습니다. 암호화 채널이 필요한 환경이라면 `ssh -L 8000:127.0.0.1:8000 서버머신`과 같이 SSH 로컬 포트 포워딩 터널을 구성하여 접속하십시오.
>
> ⚠️ **리버스 프록시 뒷단에 직접 배치하지 마십시오.** 모든 인입 요청이 프록시의 루프백 주소(`127.0.0.1`)로 유입되어 누구나 관리자 권한을 획득하는 보안 사고가 발생합니다.

## `llm` — 전역 LLM 기본값

여기에 선언된 기본값들은 개별 에이전트 설정에서 동일한 키를 **명시적으로 오버라이드하지 않는 한** 모든 에이전트에게 일괄 상속됩니다. 사내 공용 게이트웨이나 로컬 추론 서버를 연동할 때는 이 전역 설정 블록 하나만 수정하시면 됩니다.

| 키 | 타입 | 기본값 | 설명 |
| :--- | :--- | :--- | :--- |
| `model` | str | `openai/gpt-4o` | LiteLLM 규격의 `<공급자>/<모델명>` 문자열입니다. |
| `api_base` | str | – | 대상 엔드포인트 URL입니다 (`api_url`, `base_url`로 기재해도 동일하게 인식됩니다). |
| `api_key` | str | – | 인증 API 키입니다 (로컬 추론 모델인 경우 비워둘 수 있습니다). |
| `api_version` | str | – | Azure OpenAI 전용 API 버전입니다. |
| `provider` | str | – | LiteLLM 공급자 타입을 강제 지정할 때 사용합니다. |
| `temperature` | float | `0.4` | 생성 다양성을 조절하는 샘플링 온도값입니다 (0.0 ~ 2.0). |
| `top_p` | float | – | 뉴클리어스 샘플링 확률 임계치입니다. |
| `max_tokens` | int | `4096` | 단일 응답당 최대 출력 토큰 상한선입니다. |
| `max_context_window` | int | `128000` | **모델 엔드포인트의 실제 수용 한도에 맞추어 반드시 설정하십시오.** |
| `timeout` | float | `600` | 응답 청크 간 최대 대기 시간(초)입니다. 전체 응답 완료 시간이 아니라 스트리밍 침묵 허용 시간이므로 길게 설정하는 것을 권장합니다. |
| `num_retries` | int | `2` | 일시적 네트워크 장애 시 자동 재시도 횟수입니다. |
| `drop_params` | bool | `true` | 대상 엔드포인트가 지원하지 않는 부가 파라미터를 자동 필터링합니다. |
| `max_tool_iterations` | int | `30` | 단일 발언 내에서 허용되는 MCP 도구 호출 루프 최대 횟수입니다 (1~100). |
| `extra_headers` | dict | `{}` | 사내 게이트웨이 요구 커스텀 HTTP 헤더 맵입니다. |
| `extra_body` | dict | `{}` | 상류 요청에 포함할 커스텀 JSON 바디 필드입니다. |

> **`max_context_window` 설정 시 주의사항**: 토론의 전체 대화 이력(전사)이 이 설정값을 기준으로 자동 절삭됩니다. 실제 모델의 물리적 수용 한도보다 과도하게 크게 지정할 경우, 잘리지 않은 채 초과 토큰이 전송되어 엔드포인트로부터 400 Bad Request 오류를 반환받게 됩니다.

### 상속 규칙

- 개별 에이전트 설정에서 값을 비워두거나(`${VAR}`가 빈 문자열로 치환된 경우) 항목 자체를 생략하면 `llm` 전역 설정을 그대로 상속받습니다.
- 상호 호환 별칭 그룹 중 하나만 지정하더라도 그룹 전체의 기본값을 덮어씁니다: `api_base`/`api_url`/`base_url`, `provider`/`custom_llm_provider`.

## `llm.sequential_thinking` — 단계적 사고

```json
"sequential_thinking": {
  "enabled": true,
  "mode": "prompt",
  "max_steps": 5,
  "show_steps": true
}
```

| mode | 동작 방식 | 권장 적용 대상 |
| :--- | :--- | :--- |
| `prompt` | 순차적 단계별 사고 프로토콜을 시스템 프롬프트에 자동 주입합니다. | 로컬 모델을 포함한 모든 일반 LLM |
| `native` | `reasoning_effort` 또는 `thinking` 파라미터를 API 요청 본문에 직접 전달합니다. | 공급자 네이티브 추론 지원 모델 (OpenAI o-series, Claude 3.7 등) |
| `mcp` | sequential-thinking MCP 공식 도구 서버를 강제 호출하도록 유도합니다. | 해당 MCP 서버가 활성화된 환경 |

`show_steps: false`로 설정할 경우 최종 결론 텍스트만 토론 피드에 노출하고 중간 사고 과정은 접어둡니다. `native` 모드에서는 `reasoning_effort`(`minimal`|`low`|`medium`|`high`) 및 `thinking_budget_tokens` 파라미터를 추가 지정할 수 있습니다.

개별 에이전트 블록의 `sequential_thinking` 설정은 전역 설정과 **키 단위로 병합**되므로, 변경을 원하는 특정 옵션만 부분 선언하시면 됩니다.

## `mcp_servers` — 도구 서버

```json
"filesystem": {
  "command": "${NODE_BIN:-node}",
  "args": [
    "${MCP_NODE_HOME:-./mcp_node}/node_modules/@modelcontextprotocol/server-filesystem/dist/index.js",
    "${WORKSPACE_DIR:-./workspace}"
  ],
  "enabled": true
}
```

| 키 | 타입 | 기본값 | 설명 |
| :--- | :--- | :--- | :--- |
| `command` | str | 필수 | 실행 파일 명령어입니다 (`node`, `python` 등). |
| `args` | list[str] | `[]` | 프로세스 기동 시 전달할 명령행 인자 목록입니다. |
| `env` | dict[str,str] | `{}` | 자식 프로세스에 주입할 추가 환경변수 맵입니다. |
| `enabled` | bool | `true` | 비활성화(`false`) 시 서버 프로세스를 기동하지 않습니다. |

기본 탑재된 도구 서버들의 상세 사양은 [MCP 호스트](../03-core/04-mcp-host.md#기본-구성-서버) 문서를 참고하시기 바랍니다.

## `agents` — 에이전트 정의

```json
"architect": {
  "name": "System Architect",
  "role": "High-Level Architecture & Tech Stack",
  "model": "${ARCHITECT_MODEL:-${LLM_MODEL:-anthropic/claude-3-5-sonnet-20241022}}",
  "api_base": "${ARCHITECT_API_BASE}",
  "api_key": "${ANTHROPIC_API_KEY}",
  "temperature": 0.5,
  "debate_priority": 20,
  "debate_stance": "proponent",
  "allowed_mcp_servers": ["filesystem", "memory", "fetch"],
  "system_prompt": [
    "당신은 수석 소프트웨어 아키텍트입니다.",
    "시스템 아키텍처 설계, 모듈 분리, 기술 스택 선정을 전담합니다."
  ]
}
```

| 키 | 타입 | 기본값 | 설명 |
| :--- | :--- | :--- | :--- |
| `name` | str | 필수 | UI 화면에 표시되는 에이전트 이름입니다. |
| `role` | str | 필수 | 에이전트의 전문 도메인 역할 설명입니다. |
| `enabled` | bool | `true` | 비활성화(`false`) 시 에이전트 풀에 등록되지 않습니다. |
| `allowed_mcp_servers` | list[str] | `[]` | 해당 에이전트에게 호출 권한이 허용된 MCP 도구 서버 목록입니다. |
| `debate_priority` | int | `100` | 라운드 내 발언 순서입니다. 값이 작을수록 선순위이며, 동일할 경우 파일 선언 순서를 따릅니다. |
| `debate_stance` | str | `neutral` | 토론 진영 속성이며 `proponent`(제안), `critic`(비판), `neutral`(중립)을 지원합니다 (디베이트 전략에서 활용). |
| `system_prompt` | str \| list[str] | `""` | 에이전트의 기본 시스템 프롬프트(페르소나)입니다. |
| 기타 LLM 파라미터 | – | `llm` 상속 | `model`, `api_base`, `temperature` 등의 설정을 개별 오버라이드할 수 있습니다. |

**`orchestrator` 키는 필수 항목입니다.** 누락될 경우 스키마 검증에서 즉시 거절되며, UI 상에서도 비활성화하거나 삭제할 수 없습니다. 오케스트레이터는 토론 진행 총괄과 최종 종합 보고서 작성을 전담하는 시스템의 핵심 제어자이기 때문입니다.

## 환경변수 치환

모든 문자열 타입 설정값에 적용됩니다.

| 문법 포맷 | 치환 동작 |
| :--- | :--- |
| `${VAR}` | 해당 환경변수가 없으면 빈 문자열로 치환되어 "미설정" 상태로 간주되고 상위 설정을 상속합니다. |
| `${VAR:-기본값}` | 해당 환경변수가 없으면 지정한 기본값을 채택합니다. |
| `${A:-${B:-기본값}}` | 다단계 중첩 치환을 완벽히 지원합니다. |

시스템 특수 환경변수:

| 환경변수명 | 용도 및 기본 동작 |
| :--- | :--- |
| `PYTHON_BIN` | 파이썬 MCP 도구 서버 실행기입니다. 미지정 시 **메인 앱과 동일한 파이썬 인터프리터**(`sys.executable`)로 자동 바인딩됩니다. |
| `NODE_BIN` | Node.js 실행 바이너리입니다 (기본값: `node`). |
| `MCP_NODE_HOME` | Node MCP 도구 서버 설치 디렉터리 경로입니다 (기본값: `./mcp_node`). |
| `MCP_SANDBOX_HOME` | 파이썬 샌드박스 서버 디렉터리 경로입니다 (기본값: `./mcp_sandbox`). |
| `WORKSPACE_DIR` | 에이전트 공용 작업 공간 디렉터리입니다. **애플리케이션 기동 시 절대 경로로 자동 정규화**됩니다. |

`WORKSPACE_DIR`을 절대 경로로 고정하는 이유: 파일 시스템 서버(Node.js)와 샌드박스 서버(Python)는 서로 독립된 프로세스이며 각자의 현재 작업 디렉터리(cwd)를 기준으로 상대 경로를 해석합니다. 이를 절대 경로로 고정하지 않으면 동일한 `./workspace` 경로를 전달하더라도 두 서버 프로세스가 서로 다른 물리 디렉터리를 참조하는 치명적인 경로 불일치 결함이 발생하기 때문입니다.

## 엔드포인트 설정 예시

### 사내 OpenAI 호환 게이트웨이

```json
"llm": {
  "model": "openai/qwen2.5-coder-32b",
  "api_base": "https://llm-gateway.mycorp.com/v1",
  "api_key": "${CORP_LLM_TOKEN}",
  "extra_headers": { "X-Team": "platform" }
}
```

### Ollama (API 키 불필요)

```json
"model": "ollama_chat/qwen2.5-coder:14b",
  "api_base": "http://localhost:11434"
```

### LM Studio / vLLM

```json
"model": "openai/local-model",
"api_base": "http://localhost:1234/v1",
"api_key": "lm-studio"
```

### Azure OpenAI

```json
"model": "azure/my-gpt4o-deployment",
"api_base": "https://my-resource.openai.azure.com",
"api_version": "2024-10-21",
"api_key": "${AZURE_OPENAI_API_KEY}"
```

## 호출 모드 판정

에이전트가 실제 언어 모델을 호출할 수 있는 상태인지(`is_live`)는 다음 순서로 결정됩니다.

1. `api_base` 엔드포인트 URL이 선언되어 있는 경우 → `live` 모드로 판정합니다.
2. `api_key` 자격 증명이 선언되어 있는 경우 → `live` 모드로 판정합니다.
3. 모델명이 `ollama/`, `ollama_chat/`, `lm_studio/`로 시작하는 경우 → `live` 모드로 판정합니다.
4. 그 외의 경우 → **`unconfigured`**로 판정합니다. 에이전트의 발언 차례에 통신 실패로 처리되며 시스템 기록에 남습니다.

## 편집 시 주의

- 웹 UI(로스터 패널)에서 수정한 설정값 역시 이 파일에 자동으로 영속화됩니다. 만약 애플리케이션 실행 중에 외부 텍스트 에디터로 파일을 직접 수정하셨다면 상단의 **`conf.json 다시 읽기`** 버튼을 클릭하여 변경 사항을 동기화하십시오.
- 현재 진행 중인 토론 세션이 존재할 경우 설정 충돌을 방지하기 위해 웹 UI에서의 설정 편집이 안전하게 잠깁니다.
- JSON 문법 오류가 발생할 경우 콘솔에 **행 번호와 열 번호**가 명확히 보고됩니다.
- 초기 템플릿의 서식 공백(빈 줄)은 첫 화면 편집 및 저장 시 표준 JSON 규격으로 정규화되면서 제거됩니다 (데이터 값과 주석 내용은 완벽히 보존됩니다).
